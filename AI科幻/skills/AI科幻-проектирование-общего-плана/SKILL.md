# AI科幻-проектирование-общего-плана (Проектирование общего плана — ИИ-фантастика)

Это жанровая обёртка и совместимый вход. При срабатывании этого навыка **в первую очередь обязательно принудительно загрузить** текущий жанровый Skill и `通用-设计总大纲`; текущий жанровый Skill отвечает за жанровые критерии и границы вердикта, `通用-设计总大纲` — за общий каркас и общий процесс.


<!-- ===== Layer 3: кэш сценария ===== -->

## Соответствующий общий Skill

- `通用-设计总大纲`

## Обязанности слоя

- Сохранять жанровое входное имя «AI科幻-проектирование-общего-плана».
- Маршрутизировать общий каркас уровня общего плана в `通用-设计总大纲`.
- Продолжать сохранять жёсткие правила жанра ИИ-фантастики на уровне общего плана: цепочка данных, честное рассуждение, системное трение, система нумерации, согласование файловой группы уровня общего плана.

## Дополнения жанра ИИ-фантастики (продолжают сохраняться)

- Общий план по умолчанию понимается как «файловая группа уровня общего плана», а не только правка `小说总大纲.md`.
- Три слоя `M0 / X / C` обязаны и далее опираться на жёсткие зацепки: цепочку данных, изменения пула подозреваемых, системное трение и систему нумерации.
- Каждое дело в матрице сюжетных случаев-юнитов должно чётко указывать: какой пазл оно продвигает для основной линии, какой проверяемый носитель оставляет, какую цену для персонажей или изменение границ правил приносит.
- Нельзя писать общий план ИИ-фантастики как тематическую инструкцию; обязательно непрерывно сохранять инженерное выражение «кто что сделал → какие следы данных / номер оставил → к какому последствию привело».

## Обязательные требования

- Нельзя в обход `通用-设计总大纲` писать другой параллельный набор общих правил.
- При ссылке на общие способности ссылаться только по названию, без пути.
- Общий план обязан реально подключить усиленную поверхность истории, критерии оценки подписания и обещание первого тома к файловой группе уровня общего плана, нельзя оставлять их «плавать» по отдельности.

## Инженерное определение исходного жанра (сохраняется)

- «Общий план» в этом Skill **по умолчанию не означает единственно** `小说大纲/小说总大纲.md`.
- Он означает взаимосвязанную **файловую группу уровня общего плана**, которая как минимум включает:
	- `小说大纲/小说总大纲.md`
	- `小说大纲/故事面/`
	- `小说大纲/伏笔与回收总纲.md`
	- `小说大纲/故事多面体大纲.md`
	- И другие связанные файлы уровня общего плана, такие как `时间轴_总表.md`, индекс общего плана, матрицы / реестры уровня сводных таблиц и т. п.
- Поэтому, когда пользователь говорит «измени общий план», по умолчанию следует сначала определить, это **правка одного файла** или **согласованная правка уровня общего плана**; если пользователь явно не ограничил, нельзя механически править только `小说总大纲.md`.
- Если пользователь устно использует формулировку вроде «общий план предзнаменований и перекличек», в текущем репозитории единообразно обрабатывать как `小说大纲/伏笔与回收总纲.md`.

## Когда использовать
- Пользователь хочет создать, переписать или изменить план уровня всей книги.
- Целевой файл относится к файловой группе уровня общего плана, например `小说总大纲`, `故事面/`, `伏笔与回收总纲`, `故事多面体大纲`, индекс общего плана, планирование уровня сводных таблиц.
- Основное внимание задачи — на загадке основной линии `M0`, побочных поверхностях истории `Xxx`, матрице сюжетных случаев-юнитов `Cxx`, межтомовом продвижении и приёмке уровня общего плана.

## Разделение обязанностей со входным Prompt
- Входной Prompt продолжает отвечать за **общие правила**: позиционирование авторской версии исполнения, стратегию записи файла, исследование и глубокое мышление, жёсткие критерии цепочки данных, источники вердикта, взаимодействие временной оси и реестров, общий контроль качества.
- Этот Skill отвечает только за **специальные правила уровня общего плана**, чтобы не продолжать нагромождать во входном Prompt шаблон общего плана, приёмку общего плана и специальные ограничения общего плана.

## Порядок выполнения по умолчанию

1. Сначала по входному Prompt обработать общие ограничения и стратегию записи целевого файла.
2. Подтвердить, что текущая задача относится к «уровню общего плана», и не втягивать по ошибке задачи частей / томов.
3. Выполнить [специальные правила проектирования общего плана](references/总纲专属设计规则.md).
4. При выводе строго сверяться с [шаблон общего плана и приёмка](references/总纲模板与验收.md).
5. Если пользователь дополнительно просит продолжить разбиение на части / тома, сначала окончательно утвердить общий план, затем вызывать `AI科幻-проектирование-плана-тома`.

## Минимальная сдача уровня общего плана

- Чётко указать, какие файлы уровня общего плана затрагивает данное изменение и какие обязательно нужно синхронно согласовать.
- Фраза-«фишка» всей книги и точки дифференциации.
- Загадка основной линии `M0`: условие загадки, истина, цена.
- Важные побочные линии `X01+` и матрица единичных дел `C01+`.
- Траектория межтомного продвижения, стратегия завязок и развязок, чек-лист приёмки уровня общего плана.
- Пометки о конфликтах и предложения по правке в связи с биографиями персонажей, временной осью, реестрами зацепок / пула подозреваемых.

## Запрещённое

- Подменять краткое содержание истории тематическими концепциями.
- Писать общий план в гранулярности планов томов и глав.
- Давать только «пояснение настроек», не давая «кто что сделал → какие следы данных оставил, какую цену повлёк».
- Прыгать к детальному разбиению на тома без закрытия общего плана.
