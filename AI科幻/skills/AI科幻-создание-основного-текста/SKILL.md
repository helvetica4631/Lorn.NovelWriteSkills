# AI科幻-создание-основного-текста (Создание основного текста — ИИ-фантастика)

Это жанровая обёртка, совместимый вход и слой маршрутизации.


<!-- ===== Layer 3: кэш сценария ===== -->

## Соответствующий общий Skill

- `通用-创建小说正文`

## Обязательные требования

- Нельзя в обход `通用-创建小说正文` писать параллельный набор общих правил.
- При ссылке на общие способности ссылаться только по названию, без пути.
## Обязанности слоя

- Сохранять стандартное входное имя «AI科幻-создание-основного-текста».
- Маршрутизировать общий каркас создания основного текста в `通用-创建小说正文`.
- Добавлять в жанре ИИ-фантастики умолчательную рамку Qidian, реальное системное сопротивление, носители следов данных, границы реальных номеров и правила записи в рабочий файл автора.

## Жанровые references для дальнейшего чтения

- `references/题材正文创作补充规则.md`
- `references/控制卡落正文与镜头化桥接.md`

## Справочник частых триггерных слов / формулировок пользователя

- Помоги написать основной текст этой главы ИИ-фантастики
- Сразу оформи эту главу как основной текст
- Награды в середине этой главы не хватает, заодно впиши её
- Перепиши эту главу в рамке ИИ-фантастики
- Запиши прямо в файл главы

## Порядок комбинированных вызовов по умолчанию

1. `通用-创建小说正文`
2. `AI科幻-управление-горячими-и-холодными-линиями`
3. `AI科幻-генерация-контрольной-карточки-главы`
4. `AI科幻-исполнение-сценической-единицы`
5. По обстоятельствам дополнительно вызвать `AI科幻-усиление-начала-главы` / `AI科幻-усиление-хука-конца-главы`
6. Если `

## 作者有话说` (слово автора) склоняется к разбору технических событий, объяснению сеттинга или прямому спойлеру, затем вызвать `AI科幻-шлифовка-слова-автора`
7. При финальной очистке по необходимости вызвать `AI科幻-шлифовка-основного-текста` и `AI科幻-устранение-духа-ии`

## Пояснение о комбинации для подряд идущих глав

- Задачи с подряд идущими главами или подхватом старых линий больше не пересылаются через нестандартные комбинированные входы.
- Перед написанием сначала через `AI科幻-управление-горячими-и-холодными-линиями` определить, какие старые проблемы, старые персонажи, старые отношения, старые следы данных подошли к окну возврата.
- Затем через `AI科幻-генерация-контрольной-карточки-главы` намертво зафиксировать линию, которую эта глава обязана продвинуть, награду в середине, действие в поле следов данных и хук конца главы.
- Затем контрольную карточку в первую очередь разобрать через `AI科幻-исполнение-сценической-единицы`, при необходимости продолжить разбор через `AI科幻-исполнение-диалога-конфликта` и `AI科幻-исполнение-сцены-в-ограниченном-пространстве`.
- После написания, если глава реально продвинула старую линию или следы данных, вернуться в `AI科幻-управление-горячими-и-холодными-линиями` для обновления минимального динамического состояния и послезаписного реестра.

## Обязательные требования

- При срабатывании этого навыка в первую очередь обязательно принудительно загрузить текущий жанровый Skill и `通用-创建小说正文`.
- Перед тем как оформлять основной текст, обязательно внимательно прочитать биографии персонажей, фактически появляющихся в этой главе, и документы сеттинга / фона, связанные с фоном, технологиями, правилами, системной логической цепочкой следов данных этой главы.
- Нельзя начинать писать лишь по жанровой инерции, краткому изложению плана главы, впечатлению от предыдущей главы или отдельному фрагменту; если ключевой источник вердикта отсутствует, сначала нужно его восполнить, найти или явно заблокировать, и лишь затем переходить к построению основного текста.
- Умолчательная версия основного текста — исходная версия главы для Qidian, по умолчанию записывается в `小说正文/`.
- В основном тексте, эпиграфе главы и

## 作者有话说` (слово автора) не должно быть управленческих номеров на стороне автора; исключение — реальные номера внутри сюжета.
- `

## 作者有话说` (слово автора) по умолчанию должно писаться как читательский мини-театр «городская микродеталь + немного запоздалого страха или холодной усмешки + один небольшой вопрос»; нельзя переписывать его в разбор технических событий, итоги творчества или институциональный комментарий.
- `

## 章节后记` (послесловие к главе) по умолчанию продолжает использовать полный шаблон `通用-创建小说正文`, охватывая как минимум: позиционирование главы, сверку приземления функциональных точек, регистрацию точек 爽, предзнаменования и развязки, подачу сеттинга/процедур, развитие персонажей, элементы следов данных, тип хука, проверку цифровой дисциплины, записи об отклонениях, дальнейшую подводку, читательские привлекающие точки и рекомендации по оптимизации.
- Нельзя писать процедуры, следы данных и институциональное сопротивление как учебник; нужно писать как то, что переживает персонаж.
- Если пользователь явно не требует «только обсудить, не сохранять в файл», обязательно записывать прямо в целевой файл Markdown.
- Построение основного текста по умолчанию должно позволять обратно проверить, исполнено ли обещание контрольной карточки; если награда в середине, поле следов данных или эскалация опасности в конце главы, указанные в контрольной карточке, не вошли в основной текст, построение считается незавершённым.
