# Дополнительные правила замкнутого цикла жанрового плана (ИИ-фантастика)

## Правило фиксации основного отчёта

- Для одного общего плана / тома / единичного случая по умолчанию ведётся только один действующий основной отчёт рецензии.
- Каждая повторная рецензия обязана перезаписывать один и тот же основной отчёт, нельзя заводить ответвления «вторая версия / третья версия».
- Только если комплексная оценка в последнем отчёте строго больше порога, разрешается остановить замкнутый цикл.

## Правила разведения по объектам

- Слой общего плана: в первую очередь проверять питание главной линии, нарастание механизма, вход технической реальности, долгую загадку и платформенную рамку жанра.
- Слой тома: в первую очередь проверять подхват вышестоящего, ритм тома, награды в середине глав, распределение хуков, отношения единичных случаев и мозаики главной линии.
- Слой единичного случая: в первую очередь проверять честную дедукцию, носитель следов данных, системную логическую цепочку, изменение пула подозреваемых и то, смогут ли отголоски питать главную линию.

## Нижняя граница рецензии и правки ИИ-фантастики

- Никакая правка не должна терять инженерное выражение «кто что сделал → какие следы данных/номера оставил → какую цену вызвал».
- Нельзя править план ИИ-фантастики в инструкцию по теме, краткое изложение общественного комментария или пустой атмосферный рекламный текст.
- Нельзя ради высокой оценки смолоть технические якоря жанра, технические срезы, системное трение и цифровое давление в нейтральный черновик интриги.

## Что в первую очередь править при возврате на переплавку

1. Дрейф позиционирования жанра
2. Недостаточное питание главной линии
3. Незамкнутость ключевой цепочки данных / процедур / времени
4. Дисбаланс подхвата томов и расстановки по главам
5. Несостоятельность цены персонажей и цепочки отношений

## Напоминание об условии остановки

- `9.2` не считается прохождением.
- Только `综合评分 > 9.2` (комплексная оценка > 9.2) разрешает завершить замкнутый цикл.
- Если оценка не прошла порог, обязательно продолжать «рецензия → правка → повторная рецензия», нельзя только давать рекомендации, не правя файл.

## Обязательный порядок первого раунда цикла

- Первый раунд цикла обязан сначала полностью пройти: определение основного отчёта → первичная рецензия → чтение оценки → правка плана → перезапись того же основного отчёта.
- Нельзя из-за наличия старого отчёта, старой высокой оценки или «выглядит достаточно хорошо» пропускать первичную правку / повторную рецензию.
- Оценка лишь после каждой повторной рецензии определяет, продолжать ли переплавку, нельзя заранее предугадывать и пропускать шаги.

## Патч определения основного отчёта

- Для одного объекта ведётся только один действующий основной отчёт рецензии; если попадается несколько отчётов по одному объекту, по умолчанию использовать версию с самой поздней датой.
- Каждая повторная рецензия обязана перезаписывать один и тот же основной отчёт, нельзя заводить ответвления «вторая версия / третья версия / исправленная версия».
- В чате можно пояснять «в этом раунде перезаписано / создано заново», но на стороне файлов всегда сохраняется только одна цепочка действующего основного отчёта.

## Патч стадии правки

- При правке обязательно одновременно ориентироваться на: перечень проблем прошлого раунда, рекомендации по исправлению прошлого раунда и направление усиления «рывок к 9.2+».
- Правка обязана записываться прямо в целевой файл плана, нельзя останавливаться на черновике-совете в чате.
- При возврате плана ИИ-фантастики на переплавку в первую очередь править: позиционирование жанра, питание главной линии, замкнутость следов данных / процедур / временной цепочки, подхват томов, цену персонажей и цепочку отношений.
