# Базовая таблица POV платформ (руководство по созданию и шаблон)

Этот файл состоит из двух частей:

- **Верхняя часть: руководство по созданию** — механизм взаимодействия, принципы красных линий, справочные данные для запросов, критерии аудита (для принятия решений, в файлы проекта не записывается)
- **Нижняя часть: выходной шаблон** — после заполнения записывается прямо в `平台POV基线表/[作品名]-平台POV基线表.md` проекта и регистрируется в `Agents.md`

Две части разделены строкой `--- ⭐模板输出分隔线⭐ ---` (разделитель вывода шаблона). При создании файла проекта выводится только часть ниже разделителя.

## Верхняя часть: руководство по созданию и справочные данные

> Содержимое ниже — вспомогательная информация для принятия решений, **в файлы проекта не записывается**.

### 1. Механизм взаимодействия Skill

**Файл базовой линии POV проекта — единственный авторитетный источник лица повествования для всех Skill `общий-вывод-*` и `общий-адаптация-под-платформы`.**

При выполнении каждый Skill обязан:

1. **Сначала прочитать** файл базовой линии POV проекта, найти текущее зафиксированное лицо целевой платформы.
2. Если в файле базовой линии **нет записи об этой платформе**, Skill должен по «анализу применимых сценариев» этой платформы (встроенному в `POV 选择指南` каждого Skill) создать в файле базовой линии запись и зафиксировать лицо, затем продолжить выполнение.
3. Если в файле базовой линии **уже есть запись об этой платформе**, прямо наследовать зафиксированное значение, внутри Skill заново не решать.
4. Любой дрейф лица повествования (отклонение от зафиксированного значения файла базовой линии) обязан записывать причину отклонения в `适配策略/` и приводить доказательства по пунктам.

**Базовая линия POV не фиксирует лицо наперёд — разные романные проекты на одной платформе могут использовать разные лица, базовая линия лишь фиксирует выбор текущего проекта.**

### 2. Красные линии, оговорённые заранее

1. **Платформа допускает двойную колею — это не означает, что в одном томе на одной платформе можно туда-сюда переключать передачи.**
2. **Интонация заголовка — не POV основного текста.** Появление в заголовке «я», «имя главного героя», «он» считается лишь слабым сигналом, окончательно решает основной текст.
3. **Если в главе несколько файлов, сначала выбрать canonical, потом исправлять POV.** Иначе легко получить, что по ходу правки тебя «кусает» старая версия.
4. **Основной повествовательный каркас этой книги определяет итоговую логику решения для платформ с двойной колеёй.** Нужно смотреть не только на общие предпочтения платформы, но и на текущий способ инженерного несения этой книги.
5. **При использовании этого шаблона для нового проекта лицо повествования по каждой платформе нужно определять с нуля**, ориентируясь на встроенный анализ применимых сценариев в каждом Skill `общий-вывод-*` (раздел `POV 选择指南`), нельзя прямо копировать зафиксированные значения других проектов.

### 3. Справочные данные по адаптации лица повествования к платформам

#### Общие красные линии для всех платформ

- **Абсолютно запрещён всеведущий взгляд**: на всех платформах во всех жанрах нельзя использовать всеведущее третье лицо. Всеведущий взгляд разрушает вовлечение и интригу и является общей запретной зоной всех платформ.
- **Ограниченный взгляд — единственный выбор**: выбирать одно из двух — первое лицо с ограниченным знанием или третье лицо с ограниченным знанием, в одной главе смешивать нельзя.
- **Переключение взгляда строго контролируется**: в одной главе ≤ 1-2 переключений, каждое должно сопровождаться чёткой границей сцены или меткой главы.

### 4. Правила заполнения базовой таблицы

Каждая строка заполняется по следующим правилам:

- **Платформа**: название платформы, совпадающее с названием платформы в имени Skill `общий-вывод-*`
- **Применимые сценарии**: для каких сценариев подходит каждое из двух лиц на этой платформе (из `POV 选择指南` соответствующего Skill выделить 1–2 фразы, помогающие последующим принимающим решения понять «почему именно такой выбор»)
- **Текущая фиксация**: `первое лицо` или `третье лицо`, выделить жирным
- **Причина фиксации**: 1–3 фразы, объясняющие «почему эта книга на этой платформе выбирает это лицо» — единственное основание для последующего аудита и возврата к логике решения при доработке
- **Примечание к исполнению**: жёсткие ограничения уровня исполнения (например, запрет на какую-то операцию, допустимое исключение, особая формулировка для конца главы/заголовка и т. п.)

При заполнении «применимых сценариев» источники для справки:

- «Сценарии, где выигрывает первое/третье лицо» в разделе `POV 选择指南` каждого Skill `общий-вывод-*`
- Таблица «Быстрая справка по сценариям платформ» в `CommonSkills/общий-адаптация-под-платформы/references/карточка-двусторонней-смены-лица-и-точки-зрения.md`

### 5. Критерии суждения при последующем аудите

#### 1. Критерий начала

- Смотреть только первые 4 непустые строки основного текста
- Заканчивать перед `## 作者有话说` / `## Author...`
- Игнорировать первую строку файла H1

#### 2. Критерий основного текста

- После удаления прямой речи в кавычках считать сигналы первого / третьего лица в основном тексте
- Для платформ первого лица смотреть: нет ли «почти нет „я“ во всей главе» или «подавляющего преобладания третьего лица»
- Для платформ третьего лица смотреть: нет ли «основная часть главы превратилась в повествование от „я“»

#### 3. Патч ручной перепроверки

- Если заголовок и основной текст конфликтуют, приоритет у основного текста
- Если в первых 4 строках POV не проявился, но в середине основного текста явно «переключили передачу», ручная перепроверка может повысить уровень риска
- Если в главе две версии, сначала выбрать canonical, потом делать вывод по POV
