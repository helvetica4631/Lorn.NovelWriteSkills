## Когда использовать

- Переписать главу любого жанра в версию, лучше подходящую читателям платформы Toutiao.
- Нужно усилить хук начала, драйвер взаимодействия, сильный сюжет и малую избыточность.
- Нужно дать жанровым обёрткам единый общий каркас платформы Toutiao.

## Случаи, когда не применяется

- Только дополнение границ жанра, без основы вывода на платформу.
- Только оркестрация нескольких платформ, сохранение в файлы и итоговая проверка, без обработки самого стиля платформы Toutiao.

## Пояснение об оптимизации кэша

Структура этого Skill следует принципу оптимизации префиксного кэша; при вызове:

- **Кэш-слой 1 (неизменен всегда)**: frontmatter + обязанности слоя + жёсткие правила платформы + запреты + контракт POV → при каждом вызове полностью одинаков, префиксный кэш LLM API попадает постоянно, оплата по минимальной цене
- **Кэш-слой 2 (неизменен в рамках платформы)**: правила автообнаружения шаблона платформы + список references + порядок выполнения по умолчанию → меняется только при смене платформы или регистрации нового шаблона
- **Изменяемый слой (меняется каждый раз, в этот файл не записывается)**: номер целевой главы, путь к исходнику, особые ограничения платформы, заданные пользователем → пользователь задаёт при каждом вызове, оплата по обычной цене входа

Биографии персонажей, настройки истории, шаблоны писательских исследований и прочие references объявляются обязательными к загрузке через `## 继续读取的 references`; их неизменная часть загружается вместе с этим Skill в кэшируемый префикс.

## Правила автообнаружения шаблона платформы

Если в корне обслуживаемого проекта есть `Agents.md`, перед выводом версии для Toutiao обязательно:

1. Прочитать `Agents.md` в корне проекта
2. Если в `Agents.md` зарегистрированы три вида шаблонов, искать по такому приоритету:
   - **Приоритет**: шаблон того же вида, у которого в поле «适用平台» при регистрации указано `今日头条`
   - **Откат**: шаблон того же вида, у которого в поле «适用平台» при регистрации указано `默认`
   - **Игнорировать**: шаблоны, у которых в поле «适用平台» указана другая платформа (например, `番茄`, `起点`), в этом раунде не загружаются
3. Если найдены подходящие шаблоны трёх видов — прочитать файлы шаблонов по соответствующим путям:
   - шаблон писательского исследования: как дополнительное базовое ограничение платформы Toutiao
   - шаблон авторского стиля: как ориентир для сохранения базового тона и границ стиля версии для Toutiao
   - шаблон образца произведения: как ориентир для сохранения структуры начала главы / награды / хука
4. Если в корне проекта нет `Agents.md` или в нём не зарегистрированы шаблоны, специфичные для Toutiao, — откат к общему режиму по умолчанию, это не мешает обычному выводу
5. Главное ограничение этого Skill всегда одно: правила платформы > безопасность и соответствие нормам > факты материнского текста > ограничения трёх шаблонов. Три шаблона вспомогательны и не меняют правила вывода на платформу

## Порядок выполнения по умолчанию

1. Сначала зафиксировать неизменяемый слой исходника: факты, цепочку событий, цепочку улик, отношения персонажей и причинно-следственный порядок нельзя испортить.
2. Прочитать `题材名-输出今日头条版` Skill соответствующего жанра и подтвердить жанровый вход и отношения маршрутизации.
3. Затем прочитать `references/平台共性执行细则.md` и `references/分节级补救映射与详细规则回填.md` этого Skill и выполнить усиление темпа платформы Toutiao, расстановку цепляющих точек, жёсткий хук в конце главы и оптимизацию свойств социальных медиа.
4. Жанровая обёртка продолжает читать свои жанровые references, фиксируя границы жанра, запреты жанра и специальные жанровые патчи (как страховочные ограничения).
5. При условии «приоритет у платформы, жанр страхует» выполнить переписывание текста, обеспечив одновременно платформенное выражение и сохранность исходника.
6. Только в последнюю очередь заниматься снижением сходства; нельзя ради снижения повтора разрушать цепляющую силу для мобильных и драйвер продолжения в конце главы.
7. Выполнить сверку контракта POV, убедиться в соответствии `platformPovContract`, недопустим несанкционированный дрейф лица повествования.
8. После завершения переписывания обязательно сразу выполнить пять самопроверок из раздела «Самопроверка и правка после вывода», пропускать нельзя.
9. Если самопроверка не пройдена, нужно по выводу вернуть на доработку и перепроверить, и только после «самопроверка пройдена / правка по самопроверке завершена» можно сохранять в файл.

## Самопроверка и правка после вывода (обязательно, пропускать нельзя)

Сразу после завершения переписывания и вывода обязательно выполнить самопроверку этого раздела; по найденным проблемам вносить исправления на месте, и только после подтверждения прохождения можно сохранять в файл. **Пропускать этот шаг ни по какой причине нельзя.**

**Пять самопроверок:**

0. **Объём в норме**: основной текст и `## 作者有话说` должны ориентироваться на «диапазон объёма по умолчанию на платформе» этого Skill (или значение, переопределяемое в `Agents.md` проекта). Пока основной текст не достиг рекомендуемой нижней границы, рекомендуется сначала вернуть на доработку и добрать объём. **Категорически запрещено набирать объём шаблонной добавкой слов или механическим расширением**; если обнаружено загрязнение шаблонными фразами, нагромождение объясняющей интонации или бессмысленные повторы, самопроверка считается проваленной даже при достаточном объёме, и текст нужно переписать.
1. **Нулевое добавление фактов**: в переписанной версии не появилось ключевых фактов, персонажей или настроек, которых нет в исходнике; если появились — удалить / восстановить.
2. **Ключевая цепочка событий полна**: причина → продвижение → кульминация → направление хука в конце главы — всё отражено в переписанной версии; при разрыве — восстановить.
3. **Стиль платформы соблюдён**: переписанная версия удовлетворяет всем пунктам «минимальной поставки» этого Skill (или требованиям к ключевому стилю платформы); если не хватает — править на месте.
4. **Нет загрязнения шаблонными фразами**: нет двух и более подряд групп фраз в объясняющей интонации / шаблонной интонации / из слов-«формулировок»; при срабатывании весь абзац возвращается на доработку.
5. **POV согласован**: POV переписанной версии согласуется с уже зафиксированным `platformPovContract`; при дрейфе — вернуть на доработку и исправить.

**Формат вывода (обязательно выдавать):**

- Всё в норме: `[自检通过] 五项均达标，可落盘。` (самопроверка пройдена: все пять пунктов в норме, можно сохранять в файл)
- Исправлено и в норме: `[自检修订完成] 已修订：<问题描述>，现五项均达标，可落盘。` (правка по самопроверке завершена: исправлено <описание проблемы>, теперь все пять пунктов в норме, можно сохранять)
- Не пройдено (сохранять нельзя): `[自检未通过] 命中：<问题描述>，需继续处理。` (самопроверка не пройдена: обнаружено <описание проблемы>, нужно продолжать обработку)

Если выведено «не пройдено», обязательно исправить и заново вывести заключение самопроверки; цикл повторяется, пока не будет выведено «пройдено» или «правка завершена», и только тогда можно сохранять в файл.

## Контракт POV и непрерывность (обязательно)

- Если вызов идёт через оркестрацию `общий-оркестрация-вывода-на-платформы`, обязательно унаследовать зафиксированный этим процессом `platformPovContract`; заново решать вопрос о лице повествования внутри этого Skill нельзя.
- Если пользователь вызывает этот Skill напрямую, то перед переписыванием обязательно сначала вывести и зафиксировать `platformPovContract` по тексту исходника и по уже завершённым предыдущим главам текущей платформы; приоритет по умолчанию: явное указание пользователя > уже завершённые предыдущие главы текущей платформы > существующая цепочка POV исходника > первая прошедшая глава текущей партии.
- Без разрешения нельзя тихо переводить подряд идущие главы из третьего лица в первое или наоборот; если исходная глава сама является главой со сменой точки зрения / серией глав с несколькими точками зрения, выполнять можно только по зарегистрированному `switchPlan`, нельзя менять «оболочку» на ходу.
- Явную проверку POV обязательно выполнять и до, и после сохранения в файл и записывать результат в журнал или запись выполнения; для китайских платформ по умолчанию используется `scripts/pov_validate.py` или `scripts/run_pov_gate.ps1` с `lang=zh` или `auto` для сверки блоков текста; при цепочке от третьего лица проверяется наличие первого / второго лица вне диалогов, при цепочке от первого лица — наличие якорей первого лица вне диалогов.

## Заглавная картинка главы и промпты для иллюстраций (обязательно для каждой главы)

При сохранении в файл платформенной версии каждой главы в конце файла (после `## 作者有话说` и `## 章节后记`) обязательно добавляй блок «заглавная картинка главы и промпты для иллюстраций», чтобы дать промпты, которые можно напрямую подавать в модели генерации изображений ИИ. В этом разделе выдаются только тексты промптов, сами картинки не выдаются.

### Структура вывода

Конец файла организуется в таком порядке:

1. **Промпт заглавной картинки (картинка начала главы / картинка заголовка главы)**: 1 штука, для карточки главы и показа начала главы на платформе; выбирается из ключевого яркого кадра или ядра образа этой главы.
2. **Промпты иллюстраций (картинки внутри текста)**: на каждую главу 0–2 картинки (по умолчанию 1; если в главе нет визуализируемого яркого кадра — не делать, лучше меньше, чем лишнее); к каждой картинке обязательно одновременно дать место вставки и промпт генерации.

### Правила места вставки иллюстраций (обязательно)

- Формат описания места каждой иллюстрации: `插在第 N 段末（段首句："……"）` — сначала номер абзаца, затем повторное уточнение по первым 8–15 знакам этого абзаца, чтобы не было неоднозначности.
- **Иллюстрации всегда вставляются после конца абзаца (между абзацами), запрещено вставлять посреди абзаца, запрещено разбивать или переписывать абзацы ради иллюстрации.**
- Запрещены расплывчатые описания вроде «в подходящем месте текста», «около кульминации».

### Нулевое загрязнение текста (обязательно)

- В текст нельзя вставлять никаких заполнителей изображений, `[插图]`, `（此处配图）`, HTML-комментариев и прочих якорей или меток; текст платформенной версии остаётся чистым.
- Информация о месте иллюстраций пишется только в блоке промптов иллюстраций в конце файла; когда иллюстрации не вставляются, текст можно целиком скопировать для загрузки, и ничто не мешает.

### Требования к качеству промптов

- Промпты заглавной картинки и иллюстраций обязаны быть полными, пригодными для прямого копирования промптами для генерации изображений ИИ (с субъектом, средой, светом, композицией, цветовой гаммой, стилем и негативными словами), нельзя писать абстрактные описания или советы по письму.
- Промпты должны быть тесно связаны с содержанием главы; запрещены универсальные шаблонные картинки; между несколькими главами одной партии нельзя повторно использовать один и тот же набор промптов.

## Формулировки вывода по умолчанию

- По умолчанию выдаётся одна версия производного от Toutiao текста, которую можно сразу сохранять в файл или направлять на итоговую проверку платформы.
- По умолчанию сохраняются ключевая цепочка событий исходной главы, логическое продвижение в среднем темпе, плотность хуков начала и постоянный драйвер продолжения чтения в конце главы.
- Сохранить реалистичные якоря исходной главы, логическую цепочку дела / события, цену для персонажей и точки для обсуждения.
- Читаться должно как длинный сериал детективного расследования, оптимизированный для социальных медиа без потери глубины содержания.

## Минимальная поставка

- Есть явные цепляющие точки Toutiao (конфликт в начале, награда в середине главы, дискуссионный хук в конце главы).
- Сохранить ключевую цепочку событий исходной главы и поддающуюся разбору цепочку улик, не добавляя ключевых фактов.
- Есть точки для обсуждения, которые можно комментировать и которыми можно делиться, но без ущерба для самосогласованности логики.
- Текст заголовка главы проверяется по формулировке «сначала удалить номер главы вида `x.y.z ` и следующий за ним пробел, затем считать чистый заголовок»; чистый заголовок не должен превышать 20 знаков.
- Читаться должно так, чтобы это не походило на информационную заметку, не на шаблонную интонацию и не на лёгкую правку общеплатформенного текста, где просто сменили оболочку.

## Жёсткие правила

- Категорически запрещено выводить мусорные группы фраз вида «абстрактное самоописание + шаблонный глагол + слово-формулировка»; при появлении похожих шаблонных оборотов вроде «对照项落在… / 先把同一句话拆碎 / 先把顺滑的解释拆开 / 只求能追溯（复核、对得上）» это нужно признать загрязнением и вернуть на доработку весь текст.
- Строго запрещено использовать или косвенно вызывать следующие скрипты для генерации, расширения, склейки или снижения повтора основного текста: `scripts/append_cn_unique_monologue.ps1`, `scripts/append_cn_unique_narration.ps1`, `scripts/append_cn_unique_thirdperson.ps1`, `scripts/rephrase_cn_body.ps1`, `scripts/rephrase_en_body.ps1`, `scripts/cn_lexicon_profile_transform.ps1`. Эти инструменты не должны попадать в цепочку производства основного текста платформы.
- В текст платформы добавляется «гейт нулевого загрязнения шаблонными фразами»: в основном тексте не должно быть двух и более подряд фраз со структурой «я / с моей стороны / в душе я… + 把/将… + 对齐/校准/锁死/拆开… + союз + слово-формулировка + 只求/不求/先把…»; при совпадении — провал, независимо от того, прошли ли объём и сходство.
- Подряд идущие главы платформы обязаны подчиняться зафиксированному `platformPovContract`; нельзя в этом Skill самовольно переводить прежнюю стабильную цепочку на новую цепочку лица повествования.
- Если сработал несанкционированный переход POV или проверка POV провалена, нужно признать провал по `pov_drift_detected` / `pov_switch_without_approval` и вернуть на доработку весь текст.
- При срабатывании этого Skill обязательно одновременно загружать `题材名-输出今日头条版` Skill соответствующего жанра (если он существует).
- Правила, специфичные для жанра, нельзя записывать обратно в этот файл для параллельного ведения.
- При изменении общих правил платформы Toutiao в первую очередь меняй этот Skill, а не несколько жанровых входов.
- Производный текст платформы по умолчанию сохраняется в рабочий каталог этого Skill `今日头条/`.
- Каталог производного текста на уровне глав определяется структурой романа единообразно: если у произведения есть части, то он находится в `今日头条/第X部/第Y卷/`; если частей нет — в `今日头条/第X卷/`.
- Имя файла производного текста платформы по умолчанию без даты, следует существующему правилу синхронизации номера главы и заголовка платформы; дата используется только для сопутствующих производных материалов — отчётов рецензий, рецензий на книгу и т. п.
- Жёсткое ограничение длины заголовка главы платформенного текста: заголовок считается по чистому заголовку после «удаления номера главы вида `x.y.z ` и пробела за ним», чистый заголовок не должен превышать 20 знаков; при превышении нужно сначала сжать заголовок и только потом сохранять в файл.
- Ограничение длины заголовка не означает «чем короче, тем лучше»; на Toutiao в первую очередь нужно обеспечить плотность сильных хуков и точек для обсуждения, а в пределах лимита по возможности повышать цепляющую силу информации.
- Производный текст главы обязательно сохраняется в виде файла `.md`: если каталога соответствующей главы нет, перед выполнением нужно сначала создать полный путь каталога, затем записать переписанное содержимое главы в `.md`-файл в этом каталоге; нельзя только выдать черновик в чате и не записать в файл.
- Полный приоритет определения пути сохранения: ① явно указанный пользователем chapterPath → ② автоматический вывод по имени исходного файла и сведениям о части / томе → ③ если часть / том определить нельзя, приостановиться и спросить пользователя, нельзя выводить наугад и молча сохранять.
- После сохранения платформенной версии обязательно явно запустить гейт по объёму: **проверка объёма основного текста обязательно выполняется через `scripts/count-chapter.ps1`**, нельзя подменять `Len`, `NoWhitespaceLen`, счётчиком знаков редактора или прикидкой на глаз. Параметры объёма берутся из «диапазона объёма по умолчанию на платформе» этого Skill или значения, переопределяемого в `Agents.md` проекта; основной текст проверяется `scripts/count-chapter.ps1`; гейт основного текста смотрит только на `BodyCJK / MeetsMinCJK / WithinRange`, `MeetsMinCJK` обязательно `True`, `WithinRange` желательно `True`. `## 作者有话说` проверяется отдельно через `scripts/count-afterword.ps1`.
- На этапе генерации рекомендуется сначала достичь страховочной цели по объёму, и только затем разрешать сохранение в файл: ориентироваться на «диапазон объёма по умолчанию на платформе» этого Skill или значение, переопределяемое в `Agents.md` проекта.
- Пока безущербный перенос не завершён, нельзя удалять в исходном `输出今日头条版.prompt.md` ещё не отображённое содержимое.

## Границы с другими Skill / Prompt

- Этот Skill отвечает только за межжанровой общий каркас платформы Toutiao.
- Границы жанра, запреты жанра и специфичные для жанра формулировки по-прежнему обеспечивает соответствующий `题材名-输出今日头条版`.
- Жанровый Prompt должен маршрутизироваться только на `题材名-输出今日头条版`; не следует ставить этот Skill и жанровые refs как двойной вход.
