# общий-глубокое-исследование
> **Маршрутизация по жанру**: если в каталоге .github\题材专用Skills\ есть соответствующий Skill <жанр>-深度研究, то:
> - Жанровый скелет маршрутизируется в <жанр>-深度研究; этот Skill находится в каталоге .github\题材专用Skills\.
> - При срабатывании этого навыка необходимо в первую очередь принудительно загрузить текущий Skill вместе с <жанр>-深度研究.


Это не поверхностное действие вроде «поискать, какие есть материалы» и не формальное отписывание несколькими ссылками из поисковой выдачи, а тем более не выдача общеэнциклопедических знаний за применимые выводы исследования письма.

Цель этого Skill — разложить «тему, которую романисту нужно изучить глубоко», на полный рабочий процесс, который можно **планировать, глубоко искать, проверять, сохранять в файл и на который могут ссылаться другие Skill**:

- Сначала по **семи исследовательским доменам** написания романа определяется направление и измерения исследования;
- Затем создаётся структурированный план исследования (items + fields), после **подтверждения человеком** запускается параллельный глубокий поиск;
- Каждый пункт исследования глубоко прорабатывается специальным поисковым агентом, по пунктам собирается структурированная информация, пригодная для творчества;
- Наконец, всё сводится в Markdown-отчёт, который можно напрямую сохранить в `调研报告/` (тесно связано с проектом) или в `исследования-письма/` (универсальное / по жанру).

Основано на архитектуре проекта [Deep-Research-skills](https://github.com/Weizhena/Deep-Research-skills), переработано в версию, специализированную для написания романов.

## Основные команды

| Команда | Описание |
|------|------|
| `/research <тема>` | Предварительное исследование: определить домен → создать outline.yaml + fields.yaml |
| `/research-deep` | Параллельный глубокий поиск: запускать поисковых агентов по пунктам, собирать структурированные данные |
| `/research-report` | Свести всё в Markdown-отчёт исследования, который можно сразу сохранить в файл |
| `/research-add-items` | Добавить пункты исследования |
| `/research-add-fields` | Добавить поля исследования |

## Рабочий процесс

```
/research "Тренды жанра городского саспенса на Qidian (起点中文网) в 2025–2026 годах"
    ↓ Определить домен: исследование трендов жанра
    ↓ Создать план (items: Топ-10 произведений / предпочтения читателей / тренды подписания… + fields)
    ↓ 【Контрольная точка 1】пользователь подтверждает/правит пункты и измерения исследования
/research-deep
    ↓ Параллельные web-search-agent выполняют глубокий поиск по пунктам
    ↓ Результаты записываются в results/
    ↓ 【Контрольная точка 2】сводка качества исследования → пользователь подтверждает
/research-report
    ↓ Свод в «Тренды жанра городского саспенса на Qidian.md» (起点中文网都市悬疑题材趋势研究.md)
    ↓ 【Контрольная точка 3】честные границы + самопроверка тройной верификацией
    ↓ Определить место сохранения: универсальное исследование жанрового уровня → сохранить в городской-саспенс/исследования-письма/
    （если тесно связано с проектом — сохранить в 项目根/调研报告/）
```

## Семь исследовательских доменов написания романа

Этот Skill сводит исследовательские потребности написания романа к следующим семи доменам. При каждом запуске `/research` необходимо сначала подтвердить из семи **основной домен исследования**, а затем создать соответствующие пункты и поля исследования.

### 1. Исследование трендов жанра
Динамика популярности жанра на целевой платформе, насыщенность, пространство для новшеств, миграция предпочтений читателей, новые поджанры.

**Типичные темы**:
- «Тренды детальных дорожек городского жанра на Qidian в 2026 году»
- «Эволюция популярных элементов жанра женской романтики на Fanqie Novel (番茄小说)»
- «Различия в показателях жанра детектива-расследования на бесплатных и платных платформах»

**Обслуживаемые Skill**: `общий-проектирование-позиционирования-жанра`, `общий-оценка-подписания-на-платформе`

### 2. Исследование экосистемы платформы
Портрет читателей платформы, предпочтения в содержании, механизм рекомендаций, стандарты подписания, правила распределения трафика, экосистема авторов.

**Типичные темы**:
- «Портрет читателей и особенности читательского поведения на бесплатной платформе Qimao (七猫)»
- «Тематические предпочтения и стандарты прохождения модерации в колонках Zhihu Yanxuan (知乎盐选)»
- «Система рекомендательных ресурсов Qidian в 2026 году и условия их получения»

**Обслуживаемые Skill**: `общий-оценка-подписания-на-платформе`, `общий-адаптация-под-платформы`

### 3. Исследование профессиональных знаний
Реальные детали какой-либо профессии, технологии, процедуры, научного принципа — для усиления достоверности, профессионального ощущения и незаменимости настроек истории.

**Типичные темы**:
- «Реальный процесс судебно-медицинской ДНК-экспертизы, временная шкала и типичные заблуждения»
- «Стандартные процедуры и внутренняя терминология расследования убийств китайской уголовной полицией»
- «Принципы технологии блокчейн и возможные применения в социальном управлении»

**Обслуживаемые Skill**: `общий-проектирование-настроек-истории`, `общий-исполнение-сценической-единицы`

### 4. Исследование сцены / среды
Конкретные особенности реального места, эпохи, типа здания, городского пространства — для усиления фактуры и убедительности описания сцен.

**Типичные темы**:
- «Повседневные детали «городской деревни» Гуанчжоу 2003 года»
- «Офисная экосистема и особенности пространства финансовых офисных зданий Луцзяцзуй в Шанхае»
- «Архитектурная планировка и внутренняя атмосфера китайского уездного отдела общественной безопасности»

**Обслуживаемые Skill**: `общий-исполнение-сцены-в-ограниченном-пространстве`, `общий-создание-основного-текста`

### 5. Исследование прототипов персонажей
Модели поведения, речевые привычки, психологические особенности, социальное положение определённой группы людей — для усиления достоверности и узнаваемости биографий персонажей.

**Типичные темы**:
- «Профессиональное выгорание и психологические механизмы совладания у китайских рядовых уголовных следователей»
- «Жизненное состояние и модели социального общения одиноких женщин в китайских мегаполисах 2020-х годов»
- «Реальный опыт и социальные настроения программистов, ставших курьерами доставки еды»

**Обслуживаемые Skill**: `общий-проектирование-биографии-персонажей`, `общий-исполнение-диалога-конфликта`

### 6. Исследование писательской техники
Принципы и классические примеры какого-либо повествовательного приёма, управления ритмом, диалоговой техники, проектирования интриги, компоновки точек удовлетворения.

**Типичные темы**:
- «12 классических типов хуков в конце главы и разбор хитов Qidian»
- «Стратегии защиты середины длинного романа от краха и структурное проектирование»
- «Сравнение повествовательных эффектов первого и третьего лица в детективе-расследовании»

**Обслуживаемые Skill**: `общий-усиление-хука-конца-главы`, `общий-усиление-начала-главы`, `общий-устранение-духа-ии`, `общий-шлифовка-основного-текста`

### 7. Исследование читателей / рынка
Предпочтения определённой читательской группы, привычки оплаты, сценарии чтения, причины отказа от книги, горячие темы обсуждений.

**Типичные темы**:
- «Порог чувствительности основных платных читателей мужского канала Qidian к „глупеющим“ персонажам»
- «Различия в предпочтениях точек удовлетворения у читателей бесплатных и платных платформ»
- «Распределение времени чтения, сценариев и устройств у китайских читателей веб-романов в 2025–2026 годах»

**Обслуживаемые Skill**: `общий-оценка-подписания-на-платформе`, `общий-адаптация-под-платформы`, `общий-анализ-конкурирующих-произведений`

## Границы и взаимодействие с `общий-анализ-конкурирующих-произведений`

Этот Skill и `общий-анализ-конкурирующих-произведений` находятся в **отношениях дополнения**, а не замены:

| Измерение | общий-глубокое-исследование | общий-анализ-конкурирующих-произведений |
|------|-------------|-----------------|
| Объект исследования | Широкие темы: жанры, платформы, знания, техника, читатели | Четырёхслойный глубокий разбор конкретных произведений-конкурентов |
| Форма результата | Отчёт исследования (Markdown): тесно связано с проектом → `调研报告/`, универсальное / по жанру → `исследования-письма/` | Отчёт анализа конкурентов, сохраняется в `竞对分析/` |
| Гранулярность исследования | Может охватывать от макротрендов до микродеталей | Фокус на глубоком разборе и сравнении одной / нескольких книг |
| Типичный триггер | «Помоги исследовать тренды городского саспенса 2026» | «Проанализируй, почему первые 5 книг рейтинга сильны» |

**Путь взаимодействия**:
- Результаты глубокого исследования (например, отчёт о трендах жанра) могут служить **предварительным знанием** для анализа конкурентов — помогают определить, какие произведения рейтинга стоит разбирать глубже.
- Выводы анализа конкурентов (например, сильные и слабые стороны какого-либо конкурента) могут служить **входом для пунктов** глубокого исследования — углубляться в пробел знаний, обнаруженный у конкурента.
- Оба Skill можно вызывать в одной задаче последовательно: сначала глубокое исследование области, чтобы создать познавательную основу, затем глубокий разбор конкурентов, чтобы зафиксировать конкретные эталоны.

## Правила места сохранения отчётов исследования

Место сохранения отчёта исследования делится на два класса в зависимости от связи содержания исследования с проектом:

### Тесно связано с проектом → `调研报告/`

Если тема исследования **напрямую обслуживает конкретный проект романа** (например, исследование профессиональных знаний, сцены и среды, прототипов персонажей «для проекта X»), отчёт следует сохранять в подкаталог **`调研报告/` в корневом каталоге этого проекта**.

Типичные ситуации:
- Исследование профессиональных знаний для романа, который сейчас пишется (например, судебно-медицинский процесс, принципы блокчейна) → `调研报告/`
- Исследование прототипов персонажей текущего проекта (например, профессиональное состояние рядового уголовного следователя) → `调研报告/`
- Историческая сверка среды для сцен текущего проекта (например, «городская деревня» Гуанчжоу 2003 года) → `调研报告/`

> Критерий: если выводы исследования имеют прямую пользу только для этого проекта, класть в `调研报告/`.

### Универсальное / по жанру → `исследования-письма/`

Если тема исследования **не привязана к конкретному проекту**, а представляет собой универсальное исследование трендов жанра, экосистемы платформы, писательской техники, рынка читателей, или связана лишь с каким-либо жанром, но не указывает на конкретный проект романа, её следует сохранять в подкаталог **`исследования-письма/` в корневом каталоге проекта**.

Типичные ситуации:
- «Тренды детальных дорожек городского жанра на Qidian в 2026 году» (общее по жанру) → `исследования-письма/`
- «Эволюция популярных элементов жанра женской романтики на Fanqie» (общее по жанру) → `исследования-письма/`
- «12 классических типов хуков в конце главы и разбор хитов Qidian» (общая писательская техника) → `исследования-письма/`

> Критерий: если выводы исследования могут быть использованы в нескольких проектах или относятся к накоплению знаний жанрового уровня, класть в `исследования-письма/`.

### Проверка перед сохранением

- Если в целевом каталоге уже есть отчёт исследования, относящийся к данной теме, **необходимо сначала его прочитать и учесть**, чтобы не повторять исследование той же темы, — но можно обновлять, углублять и дополнять.
- Правило именования файла отчёта: `{краткое_название_домена}_{краткое_описание_темы}.md`, например:
  - Тесно связано с проектом: `专业知识_法医DNA检验流程.md` (лежит в `调研报告/`)
  - Общее по жанру: `题材趋势_起点都市悬疑2026趋势.md` (лежит в `исследования-письма/`)
- Другие Skill (например, `общий-проектирование-настроек-истории`, `общий-проектирование-биографии-персонажей`) при необходимости могут получать выводы исследования, ссылаясь на отчёты из `调研报告/` или `исследования-письма/`.

## Правила сохранения результатов исследования (обязательно)

- Результат по умолчанию — **Markdown-отчёт исследования, на который можно напрямую ссылаться**; его необходимо записать обратно в файл, нельзя ограничиваться обсуждением в чате.
- Отчёт должен содержать: `## Тема исследования`, `## Методы исследования и источники`, `## Основные находки`, `## Выводы и рычаги, пригодные для творчества`, `## Источники информации`.
- Раздел «Выводы и рычаги, пригодные для творчества» обязан переводить находки исследования в **конкретные рекомендации, которые автор может прямо использовать в тексте, настройках и плане**, нельзя останавливаться на абстрактных резюме.
- Каждый ключевой вывод по возможности помечается источником информации и уровнем уверенности (высокий / средний / низкий), неопределённое обязательно указывается.
- Место сохранения определяется по **«Правилам места сохранения отчётов исследования»**: тесно связано с проектом → `调研报告/`, универсальное / по жанру → `исследования-письма/`.
- Если в ходе исследования обнаружен конфликт со старыми отчётами, приоритет у новых доказательств этого раунда, а конфликт и причина обновления явно указываются в отчёте.

### Честные границы (обязательно)

Каждый отчёт исследования должен содержать раздел «Честные границы», ясно описывающий ограничения исследования:

- **Дата отсечения информации**: момент исследования, изменения после него не охвачены.
- **Декларация пробелов информации**: по каким измерениям открытой информации очень мало, какие выводы основаны на предположениях по ограниченной выборке.
- **Перечень неопределённых пунктов**: чётко перечислить поля и пункты данного исследования, помеченные `[不确定]` (`[неопределённо]`).
- **Общая оценка уверенности**: дать общую оценку достоверности выводов всего исследования (высокая / средняя / низкая) с причинами.
- **Декларация «против здравого смысла»**: если какой-либо вывод не согласуется с общепринятым восприятием, явно пометить это и указать силу доказательств.

> Отчёту исследования, который не говорит, где его ограничения, доверять не стоит.

## Рамка проверки качества информации (тройная верификация Nuwa)

Не всякая найденная информация заслуживает записи в отчёт исследования. Трёхслойный фильтр, перенесённый из методологии верификации ментальных моделей nuwa-skill, обеспечивает, что каждый записанный в отчёт вывод выдержит проверку:

### Проверка 1: воспроизводимость между источниками
Появляется ли одна и та же находка / тренд / паттерн как минимум в **2 независимых источниках**?

- Пример: «читатели городского саспенса предпочитают социальный детектив» — подтверждается, только если встречается и в разделе отзывов Qidian, и в отраслевом анализе, и в обсуждениях читателей на Zhihu
- Появляется только в одном источнике → понизить до «версии для проверки», пометить `[待验证]` (`[требует проверки]`)
- Несколько источников противоречат друг другу → переход в процесс обработки противоречий (см. следующий раздел)

### Проверка 2: переносимость в творчество (порождающая сила)
Можно ли из этой находки **вывести конкретные творческие рекомендации**? Может ли она направить автора в написании сцены, проектировании персонажа, настройке ритма?

- Позволяет породить ≥2 конкретных творческих рекомендации → пройдено
- Остаётся на уровне абстрактного резюме вроде «этот жанр популярен», «читателям нравится XX» → не пройдено, отбросить или углубить поиск
- Порождающая сила — основной критерий, отличающий «вывод исследования» от «краткого изложения поиска»

### Проверка 3: различающая способность (исключительность)
Эта находка — **«и без слов ясная» банальность** или действительно информативное прозрение?

- Пример: «веб-романам нужны сильные конфликты» = банальность, в основные находки не включается
- Пример: «в городском саспенсе Qidian число комментариев к главе (本章说) у социального детектива в среднем в 2,3 раза больше, чем у чисто следственного» = информативное прозрение
- Банальные находки могут служить фоном, но не должны занимать место в разделе «Основные находки»

### Классификация результатов тройной верификации

| Число пройденных проверок | Уровень | Способ обработки |
|---------|------|---------|
| Все три пройдены | **Основная находка** | Записывается в основные находки отчёта, другие Skill могут ссылаться на неё как на вход высокой уверенности |
| Пройдены две | **Справочная находка** | Записывается в отчёт, помечается уровнем уверенности «средний» с указанием непройденного измерения |
| Пройдена только одна | **Версия для проверки** | Записывается в приложение отчёта, помечается `[待验证]`, сильных выводов не делается |
| Пройдено ноль | **Отбросить** | В отчёт не включается (возможно, случайная реплика в частном контексте или поисковый шум) |

| **Низкий** | Аналитические статьи самомедиа / личных блогов | Личное мнение | ★★ (только для справки) |
| **Наинизший** | Обзоры / резюме, сгенерированные ИИ | Могут содержать галлюцинации | ★ (нельзя использовать как единственное основание вывода) |

Следующие источники в исследовательские материалы не включаются:

- **Анонимные ответы на Zhihu / утверждения без источника**: личность и квалификацию нельзя проверить, высокая доля искажений информации

## Принципы обработки противоречий и неопределённости

Противоречивая информация, встреченная в ходе исследования, — это **сигнал, а не шум**. Противоречие часто обнажает напряжение темы — а для творца напряжение и есть пространство для письма.

### Три типа противоречий

| Тип | Особенности | Способ обработки |
|------|------|---------|
| **Временное противоречие** | Одно и то же в разные моменты проявляется по-разному (например, жанр бурно рос в 2024 году и остыл в 2025-м) | Записать траекторию изменений, пометить временное окно, опираться на новейшие данные, но сохранять историческую справку |
| **Источниковое противоречие** | Разные источники описывают одно и то же по-разному (например, рейтинги платформы и читательская молва расходятся) | Представить доказательства и позиции обеих сторон рядом, проанализировать возможные причины расхождения, жёстко не «мирить» |
| **Мнительное противоречие** | Разные группы дают противоположные оценки одному и тому же (например, приём пользуется успехом у опытных читателей и отвергается новичками) | Пометить портреты групп обеих сторон; само такое расхождение и есть «пространство выбора творца» |

### Запрещённые способы обработки ошибок
- ❌ Выбрать одну сторону, проигнорировать другую, сделав вид, что противоречия нет
- ❌ Придумать примиряющее объяснение, «замазав» противоречие
- ❌ Удалить всю находку из-за неопределённости

### Обработка при недостатке информации

| Ситуация | Обработка |
|------|------|
| По какому-то измерению очень мало открытой информации | Пометить «информации недостаточно», понизить уверенность по этому измерению |
| Есть только вторичная информация | Пометить «по сообщению [источник], без первичной проверки» |
| Информация противоречива, невозможно определить главное и второстепенное | Представить рядом, пусть пользователь судит сам |
| Ключевые данные недоступны (например, средние подписки / показатели следования) | Использовать косвенные сигналы (например, место в рейтинге / число комментариев к главе) и явно пометить как косвенные |

## Контрольные точки качества исследования

Исследование не заканчивается одним прогоном. По образцу поэтапного контроля качества nuwa-skill в ключевых узлах ставятся контрольные точки: мусор на входе — мусор на выходе; перехватить здесь гораздо дешевле, чем переделывать после сохранения отчёта.

### Контрольная точка 1: после подтверждения плана (результат /research → до запуска /research-deep)

Показать пользователю краткое содержание плана исследования и получить подтверждение:

```
Краткое содержание плана исследования
├── Тема исследования: [topic]
├── Основной домен: [domain]
├── Вспомогательные домены: [sub-domains, если есть]
├── Пунктов исследования: [N]
├── Полей исследования: [M]
├── Предварительная оценка пробелов информации: [предварительно: по каким измерениям информации может быть мало]
└── Продолжить /research-deep?
```

### Контрольная точка 2: после завершения глубокого поиска (/research-deep завершён → до запуска /research-report)

Автоматически подсчитать и показать сводку качества исследования:

```
┌──────────────────┬──────────┬──────────────────────────┐
│ Измерение                          │ Статус  │ Ключевые находки                            │
├──────────────────┼──────────┼──────────────────────────┤
│ Завершено пунктов                  │ N/N     │                                             │
│ Неопределённые поля                │ M шт.   │ [перечислить ключевые неопределённые поля]  │
│ Противоречия в информации          │ K мест  │ [перечислить основные противоречия]         │
│ Находки высокой уверенности        │ P шт.   │ [перечислить топ-3]                         │
│ Измерения с нехваткой информации   │ Q шт.   │ [отметить пробелы]                          │
│ Доля прошедших тройную верификацию │ X%      │ Распределение основные / справочные / для проверки │
└──────────────────┴──────────┴──────────────────────────┘
```

Пользователь подтверждает, что качество исследования в порядке → переход к /research-report. Пользователь считает, что по какому-то измерению недостаточно → дополнить исследование и затем продолжить.

### Контрольная точка 3: перед сохранением отчёта (после результата /research-report)

Контрольный список самопроверки:
- [ ] Содержит ли отчёт раздел «Честные границы»?
- [ ] У каждой основной находки есть поддержка ≥2 источников?
- [ ] В разделе «Выводы и рычаги, пригодные для творчества» есть ≥3 конкретных рекомендации, которые можно использовать сразу?
- [ ] Неопределённая информация явно помечена?
- [ ] Противоречивые находки сохранены (а не принудительно унифицированы)?
- [ ] Имя файла отчёта соответствует правилу `{краткое_название_домена}_{краткое_описание_темы}.md`?
- [ ] Подтверждено, что место сохранения верное (тесно связано с проектом → `调研报告/`, универсальное / по жанру → `исследования-письма/`)?
- [ ] Проверено, что в целевом каталоге нет дублирующего исследования?

## Кодекс вкуса исследователя

При трудном выборе возвращайтесь к этим принципам. Локализованы из методологии контроля качества nuwa-skill.

| Принцип | Пояснение |
|------|------|
| **Длинный текст > афоризм** | Отраслевой анализ на 3000 знаков раскрывает глубинную структуру лучше, чем 50 обрывочных постов |
| **Спор > консенсус** | Самые спорные приёмы / тренды лучше всего показывают творческие возможности — консенсус означает «красный океан» |
| **Изменение > неподвижность** | Траектория эволюции одного и того же явления несёт больше информации, чем статичный снимок |
| **Практики > комментаторы** | Рассуждения рядовых авторов / редакторов могут быть ценнее для творчества, чем резюме отраслевых медиа |
| **Негатив > позитив** | Почему читатель «бросил книгу» стоит изучать больше, чем почему «нравится» — причины отказа указывают на творческие нижние границы |
| **Мелкая гранулярность > макро** | «Реальный рабочий процесс определённой профессии» полезнее творцу, чем «общий обзор отрасли профессии» |

### Чего не делать никогда
- Принимать сгенерированный ИИ обзор / энциклопедию за первичную информацию
- Выдумывать несуществующие данные или тренды
- При нехватке информации принудительно генерировать «выглядящий полным» вывод
- Игнорировать находки, противоречащие общепринятому восприятию
- Довольствоваться первой страницей результатов поиска — самая ценная информация часто на 2–3-й странице

## Метод осознанной практики самого навыка исследования (новое — на основе колонки Zhihu «Исследование китайской веб-литературы» № 28)

Глубокое исследование само по себе — профессиональный навык, которому можно учиться осознанной практикой. Следующие четыре метода — общие приёмы письменной практики, обобщённые автором колонки; они также подходят для повышения качества исследования и отчётов:

### 1. Чтение с разбором
Найдите отличный отчёт исследования или качественный отраслевой анализ и смотрите на него не как читатель, а как на учебник. По пунктам спрашивайте себя:
- Как спроектированы пункты исследования? Почему выбраны именно эти измерения?
- Как основные находки извлечены из исходной информации? Какая классификационная рамка использована?
- Как «выводы и рычаги, пригодные для творчества» переведены в конкретные действия?
- Если бы мне пришлось переделывать эту тему, по каким измерениям я бы углубился?

### 2. Практика подражания
Разберите структуру и способ аргументации высококлассного отчёта и тем же способом сделайте отчёт на совершенно другую тему. Это не копирование содержания, а копирование методологии.

### 3. Исследование на время
Поставьте себе лимит времени: исследование средней сложности должно быть завершено за X часов. Лимит заставляет: отказаться от перфекционизма — сначала закончить, потом улучшать; вытаскивает интуитивное чутьё — многие хорошие исследовательские суждения возникают именно без излишнего раздумья.

### 4. Целевая тренировка слабых мест
Не нужно каждый раз проходить весь процесс исследования. Если ваши отчёты всегда страдают от «недостаточно острых основных находок», тренируйте именно шаг «извлечения ключевых прозрений из исходных материалов», подряд на 5 разных темах, каждая не более 500 знаков.

> Источник: колонка Zhihu «Исследование китайской веб-литературы» № 28 «Роман пишется плохо? Не унывайте, написание веб-романов — профессиональный навык, который можно осознанно тренировать», «Таверна Гули Мутуя»
> Уверенность: средняя — четыре метода в колонке являются общими приёмами письменной практики, здесь адаптированы под сценарий исследования; сами методы разумны, но специальной проверки в направлении написания отчётов нет
