# общий-глубокое-исследование-深度探索

## Способ запуска
`/research-deep`

## Процесс выполнения

### Шаг 1: автоматически найти Outline
Найти в текущем рабочем каталоге файл `*/outline.yaml`, прочитать список items, research_domain, конфигурацию execution (включая items_per_agent).

### Шаг 2: проверка возобновления с контрольной точки
- Проверить уже завершённые JSON-файлы в output_dir
- Пропустить уже завершённые items

### Шаг 3: выполнение по партиям
- Делить на партии по batch_size (для перехода к следующей партии после завершения предыдущей нужно согласие пользователя)
- Каждый агент отвечает за items_per_agent пунктов
- Запускать web-search-agent (в фоне параллельно, task output отключён)

**Получение параметров**:
- `{topic}`: поле topic в outline.yaml
- `{research_domain}`: поле research_domain в outline.yaml
- `{item_name}`: поле name item
- `{item_related_info}`: полное yaml-содержимое item (name + category + description и т. д.)
- `{output_dir}`: execution.output_dir в outline.yaml (по умолчанию `./results`)
- `{fields_path}`: абсолютный путь к `{topic}/fields.yaml`
- `{output_path}`: абсолютный путь к `{output_dir}/{item_name_slug}.json` (slugify для item_name: пробелы заменить на `_`, убрать спецсимволы)

**Жёсткое ограничение**: следующий prompt необходимо воспроизводить строго, заменяя только переменные в `{xxx}`; запрещено менять структуру или формулировки.

**Шаблон Prompt**:
```python
prompt = f"""## Задача
Как помощник глубокого исследования для романиста, исследуйте следующий объект, выведите структурированный JSON.

Тема исследования: {topic}
Домен исследования: {research_domain}
Объект исследования: {item_related_info}

## Определения полей
Прочитайте {fields_path}, чтобы получить определения всех полей.

## Требования к выводу
1. Выводить JSON по полям, определённым в fields.yaml
2. Значения неопределённых полей помечать [不确定] ([неопределённо])
3. В конце JSON добавить массив uncertain, перечисляющий названия всех неопределённых полей
4. Все значения полей должны быть на русском языке (процесс исследования может вестись на английском и китайском, но итоговые значения JSON — на русском; китайские термины, названия произведений и платформ можно давать в оригинале в скобках)
5. **Особое внимание полям категории «переносимость в творчество» (创作可迁移)**: нужно переводить находки исследования в конкретные рекомендации, которые романист может прямо использовать в тексте, настройках и плане, нельзя останавливаться на абстрактных резюме

## Стратегия поиска
В первую очередь искать информацию из источников следующих типов (акцент выбирать по домену исследования):
- Официальные данные романных платформ, списки, информация о рекомендательных позициях
- Обсуждения в читательских сообществах, отзывы, комментарии к главам (本章说), форумы
- Отраслевые исследовательские отчёты, статьи по методологии творчества
- Источники профессиональных знаний (техническая документация, профессиональные справочники, научные статьи)
- Интервью с писателями, обмен творческим опытом
- Документальные репортажи, документальные фильмы, статьи по выездным обследованиям, связанные со сценой / средой

## Путь вывода
{output_path}

## Проверка
После вывода JSON запустить скрипт проверки, чтобы убедиться в полном покрытии полей:
python {research_dir}/validate_json.py -f {fields_path} -j {output_path}
Задача считается выполненной только после успешной проверки.
"""
```

### Шаг 5: сводный отчёт и контрольная точка качества

По завершении всего необходимо вывести следующую **сводку качества исследования** (по методологии контрольной точки Phase 1.5 nuwa-skill), чтобы пользователь подтвердил её перед переходом к /research-report:

```markdown
## Сводка качества исследования

| Измерение | Статус | Пояснение |
| --- | --- | --- |
| Завершено пунктов | N/N | |
| Неопределённые поля | M шт. | [перечислить ключевые неопределённые поля] |
| Противоречия в информации | K мест | [перечислить основные противоречия, противоречия сохранять, не примирять] |
| Находки высокой уверенности | P шт. | [перечислить топ-3 основные находки] |
| Измерения с нехваткой информации | Q шт. | [отметить пробелы, честно сообщить, на какие вопросы не найдено удовлетворительных ответов] |
| Доля прошедших тройную верификацию | X% | Распределение: основные находки / справочные находки / версии для проверки |

### Ключевые сигналы
- **Подробности противоречий**: [по пунктам, противоречие — сигнал, а не шум]
- **Пробелы информации**: [что хотели найти, но не нашли]
- **Неожиданные находки**: [важная информация, не вошедшая в исходный план, но всплывшая при поиске]
```

**Пользователь подтверждает, что качество исследования в порядке → переход к /research-report.**

Пользователь считает, что по какому-то измерению недостаточно → дополнить исследование и затем продолжить.

> Смысл этой контрольной точки: качество исследования определяет потолок итогового отчёта. Мусор на входе — мусор на выходе; перехватить здесь гораздо дешевле, чем переделывать после сохранения отчёта.

## Правила качества информации (агент обязан соблюдать)

Следующие правила взяты из методологии контроля качества nuwa-skill и обязательны при глубоком поиске по каждому item:

### Приоритет источников
Результаты поиска должны следовать положению «Классификация источников информации и чёрный список» главного SKILL.md — в первую очередь использовать официальные данные платформ, рассказы практиков передовой, читательскую обратную связь; запрещено использовать источники из чёрного списка — анонимные ответы Zhihu, публичные аккаунты WeChat, Baidu Baike и т. п.

### Сохранение противоречий
Если разные источники описывают одно и то же по-разному, **представлять рядом**, помечать тип источника и достоверность каждого, насильно не примирять. Само противоречие — ценный творческий сигнал.

### Честные границы
В JSON-выводе каждого item все неопределённые поля обязательно помечать через массив `uncertain`. К неопределённому относятся случаи:
- Информация из единственного источника и не поддаётся перекрёстной проверке
- Актуальность информации под вопросом (старше 2 лет, обновлений не найдено)
- Низкая достоверность источника (самомедиа, личные блоги, анонимные посты)
- Поиск не охватил (открытой информации по этому измерению очень мало)

### Требования к глубокому поиску
- Запрещено останавливаться на первой странице поиска — самая ценная информация часто на 2–3-й странице
- Для каждого item использовать как минимум 3 разных варианта поисковых запросов
- В первую очередь искать «рассуждения практиков передовой», а не «официальное руководство по эксплуатации» — первые для творца пригоднее для письма
- Выполнение в фоне: да
- Task Output: отключён (у агента по завершении есть явный выходной файл)
- Возобновление с контрольной точки: да
