# общий-глубокое-исследование-初步研究

## Способ запуска
`/research <topic>`

После запуска необходимо сначала загрузить систему классификации «Семь исследовательских доменов написания романа» из главного `SKILL.md` и по ней определить основной домен исследования текущей темы.

## Процесс выполнения

### Шаг 0: определить домен исследования
На основе темы пользователя подтвердить из семи исследовательских доменов главного `SKILL.md` основной домен данного раунда:
- Исследование трендов жанра
- Исследование экосистемы платформы
- Исследование профессиональных знаний
- Исследование сцены / среды
- Исследование прототипов персонажей
- Исследование писательской техники
- Исследование читателей / рынка

Тема может охватывать несколько доменов; если так, пометить основной и вспомогательные домены.

### Шаг 1: предварительный каркас из внутренних знаний модели
На основе topic и домена исследования, используя имеющиеся знания модели, сформировать:
- Список основных объектов исследования / items в этой области
- Предлагаемый каркас полей исследования (для каждого поля указать name, description, detail_level)

Вывести `{step1_output}`, подтвердить через AskUserQuestion:
- Нужно ли добавить или убрать items? (чётко разграничить обязательные для проверки и необязательные)
- Удовлетворяет ли каркас полей творческим потребностям? (нет ли пропущенных ключевых измерений информации?)

### Шаг 2: дополнение через Web Search
Через AskUserQuestion спросить временной диапазон (например: последние 6 месяцев, с 2024 года до сих пор, без ограничений).

**Получение параметров**:
- `{topic}`: тема исследования, введённая пользователем
- `{YYYY-MM-DD}`: текущая дата
- `{step1_output}`: полное содержимое вывода Шага 1
- `{time_range}`: временной диапазон, указанный пользователем
- `{research_domain}`: подтверждённый домен исследования

**Жёсткое ограничение**: следующий prompt необходимо воспроизводить строго, заменяя только переменные в `{xxx}`; запрещено менять структуру или формулировки.

Запустить 1 web-search-agent (в фоне), **шаблон Prompt**:
```python
prompt = f"""## Задача
Тема исследования письма романа: {topic}
Домен исследования: {research_domain}
Текущая дата: {YYYY-MM-DD}

На основе следующего предварительного каркаса дополните актуальные items и рекомендуемые поля исследования с точки зрения романиста.

## Имеющийся каркас
{step1_output}

## Цель
Как помощник глубокого исследования для романиста, пожалуйста:
1. Проверьте, не пропущены ли в имеющихся items важные объекты, имеющие практическую ценность для творца
2. Дополните items по пропущенным объектам
3. Продолжите поиск items, относящихся к {topic} и укладывающихся в {time_range}, и дополните
4. Дополните новые fields, действительно полезные романисту, — в первую очередь те измерения информации, которые «автор может прямо вписать в текст / настройки / план»

## Требования к выводу
Вернуть структурированный результат напрямую (файл не писать):

### Дополнительные Items
- item_name: краткое пояснение (почему этот объект ценен для романиста)
...

### Рекомендуемые дополнительные поля
- field_name: описание поля (что конкретное это измерение поможет автору написать)
...

### Источники информации
- [Источник 1](url1)
- [Источник 2](url2)
"""
```

**Пример one-shot** (допустим, исследуются тренды жанра городского саспенса на Qidian):

4. Дополните новые fields, действительно полезные романисту

- [Источник 1](url1)
- [Источник 2](url2)

### Шаг 3: спросить пользователя об имеющихся полях
Через AskUserQuestion спросить пользователя:
- Есть ли файл уже определённых полей исследования? Если есть — прочитать и объединить.
- Есть ли связанные файлы текущего проекта — общий план, настройки, биографии персонажей, — которые нужно учесть? (пробелы информации в этих файлах могут указывать на фокус исследования)

### Шаг 4: проверить существующие отчёты исследования
Проверить, есть ли в `写作研究/` текущего каталога проекта или каталога жанра отчёт исследования, относящийся к данной теме. Если есть:
- Прочитать и извлечь имеющиеся выводы как справочные
- Избегать повторного исследования той же темы
- Если тема этого раунда — углубление или обновление уже имеющегося отчёта, пометить это в outline
- Если тема этого раунда сильно пересекается с имеющимся отчётом и не несёт новой ценности, рекомендовать изменить ракурс исследования

### Шаг 5: создать Outline (раздельные файлы)
Объединить `{step1_output}`, `{step2_output}`, имеющиеся поля пользователя и существующие отчёты исследования, создать два файла:

**outline.yaml** (items + конфигурация):
- topic: тема исследования (с пометкой домена исследования)
- research_domain: основной домен + вспомогательные домены
- items: список объектов исследования (каждый item содержит name, category, description, пояснение творческой ценности)
- execution:
  - batch_size: число параллельных агентов (подтвердить через AskUserQuestion, по умолчанию 3)
  - items_per_agent: число пунктов исследования на агента (подтвердить через AskUserQuestion, по умолчанию 2)
  - output_dir: каталог вывода результатов (по умолчанию `./results`)

**fields.yaml** (определения полей):
- Категории и определения полей — названия категорий используют систему, специальную для исследований написания романов (китайские названия — литералы протокола, их считывает `validate_json.py`; в скобках дан русский перевод):

| Категория | Применимые домены исследования |
|------|----------|
| 市场数据 (рыночные данные) | Тренды жанра, экосистема платформы, рынок читателей |
| 内容特征 (особенности содержания) | Тренды жанра, писательская техника |
| 读者反馈 (обратная связь читателей) | Тренды жанра, экосистема платформы, рынок читателей |
| 专业知识 (профессиональные знания) | Исследование профессиональных знаний, исследование сцены и среды |
| 人物特征 (черты персонажей) | Исследование прототипов персонажей |
| 场景细节 (детали сцены) | Исследование сцены и среды |
| 技法要素 (элементы техники) | Исследование писательской техники |
| 创作可迁移 (переносимость в творчество) | Общая для всех доменов — «как эту находку исследования можно использовать в вашем романе» |

- name, description, detail_level каждого поля
- Уровни detail_level: минимальный → краткий → подробный
- uncertain: список неопределённых полей (зарезервированное поле, автоматически заполняется на стадии deep)
- **Поля переносимости в творчество обязательны**: каждый item обязан выводить поле `创作可用抓手` (рычаг для творчества), объясняющее, как эту находку исследования можно использовать в написании романа

### Шаг 6: вывод и подтверждение

#### 6.1 Создать каталог и сохранить файлы
- Создать каталог: `./{topic_slug}/`
- Сохранить: `outline.yaml` и `fields.yaml`

#### 6.2 Подтверждение плана исследования (контрольная точка 1)
Показать следующую сводку, **обязательно получить подтверждение пользователя до перехода к /research-deep**:

```markdown
## Краткое содержание плана исследования
- **Тема исследования**: [topic]
- **Основной домен**: [domain]
- **Вспомогательные домены**: [sub-domains, если есть]
- **Пунктов исследования**: [N]
- **Полей исследования**: [M] (включая [K] полей переносимости в творчество)
- **Параллельная конфигурация**: [batch_size] агентов × [items_per_agent] пунктов на агента
- **Предварительная оценка пробелов информации**: [предварительно: по каким измерениям информации может быть мало — из принципа честного предварительного допущения nuwa-skill]
```

#### 6.3 Подсказка о следующих командах
- Для добавления пунктов или полей используйте `/research-add-items` или `/research-add-fields`
- После подтверждения выполните `/research-deep`, чтобы начать глубокое исследование

## Путь вывода
```
{текущий рабочий каталог}/{topic_slug}/
  ├── outline.yaml    # список items + конфигурация execution + пометка домена исследования
  └── fields.yaml     # определения полей (включая поля переносимости в творчество)
```

## Следующие команды
- `/research-add-items` — добавить пункты исследования
- `/research-add-fields` — добавить поля исследования
- `/research-deep` — начать глубокое исследование
