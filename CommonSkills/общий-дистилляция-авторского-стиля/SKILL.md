# общий-дистилляция-авторского-стиля
> **Маршрутизация по жанру**: если в каталоге .github\题材专用Skills\ есть соответствующий Skill <жанр>-蒸馏作者文风, то:
> - Жанровый скелет маршрутизируется в <жанр>-蒸馏作者文风; этот Skill находится в каталоге .github\题材专用Skills\.
> - При срабатывании этого навыка необходимо в первую очередь принудительно загрузить текущий Skill вместе с <жанр>-蒸馏作者文风.


> Основная идея заимствована из [Nuwa · Skill-«творение людей»](https://github.com/alchaincyf/nuwa-skill): не копировать текст автора, а **выделить измеримую ДНК слога автора** — чтобы Skill письма / рецензии / правки могли выводить результат в рамках этой ДНК, а не подражать «на пустом месте».

## Модель мышления письма — от внешнего сходства к духовному (обязательно)

Полная методология выделения слоя духовного сходства (три вопроса, проверка воспроизводимости между областями, тест порождающей силы, запись напряжения противоречия) — в `references/модель-мышления-письма-и-выделение-слоя-духа.md`. Ниже жёсткие правила, которые необходимо соблюдать:

1. **Проверка воспроизводимости между областями**: каждая основная находка должна подтверждаться как минимум в ≥ 2 типах сцен, иначе понижается до «привычки, специфичной для сцены».
2. **Тест порождающей силы**: взять сцену из произведения, не участвовавшего в дистилляции, сгенерировать текст только по слою духовного сходства и провести слепой A/B-тест; процент ошибочных суждений ≥ 50 % — пройдено.
3. **Запись напряжения противоречия**: необходимо фиксировать пары противоречий «обычная закономерность vs момент нарушения» и записывать в §13. Противоречие — не баг, а источник глубины слога.

Когда цель дистилляции служит подражанию, после завершения статистики Phase 2 необходимо дополнить следующей оценкой.

### Жёсткие правила, обязательные к исполнению

1. **Оценка степени привязки стиля к жанру**: по измерениям помечать `привязан к жанру` / `независим от автора`, это определяет, можно ли переносить стиль между жанрами.
2. **Выделение «ядра» слога**: определить тип рассказчика (сострадательный / холодный / ворчащий / погружающий), это определяет переносимость ядра.
3. **Проверка согласованности после переноса**: проверять конфликты по четырём измерениям — «длина предложения – ритм, чувства – жанр, дистанция – точка зрения, стиль речи – мир», и исправлять направление конфликта.

| Потребность пользователя | Какой путь |

## Стратегия слияния стилей нескольких авторов

> Полные стратегии слияния (метод основного–вспомогательного / метод по областям / метод пересечения, арбитраж конфликтов, правила именования и регистрации) — в `references/стратегия-слияния-стилей-нескольких-авторов.md`.

Когда нужно слить особенности слога 2–3 авторов в одном проекте, поддерживаются три стратегии слияния: **метод основного–вспомогательного** (рекомендуется для первого использования), **метод по областям** (разделение труда на уровне измерений), **метод пересечения** (приоритет общего).

---
```text
Автор [A] → §1 длина предложения + §2 абзацы + §7 выражение эмоций (область ритма и эмоций)
Автор [B] → §4 диалог + §10 голос + §14-2 тон и стиль речи (область диалога и голоса)
Автор [C] → §3 чувства + §6 метафоры + §11 время + §12 пространство (область восприятия и композиции)
```

**Способ вывода**: один «синтезированный шаблон стиля», в каждом разделе указан автор — источник данных.

#### Стратегия C: метод пересечения (приоритет общего)

По каждому измерению отдельно подсчитать данные нескольких авторов и выделить закономерности, «верные для большинства», в качестве синтезированной базовой линии. Конкретный способ тот же, что у метода пересечения для образца произведения, только «образец» заменяется на «автор».

### Арбитраж конфликтов нескольких авторов

Так же, как арбитраж конфликтов образцов произведений, дополнительно добавлены типы конфликтов, специфичные для стиля:

| Тип конфликта | Способ обработки |
| --- | --- |
| **Риск сближения голосов** | Если у основного и вспомогательного стиля слабы отпечатки дифференциации голосов (различие длины предложений между персонажами < 0,2), после слияния может возникнуть ещё более сильное сближение голосов. Следует привлечь данные третьего автора по этому измерению в качестве базовой линии либо явно понизить уверенность синтезированного шаблона по этому измерению |

### Именование результата — синтезированного шаблона стиля

Синтезированный шаблон стиля записывается как:

```text
蒸馏产物/作者风格模板/[合成标识]-综合风格模板.md
```

Правила именования те же, что у образца произведения: метод основного–вспомогательного — `[主作者]-[辅作者]-综合`; метод по областям — `[赛道名]-[题材]-综合`; метод пересечения — `[赛道名]-共性综合`.

### Регистрация в Agents.md

Синтезированный шаблон стиля регистрируется как группа связанных записей:

```markdown
### 作者风格模板（合成）(шаблон стиля автора, синтезированный)
- 合成标识 (идентификатор синтеза)：[如 "作者A-作者B-综合"]
- 主模板路径 (путь к основному шаблону)：蒸馏产物/作者风格模板/[合成标识]-综合风格模板.md
- 融合策略 (стратегия слияния)：[主辅法 / 分域法 / 交集法]
- 融合日期 (дата слияния)：YYYY-MM-DD
- 适用平台 (применимые платформы)：[平台名] 或 默认
- 源模板 (исходные шаблоны)：
  1. [作者 A] — 路径 (путь)：蒸馏产物/作者风格模板/[作者A]-作者风格模板.md — 贡献维度 (вклад по измерениям)：§1 句长 / §2 段落 / §7 情绪
  2. [作者 B] — 路径 (путь)：... — 贡献维度 (вклад по измерениям)：§4 对话 / §10 声口
```

Синтезированная запись и запись одного автора существуют в `Agents.md` параллельно, различаются суффиксом `（合成）`. При автоматическом обнаружении нижестоящими Skill **синтезированная запись имеет приоритет выше, чем запись одного автора**.

### Связь процесса «дистилляция одного автора → синтезированная дистилляция»

Так же, как у образца произведения: по умолчанию сначала раздельно дистиллируются авторы (каждый регистрирует отдельную запись в Agents.md), затем делается синтез; по требованию можно пропустить отдельную регистрацию и сразу синтезировать, но результат синтеза обязан ссылаться на информацию об исходных шаблонах.

## Различение источников списка табу (обязательно)

Каждое табу в списке табу обязано быть помечено типом источника, смешивать нельзя:

| Тип источника | Префикс пометки | Надёжность | Обработка нижестоящими |
| --- | --- | --- | --- |
| Статистический вывод | `[统计]` | Средняя — ограничена объёмом выборки | Справка как сильное ограничение, но допускается оспаривание в сценариях между произведениями |
| Самоописание автора | `[自述]` | Высокая — есть свидетельство осознанности автора | Жёсткий барьер, нарушать нельзя |
| Вывод из внешних комментариев | `[评论]` | Низкая — вторичное суждение, нужна перекрёстная проверка | Только мягкая рекомендация, не может быть жёстким барьером |

- Если одно и то же табу подкреплено и статистическим выводом, и самоописанием автора, помечается `[统计+自述]`, надёжность наивысшая.
- В рецензии выборки Phase 1.5 обязательно отдельно выделять «распределение источников табу».

## Правила арбитража конфликтов трёх шаблонов (новое)

Когда шаблон стиля автора, шаблон образца произведения и шаблон исследования письма одновременно действуют на одно поле и ограничения различаются, решать по следующим приоритетам:

| Сценарий конфликта | Порядок приоритета | Логика решения |
| --- | --- | --- |
| Одно поле ограничено всеми тремя шаблонами | Стиль автора > образец произведения > исследование письма | Явное указание пользователя выше структурной справки, структурная справка выше платформенного значения по умолчанию |
| Конфликт стиля автора и исследования письма | Приоритет у стиля автора | Первичная статистика > вторичный вывод исследования; но жёсткий платформенный порог (например, «в первых 300 знаках Qidian должен быть конфликт») не может быть перекрыт «медленным разогревом» стиля автора |
| Конфликт образца произведения и исследования письма | Приоритет у образца | Проверенная структурная закономерность > общая рекомендация исследования |
| Жёсткий порог платформы vs любой шаблон | Приоритет у жёсткого порога платформы | Если какое-то ограничение в исследовании письма помечено «жёсткий порог платформы» (например, нижняя граница следования Qidian), оно перекрывает ограничения того же поля стиля автора и образца |

**Жёсткие правила**:
- Решение о конфликте обязательно явно записывать в отчёте дистилляции, нельзя решать втайне
- Если решение приводит к перекрытию какого-то ограничения шаблона стиля автора, рядом с этим ограничением обязательно пометить источник перекрытия и причину
- Если и после решения нельзя определиться, сохранить конфликт для решения пользователя, нельзя насильно примирять

## Аудит соответствия ДНК стиля

> Полный процесс аудита (таблица измерений аудита, способ расчёта JS-дивергенции, формула комплексного соответствия, градация соответствия, формат отчёта аудита, замкнутые действия, особая обработка срабатывания табу) — в `references/аудит-соответствия-стилевой-днк.md`.

Конечный критерий проверки дистилляции: **насколько текст, написанный в рамках этого шаблона, почти неотличим от слога самого исходного автора**.

### Момент аудита

Если и только если:
1. Есть **шаблон стиля автора**, прошедший проверку Phase 4
2. Нижестоящие Skill выдали готовый текст для сопоставления (≥ 3000 знаков)
3. Пользователь явно требует аудит

### Основной метод

Поэлементное количественное сопоставление. Брать неотобранные главы исходного автора как «базовую линию собственных колебаний» — чем ближе разница выведенного текста к базовой линии, тем успешнее подражание.
