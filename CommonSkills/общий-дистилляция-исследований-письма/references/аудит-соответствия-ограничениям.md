# Аудит соответствия ограничениям

> Источник: SKILL.md § «Аудит соответствия ограничениям»

Конечный критерий проверки шаблона исследования письма: **действительно ли основной текст/планы, выданные нижестоящими Skill по этим ограничениям, соблюдают каждое правило шаблона**. Аудит соответствия ограничениям — не эстетическое суждение, а построчный checklist с галочками: его не интересует «красиво ли», его интересует только «сделано ли».

## Момент аудита

Аудит соответствия ограничениям запускается тогда и только тогда, когда одновременно выполняются условия:

1. В текущем проекте уже есть **шаблон исследования письма**, прошедший проверку качества Phase 4
2. Нижестоящий Skill (`общий-создание-основного-текста` / `общий-проектирование-общего-плана` / `общий-проектирование-плана-тома` / `общий-генерация-контрольной-карточки-главы`) уже выдал **готовый продукт, доступный для проверки**
3. Пользователь явно требует «аудит ограничений», «проверь соответствие», «посмотри, нет ли пропущенных правил» или подобное

## Методология аудита

Основа аудита соответствия ограничениям — **построчная таблица сканирования**: каждое ограничение шаблона исследования письма поочерёдно сверяется с выданным содержимым, выносится суждение «соответствует / частично соответствует / не соответствует / неприменимо».

**Стратегия градации аудита**: по жёсткости ограничений — жёсткие гейты в приоритете, затем сильные ограничения, мягкие рекомендации в последнюю очередь. Ограничения-жёсткие гейты должны проходить на 100%, при непрохождении любого весь продукт признаётся не соответствующим ограничениям.

## Процесс аудита

1. **Загрузить список ограничений**: извлечь из шаблона исследования письма все ограничения, упорядочить по четырём классам «письмо/структура/персонажи/запреты» + жёсткость
2. **Отфильтровать применимые ограничения**: по стадии творчества объекта аудита исключить ограничения, у которых «стадия применения» не совпадает (например, при аудите контрольной карточки главы исключить ограничения стадии «основной текст»)
3. **Построчная сверка**: для каждого ограничения выполнить —
   - Количественные ограничения: извлечь из выданного текста соответствующее статистическое значение, сравнить со значением ограничения
   - Неколичественные ограничения (например «запрещено „убегание“ божественного взгляда»): вручную/по шаблонам просканировать весь текст, определить, сработало ли
4. **Сформировать список нарушений**: перечислить по степени серьёзности (нарушение жёсткого гейта > нарушение сильного ограничения > отклонение от мягкой рекомендации)

## Измерения аудита и критерии суждения

| Класс ограничений | Критерий суждения для количественных ограничений | Способ суждения для неколичественных ограничений |
| --- | --- | --- |
| Письмо | Отклонение статистического значения от значения ограничения ≤ допустимого диапазона ограничения (по умолчанию ±20%, если не указано) | Сканирование всего текста по ключевым словам/шаблонам |
| Структура | Отклонение статистического значения от значения ограничения ≤ допустимого диапазона ограничения | Сканирование структуры всего текста + выборочная проверка ключевых позиций |
| Персонажи | Поэлементная сверка полей биографии персонажа с требованиями ограничений | Проверка полноты файла персонажа |
| Запреты | Сканирование всего текста по ключевым словам/шаблонам, срабатывание = нарушение | Так же |

## Расчёт соответствия ограничениям

```text
Коэффициент соответствия класса = число «соответствующих» ограничений этого класса / общее число применимых ограничений этого класса × 100%

Комплексный коэффициент соответствия = Σ(коэффициент соответствия каждого класса × вес класса) / Σ(вес класса)

Веса классов:
- Запреты: 35% (нарушение запретов самое разрушительное, вес самый высокий)
- Структура: 30%
- Письмо: 20%
- Персонажи: 15%
```

## Градация соответствия

| Комплексный коэффициент соответствия | Доля прохождения жёстких гейтов | Уровень | Значение | Пропускать ли |
| --- | --- | --- | --- | --- |
| ≥ 95% | 100% | Уровень S | Почти полное соответствие | ✅ Пропустить |
| 85%–94% | 100% | Уровень A | Основные ограничения пройдены полностью, небольшие отклонения по сильным ограничениям/мягким рекомендациям | ✅ Пропустить |
| 75%–84% | 100% | Уровень B | Есть ощутимые точки несоответствия | ⚠️ Пропустить с приложением списка исправлений |
| 60%–74% | < 100% | Уровень C | Есть нарушения жёстких гейтов | ❌ Вернуть на доработку, исправить жёсткие гейты |
| < 60% | < 100% | Уровень D | Большое число ограничений не соблюдено, шаблон существует лишь формально | ❌ Вернуться к стадии дистилляции исследования письма, проверить, исполним ли шаблон |

> Правила именования объекта аудита: если объект аудита — конкретная глава, использовать `ChX-章名` (название главы); если пакет глав — `ChX-Y`; если план — `Outine-类型` (тип).

## Замыкающие действия после аудита

- **Уровень S/A**: архивировать отчёт об аудите.
- **Уровень B**: перевести «список нарушений сильных ограничений» отчёта об аудите в задачи правки соответствующего Skill, после выполнения **повторно прогнать аудит**.
- **Уровень C**: обязательно исправить все нарушения жёстких гейтов. После исправления повторно прогнать аудит, пока доля прохождения жёстких гейтов не достигнет 100%. Пока все жёсткие гейты не пройдены, нельзя переходить к следующей стадии творчества.
- **Уровень D**: это говорит о том, что сам шаблон исследования письма может иметь проблемы с исполнимостью (ограничения слишком расплывчаты, слишком строги или противоречат друг другу). Вернуться к стадии слияния и удаления дублей Phase 2 и проверить, нет ли конфликтующих, неисполнимых или чрезмерных ограничений.

## Правила приоритета конфликтов ограничений

Когда аудит выявляет, что два ограничения в продукте нельзя выполнить одновременно (например «короткие предложения» и «богатые сенсорные описания» — сенсорные описания часто требуют более длинных предложений):

1. Сохранить ограничение с более высокой жёсткостью
2. При равной жёсткости сохранить ограничение, у которого платформенная чувствительность соответствует целевой платформе
3. Если по-прежнему невозможно решить, записать в раздел «Конфликт ограничений» отчёта об аудите и передать решение пользователю
