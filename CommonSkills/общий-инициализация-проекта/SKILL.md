# общий-инициализация-проекта

> **Маршрутизация по жанру**: если в каталоге `.github/题材专用Skills/` есть соответствующий Skill `{жанр}-小说项目初始化`, необходимо в первую очередь принудительно загрузить текущий Skill вместе с этим жанровым Skill.

<!-- ===== Layer 1: постоянный кэш ===== -->

## Единственная цель этого Skill

В рамках ограничений заданной **платформы** и **жанра** определить полный перечень элементов, которыми должен обладать роман, лучше всего привлекающий читателей и приносящий больше всего денег.





<!-- ===== Layer 3: кэш сценария ===== -->

## Самый главный результат: Agents.md (обязательный результат)

Самый главный результат этого Skill — **`Agents.md` в корневом каталоге проекта романа**. Его **необходимо создать**, пропускать нельзя.

Все нижестоящие ключевые Skill (`общий-создание-основного-текста`, `общий-цикл-создания-главы`, `общий-шлифовка-основного-текста`, `общий-оркестрация-вывода-на-платформы` и др.) автоматически находят `Agents.md`, чтобы получить **основную платформу вывода** и **настройки точки зрения (POV)**, загружают по соглашению об именовании соответствующий Skill `общий-вывод-{платформа}` и объединяют правила, специфичные для платформы, при исполнении.

> Единственный критерий того, что этот Skill действительно «завершён»: **в корневом каталоге проекта существует корректный `Agents.md`**. Если в `Agents.md` нет поля `## 项目初始化蓝皮书`, нижестоящие проектировочные Skill не могут найти путь к синей книге, и инициализация проекта считается выполненной частично.

Помимо `Agents.md`, этот Skill одновременно создаёт «синюю книгу инициализации проекта» как файл с подробным обоснованием решений; её путь регистрируется в поле `## 项目初始化蓝皮书` файла `Agents.md`.

## Позиция этого Skill по умолчанию

**Пользователю не нужно знать, какие шаблоны-паттерны (套路) самые горячие, какие сочетания самые сильные, какие эмоции приносят больше всего денег.** Этот Skill принимает все решения с нуля, опираясь на уже имеющиеся в рабочей области активы данных:

- Отчёты макроанализа рынка в каталоге `исследования-письма/`
- Отчёты анализа конкурентов в каталоге `竞对分析/` (как дополнительная проверка)
- Источники-арбитры жанра в `题材名-设计题材定位框架/references/` жанровой обёртки
- Платформенные правила, накопленные в общем слое Skill `общий-вывод-{платформа}` / `общий-анализ-конкурирующих-произведений` и др.

> Этот Skill выполняется после макроанализа рынка (вызов `общий-глубокое-исследование`). Анализ конкурентов и дистилляционное исследование выполняются после этого Skill, для проверки и уточнения.

## References для дальнейшего чтения (гейт обязательного чтения)

**Перечисленные ниже файлы references обязательно читать по одному через инструмент `read_file`; нельзя пропускать ни один под предлогом «знания уже есть», «в прошлый раз уже читал» или «этот файл — всего лишь справка».** Каждая запись references выполняется принудительно по указанному для неё уровню обязательности чтения:

- Файлы с пометкой **обязательно читать**: их нужно прочитать, пропуск хотя бы одного считается нарушением процесса, начинать выполнение процесса нельзя.
- Файлы без пометки «обязательно»: их нужно прочитать, но после прочтения можно извлечь только фрагменты, прямо относящиеся к текущей задаче, построчное прочтение не требуется.
- Если файла по указанному пути не существует (например, внешний путь не подготовлен), в журнале обязательно явно записать `reference_missing_{refName}`, молча пропускать нельзя.

- `references/монетизация-на-платформе-и-позиционирование-эмоций-читателя.md` — полные правила исполнения модуля 1 (адаптация к платформе), модуля 2 (коммерческая привязка), модуля 3 (эмоции читателя)
- `references/основы-повествования-и-коммерческий-слой.md` — полные правила исполнения модуля 4 (метасеттинг), модуля 5 (паттерны-套路), модуля 6 (точки коммерциализации), модуля 7 (проверка осуществимости)
- `references/спецификация-перечня-ключевых-выходных-элементов.md` — полная спецификация вывода главы 9 синей книги (шаблоны таблиц/матриц 9.1→9.10)
- `references/спецификация-результатов-и-контрольные-точки.md` — структура файлов итоговых результатов, стандарт исполнения каждой главы, три красные линии, контрольные точки /init и /init-check
- `../../исследования-письма/网文留存模型.md` — общая базовая модель удержания (общая ссылка для разных Skill)

## Сценарии применения

- Готовитесь писать новый проект в определённом жанре на определённой платформе, но не уверены, какие шаблоны-паттерны (套路) приносят больше всего денег
- Есть смутное вдохновение, но хочется проверить, «может ли это направление выстрелить»
- Есть исследования письма и анализ конкурентов, но неясно, как превратить их в конкретные творческие решения

## Неподходящие сценарии

- Беспечное писание «из любви к искусству»
- Создание коротких/средних произведений
- Продолжение отдельного тома уже существующего многотомного произведения

## Правила исполнения (обязательно)

### Правило 1: самостоятельные решения с нуля

Перед исполнением не нужно предполагать, что пользователь знает особенности хитов целевой платформы, популярные паттерны-套路, эмоциональные предпочтения. Все данные для решений берутся автоматическим сканированием по следующим путям (приоритет от высокого к низкому):

1. `исследования-письма/` в корневом каталоге проекта — отчёты макроанализа рынка, главное основание решений
2. `CommonSkills/исследования-письма/` — межжанровые исследования писательской техники
3. `竞对分析/` в корневом каталоге проекта — анализ конкурентов той же дорожки (если есть, как дополнительная проверка)
4. `.github/skills/题材名-分析竞对作品/references/` — дополнительные измерения жанрового анализа конкурентов
5. `.github/skills/题材名-设计题材定位框架/references/` — источники-арбитры жанра

### Правило 2: однофайловая синяя книга — глубокая версия

Все результаты сводятся в один файл `项目初始化/项目初始化蓝皮书.md`. Каждая глава имеет четырёхчастную структуру (процесс анализа → перечень оснований для решений → итоговое решение → вход для нижестоящих), ничто нельзя пропускать. Подробности см. в `references/спецификация-результатов-и-контрольные-точки.md`.

### Правило 3: приоритет решений, опирающихся на данные

Каждое ключевое решение должно указывать источник основания. Решения без подтверждения данными должны быть помечены «на основе общеотраслевого опыта, рекомендуется последующая проверка». Приоритетно использовать отчёты макроанализа рынка из `исследования-письма/`.

### Правило 4: привязка к возрастной группе целевых читателей (обязательно)

> **Источник**: Zhihu · колонка «Таверна Гули Мутуя» (顾里木图的小酒馆), «Перед тем как писать роман, нужно знать, что нравится и что волнует нынешних читателей» (2026-07-09); цитируемые данные: «Синяя книга китайской интернет-литературы 2024», данные платформ Qidian/Fanqie.

Прежде чем определять жанр, торговые точки и паттерны-套路, необходимо зафиксировать **одну конкретную целевую возрастную группу**. Читатель — не расплывчатая масса: то, что хотят 18-летний и 44-летний, открывая приложение для чтения, совершенно разное. Нельзя угодить всем, но необходимо, чтобы определённая группа людей почувствовала: «эта книга написана для меня».

**Общая картина данных**: пользователей китайской интернет-литературы 575 млн, возраст 26–45 лет — 50 %, 18–25 лет — почти 25 %, старше 45 лет — более 25 %. Но «26–45 лет» — это четыре совершенно разных жизненных этапа, смешивать их при таргетинге нельзя.

| --- | --- | --- | --- | --- |

**Правила исполнения**:
- При инициализации проекта необходимо из указанных восьми слоёв **явно выбрать одну целевую возрастную группу** и записать её в `Agents.md`
- Выбранная возрастная группа определяет базовую тональность всех нижестоящих Skill — плотность точек удовлетворения, длину глав, сложность повествования, стиль диалогов, частоту поворотов
- Диапазон 18–25 лет → стратегия быстрого ритма / коротких глав / сильных хуков
- Диапазон 30–45 лет → принцип «правдоподобие важнее удовлетворения»
- Старше 45 лет → стратегия неспешного ритма / счастливой концовки / описания духа повседневности
- Запрещено «охватывать сразу несколько возрастных групп» — это самая частая стратегическая ошибка при инициализации проекта. Сначала выберите одну, пропишите её до конца

### Правило 4 · приложение: жанровые смещения возрастных групп (новое — на основе глубокого исследования)

## Честные границы

- Предлагаемый этим Skill метод модульной адаптации паттернов-套路 основан на общеотраслевом опыте. Лучшие практики разных платформ и разных периодов могут меняться.
- Данные о портретах пользователей платформ основаны на открытых материалах 2025–2026 годов, требуют постоянного обновления.
- «Коэффициент конверсии» воронки эмоциональных решений читателя не подкреплён открытыми данными, реальный эффект нужно проверять данными.
- Коммерческая проверка (модуль 7) не заменяет формальную оценку `общий-оценка-подписания-на-платформе`.
- Если выбор платформы изменился в середине проекта, **необходимо обновить `Agents.md`** и заново выполнить модуль 1.
- **Напоминание, противоречащее здравому смыслу**: самая частая ловушка стадии инициализации — «стремление к совершенству». Рекомендуются три итерации: сначала прогнать весь процесс командой `/init-quick`, затем сделать детальные решения командой `/init`, в конце дополнить слабые модули.

## Модуль 8: создание файла конфигурации проекта Agents.md (обязательный результат, основной результат)

После завершения инициализации проекта **необходимо** создать в корневом каталоге романа `Agents.md`, зарегистрировав в нём **основную платформу вывода**, **настройки POV**, **конфигурацию языкового стиля** и **путь к синей книге инициализации проекта**. ### Пояснение полей

**Основная платформа вывода** (обязательное поле, `主输出平台`):

- Указывается название целевой платформы, сопоставляемое с Skill `общий-вывод-*` по таблице из `.github/instructions/platform-output-skill-architecture.instructions.md`. Например: `起点中文网` (Qidian), `番茄小说` (Fanqie), `七猫小说` (Qimao), `晋江文学城` (Jinjiang), `知乎盐选` (Zhihu Yanxuan), `豆瓣阅读` (Douban Read), `纵横中文网` (Zongheng), `出版社` (издательство), `微信订阅号` (WeChat Official Accounts), `小红书` (Xiaohongshu), `新浪微博` (Sina Weibo), `百度百家号` (Baidu Baijiahao), `B站` (Bilibili), `WebNovel`, `My Fiction`, `GoodNovel`.
- Эта настройка автоматически находится такими Skill, как `общий-создание-основного-текста`: Skill по соглашению об именовании загружает соответствующий Skill `общий-вывод-{платформа}` и объединяет платформенные правила при исполнении.
- Если `Agents.md` не существует или основная платформа вывода не зарегистрирована, все нижестоящие Skill откатываются к платформонезависимому универсальному режиму по умолчанию, без ошибок и блокировок.

**POV основной платформы вывода** (рекомендуется заполнять, `主输出平台POV`):

- `叙事人称`: предполагаемое повествовательное лицо основной платформы вывода. Допустимые значения: `第一人称` (первое лицо), `第二人称` (второе лицо), `第三人称` (третье лицо). Третье лицо — значение по умолчанию для подавляющего большинства платформ веб-литературы.
- `语言`: язык. `中文简体` (китайский упрощённый), `中文繁体` (китайский традиционный), `英文` (английский) и др.
- `POV基线来源`: источник базовой линии POV. Фиксированное значение `源稿` — означает, что за основу берётся существующая цепочка точек зрения основного текста исходной рукописи.
- `切换策略`: стратегия переключения POV. Рекомендуемое значение `每卷需审批` (переключение каждого тома требует утверждения) или `全书锁定` (фиксация на всю книгу). Запрещено менять повествовательное лицо посреди публикации без явной причины и утверждения в журнале.

Эта настройка POV считывается Skill `общий-оркестрация-вывода-на-платформы` как начальное значение по умолчанию для `platformPovContract` каждой платформы. Для проектов с выводом на несколько платформ перед многоплатформенным выводом следует дополнить `平台POV基线表` (таблицу базовых линий POV платформ; см. `общий-оркестрация-вывода-на-платформы`).

**Конфигурация языкового стиля** (рекомендуется заполнять, `语言风格配置`):

Конфигурация стиля письма: регистрирует выводы исследовательского отчёта «Система классификации стилей письменного языка» как ограничения уровня проекта. Нижестоящие `общий-создание-основного-текста`, `общий-шлифовка-основного-текста`, `общий-устранение-духа-ии` автоматически находят её и сопоставляют с источниками-арбитрами уровня предложения / ритма / точки зрения.

- `对偶区位`: пять осей-противопоставлений языковой фактуры, определяющих языковые особенности на уровне предложения с точки зрения китайской стилистики. На каждой оси выбирается одно из двух. Пока не определённые измерения можно оставить в формате-заполнителе `[X/Y]`.
- `网文色标`: стилевой ярлык рыночного уровня, определяющий комбинационную стратегию «какое ощущение читатель ожидает прочитать». Основной цветовой ярлык обязателен; дополнительный и структурное распределение можно оставить пустыми, если пока не определены.
- `叙述者类型`: позиция автора на уровне повествования. По умолчанию «погружающий» (подходит подавляющему большинству веб-романов); если у жанра особые требования (например, «ворчащий» рассказчик подходит для лёгких комедийных дорожек), можно скорректировать.
- `表达方式目标占比`: ожидаемые диапазоны долей четырёх основных способов выражения. Пока не определено — оставить диапазоны по умолчанию `35%-45%` / `15%-25%` / `30%-40%` / `3%-8%` в качестве базовой линии для последующей тонкой настройки.

Эта настройка автоматически находится `общий-создание-основного-текста`, `общий-шлифовка-основного-текста`, `общий-устранение-духа-ии` и сопоставляется с соответствующими источниками-арбитрами уровня предложения / ритма / точки зрения / абзаца. Если в `Agents.md` нет раздела `## 语言风格配置`, все нижестоящие Skill откатываются к универсальному режиму по умолчанию, без ошибок и блокировок.

**Синяя книга инициализации проекта** (рекомендуется заполнять, `项目初始化蓝皮书`):

- Указывается путь к синей книге относительно корневого каталога проекта, формат например `项目初始化/项目初始化蓝皮书.md`.
- Эта настройка автоматически находится нижестоящими проектировочными Skill — `общий-проектирование-общего-плана`, `общий-проектирование-плана-тома`, `общий-проектирование-биографии-персонажей`, `общий-проектирование-настроек-истории`, `общий-написание-аннотации`, `общий-проектирование-названия`, `общий-генерация-контрольной-карточки-главы`, `общий-оценка-подписания-на-платформе` и др. — как источник стратегического ввода.
- Прочитав этот путь, нижестоящие Skill загружают синюю книгу и по мере необходимости используют из неё разделы: рыночное позиционирование, каркас метасеттинга, схему сочетания паттернов, перечень элементов и т. д.
- Если путь к синей книге в `Agents.md` не зарегистрирован, нижестоящие проектировочные Skill откатываются к универсальному режиму без синей книги, без ошибок и блокировок.

### Дописывание в уже существующий Agents.md

Если в проекте уже есть `Agents.md` (например, уже зарегистрированы дистилляционные шаблоны и т. п.), допишите в конец файла полный шаблон из «Требований к формату Agents.md» выше (без пояснительного текста подполей `### 对偶区位`, вставляется только markdown-блок от `## 主输出平台` до `## 语言风格配置`). Пока не определённые значения оставляйте в формате-заполнителе (например, `[平实/藻丽]` или `[待定]`), пропускать какой-либо раздел нельзя. Все заполнители можно постепенно уточнять в последующих итерациях, это не влияет на автоматическое обнаружение нижестоящими Skill и безопасность отката.

### Результаты

#### Результат 1: Agents.md (обязательный результат, основной файл конфигурации)

- **Путь**: `项目根目录/Agents.md`
- **Характер**: **обязательный результат**. Единственный критерий того, что этот Skill действительно завершён. Если не создан, ни один нижестоящий Skill не сможет автоматически адаптироваться к правилам платформы.
- **Содержание**: регистрация основной платформы вывода + настройки POV + конфигурация языкового стиля + путь к синей книге инициализации проекта (подробности в «Требованиях к формату Agents.md» и «Описании полей» выше)

#### Результат 2: синяя книга инициализации проекта (подробное обоснование решений)

- **Путь**: `项目根目录/项目初始化/项目初始化蓝皮书.md`
- **Характер**: подробное обоснование решений. Основания решений всех модулей сводятся в один единый файл.
- **Структура файла** (обязательно):

```text
# Синяя книга инициализации проекта

## 1. Выводы по калибровке рынка (четырёхчастная структура: процесс анализа → перечень оснований для решений → итоговое решение → вход для нижестоящих)
## 2. Привязка коммерческой логики (четырёхчастная структура)
## 3. Позиционирование эмоций читателя (четырёхчастная структура)
## 4. Каркас метасеттинга (четырёхчастная структура)
## 5. Схема сочетания паттернов-套路 (четырёхчастная структура)
## 6. Расстановка точек коммерциализации (четырёхчастная структура)
## 7. Выводы проверки осуществимости (четырёхчастная структура)
## 8. Перечень разрывов с конкурентами (матрица данных: по строке на каждого конкурента, сравнение по пяти измерениям)
## 9. Перечень элементов романа, которые лучше всего привлекают читателей и приносят больше всего денег (основной результат, четырёхчастная структура вывода, подробности см. выше в спецификации)
## 10. Честные границы (сводная таблица всех неопределённых пунктов + общая оценка уверенности + декларация пробелов информации + декларация «против здравого смысла»)
```

**Стандарт исполнения каждой главы** (кроме главы 9):

| Требование | Стандарт |
|---|---|
| ① Процесс анализа | цепочка рассуждений ≥300 знаков, ссылка на ≥2 источника данных, сравнение с ≥1 отвергнутой альтернативой |
| ② Перечень оснований для решений | перечислить 3–5 ключевых оснований, к каждому указать файл-источник и уровень уверенности |
| ③ Итоговое решение | одной фразой сказать «что выбрано, от чего отказались, почему» |
| ④ Вход для нижестоящих | чётко указать, как это решение будет использоваться нижестоящими Skill |

Исключение для главы 9: исполняется в формате таблиц/матриц, предписанном «Перечнем основных элементов результата»; четырёхчастная структура не нужна (цепочка анализа первых 8 глав — уже её «процесс анализа»).

**Три красные линии**:

- ❌ Не допускается распределённый вывод по нескольким файлам. Все главы пишутся в один файл.
- ❌ Не допускается цепочка рассуждений менее 300 знаков в одной главе. Глава из одного списка без анализа считается незавершённой.
- ❌ Не допускается решение без указания источника. Каждое решение должно указывать отчёт-источник, конкурента или исследование.

**Место сохранения**:

| Результат | Путь |
|---|---|
| Обязательный (основной) | `项目根目录/Agents.md` |
| Подробное обоснование решений | `项目根目录/项目初始化/项目初始化蓝皮书.md` |

### Контрольные точки

- [ ] Решения по всем 7 модулям завершены?
- [ ] Результаты каждого модуля записаны в каталог `项目初始化/`?
- [ ] Выводы модулей 1–3 (слой жёстких ограничений) согласованы и без внутренних противоречий?
- [ ] Весь модуль 4 (метасеттинг) служит основной эмоции?
- [ ] В модуле 5 (адаптация паттернов) есть неизменное ядро логики + чёткое отображение адаптации?
- [ ] Модуль 6 (точки коммерциализации) покрывает два измерения: оплата + IP?
- [ ] Модуль 7 (проверка осуществимости): все четыре барьера пройдены?
- [ ] Перечень предупреждений о рисках составлен и снабжён стратегиями реагирования?
- [ ] **Модуль 8 (Agents.md) создан и заполнен с корректными названием платформы и настройками POV?**
- [ ] Внешние зависимые Skill вызваны согласно требованиям?

#### Ретроспективная проверка инициализации (/init-check)

- **Действителен ли ещё `Agents.md` в корневом каталоге проекта?** (По-прежнему ли верна основная платформа вывода?)
- На каком уровне сейчас слабое звено проекта? (слой жёстких ограничений / слой повествовательной основы / слой коммерческого исполнения / слой регистрации проекта)
- Не устарела ли адаптация к платформе? (правила платформы / популярность жанра могли измениться)
- Нужно ли обновить сочетание паттернов? (конкуренты могли применить более новые приёмы)
- Остаются ли в силе точки коммерциализации? (подтверждение данными: конверсия в оплату / время чтения и т. п.)
- Нет ли риска логического краха повествовательной основы? (система сил / отношения между силами / согласованность персонажей)
