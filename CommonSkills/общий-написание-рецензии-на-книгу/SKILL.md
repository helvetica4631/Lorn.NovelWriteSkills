# общий-написание-рецензии-на-книгу
> **Маршрутизация жанров**：если в каталоге .github\题材专用Skills\ существует соответствующий Skill <жанр>-撰写书评, то:
> - направь жанровый каркас особенностей на <жанр>-撰写书评, этот Skill находится в каталоге .github\题材专用Skills\.
> - при срабатывании этого Skill в первую очередь обязательно загрузи принудительно и текущий Skill, и <жанр>-撰写书评.


Рецензия — это не пересказ сюжета и не учебник по творчеству, а нерекламный по отношению к сюжету (без спойлеров) рекомендательный текст, написанный так, чтобы ответить на вопрос «почему стоит открыть и читать дальше»: такой текст читатель захочет переслать, а платформа — показать.

## References для дальнейшего чтения (гейт обязательного чтения)

**Перечисленные ниже файлы references обязательно читать по одному через инструмент `read_file`; нельзя пропускать ни один под предлогом «знания уже есть», «в прошлый раз уже читал» или «этот файл — всего лишь справка».** Каждая запись references выполняется принудительно по указанному для неё уровню обязательности чтения:

- Файлы с пометкой **обязательно читать**: их нужно прочитать, пропуск хотя бы одного считается нарушением процесса, начинать выполнение процесса нельзя.
- Файлы без пометки «обязательно»: их нужно прочитать, но после прочтения можно извлечь только фрагменты, прямо относящиеся к текущей задаче, построчное прочтение не требуется.
- Если файла по указанному пути не существует (например, внешний путь не подготовлен), в журнале обязательно явно записать `reference_missing_{refName}`, молча пропускать нельзя.

## Встраивание портрета стиля автора (автоматически)

- Если в корне проекта есть `Agents.md` и в нём зарегистрирован источник данных «эволюция авторского стиля» (`作者风格画像.md` и `作者原声样本库.md` в `蒸馏产物/作者风格进化/`):
  - **Предварительно (только чтение)**: прочитай **слой ценностных мотивов + остроту повествования + авторскую языковую библиотеку** из `作者风格画像.md` — рецензия — это «рекомендательный текст с позиции автора»: позицию брать из слоя мотивов / остроты повествования (что автору претит, что он одобряет), афоризмы — из языковой библиотеки, чтобы рецензия выглядела так, будто её написал сам автор
  - **Окно автора (точка касания S4)**: дословные реплики автора с правками рецензии → дословно в библиотеку образцов (с пометкой точки касания S4)
- Источник данных не зарегистрирован или автор явно пропустил: писать по существующим формулировкам по умолчанию, без ошибки, без блокировки

## Правила автообнаружения шаблонов стиля / образца / писательских исследований

Если в корневом каталоге обслуживаемого проекта есть `Agents.md`, перед написанием или аудитом рецензии обязательно:

1. Прочитать `Agents.md` в корне проекта; если там объявлена `主输出平台`, при поиске трёх видов шаблонов в первую очередь подбирать шаблоны, у которых «适用平台» совпадает с основной платформой вывода, при отсутствии совпадений откатываться к шаблонам того же вида с «适用平台：默认»
2. Если в `Agents.md` зарегистрирован «шаблон исследования письма» — прочитай файл шаблона по соответствующему пути и используй как базовую линию платформенной подачи, читательских интересов и запретов
3. Если в `Agents.md` зарегистрирован «шаблон стиля автора» — прочитай файл шаблона по соответствующему пути и используй как слабый ориентир языкового характера рецензии; нельзя писать рецензию как подражание основному тексту
4. Если в `Agents.md` зарегистрирован «шаблон блюпринта произведения» — прочитай файл шаблона по соответствующему пути и используй как ориентир структурных, ритмических достоинств, хуков без спойлеров и обещаний чтения
5. Этот Skill потребляет только поля, связанные с рецензией / рекомендательным текстом; если поля шаблона конфликтуют с принципом «без спойлеров», приоритет у принципа «без спойлеров»
6. Если в корне проекта нет `Agents.md` или в нём не зарегистрированы соответствующие шаблоны — откат к общему режиму по умолчанию, без ошибок и без блокировки

Поля, потребляемые этим Skill по умолчанию:

- Шаблон исследования письма: платформенная подача, читательские интересы, углы рекомендации, запреты
- Шаблон стиля автора: общий стиль текста, базовая длина предложений, список запретов, языковой характер
- Шаблон блюпринта произведения: общая стратегия повествования, паттерн начала главы, интервал награды, чередование хуков, распределение эмоциональной дуги

## Когда использовать

- Нужно написать рецензию на всю книгу, часть, том или главу.
- Существующая рецензия слишком похожа на синопсис, на шаблонные оценки или уже слишком спойлерит, нужно переписать.
- Нужно сгенерировать версии рецензии с разной подачей для разных платформ или сценариев распространения.
- Нужно проверить, действительно ли рецензия написана с позиции читателя, есть ли хук, способна ли она поддержать распространение.

## Место сохранения рецензии в файл и правила именования (обязательно)

- Рабочий каталог этого Skill по умолчанию фиксирован: `书评/`.
- Имена всех файлов рецензий должны содержать дату, формат даты фиксирован `YYYY-MM-DD`.
- Рецензии на всю книгу, часть и том размещаются прямо в корне `书评/`, имя файла по схеме «диапазон/заголовок + `_书评_` + дата» или эквивалентному принятому формату; например: `书评/全书书评_2026-04-15.md`, `书评/第1部·日常裂缝_书评_2026-04-15.md`, `书评/第1卷·夜班监控_书评_2026-04-15.md`.
- Рецензии по главам хранятся по структуре романа: если у произведения есть части — в `书评/第X部/第Y卷/`; если частей нет — в `书评/第X卷/`. Имя файла по схеме «номер главы и заголовок + `_书评_` + дата»; например: `书评/第1部/第1卷/1.1.1 HR 让我先签字再说_书评_2026-04-15.md`, `书评/第1卷/1.1 HR 让我先签字再说_书评_2026-04-15.md`.
- Дата должна стоять в конце имени файла перед расширением `.md`; если пользователь явно не просит набросать только в чате, нельзя опускать имя файла с датой.

## Порядок выполнения по умолчанию

1. Сначала подтвердить уровень рецензии, соответствующий диапазон, целевую платформу и угол письма.
2. Затем выделить публично допустимые торговые точки, обещание чтения, эмоциональную кривую и целевую аудиторию, запрещено пересказывать полную причинно-следственную цепочку.
3. Затем по контексту платформы и углу сосредоточенно скорректировать заголовок, характер абзацев, профессионализм и формулировку взаимодействия.
4. Затем дописать `# 短评` (краткий отзыв), перекликающийся с основным текстом, но без повторных спойлеров.
5. Наконец, сохранить по правилам независимого именования файла и сохранения, проверить, остаётся ли позиция обычного читателя.

## GEO-дружественная рецензия (новое)

### Видимость рецензии в ИИ-поиске

В эпоху ИИ-поиска рецензия — не только рекомендательный текст для читателя, но и важнейший материал для цитирования, когда ИИ отвечает на вопрос «порекомендуй роман». При цитировании рецензий ИИ предпочитает контент с **высокой степенью структурированности, с метаданными произведения и с причинами рекомендации, пригодными для самостоятельного извлечения**.

### Требования к структуре GEO-дружественной рецензии

В начале основного текста каждой рецензии обязательно должен быть структурированный блок из следующих четырёх полей (в первых 4 строках основного текста):

```
## 《XXX》书评 (рецензия на «XXX»)
- **评分** (оценка)：★★★★☆
- **类型** (жанр)：都市悬疑 (городской саспенс)
- **一句话总评** (общая оценка одной фразой)：___
```

### Формат рекомендации, удобный для цитирования ИИ

В основном абзаце рекомендации как минимум один абзац должен быть в следующем формате — он изоморфен рекомендательной формулировке ИИ:

```
《{书名}}》是一部{题材类型}小说，适合喜欢{风格/情绪}的读者。 (шаблон: «{название}» — это роман жанра {жанр}, подходит читателям, которым нравится {стиль/эмоция}.)
核心看点是{1-2 句非剧透亮点描述}。 (Ключевая изюминка — {1–2 фразы описания достоинств без спойлеров}.)
```

### GEO-оптимизация краткого отзыва

В кратком отзыве как минимум **1 раз встречается полное название произведения + 1 раз тип жанра + 1 раз формула «для какой аудитории»**, чтобы ИИ мог самостоятельно сделать атрибуцию.

### Чек-лист самопроверки GEO-рецензии

- [ ] В начале блок метаданных из четырёх полей (название/жанр/оценка/общая оценка)
- [ ] В основном тексте есть абзац рекомендации, начинающийся с названия произведения
- [ ] Есть формула «подходит читателям, которым нравится ____» (适合____的读者)
- [ ] Краткий отзыв содержит название произведения + тип жанра + целевую аудиторию
- [ ] В рецензии есть информация о актуальности (год/статус выхода)

> Подробные нормы см. в `references/geo-правила-оптимизации-рецензий.md` и `../../写作研究/GEO小说项目核心参考.md`.
