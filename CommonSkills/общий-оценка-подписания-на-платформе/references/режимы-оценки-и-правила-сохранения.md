# Режимы оценки и правила сохранения на диск

## Общие принципы по умолчанию

- Оценка подписания на платформе по умолчанию выполняется как **поэтапная оценка допуска**, а не только «напоминание о нехватке материалов».
- Оценка подписания на платформе по умолчанию одновременно выполняется по критерию «**безжалостного поиска разрывов**»: главное — не доказать, что у произведения «тоже есть достоинства», а доказать, почему оно сейчас ещё недостаточно хорошо, чтобы вступить в конкуренцию за редакторские места.
- На каком слое остановились материалы, на том слое сначала определяют, стоит ли допустить его к следующему слою:
  1. общий план -> стоит ли продолжать детализацию томов;
  2. тома -> стоит ли продолжать писать основной текст глав;
  3. основной текст -> стоит ли продвигать подачу / полную оценку подписания.
- На стадиях общего плана и томов поле основной вероятности по умолчанию оценивает **вероятность допуска текущего уровня**, а не вероятность того, что «основной текст уже прошёл планку» или «подавать можно прямо сейчас».
- Если пользователь также хочет знать перспективы итогового подписания, можно дополнительно дописать **оценку верхнего предела итогового подписания**; но она может служить лишь верхней границей с низкой уверенностью и не заменяет суждения о допуске текущего уровня.

## Поддерживаемые режимы оценки

### Предварительная оценка шлюза общего плана

Как минимум должны быть:

- Название произведения / продающий пункт одним предложением / аннотация
- Общий план

Если одновременно имеются следующие материалы, их все нужно учесть, нельзя смотреть только общий план:

- Настройки главного героя
- Настройки механики / правил
- Описание мира или реалистичных якорей
- Описание целей обновлений / подачи

Этот режим обязан ответить:

- Подходит ли текущий общий план для продвижения к плану тома;
- Если сейчас продолжать писать дальше, в какой структурной точке скорее всего «рванёт»;
- Какие несколько «ударов» нужно сделать сначала, чтобы снизить риск последующей крупной переделки.

### Предварительная оценка шлюза тома

Как минимум должны быть:

- Общий план
- План тома

Лучше, чтобы одновременно было что-то из следующего:

- Биты первых 10 глав
- Микросценарий начала
- Стартовая таблица тома
- Черновик дизайна первых 3 глав

Этот режим обязан ответить:

- Подходит ли текущий план тома для продвижения к основному тексту глав;
- Закреплены ли обещание первого тома, биты первых 10 глав, первая эффективная отдача;
- Если сейчас сразу писать основной текст, что скорее всего вынудит автора вернуться к правке: общий план, том или исполнение начала.

### Оценка допуска основного текста

Как минимум должны быть:

- Первые 500 знаков
- Рекомендуется первые три главы или первые 6000 знаков

Если есть материалы по общему плану / томам / персонажам / механике, их обязательно нужно перекрёстно проверить.

Этот режим обязан ответить:

- Подходит ли текущий основной текст для дальнейшего продвижения;
- Подходит ли он уже для входа в официальную оценку подачи;
- Если основной текст обнаруживает проблемы, к какому уровню они относятся — общего плана, тома или исполнения основного текста.

### Полная оценка подписания

Когда название / аннотация, основной текст, персонажи, механика, общий план / тома, исполнение обновлений и подготовка заявки позволяют образовать перекрёстную проверку, переходят к полной оценке.

Только поле основной вероятности этого режима по умолчанию указывает на **текущую вероятность подписания / прохождения модерации**.

### Быстрый скрининг при нехватке материалов

Когда есть только название / аннотация / разрозненные фрагменты, можно выполнять лишь быстрый скрининг с низкой уверенностью.

Этот режим всё равно должен дать **рекомендацию, стоит ли дополнять материалы следующего слоя**, но не должен выдавать себя за полную оценку.

## Минимальный перечень материалов перед началом

1. Название произведения / продающий пункт одним предложением / аннотация в пределах 300 знаков
2. Ключевые материалы текущего слоя: общий план / тома / биты первых 10 глав / пробные главы основного текста
3. Главный герой: профессия, ключевое желание, ключевой изъян, теги образа
4. Механика: способ запуска, границы, цена
5. Долгосрочная линия: общий план / тома / биты первых 10 глав / стартовая таблица тома
6. Исполнение сериализации: план обновлений, объём запаса, способ подачи
7. Если оценка по критерию Qidian: журнал поиска Топ-10 рейтинга Qidian того же жанра (инструмент поиска / ключевые слова / название рейтинга / время поиска / список контрольных образцов)
8. Если материалы заявки уже имеются и применяется критерий Qidian: `投稿材料/起点内投/《作品名》/当前版本索引.md`, ключевые файлы в каталоге текущей версии, а также заявление о комбинации шаблонов общего плана или результат его восстановления

## Слои доказательств, дополнительно проверяемые по умолчанию при наличии материалов

Если материалы имеются, при оценке по умолчанию продолжают проверять:

1. Название / аннотация / продающий пункт одним предложением
2. Первые 500 знаков, первые три главы, первые 6000 знаков
3. Биография персонажей / настройки героев
4. Настройки истории / настройки правил / механика мира
5. Общий план
6. Тома / биты первых 10 глав / стартовая таблица тома / микросценарий начала
7. План обновлений, запас, путь подачи и полнота материалов пакета
8. Индекс текущей версии материалов заявки, каталог текущей версии и находящиеся в нём аннотация / основной текст / общий план / план 1-го тома / самопроверка (если материалы заявки уже имеются и применяется критерий Qidian)
9. Заявление о шаблоне общего плана / соответствие шаблону в материалах заявки (если материалы заявки уже имеются и применяется критерий Qidian)

Если отсутствует любой из этих слоёв:

- Необходимо написать об отсутствующих пунктах
- Необходимо понизить уверенность
- Необходимо ограничить сверху или понизить вес по соответствующему измерению
- Нельзя делать вид, что перекрёстные доказательства имеются
- Нельзя записывать «нет материалов нижестоящих слоёв» как причину не отвечать на вопрос допуска текущего уровня

## Предпроверка соответствия шаблону материалов заявки (критерий Qidian по умолчанию)

- Если в данном раунде оценки уже прочитаны материалы заявки, а целевая платформа — Qidian либо платформа не указана и по умолчанию применяется критерий Qidian, необходимо сначала проверить `## 模板组合声明` (заявление о комбинации шаблонов) в общем плане.
- Если заявление о шаблоне отсутствует, необходимо вернуться к чтению `CommonSkills/写作研究/起点模板/总纲模板/README.md` и восстановить по нему основной шаблон; если более подходящего шаблона по-прежнему нет, по умолчанию в качестве минимальной структурной базовой линии берётся `CommonSkills/写作研究/起点模板/总纲模板/九线写作总纲.md`.
- Предпроверка шаблона должна проверить как минимум: разумен ли основной шаблон, ровно ли `1` основной шаблон и `0–2` вспомогательных, корректно ли в материалах заявки используются соответствующие шаблоны для плана / обещания первого тома / долгосрочной подпитки, являются ли вспомогательные шаблоны лишь структурными заплатками.
- Несоответствие шаблону по умолчанию записывается как **риск нормативности дизайна / риск зрелости заявки** и в основном влияет на «рекомендуется ли подавать сейчас», «допущен ли текущий уровень» и «уверенность»; оно не заменяет основную оценку содержания напрямую.

## Правила определения уровня переделки вышестоящих слоёв

### Проблемы уровня общего плана

При следующих обстоятельствах по умолчанию следует определять как проблему уровня общего плана:

- Жанровая классификация, основной продающий пункт, опора главного героя, обещание долгосрочной линии сами по себе несостоятельны;
- Другой способ написания томов не спасёт ключевую предпосылку (premise);
- Тома и основной текст раз за разом обнаруживают «корневая тема несостоятельна, ключевой двигатель несостоятелен, долгосрочной подпитки недостаточно».

### Проблемы уровня тома

При следующих обстоятельствах по умолчанию следует определять как проблему уровня тома:

- Направление общего плана в основном состоятельно, но обещание первого тома, этапные цели, биты первых 10 глав, первая эффективная отдача не доведены до исполнимого уровня;
- Общий план годен, но разложение на тома явно не подходит для прямого начала черновика;
- Основная проблема, обнаруженная в основном тексте, — «план тома не закрепил „парадную дверь“», а не то, что предпосылка (premise) общего плана ошибочна.

### Проблемы уровня основного текста

При следующих обстоятельствах по умолчанию следует определять как проблему уровня основного текста:

- Общий план и тома состоятельны, но ритм начала основного текста, подача информации, выход персонажей, компоновка хуков не исполнены как следует;
- Один и тот же структурный дизайн в конспекте верен, лишь манера письма основного текста испортила впечатление;
- Существующие проблемы в основном можно решить переписыванием глав основного текста, без возврата на более вышестоящий слой.

### Формулировка уровня доработки

- Нужно править только основной текст -> написать «доработка уровня основного текста»
- Нужно править тома, а общий план можно сохранить -> написать «возврат на доработку на уровень томов»
- Нужно править общий план -> написать «возврат на доработку на уровень общего плана»

Пока доказательства не достаточно прочны, нельзя легко повышать проблему основного текста прямо до «весь общий план придётся сносить и начинать заново».

## Жёсткие требования к поиску Топ-10 рейтинга Qidian того же жанра

- Как только оценка в данном раунде попадает на Qidian либо платформа не указана и по умолчанию применяется критерий Qidian, обязательно до суждения по основному тексту завершить **поиск Топ-10 рейтинга Qidian того же жанра**.
- Нужно в приоритетном порядке комбинировать несколько эффективных сетевых инструментов поиска / захвата, доступных в текущей среде, для перекрёстной проверки; нельзя опираться на единственный источник поиска или составлять список образцов лишь по старой памяти.
- По умолчанию фиксируется как минимум: какие инструменты поиска / источники использовались, ключевые слова поиска, название зафиксированного рейтинга, время поиска, список образцов Топ-10, непроверяемые слепые зоны.
- Если только зафиксирован рейтинг и не продолжено поштучное изучение, это считается **пул образцов сформирован, но исследование конкурентов не завершено**.
- По каждому произведению Топ-10 по умолчанию нужно составить краткую карточку доказательств, которая отвечает как минимум на: `1) что в основном тексте / пробной части — самая эффективная опора`, `2) какие привлекательные точки или спорные моменты читательских рецензий / обсуждений упоминаются повторно`, `3) какие проверяемые преимущества или структурные особенности суммируют исследования / разборы`, `4) в чём разрыв, которым оно сильнее всего подавляет конкурентоспособность подписания текущего произведения`.
- После завершения карточек доказательств Топ-10 по умолчанию ещё нужно выбрать из них `3–5` **основных подавляющих образцов** и, продолжая комбинированно вызывать `общий-анализ-конкурирующих-произведений`, провести тяжёлую глубокую разборку по схеме «слой рыночных данных → слой создания контента → слой стратегии эксплуатации → слой отклика аудитории»; только когда пользователь прямо требует полной повторной разборки всего Топ-10, четырёхслойную глубокую разборку расширяют на все образцы.
- Оценка подписания на платформе и все шаблоны рецензирования по умолчанию совместно используют один и тот же эталон количественной оценки конкурентов: `сведение пула кандидатов Топ-10 → краткий обзор четырёхслойной глубокой разборки 3–5 основных подавляющих образцов → единая количественная карта → итоговое суждение / пояснение об ограничении сверху`; при этом фиксированные столбцы и логика ограничения сверху «единой количественной карты» определяются по `шаблон-отчёта-оценки-подписания-на-платформе.md`.
- По критерию Qidian при глубокой разборке конкурентов по умолчанию стараются использовать термины: средние подписки, высокие подписки, первые подписки, дополнительные подписки / соотношение подписок к сбору, значение фанатов, «мэнчжу», почётные значки, включение в книжные подборки, категорийный рейтинг ежемесячных билетов / рейтинг бестселлеров / рейтинг новых книг, «комментарии к главе» / комментарии к абзацам, кружок читателей, читатели «лао бай» и т. п.; если точное значение получить нельзя, необходимо записывать его как прокси-сигнал, а не выдумывать конкретные числа.
- Доказательства из основного текста / пробной части обязательны к прочтению по каждой книге; если по условиям публичного доступа полный основной текст прочитать нельзя, всё равно нужно по возможности прочитать страницу пробного чтения, открытые главы, фрагменты или надёжный пересказ и отметить ограничения.
- Рецензии / обсуждения и материалы исследований / разборов по умолчанию следует искать в приоритете; если по какой-то книге действительно трудно найти один из этих типов, нужно записать ключевые слова поиска, источник поиска и результат неудачи.
- После завершения поштучного глубокого поиска необходимо дополнительно подытожить общие сильные стороны и общие пороги Топ-10 рейтинга, чтобы по ним определить, почему текущее произведение всё ещё недостаточно хорошо.
- Если официальные страницы произведений, оглавлений или пробного чтения Qidian не удаётся стабильно прочитать из-за защиты от парсинга, капчи, необходимости входа или ограничения частоты, разрешается использовать для дополнения доказательств **проверяемые сторонние связанные материалы**, включая упорядоченные оглавления, сводки пробного чтения, обсуждения на форумах, выдержки из рецензий, энциклопедические материалы, пересказы сюжета, рекомендательные тексты и разборы.
- Но сторонние источники должны в первую очередь удовлетворять: **источник ясен, поддаётся перекрёстной проверке, не является явным нарушителем авторских прав**; нельзя использовать пиратские сайты, сайты неавторизованных полных текстов или явные зеркала-нарушители как ключевые источники доказательств основного текста / оглавления. Если недостаточно как официальных, так и законных сторонних источников, это необходимо записать как слепую зону суждения.
- Если в текущем рабочем каталоге, каталоге проекта или каталоге жанра уже существует `竞对分析/`, по умолчанию следует прочитать в нём исторические файлы, относящиеся к целевому произведению данного раунда, образцам того же жанра или близким конкурентным позициям, как уже имеющийся исследовательский кэш.
- Существующие файлы `竞对分析/` могут лишь помогать повторно использовать образцы, выводы и списки проблем и не могут заменять новый поиск по рейтингу, поштучный глубокий поиск и повторную проверку ключевых доказательств данного раунда.
- Если страница рейтинга недоступна напрямую, всё равно нужно с максимальным усилием восстановить Топ-10 образцов того же жанра через несколько наборов ключевых слов и несколько источников поиска; но нельзя пропускать этот шаг из-за неудобства доступа.
- Сопоставление по тому же жанру по умолчанию строится главным образом на **строгом поиске разрывов**: упор на то, почему текущее произведение не выдерживает сравнения с образцами рейтинга, по каким ключевым измерениям явно отстаёт и достаточен ли разрыв, чтобы повлиять на вывод о подписании.

## Дополнение о порогах пути подачи Qidian по умолчанию

### Самостоятельная заявка на подписание

- Общий слой по умолчанию проверяет лишь «достигнут ли порог основного текста для самостоятельной заявки, определённый для текущего жанра / платформы»; если на жанровом слое есть более строгие результаты исследований, жанровый слой имеет приоритет.
- Только если на жанровом слое нет более конкретного критерия, диапазон около `50`–`100` тысяч знаков принимается за обычную полосу наблюдения; не следует ошибочно записывать этот широкий диапазон как одно жёсткое число.
- При подаче заявки лучше по-прежнему поддерживать состояние непрерывных обновлений.

### Внутренняя подача через редактора

- Этот репозиторий больше не использует старую минимальную линию подачи «`6000` знаков непрерывного основного текста + `300` знаков плана» и больше не считает «начало в `20` тысяч знаков + `2000` знаков плана» зрелой линией по умолчанию.
- Единая линия подачи для внутренней подачи Qidian: не менее `30000` знаков непрерывного основного текста + `общий план для внутренней подачи (минимум 5000 знаков)` + `план 1-го тома для внутренней подачи` + `аннотация для внутренней подачи`; `самопроверка сборки пакета` как сопутствующий файл авторской стороны той же версии сохраняется вместе.
- Если единая линия подачи не достигнута, максимум можно сказать «пока подавать не рекомендуется / можно сделать лишь предварительную версию с недостающими элементами», что не равно «рекомендуется внутренняя подача сейчас».
- Даже если единая линия подачи достигнута, если соответствие шаблону, эффективность «парадной двери», долгосрочная подпитка, готовность к исполнению или разрыв с конкурентами по-прежнему не проходят планку, не следует завышать долю прохождения.

### Готовность исполнения к первичной проверке

- По умолчанию рекомендуется подготовить запас не менее `15` глав; по обычному критерию Qidian в `2000` знаков / главу это примерно уровень непрерывной подготовки в `30` тысяч знаков.
- По умолчанию рекомендуется, чтобы можно было доказать способность стабильно обновляться по `4000` знаков в день
- Если длина одной главы долго явно отклоняется от серийного критерия `2000` знаков ±`200` или есть непрерывная остановка более `3` дней, это также следует указать отдельно как риск исполнения
- Если указанная готовность исполнения явно недостаточна, следует перейти к суждению «можно продолжать подготовку», а не «рекомендуется подавать сейчас»

При отсутствии ключевых материалов:

- Необходимо написать об отсутствующих пунктах
- Необходимо понизить уверенность
- Нельзя делать вид, что доказательства имеются
- Нельзя пропускать проверку порога пути подачи

## Правила сохранения отчёта на диск

- Отчёт обязательно сохраняется в: `审阅意见/起点评估/`
- Рекомендуемый путь основного отчёта: `起点签约成功概率评估报告_【评估层级】_【书名】_YYYY-MM-DD.md`
- `【评估层级】` может использовать только: `总纲闸门预评估` (предварительная оценка шлюза общего плана) / `分卷闸门预评估` (предварительная оценка шлюза тома) / `正文准入评估` (оценка допуска основного текста) / `完整签约评估` (полная оценка подписания) / `缺材快筛` (быстрый скрининг при нехватке материалов)
- Если уже есть основной отчёт **по тому же произведению и тому же уровню оценки**: по умолчанию перезаписывать
- Разные уровни оценки должны использовать разные имена файлов и храниться параллельно, нельзя перезаписывать между уровнями
- Если не существует: обязательно создать новый

## В начале отчёта обязательно указать

- Режим оценки
- Текущий уровень оценки
- Цель текущего уровня
- Допускается ли текущий уровень к следующему
- Что именно оценивает поле основной вероятности текущего уровня
- Если дописывается оценка верхнего предела итогового подписания, необходимо указать «верхний предел с низкой уверенностью»
- Целевое произведение
- Ключевые пробные главы / основания начала
- Основные основания по плану
- Ключевые персонажи / ключевая механика — основания (если есть)
- Основания внешнего поиска по рейтингам и критерий отбора образцов Топ-10 того же жанра
- Заявление о шаблоне материалов заявки и предпроверка соответствия шаблону (если применимо)
- Коррекция каталога (если применимо)
- Стратегия вывода

## Минимальная квитанция со стороны диалога

Как минимум пояснить:

- Какие ключевые материалы прочитаны в данном раунде
- На каком уровне оценки находится данный раунд
- Допускается ли в данном раунде следующий уровень; если не допускается — на каком уровне остановились
- Какие инструменты поиска использованы в данном раунде, какой рейтинг того же жанра зафиксирован, кто контрольные образцы
- Завершён ли в данном раунде поштучный глубокий поиск по Топ-10; если есть пробелы — каких именно книг и каких типов материалов не хватает
- Если материалы заявки прочитаны: источник заявления о комбинации шаблонов, основной шаблон, вывод о соответствии шаблону
- Если материалы заявки прочитаны: путь индекса текущей версии, каталог текущей версии, набор основных читаемых файлов
- Использовалось ли в данном раунде дополнение сторонними связанными материалами; если использовалось — почему заблокирован официальный источник, насколько достоверны сторонние источники
- Читались ли в данном раунде существующие файлы `竞对分析/`; если читались — какие файлы остаются действительными, какие выводы скорректированы новыми доказательствами данного раунда
- Количественная оценка измерения конкурентов в данном раунде (__/25) и сработавшее правило ограничения вероятности сверху (если есть)
- В какой путь записан / перезаписан отчёт

## Нижняя граница завершённости

- Без диапазона вероятности — не считается завершённым
- Без пояснения, что именно оценивает основная вероятность данного раунда, — не считается завершённым
- Без вывода «допускается / не допускается текущий уровень» — не считается завершённым
- Без указания уровня доработки и минимального замкнутого цикла исправлений — не считается завершённым
- Без проверки единоличного вето / ограничения сверху — не считается завершённым
- Если прочитаны материалы заявки, но нет заявления о шаблоне и вывода о соответствии шаблону, — не считается завершённым
- Без чёткой рекомендации по подаче или рекомендации по действиям этапа — не считается завершённым
- Без пояснения основных оснований суждения данного раунда и слепых зон суждения — не считается завершённым
- Без поиска Топ-10 рейтинга Qidian того же жанра, поштучного глубокого поиска и строгого сопоставления — не считается завершённым
- Без вывода «единой количественной карты разрыва с конкурентами (пул кандидатов Топ-10 + краткий обзор четырёхслойной разборки 3–5 основных подавляющих образцов + разница + доказательства + патч на 72 часа + чего не стоит копировать)» — не считается завершённым
- Без чёткой записи «почему текущее произведение всё ещё не выигрывает у ведущих образцов того же трека» — не считается завершённым
