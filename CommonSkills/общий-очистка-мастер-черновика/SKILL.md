## Когда использовать

- Перед выводом на нескольких платформах сначала привести главу к более чистой и устойчивой мастер-рукописи.
- Текущий исходник слишком сильно звучит «по-платформенному», что мешает последующему переписыванию под другие платформы.
- Нужно сохранить цепочку событий, эмоциональную ось и хук в конце главы, но убрать избыточную оболочку, пригодную лишь для одной платформы.
- Вы хотите сократить переделки при последующем переписывании под несколько платформ, сначала намертво закрепив неприкосновенное ядро.

## Случаи, когда не применяется

- Вы хотите сразу сделать платформенно-дифференцированный вывод и сохранение в файл.
- Вы хотите написать мастер-рукопись как платформенно-нейтральный текст.
- Вы хотите только финально отшлифовать готовый текст под одну платформу, а не очистить основу перед порождением производных.

## Основная задача этого Skill

1. Выделить **более пригодный для порождения производных** формат мастер-рукописи.
2. Сохранить:
   - цепочку событий
   - цель персонажа / сопротивление / цену
   - изменение отношений
   - границы правил и ключевые точки улик
   - захват начала главы, награду в середине, хук в конце главы
3. Убрать или приглушить:
   - слишком тяжёлые тики одной платформы
   - повторное подчёркивание и повторную компенсацию одной и той же информации
   - избыточные объяснения
   - локальные «полости» и оболочки, мешающие межплатформенному переносу
4. По умолчанию считай авторской оболочкой, которую необходимо сначала вычистить, самоссылки на главы / навигацию по серийному роману / интонацию авторского комментария вроде «эти главы / первые главы / предыдущие главы / эти предыдущие главы / следующие главы / последующие главы / эти последующие главы / предыдущая глава / следующая глава / эта глава / эта самая глава / дальше будет / мы увидим» (китайские триггерные фразы: 这几章 / 前几章 / 前面几章 / 前面这几章 / 后几章 / 后面几章 / 后面这几章 / 上一章 / 下一章 / 本章 / 这章 / 后文会 / 我们会看到); иначе они будут скопированы и усилены последующими платформенными версиями.
5. «Вся глава целиком / эта вся глава / эта целая глава» (整章 / 这整章 / 这一整章) — тоже авторская оболочка, которую необходимо сначала вычистить: они выглядят как итог рукописи, а не рассказ истории; оставшись в мастер-рукописи, они продолжат усиливать эффект выпадения из текста при платформенном переписывании.
6. По умолчанию считай загрязняющей оболочкой, которую необходимо сначала вычистить, группы предложений вида «абстрактное самоповествование + шаблон глагола + канцелярское существительное» (например: «я здесь / у меня в душе … сверить/выровнять …, в конечном счёте / иными словами … формулировка/журнал …, лишь бы …» — китайские образцы: 我这边/我心里…对齐/校准…，说到底/换句话说…口径/日志…，只求…); если в мастер-рукописи есть группы предложений такого рода, на стадию платформенной адаптации переходить запрещено. 7. **Защита цепи предвкушения точек удовлетворения (новое — взято у Дин Вэньтао и «Бродячей жабы» с Zhihu)**: при очистке мастер-рукописи цепь предвкушения точек удовлетворения (анонс → накопление → реализация → новый анонс ещё большей точки удовлетворения) — самый уязвимый объект «затирания»: операция очистки по природе склонна «оставлять лишь информацию о ключевых событиях», а интервал анонс-отсрочка на информационном уровне выглядит как «избыточность, которую можно сжать». Это самое большое заблуждение. Ниже правила защиты:

   a. **В каждой главе сначала отметить позицию в цепи предвкушения точек удовлетворения**: в области метаинформации файла мастер-рукописи (комментарий в заголовке файла или строка-метка) отметить, является ли глава анонсирующей / накопительной / реализующей / переходной
   
   b. **Сигнал анонса сжимать нельзя**: любой абзац, создающий у читателя ожидание «вот-вот случится хорошее/плохое», можно сократить по объёму, но сам сигнал анонса удалять нельзя. При сокращении абзаца анонса вырезается только «риторическая избыточность», но не «повествовательная единица, создающая ожидание»
   
   c. **Интервал накопления-ожидания сжимать нельзя**: интервал отсрочки в оригинале, когда «читатель знает, что оно вот-вот придёт, но оно ещё не пришло» — самая ценная зона ритма. Если при очистке оставить только результат события и убрать процесс отсрочки, все последующие платформенные версии потеряют этот ритмический интервал — и восполнить его на уровне платформенного переписывания уже нельзя, потому что ритм проектируется на уровне мастер-рукописи
   
   d. **Связующие сигналы межглавной цепи анонса удалять нельзя**: если в конце главы для следующей главы оставлен конкретный сигнал анонса (например, «этот человек появится на следующей неделе»), при очистке нельзя сжимать его на том основании, что «в этой главе он не даёт результата» — это прямой двигатель желания читать следующую главу
   
   e. **Полная разметка цикла анонс-реализация**: в области информации об оглавлении глав мастер-рукописи отметить текущее состояние цепи предвкушения точек удовлетворения — «последняя реализация: глава X; нынешний анонс указывает на: около главы X; подряд анонсировалось глав: X». Это помогает всем последующим звеньям платформенного переписывания знать, до какой степени накоплено читательское ожидание
## Усиление по итогам обратной подпитки исследований (2026)

- При очистке мастер-рукописи обязательно сохранить три типа якорей:
   1. Якорь захвата начала (конфликт / аномалия / риск на первом экране);
   2. Эмоциональный якорь персонажа (сопереживаемая реальная боль и давление выбора);
   3. Якорь двигателя в конце главы (нерешённый вопрос, из-за которого необходимо читать дальше).
- «Очистку» нельзя превращать в «обескровливание»: убирать платформенную оболочку, а не эмоциональную ось; убирать повторные объяснения, а не ключевые награды.
- Читаемость на мобильном — часть качества мастер-рукописи: сплошные большие блоки, стены объяснений и слишком ровные группы предложений нужно разбирать уже на уровне мастер-рукописи, не оставляя нагрузку слою платформенного переписывания.

## Порядок выполнения

1. Сначала определить цель: выделить мастер-рукопись из существующей исходной главы или продолжить очистку на основе уже имеющейся основы.
2. Если входной текст сейчас находится в `小说正文/`, он служит только источником входа для очистки; очищенную мастер-рукопись нужно создать заново или записать обратно в `提纯母稿/`, нельзя продолжать держать её в `小说正文/`.
3. Сначала разделить два слоя содержимого:
   - ядро, которое необходимо прибить намертво
   - платформенный слой, который затем можно дифференцировать
4. Сначала проверить, не расшатались ли факты и улики.
5. Затем проверить, держатся ли три ключевые опоры: начало главы, середина, конец главы.
6. Затем проверить, конкретно ли и ощутимо ли давление на персонажа в этой главе.
7. Наконец, обработать одноплатформенные оболочки и повторяющиеся группы предложений, мешающие порождению производных.
8. Перепроверка: проще ли при последующем переписывании под другие платформы получить дифференцированные версии.

## Формулировки вывода по умолчанию

- По умолчанию ориентирован на очистку мастер-рукописи перед порождением платформенных производных, прямо многоплатформенные финальные версии не генерирует.
- Объект по умолчанию — китайская мастер-рукопись, которую готовят к входу в многоплатформенный процесс.
- Очищенную мастер-рукопись разрешено и желательно в первую очередь размещать в папке `提纯母稿/`.
- Нельзя размещать очищенную мастер-рукопись в папке `小说正文/`; `小说正文/` содержит только готовые тексты глав, а не мастер-рукописи до порождения производных.
- По умолчанию напрямую записывать обратно или создавать файлы мастер-рукописи в `提纯母稿/`.

## Минимальная поставка

Хорошая очистка мастер-рукописи для нескольких платформ должна как минимум:

- Чётко определить, какое содержимое нельзя терять ни для одной платформы.
- Сделать так, чтобы три ключевые опоры — начало главы, середина, конец главы — держались.
- Обеспечить устойчивость ключевых точек улик / правил, времени, отношений, цели и цены.
- Сохранить достаточно пространства для дифференциации, чтобы последующая платформенная адаптация могла писать каждую версию по-своему.

## Жёсткие правила

- Нельзя понимать очистку мастер-рукописи как «убрать платформенное ощущение, убрать индивидуальность, убрать остроту».
- Нельзя ради удобства последующих правок стирать в гладкое события, цену, правила, улики, хуки.
- Нельзя заранее превращать мастер-рукопись в тон, специфичный для одной платформы, а затем навязывать его другим платформам.
- Нельзя смешивать платформенные версии для обратной правки мастер-рукописи; мастер-рукопись должна обрабатываться как первоисточник.
- Нельзя хранить, записывать обратно или добавлять очищенную мастер-рукопись в папку `小说正文/`; очищенную мастер-рукопись разрешено и желательно в первую очередь размещать в папке `提纯母稿/`.
- Нельзя принимать самоссылки на главу, анонс следующей главы или интонацию авторского комментария за «серийность»; настоящая серийность — это незавершённое действие, отголосок отношений, новая переменная и конкретный риск.
- Нельзя очищать текст до безвкусной белой основы.
- Нельзя нагромождать шаблонные предложения или добавлять случайные группы предложений ради набора объёма; при появлении семейств загрязняющих фраз вроде «контрольные пункты приходятся на» («对照项落在»), «сначала разбить ту же фразу на осколки» («先把同一句话拆碎»), «сначала разобрать гладкое объяснение» («先把顺滑的解释拆开»), «лишь бы можно было отследить/перепроверить/сошлось» («只求能追溯/复核/对得上») их нужно сначала обнулить.
- Нельзя использовать `scripts/append_cn_unique_monologue.ps1`, `scripts/append_cn_unique_narration.ps1`, `scripts/append_cn_unique_thirdperson.ps1`, `scripts/rephrase_cn_body.ps1`, `scripts/rephrase_en_body.ps1`, `scripts/cn_lexicon_profile_transform.ps1` для генерации основного текста мастер-рукописи или добора объёма.

## Границы с другими Skill / Prompt

- Этот Skill занимается **очисткой основы перед порождением производных**, а не финальной платформенной адаптацией.
- Если пользователь хочет лишь отшлифовать текст под одну платформу, нужно в первую очередь использовать соответствующий Skill шлифовки основного текста.
- Вывод на нескольких платформах и сохранение в файл должна продолжать SOP платформенной адаптации / вывода.
