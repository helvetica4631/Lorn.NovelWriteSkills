# Полный и краткий шаблоны, динамическое состояние, записи поведения (дополнение)

> Усвоена структура досье персонажей внешних `character-template` и `archive-maintenance`; нужна, чтобы усилить биографию персонажа до долгосрочного арбитражного источника «стабильные поля + динамическое состояние + записи поведения + языковой отпечаток».

## 1. Слоистость шаблонов персонажей

### Полный шаблон (герой / злодей / ключевые важные роли)

По возможности должен охватывать:

- Основная информация
- Ядро характера
- Языковой отпечаток
- Фон
- Дуга персонажа
- Нынешнее состояние
- Записи поведения по главам

### Краткий шаблон (обычные второстепенные персонажи)

Должен охватывать как минимум:

- Основная информация
- Характер и функцию
- Языковой отпечаток
- Нынешнее состояние
- Записи поведения по главам

### Правила повышения

Если доля сцен второстепенного персонажа растёт, а структурная роль заметно расширяется, можно повысить до полного шаблона; при повышении дополнять поля, но не стирать старые записи.

## 1.5. Отображение слоёв источника (новое)

- `模板层级层 (слой уровня шаблона)`: правильно ли определено — полный шаблон / краткий шаблон / правила повышения.
- `动态状态层 (слой динамического состояния)`: по-настоящему ли ведутся положение, эмоции, известная информация, предметы в руках, состояние тела, последняя обновлённая глава.
- `行为记录层 (слой записей поведения)`: можно ли непрерывно дописывать записи поведения по главам, существенные изменения отношений, эмоциональные варианты языкового отпечатка.

## 2. Рекомендуемые поля полного шаблона

### Основная информация

- Полное имя
- Возраст
- Пол
- Профессия / личность
- Черты внешности (выделить узнаваемые точки)
- MBTI (если проект действительно использует)

### Ядро характера

- Основные черты
- Основные ценности
- Внутреннее желание
- Самый большой страх
- Роковой недостаток
- Поведенческие склонности (как поведёт себя под давлением)

### Языковой отпечаток

- Стиль речи
- Речевые привычки
- Изменения речи при смене эмоций

### Фон

- История фона
- Ключевое событие
- Секрет

### Дуга персонажа

- Исходное состояние
- Основной конфликт
- Ожидаемое направление изменений

## 3. Поля динамического состояния

При продвижении глав в первую очередь обновлять:

- Положение
- Эмоциональное состояние
- Известная информация
- Имущество
- Состояние тела
- Последняя обновлённая глава

Эти поля — первый рычаг, чаще всего используемый при выверке непрерывности и основного текста.

## 4. Записи поведения по главам

- Одна фраза на главу
- Дописывать, не переписывать задним числом
- Записывать только ключевое поведение и результат
- Не писать длинных психологических разборов

Роль:

- Быстро вспомнить, что персонаж делал в последних главах
- Дать жёсткие факты для непрерывности, рецензирования, создания основного текста

## 5. Стабильные поля vs динамические поля

### Стабильные поля

- Ядро характера
- Основа ценностей
- Главная ось языкового отпечатка
- Фон и опыт роста
- Общее направление дуги персонажа

### Динамические поля

- Текущее положение
- Текущие эмоции
- Текущая известная информация
- Текущие предметы в руках
- Новейшее состояние тела
- Новейшая разница позиций в отношениях

По умолчанию не принимать колебание эмоций в одной главе за изменение основы характера.

## 6. Рекомендации по общему обзору отношений

Биография персонажа лучше всего должна допускать взаимные отсылки с общим обзором отношений, как минимум позволять быстро найти:

- С кем какие отношения
- Нынешнее состояние
- Ключевые события
- Последнюю обновлённую главу

## 7. Дополнительные требования к языковому отпечатку

Помимо «как обычно говорит», по возможности прописывать:

- Как говорит в гневе
- Как говорит в страхе
- Как говорит при маскировке
- Как говорит при близости
- Меняет ли голос перед вышестоящим / нижестоящим / знакомым / незнакомым

## 8. Красные линии

- Нельзя иметь только достоинства персонажа без недостатков
- Нельзя иметь только статичный образ без динамического состояния
- Нельзя иметь только историю фона без записей поведения
- Нельзя, чтобы все персонажи пользовались одним шаблоном речи
- Нельзя оставлять «текущее состояние» пустым и долго не сопровождать

## 9. Минимальный динамический артефакт (новое)

```markdown
【模板层级层 (слой уровня шаблона)】полный / краткий / следует ли повышать
【动态状态层 (слой динамического состояния)】положение / эмоции / известная информация / предметы в руках / состояние тела / последнее обновление
【行为记录层 (слой записей поведения)】ключевое поведение в этой главе / изменение отношений / языковой вариант
【Текущая оценка】Green / Yellow / Red
```

## 10. Оценка динамики Green / Yellow / Red (новое)

- `Green`: уровень шаблона определён правильно, динамическое состояние реально отслеживается, записи поведения допускают продолжение.
- `Yellow`: основные поля есть, но динамическое сопровождение нестабильно или записи поведения пустоваты, позже легко возникнет разрыв.
- `Red`: шаблон выбран неверно, динамическое состояние долго пусто, записи поведения отсутствуют, от досье персонажа остаётся только статичная оболочка.
