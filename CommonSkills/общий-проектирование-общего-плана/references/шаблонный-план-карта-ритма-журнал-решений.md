# Шаблонизированный план, карта ритма, журнал решений (дополнение)

> Усвоены внешние `outline-template`, `planner-skill` и их система ритма / решений; нужны, чтобы усилить общий план от «обзора истории» до «стратегического пакета со входами в таблицу планирования глав, TODO, карту ритма, линии интриги и журнал решений».

## 1. Минимальные поля общего плана

Общий план должен чётко определять как минимум:

- Жанр
- Ожидаемое число глав
- Целевой диапазон знаков
- Основной конфликт
- Тему
- Стилистическую тональность

## I.5. Быстрое определение слоя источника (новое)

- `模板规划层 (слой шаблонного планирования)`: жанр, объём, основной конфликт, тема, сочетание шаблонов и вход в таблицу планирования глав.
- `节奏地图层 (слой карты ритма)`: весомость тяжёлых / средних / лёгких глав, риск усталости, линии интриги и этапная форма волны.
- `决策日志层 (слой журнала решений)`: структурные изменения, перестановки интриг, слияние / разделение глав, причины отклонения от структуры черновика и условия, запускающие пересмотр.

Порядок по умолчанию: сначала дополнить `模板规划层`, затем `节奏地图层`, и лишь потом `决策日志层`; не нужно сначала записывать решения, а потом обнаруживать, что даже таблица планирования глав не открыта.

## 2. Линии интриги всей книги

Рекомендуется выделить отдельно:

- Интрига главной линии
- Побочные интриги
- Итоговое раскрытие

Требования:

- Вопросы основной линии должны проходить через всю книгу
- Вопросы побочных линий должны этапно питать повествование
- Итоговое раскрытие — не новая информация, впервые придуманная в последней главе

## 3. Структурное деление

Внешний шаблон по умолчанию — три акта, но в этом репозитории его можно перевести в существующую систему `M0 / X / C / 故事面`:

- Первый акт: построение (建置)
- Второй акт: противостояние
- Третий акт: разрешение

Ключевое — не число актов, а:

- Что завершает каждый отрезок
- Каким крупным поворотом заканчивается
- Оставлено ли для последующих групп томов пространство для дальнейшей эскалации

## 4. Таблица планирования глав

На уровне общего плана рекомендуется заранее составить таблицу глав, включающую как минимум:

|Глава|Заголовок|Ключевое событие|Весомость ритма|Хук-интрига|Статус|
|---|---|---|---|---|---|
|ch01|Пока нет|Пока нет|Тяжёлая / средняя / лёгкая|Пока нет|Ожидает написания|

### Производные правила

- Весомость ритма как минимум различает `重 / 中 / 轻` (тяжёлая / средняя / лёгкая)
- Запрещено, чтобы `3` и более главы подряд были `重 (тяжёлыми)`
- Поле статуса должно поддерживать последующее продвижение `待创作 → 进行中 → 已完成` (ожидает написания → в работе → завершено)

## 5. TODO и резюме глав

### Рекомендуемые три колонки списка TODO

- Ожидает написания
- В работе
- Завершено

### Резюме глав

После финализации каждой главы добавлять `2–3` фразы:

- Ключевое событие
- Изменение персонажей
- Продвижение интриги

Не писать лишь «в этой главе произошло многое».

## 6. Статистика знаков и карта ритма

Рекомендуется, чтобы общий план вёл:

- Число завершённых глав
- Накопленное число знаков
- Прогресс завершения
- Визуальную схему ритма
- Распознавание текущей модели ритма
- Риск усталости
- Рекомендуемый диапазон корректировки

### Типичные модели ритма

- Волнообразная: тяжёлая — лёгкая — тяжёлая — лёгкая — тяжёлая
- «Сэндвич»: лёгкая — средняя — тяжёлая — средняя — лёгкая
- Восходящая: лёгкая — лёгкая — средняя — средняя — тяжёлая
- Рывок и отдых: тяжёлая — лёгкая — лёгкая — тяжёлая — лёгкая

## 7. Вход в журнал решений

На уровне общего плана следует предусмотреть механизм журнала решений, фиксирующий:

- Причины разделения / слияния глав
- Обоснование проектирования линий интриги
- Обоснование распределения весомости ритма
- Причины корректировки положения основной / побочных линий
- Причины отклонения от структуры черновика

## 7.5. Шаблонизированный артефакт общего плана (новое)

```markdown
【模板规划层 (слой шаблонного планирования)】жанр / объём / конфликт / сочетание шаблонов / таблица планирования глав
【节奏地图层 (слой карты ритма)】распределение тяжёлых-средних-лёгких / линии интриги / риск усталости
【决策日志层 (слой журнала решений)】последние ключевые решения / условия, запускающие пересмотр
【Текущая оценка】Green / Yellow / Red
```

## 8. Принципы порождения темы

Тема должна естественно вырастать из истории персонажей, а не сначала записывается одна фраза-тема, а потом персонажей заставляют её исполнять:

- Сначала опыт персонажа
- Затем фон характера
- Затем из выбора и последствий вырастает тема

Метод проверки:

- Если убрать фразу с темой, остаётся ли история состоятельной
- Есть ли у крупных выборов внутренняя мотивация
- Нет ли случаев, когда «ради выражения темы персонаж делает то, что ему не свойственно»

## 9. Красные линии уровня общего плана

- Нельзя ограничиваться настройками и понятиями без таблицы планирования глав
- Нельзя иметь только резюме основной линии без входов в TODO / резюме / карту ритма
- Нельзя ставить три тяжёлые главы подряд без осознания усталости
- Нельзя писать тему как лозунг высокого давления, превращая персонажей в функциональных «инструментов»

## 10. Оценка шаблонизации Green / Yellow / Red (новое)

- `Green`: все три слоя есть и могут напрямую поддерживать последующее сопровождение общего плана и разбивку на тома.
- `Yellow`: есть шаблон и чувство ритма, но журнал решений или вход в планирование остаются пустоватыми, риск сопровождения в дальнейшем высок.
- `Red`: есть только обзор истории, нет шаблонизированного планирования, карты ритма или осознания журнала решений, дальнейшее стабильное продолжение затруднено.
