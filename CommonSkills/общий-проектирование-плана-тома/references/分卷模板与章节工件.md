# Шаблон тома и артефакты глав

## 1. Обязательные критерии

- `章清单（Chapter Beat Sheet）` («перечень глав (Chapter Beat Sheet)») — единственный чертёж.
- `逐章微型剧本（具体章节规划）` («поэпизодные микросценарии (конкретное планирование глав)») — прямой мост между исполнительной версией тома и основным текстом; при отсутствии этого слоя нынешний продукт может считаться лишь черновиком плана арки, но не исполнительной версией, пригодной для прямого перехода к основному тексту.
- Поэпизодные микросценарии обязаны строго соответствовать перечню глав, разрешается лишь детализировать исполнительные подробности — кадры, диалоги, действия, улики / ключевые носители, изменения состояния, изменения реестра; запрещено свободно переписывать точку зрения, цель главы, основной конфликт, ключевой сюжет / перелом, связанные сюжетные линии, непосредственные последствия, закладки / переклички, тип хука.
- Число глав тома по умолчанию пересчитывается из расчёта около `3000` знаков на главу; если пользователь указал иной критерий, обязательно явно написать причину смещения.
- Каждая глава обязана ясно определить, какую задачу вышестоящего уровня подхватывает, кем она является — главой явной посадки / главой сохранения тепла / главой передачи, — и пояснить, как эта глава создаёт для читателя причину читать следующую.
- Когда в главе выбрасываются «наводящая информация» — скриншот, готовая версия, официальная формулировка, системная запись, следы правки, различие версий и т. п. — по необходимости дописывать `≤3章破口计划` («план бреши не более чем на 3 главы»); если глава несёт обязанность главы запуска бреши или ключевого продвижения, это поле обязательно.
- Если в этом томе применяется продвижение по дням истории, сначала обязательно дать единый критерий WHEN (например `D+0 = YYYY-MM-DD`), и лишь затем в последующих главах можно использовать относительные записи вроде `D+1 / D+2`; нельзя, чтобы в целом томе были только относительные даты без абсолютной точки отсчёта.
- Если нужно продолжить спуск поэпизодных микросценариев до строительства одной главы или основного текста глав, в приоритете дополнительно комбинировать вызов нижестоящих возможностей, таких как `общий-исполнение-сценической-единицы`, `общий-создание-основного-текста`.

## 1.5 Быстрое определение иерархии артефактов (новое)

> **Изменение приоритета уровней**: `слой повествования` теперь имеет наивысший приоритет среди уровней артефактов. Прежде чем переходить к любым полям чертежа или исполнения, история этого уровня должна быть ясно рассказана.

- `Слой повествования (новое — наивысший приоритет)`: краткое содержание истории тома, в каждой главе «▶ о чём эта глава». **Пока этот раздел не завершён, в слой чертежа не переходить.**
- `Слой чертежа на уровне тома`: перечень преемственности, обзор тома, стартовая таблица тома, таблица расстановки точек удовлетворения, таблица продвижения персонажей, пульт управления закладками.
- `Слой чертежа на уровне глав`: перечень глав, позиционирование главы, цель главы, основной конфликт, непосредственные последствия, тип хука.
- `Слой мостика исполнения`: поэпизодные микросценарии, ключевые носители, узлы действий, план бреши не более чем на 3 главы, обратные ссылки.

Порядок по умолчанию: **слой повествования → слой чертежа на уровне тома → слой чертежа на уровне глав → слой мостика исполнения**. Если слой повествования не пройден, то все последующие поля, даже заполненные до конца, — лишь план «структурно верный, но история крутится вхолостую».


## 4. Дополнительные пояснения по поэпизодным микросценариям

> **Изменение основного принципа**: `▶ О чём эта глава (читать в первую очередь)` теперь — **поле первого приоритета** поэпизодного микросценария. Не потому, что оно стоит первым в шаблоне, а потому, что **перед любыми инженерными полями вы обязаны суметь естественным языком ясно рассказать историю этой главы**. Если вы не можете написать даже абзаца, который можно пересказать, об «о чём эта глава», то как бы полно ни были заполнены остальные поля, это бессмысленно.

- `▶ О чём эта глава (читать в первую очередь)` — не краткий лозунг, а нужно писать так, чтобы автор мог прямо на этом основании приступать к работе. **Критерий приёмки**: показать этот абзац отдельно человеку, не видевшему эту главу, — он должен суметь пересказать «в этой главе произошло ____». Если нет → переписать, не продвигаться к инженерным полям.
- `Торговая точка главы / точка запоминания читателя` особенно подходит для первых глав тома, глав поэтапных наград, глав в конце тома; может использоваться для подхвата точек подписания, точек клика на странице оглавления, «гвоздей» распространения.
- `Разбивка на кадры` рекомендуется в `3–5` кадров, чтобы действия, информация и эмоции можно было «снять», а не оставались лишь абстрактные пояснения.
- `Ключевые фрагменты диалога` рекомендуется `3–6` реплик, обязательно с подтекстом, избегать записей вроде «двое поссорились / достигли согласия».
- `Узлы действий` — минимум `3` группы микропричинных цепочек; это важный водораздел, можно ли по микросценарию продолжать писать основной текст.
- `Перечень ключевых носителей / улик` принят в широком смысле: для интриги / офиса можно писать вещественные улики, квитанции, рабочие заказы, записи; для эмоциональной линии / роста — спусковые предметы, ключевые предметы, переписки, совместные фото, подарки, оформление места действия и другие прослеживаемые носители.
- `Изменения реестра / индекса этой главы` — усиленный пункт, включаемый по необходимости жанра; если в проекте есть реестр зацепок, реестр закладок, реестр отношений, реестр улик, рекомендуется синхронно обновлять в поэпизодных микросценариях.
- `План бреши не более чем на 3 главы` (`≤3章破口计划`) применим к главам, в которые входит «наводящая информация» — скриншот, готовая версия, официальная формулировка, системный вывод, следы правки, различие версий и т. п. В этом поле нужно как минимум ясно написать: к какому периоду плана бреши относится текущая глава — запуск / продвижение / возврат, в ближайшие `≤3` главы какую именно наводящую информацию необходимо продвинуть до какой проверяемой бреши.
- Если ключевой носитель этой главы всё ещё остаётся на уровне скриншота, пересказа, готового видео, официальной формулировки или системного вывода, как правило, нельзя опускать `≤3章破口计划` — иначе в дальнейшем легко потерять давление возврата.
- Для `типа хука в конце главы` рекомендуется выбирать хотя бы из трёх классов `перелом / раскрытие / кризис`, избегая записи лишь абстрактной эмоции без способа запуска следующей главы.
- Если у ключевых глав уже есть полные поэпизодные микросценарии, в дальнейшем можно продолжать вызывать нижестоящие возможности строительства одной главы или создания основного текста, чтобы между перечнем глав и основным текстом не было разрыва.

## 5. Контрольный перечень аудита части / тома

### 5.1 Самопроверка плана части

- [ ] Перечислен ли перечень преемственности части и охватывает ли всё содержание, распределённое слоем общего плана этой части?
- [ ] Определены ли целевое число знаков и целевое число глав части на основании целевого числа знаков, распределённого вышестоящим уровнем, а не назначены произвольно?
- [ ] Дана ли матрица распределения сюжетных блоков?
- [ ] Выполнено ли «основная линия — несколько блоков, побочная — один блок, блок однозначно отображён, продвижение через тома»?
- [ ] Является ли каждая сюжетная линия полной историей, а не ярлыком?
- [ ] Ясно ли определено, к какому тому относится каждая сюжетная линия?
- [ ] Есть ли обратные ссылки, позволяющие проследить до грани истории общего плана?
- [ ] Приземлены ли качественно и в полном объёме основные линии, побочные линии, грани истории, закладки, переклички, улики / ключевые носители, дуги персонажей, распределённые вышестоящим уровнем этой части?

### 5.2 Самопроверка плана тома

#### Слой повествования (новое — проверять в первую очередь)

- [ ] **«Краткое содержание истории тома» ясно написано**: на 200–300 знаках естественным языком рассказана история этого тома, человек, не знакомый с проектом, может её пересказать
- [ ] **«▶ О чём эта глава» каждой главы ясно написано**: не бухгалтерская запись, а микроповествование с завязкой—развитием—поворотом—развязкой
- [ ] **После прочтения тома можно ответить «о чём этот том»**, а не только сказать «в этом томе использован шаблон XX, ритм XX»
- [ ] **Повествование истории этого тома согласуется с «историей одной фразой» слоя общего плана**: сюжетная дуга тома — часть истории общего плана, а не отклонение или собственное начинание

#### Структурный слой

- [ ] Перечислен ли перечень преемственности тома и охватывает ли всё содержание, распределённое вышестоящим уровнем этому тому?
- [ ] Явно ли целевое число знаков тома взято из распределения вышестоящего уровня, а не определено самовольно?
- [ ] Выполнен ли расчёт и проектирование числа глав тома по критерию по умолчанию **около 3000 знаков / глава**?
- [ ] Дана ли стартовая таблица тома (первые пять глав)?
- [ ] Дана ли таблица расстановки точек удовлетворения?
- [ ] Дана ли схема расстановки ритма `5 / 15`?
- [ ] Можно ли перечень глав прямо разбивать на главы?
- [ ] Дополнен ли `执行级伏笔管控台（VX.Y.Z）` («пульт управления закладками уровня исполнения (VX.Y.Z)»)?
- [ ] Дополнена ли `本卷上游任务落地核对表（强制）` («контрольная таблица приземления задач вышестоящего уровня в этом томе (обязательно)»)?
- [ ] Есть ли в каждой главе `WHEN / WHERE / WHO / WHAT / WHY / HOW`?
- [ ] Есть ли в каждой главе минимум `2` аудируемых или прослеживаемых ключевых носителя?
- [ ] Если в главе выброшена наводящая информация — скриншот, готовая версия, официальная формулировка, системная запись, следы правки или различие версий, — дописан ли `≤3章破口计划`?
- [ ] Есть ли в каждой главе минимум `1` прослеживаемое изменение состояния и ясный хук в конце главы?
- [ ] Полностью ли поэпизодные микросценарии согласуются с перечнем глав?
- [ ] Связаны ли точки удовлетворения, улики / ключевые носители и цена вместе, а не просто громкие призывы к стимулам?
- [ ] Реально ли и в полном объёме приземлены основные линии, побочные линии, поэтапные задачи граней истории, закладки и переклички, распределённые вышестоящим уровнем этому тому?

## 5.3 Минимальные артефакты тома и глав (новое)

```markdown
[Слой чертежа на уровне тома] Основной вопрос тома / стартовая таблица / расстановка точек удовлетворения / реестр закладок
[Слой чертежа на уровне глав] Перечень глав / позиционирование главы / конфликт / последствия / тип хука
[Слой мостика исполнения] Поэпизодные микросценарии / ключевые носители / узлы действий / план бреши
【Текущая оценка】Green / Yellow / Red
```

## 6. Сигналы провала

- Смешаны сюжетные блоки, сюжетные линии и сюжетные точки трёх слоёв.
- У части только общий смысл, нет распределения через тома.
- У тома только пересказ сюжета, нет информации на уровне глав, пригодной для письма.
- Перечень глав и поэпизодные микросценарии противоречат друг другу.
- Есть только лозунги интриги, нет ключевых носителей, улик и цены.
- Выброшены скриншот, готовая версия, официальная формулировка, системный вывод или различие версий, а `≤3章破口计划` нет.
- Написан перечень преемственности на уровне тома, но в `本卷上游任务落地核对表` («контрольной таблице приземления задач вышестоящего уровня в этом томе») всё ещё не найти конкретного положения по главам.

## 7. Вердикт по артефактам Green / Yellow / Red (новое)

- `Green`: слои тома, глав и мостика исполнения — все три готовы, можно прямо обслуживать нижестоящее строительство одной главы.
- `Yellow`: перечень глав и логика уровня тома есть, но слой мостика исполнения ещё тонок, перед переходом к основному тексту нужно ещё детализировать.
- `Red`: сам чертёж на уровне тома или глав нестабилен, поэпизодные микросценарии лишь делают нестабильную структуру длиннее.
