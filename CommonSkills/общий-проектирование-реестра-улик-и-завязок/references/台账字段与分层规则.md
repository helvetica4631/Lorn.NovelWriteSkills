# Поля реестра и правила послойной организации

## Рекомендуемые поля

| Поле | Назначение |
| --- | --- |
| Номер | Уникальный индекс, рекомендуется делить на слои `CL` / `FB` / `MIS` |
| Тип | Зацепка / завязка / ложный ход / точка возврата |
| Первое появление | Файл, том, глава первого выдвижения |
| Текущее состояние | Выдвинута / усилена / ждёт возврата / возвращена / отменена |
| Сила интриги | Уровень любопытства / уровень беспокойства / уровень неотложности / уровень выживания / предельный уровень |
| Ключевой носитель | Улика, действие, диалог, предмет, правило, институциональный контрольный пункт |
| Последнее продвижение | Последняя глава, где она была усилена, получила ответ или была перенесена |
| Состояние цепи хуков | Прямой ответ / косвенная связь / намеренная отсрочка / риск обрыва |
| Окно возврата | Рекомендуется обработать около какого тома / какой главы |
| Действие возврата | Кто каким действием завершает возврат |
| Способ возврата | Симметричная сцена / повтор реплики / возвращение предмета / перекомпоновка информации |
| Реализация точки удовлетворения | Эмоциональная награда читателю при возврате |
| Цена / последствия | Что теряется после возврата, какой новый разрыв порождается |
| Просрочена ли | Нет / предупреждение / уже просрочена |

## Рекомендуемый формат таблицы управления

```markdown
| Номер | Содержание завязки | Место «рытья ямы» | Место «засыпания ямы» | Охват | Важность | Состояние |
|------|----------|----------|----------|----------|----------|------|
| T1 | Ключевой фрагмент пазла правды старого дела десятилетней давности | Том 1, глава 1 | Конец тома 4 | Через тома | Ядро | В процессе |
```

## Рекомендации по послойности

- `CL`: зацепка, склоняется к пазлу фактов и пути сбора улик.
- `FB`: завязка, склоняется к обещаниям, отголоскам, перекличке начала и конца.
- `MIS`: ложный ход, обязательно чётко указывать точку опровержения.

## Быстрое суждение по слоям-источникам (новое)

- `Слой структуры реестра`: стабильны ли номер, тип, носитель, первое появление, текущее состояние и сквозная формулировка нумерации между уровнями.
- `Слой окон планирования`: ясны ли последнее продвижение, окно возврата, действие возврата, способ возврата и предупреждение о просрочке.
- `Слой честной реализации`: чётки ли реализация точки удовлетворения, цена / последствия, опровергаемость и новый разрыв после возврата.

Порядок по умолчанию: сначала стабилизировать `Слой структуры реестра`, затем смотреть `Слой окон планирования`, в конце оценить `Слой честной реализации`; не писать сначала «в финале вернём», когда даже текущее состояние и окно не стабильны.

## Классификация завязок по уровням

- **Стратегические завязки**: ключевые тайны, влияющие на направление главной линии всей книги (возврат через этапы / тома)
- **Тактические завязки**: важные зацепки, влияющие на развитие сюжета на определённом этапе / группе томов
- **Исполнительные завязки**: конкретные детали, влияющие на читательский опыт главы

## Часто используемая система управления нумерацией

- Завязки общего плана: `T1`, `T2`, `T3`……
- Завязки плана части: `P1.1`, `P1.2`, `P2.1`……
- Завязки плана тома: `V1.1.1`, `V1.1.2`……

## Механизм взаимодействия уровней

- **Детализация вниз**: стратегические завязки общего плана обязательно должны иметь конкретное воплощение в частях и томах
- **Отчёт вверх**: исполнительные завязки в томе, если они имеют большое значение, нужно пометить в вышестоящем плане
- **Горизонтальная координация**: между разными файлами одного уровня формулировки завязок должны быть едиными

## Стабильные правила

- Сильную зацепку лучше с момента первого появления привязать к ощутимому носителю.
- Ключевая завязка должна пройти как минимум три этапа: «выдвижение + усиление + возврат».
- Ложный ход должен прошиваться уликой, действием или правилом более высокого уровня.
- Нельзя писать только функцию завязки, не описывая конкретный способ закладки, траекторию развития, приём раскрытия и эффект перекличек.

## Дополнительные правила управления интригой

- По умолчанию по возможности соблюдать «в каждой главе отвечать на один старый вопрос, затем открывать новый»; если долго лишь открываются новые вопросы без ответов на старые, в реестре это необходимо явно пометить красным.
- Одновременно активных линий интриги с высоким вниманием лучше держать `3–4`; при превышении нужно указать главные/второстепенные и порядок ротации.
- Малую интригу обычно возвращают в пределах `1–3` глав, среднюю — `5–8`, большая может идти через тома; при превышении окна без продвижения состояние нужно сменить на `предупреждение / уже просрочена`.
- Плохие хуки, которые нужно особо помечать красным: ложная интрига, deus ex machina, чрезмерная недосказанность, хук с малым риском, усталость от хуков одного типа несколько глав подряд.

## Минимальный артефакт реестра (новое)

```markdown
【Слой структуры реестра】номер / тип / носитель / первое появление / текущее состояние
【Слой окон планирования】последнее продвижение / окно возврата / действие возврата / способ возврата / просрочена ли
【Слой честной реализации】реализация точки удовлетворения / цена и последствия / точка опровержения / новый разрыв после возврата
【Текущая оценка】Green / Yellow / Red
```

## Оценка реестра Green / Yellow / Red (новое)

- `Green`: все три слоя ясны, реестр может отслеживать и окна, и качество реализации.
- `Yellow`: структура есть, но слой окон планирования или реализации ещё пустоват, потом легко «помнить номер, но забыть награду».
- `Red`: есть только номера и названия, нет окна, действия, последствий и формулировки честности — реестр не может по-настоящему направлять возврат.
