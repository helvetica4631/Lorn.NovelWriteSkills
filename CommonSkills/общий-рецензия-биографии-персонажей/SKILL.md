## Порядок выполнения по умолчанию

Рецензирование биографии персонажа выполняется по следующим шагам, на каждом указано, какие справочные файлы нужно прочитать:

### Шаг 1: подготовка перед рецензией
1.1 Подтвердить целевой файл биографии персонажа, собрать связанное с персонажем содержимое из общего плана, тома, документов событий.
1.2 Если в корне проекта есть `Agents.md`, выполнить `## Правила автоматического обнаружения шаблонов стиля / эталонов / исследований письма` и загрузить соответствующие измерения сопоставления с дистилляционными шаблонами.
1.3 Загрузить `references/чек-лист-рецензии-биографий.md` как базовую таблицу поэлементной сверки.

### Шаг 2: сквозное чтение и многомерный аудит
2.1 Полностью прочитать текст биографии один раз, не прерываясь на суждения. Поэлементно проверить принадлежность идентичности, замкнутость цикла «мотивация — цена», границы способностей и набор инструментов, сеть отношений и зеркального противника.
2.2 Загрузить `../общий-проектирование-биографии-персонажей/references/nuwa-внедрение-глубокой-ментальной-модели-персонажа.md`, выполнить глубокую рецензию Nuwa: выделение ментальной модели, распознавание ДНК выражения, проверка напряжения противоречия, суждение о честных границах, оценка эвристик решений.
2.3 Выполнить быстрый отсев персонажа хита Qidian и оценку сопереживания (10-секундный отсев + оценка платной ценности + проверка позиционирования вживания в читательскую группу).

### Шаг 3: специальная рецензия
3.1 Выполнить двухдорожечную повторную проверку инструментальности / независимости второстепенных персонажей, повторную проверку точек распространения-обсуждения персонажа.
3.2 Загрузить `references/колонка-tencent-рецензия-персонажей-играбельность-и-узнаваемость.md` и проверить, достигнуты ли пригодность персонажа для сцены и узнаваемость перед читателями Qidian.
3.3 Если загружены измерения сопоставления с дистилляционными шаблонами, выполнить аудит сопоставления по правилам рецензии сопоставления с дистиллятом.
3.4 **Выполнить аудит взаимного зацепления пяти измерений персонажа** (новое — на основе системы «пять измерений для построения образа» Лао Дао с Zhihu):
   - Проверить, служат ли пять основных измерений персонажа (настройка идентичности, настройка положения, проектирование характера, позиционирование способностей, направление желаний) **одному и тому же ядру персонажа**, нет ли взаимно противоречивых сочетаний.
   - Критерии противоречия: конфликт архетипа идентичности и направления желаний (например, «личность хладнокровного убийцы + желание безмятежно заниматься землёй»), конфликт позиционирования способностей и проектирования характера (например, «задан как непобедимый в мире + характер крайне труслив»), противоречие настройки положения и позиционирования способностей (например, «долго угнетаемый низами + с самого начала скрытый босс» без разумного объяснения).
   - **Проверка одной фразой**: можно ли одной фразой сказать, «каков это человек»? Если нет, значит пять измерений ещё не сошлись в единое ядро.
   - Если есть ≥1 явное противоречие, пометить «раскол пяти измерений» как Critical, слой-источник: `[пять измерений персонажа]`.
3.5 **Выполнить рецензию масштаба влияния способностей** (на основе урока Zhihu «Недавно бросил семь книг» о «гении, спасающем только себя»):
   - Проверить, соответствует ли позиционирование героя повествовательному влиянию его способностей — если герой позиционируется как «гений / обладатель необыкновенных способностей», соответствует ли масштаб влияния его способностей на мир этому позиционированию.
   - Если уже написано несколько десятков тысяч знаков основного текста, проверить, не ограничивается ли влияние способностей героя лишь им самим и очень малым числом окружающих, не имея почти никакого влияния на более широкий масштаб (общество / организация / ситуация) — это типичный симптом «гения, спасающего только себя».
   - Критерий рецензии масштаба влияния способностей: к 200 тыс. знаков основного текста ощутимое влияние таланта героя на мир должно как минимум достигать «изменения малой экосистемы, где он находится (класс / отделение / лагерь / компания)», к 500 тыс. знаков — как минимум «вызвать изменение расклада среднего масштаба (город / секта / отрасль / район поля боя)».
   - Если способности героя и масштаб его повествовательного влияния серьёзно не соответствуют, признать риск «растраты способностей», слой-источник: `[масштаб влияния способностей]`.
### Шаг 4: построение отчёта рецензии
4.1 Загрузить `references/каркас-отчёта-рецензии-биографий.md` как основной скелет отчёта.
4.2 Сопоставить с `references/дополнение-отчёта-рецензии-биографий.md`, дописать раздел глубокой рецензии Nuwa, аудит сопоставления с дистиллятом (если выполнялся), градацию потенциала Qidian.
4.3 Обеспечить, чтобы отчёт полностью охватывал выводы семимерного аудита + повторно используемые материалы для письма (не менее 4 классов, по 3–7 пунктов в каждом) + кадр появления, который можно прямо вставить обратно в основной текст (не менее 1 абзаца) + реплики, которые можно прямо использовать повторно (не менее 3 фраз).
4.4 Дать вердикт о принятии в библиотеку Green / Yellow / Red.

### Шаг 5: оценка
5.1 Загрузить `references/пояснение-измерений-рецензии.md` и оценить по очереди семь измерений (идентичность / мотивация / границы / отношения / рычаги / дуга / индекс).
5.2 Если комплексная оценка ниже 9,20, нужно приложить конкретный путь оптимизации.

### Шаг 6: градация проблем и рекомендации по обратной записи
6.1 Загрузить `references/градация-проблем-биографий-и-рекомендации-записи.md` и отнести каждую проблему к одному из трёх уровней Critical / Warning / Suggestion.
6.2 Вывести минимальный рецепт доработки (в первую очередь дополнить действие первого появления, конкретность мотивации, проявление цены, функцию событий сети отношений).

### Правила исполнения рецензии с сопоставлением

1. **Приоритет сопоставления**: шаблон образца произведения (сопоставление структуры персонажей) > шаблон стиля автора (аудит голоса / выражения) > шаблон исследования письма (сопоставление ограничений на проектирование персонажей).
2. **Влияние на оценку**: измерения сопоставления с дистилляционными результатами по умолчанию имеют вес **20 %** в комплексной оценке рецензии персонажей; если из-за отсутствия дистилляционного шаблона ключевое измерение сопоставления отсутствует, нужно пометить «слепая зона сопоставления с дистиллятом».
3. **Откат при отсутствии шаблона**: если какого-то вида дистилляционного шаблона нет, соответствующее измерение сопоставления автоматически пропускается, баллы не снимаются, процесс не блокируется.
4. **Обработка конфликтов**: при конфликте с мотивацией / ценой / границами из самой биографии персонажа приоритет у биографии персонажа. При конфликте между ограничениями дистилляционных результатов: жёсткий барьер шаблона исследования письма > сильное ограничение шаблона образца произведения > мягкая рекомендация шаблона стиля автора.

## Требования к исполнению полного шаблона (обязательно)

- При создании отчёта рецензии биографии персонажа необходимо использовать `references/каркас-отчёта-рецензии-биографий.md` как основной скелет, нельзя сводить к упрощённому отчёту вида «несколько абзацев комментариев о персонаже + немного рекомендаций».
- При рецензировании шаблона биографии персонажа сначала необходимо проверить, явно ли он, помимо имеющейся детальной структуры, покрывает четыре базовые графы: **биография, характер, внешность, прочее**; при отсутствии графы, смешении граф или невозможности быстро найти любую из них это необходимо записать как структурный пробел.
- Отчёт должен полностью охватывать как минимум: подтверждение цепочки чтения, проверку базовой информации, определение персонажа одной фразой, функциональную позицию роли, проверку первого появления и удержания в первых трёх главах, согласованность «персонаж — ситуация — взгляд», оценку пригодности для сцены и пригодности для письма, повторную проверку удержания веб-романа и узнаваемости роли, принадлежность идентичности и организации, замкнутость цикла «мотивация — цена», границы способностей и набор инструментов, сеть отношений и зеркального противника, новизну и адаптацию к трендам, проверку ярлыков персонажа и дуги роста, библиотеку повторно используемых материалов для письма, тайны и точки взрыва, психологическую дугу и отображение индексов, проверку полноты плана, холодные/горячие точки и давление возврата, градацию проблем, оценку, конкретный план правок, идеи для рывка к комплексной оценке 9.2+ и общую оценку / вывод рецензии.
- Если в задаче дополнительно загружен жанровый Skill, то в разделах-заполнителях общего скелета необходимо дописать жанровый специальный раздел, жанровые специальные пункты оценки и акценты жанрового вывода.
- В отчёте обязательно должны быть созданы `4` класса повторно используемых материалов для письма, по `3–7` пунктов в каждом; а также указан как минимум `1` абзац кадра появления, который можно прямо вставить обратно в основной текст, и `3` реплики, которые можно прямо использовать повторно.

## Удержание в веб-романе и давление возврата персонажа (обязательно)

- При рецензировании биографии персонажа необходимо рассматривать персонажа как актив серийной публикации — «почему читатель продолжает следить, почему запоминает, почему готов ждать его / её возврата», а не как статичную страницу настроек.
- Необходимо явно оценить, состоятельны ли: запоминающаяся точка одной фразой, причина читателя продолжать следовать, давление возврата холодной линии, зеркальные отношения с важным противником, способность сети отношений порождать события.
- Если у ключевого персонажа нет узнаваемого «гвоздя», после ухода со сцены нет давления возврата либо недостаток никогда не входит в ключевые выборы, нельзя легко признавать это мелкой проблемой, которую можно исправить позже.

## Первое появление в веб-романе и питание следования (обязательно)

- При рецензировании персонажа необходимо оценить: приходится ли его / её первое появление на знакомую ситуацию, лучше всего выявляющую ценность и давление, и совершено ли в первых трёх главах одно действенное вознаграждение, неверное прочтение, ответный удар или напряжение отношений.
- Необходимо явно оценить: чем этот персонаж в основном питает постоянно (профессиональное подавление, эмоциональная награда, напряжение отношений, продвижение опасности, контрастный юмор, точка удовлетворения от ответного удара, выбор стороны по ценностям).
- Если первое появление персонажа — лишь пояснение биографии без ситуационного действия либо в первых трёх главах нет хука, на который можно сделать скриншот / выбрать сторону / призвать к обновлениям, нельзя признавать его персонажем высокой завершённости для веб-романа.

## Быстрый отсев персонажа хита Qidian и оценка сопереживания (новое)

При рецензировании персонажа по умолчанию смотрят не только «полны ли данные», но и оценивают, **есть ли у этого персонажа для читателей Qidian непрерывная платная ценность и ценность удержания в памяти**.

### 10-секундный отсев (версия для персонажа)

Рассматривайте текущего персонажа как актив роли, который читатель быстро воспринимает на стадии первого появления, по умолчанию сначала проведите `10`-секундный отсев; при попадании `3` и более слабых сигналов из следующих персонажу по умолчанию нельзя давать высокий уровень:

1. **Состоятельна ли запоминающаяся точка одной фразой**: можно ли одной фразой назвать самую запоминающуюся черту, положение или противоречие этого человека.
2. **Состоятельны ли четыре элемента героя**: если это герой, есть ли «низкий старт + сильная мотивация + анти-шаблон + объёмная дуга»; при отсутствии двух и более элементов сразу понижать оценку.
3. **Реален ли и применим ли недостаток**: есть ли слабое место, способное многократно обернуться против героя в ключевых выборах, а не «в настройках недостаток есть, а в тексте с ним ничего не случается».
4. **Можно ли сыграть напряжение отношений**: есть ли между этим персонажем и хотя бы одним ключевым персонажем напряжение отношений, достаточное для порождения событий.
5. **Есть ли у первого появления рычаг**: способен ли он / она в первых трёх главах запомниться читателю хотя бы одним из: действие, суждение, ответный удар, недоразумение, выбор стороны, контраст.

### Оценка сопереживания и платной ценности

Персонажи-хиты Qidian непрерывно удерживают читателя обычно не потому, что «настроек много», а потому, что одновременно удовлетворяют как минимум двум из следующих трёх пунктов:

1. **Вызывает сопереживание**: читатель видит в нём / ней себя в реальном положении — недооценённого, непонятого, придавленного на работе, раненного в отношениях, неудачливого в жизни.
2. **Компенсаторность**: читатель видит в нём / ней себя идеального — дерзающего дать отпор в критический момент, способного прорвать тупик, взять на себя груз, умно победить.
3. **Побуждает следовать**: персонаж непрерывно порождает ощущение следования «хочу знать, что он сделает дальше», а не бывает силён лишь в таблице настроек.
### Проверка позиционирования вживания в читательскую группу (новое)

На основе приведённой оценки сопереживания добавляется круг проверки группового позиционирования — с точки зрения плана с рыночным позиционированием оценить, действительно ли проектирование персонажа нацелено на конкретную читательскую группу, а не является самолюбованием вроде «настройки полные, а читатель ничего не чувствует»:

1. **Направленность на группу**: может ли этот персонаж за 10 секунд вызвать у целевой группы вживание «да это же я»? Если проектирование персонажа «тоже состоятельно» и без упоминания целевой читательской группы, значит позиционирование вживания отсутствует.
2. **Конкретность группы**: достаточно ли целевая читательская группа конкретна, чтобы направлять творческие решения (студенты / офисные работники / «офисный планктон, пошедший вверх» / предпринимательский реванш / недооценённые профессионалы и т. д.), а не расплывчатая формулировка вроде «для широкого читателя».
3. **Триггер вживания при первом появлении**: при первом появлении персонажа использована ли в качестве крючка вживания самая знакомая целевому читателю ситуация, боль или желание, а не знакомство с персонажем начинается с послужного списка, фона мира или абстрактных настроек.
4. **Вердикт о самолюбовании**: если в биографии персонажа объём «насколько персонаж крут / особенный» заметно превышает объём «почему читатель решит, что это он сам», признаётся склонность к самолюбованию — это самая частая ошибка рыночного позиционирования в проектировании персонажей.
В отчёте рецензии по умолчанию нужно ответить:

- Ближе ли этот персонаж к «типу сопереживания, типу компенсации или типу следования»;
- Откуда в основном приходит его платная ценность: от рычага героя, напряжения отношений, давления антагониста, контрастного обаяния или стиля речи / действий;
- Если платная ценность текущей версии слаба, что нужно добавить в первую очередь: действие первого появления, конкретность мотивации, проявление цены или функцию событий сети отношений.

### Двухдорожечная повторная проверка инструментальности / независимости второстепенных персонажей

Для важных второстепенных персонажей и антагонистов по умолчанию дополнительно проводится двухдорожечная оценка:

- **Состоятельна ли инструментальность**: явно ли он / она несёт сюжетную функцию (создание конфликта, предоставление информации, запуск переворота, поддержка награды).
- **Состоятельна ли независимость**: есть ли у него / неё самостоятельные стремления, скрытые цели, личные старые счёты или цена позиции, а не вращается ли только вокруг героя.

Если у второстепенного персонажа есть только инструментальность без независимости, признаётся «риск персонажа-инструмента»; если есть только независимость без сюжетной функции, признаётся «риск насыщенных данных, не питающих сюжет».

### Градация потенциала Qidian (вспомогательный критерий рецензии персонажа)

Помимо вердикта о принятии в библиотеку `Green / Yellow / Red`, при рецензировании персонажа по стандарту Qidian по умолчанию разрешается дополнительно дать слой суждения «градация вклада персонажа в хит»:

| Градация | Критерий | Смысл для рецензии |
| --- | --- | --- |
| S | Сильная запоминающаяся точка, твёрдая мотивация, недостаток действительно оборачивается против героя, достаточное напряжение отношений, первое появление в первых трёх главах захватывает | Это персонаж, способный напрямую поднимать следование и обсуждения |
| A | Основа персонажа стабильна, есть чёткий рычаг, локальные пробелы быстро исправляются добавлением первого появления / цены | Это персонаж, способный непрерывно питать |
| B | Данные в основном состоятельны, но первое появление, сеть отношений или проявление цены слабы | Это годный, но недостаточно яркий персонаж |
| C | Попадание двух и более: слабая запоминающаяся точка, пустая мотивация, ложный недостаток, отношения не порождают событий | Это персонаж, который потянет вниз вживание и следование всей книги |

Эта градация используется только для вспомогательной оценки «силы подъёма этим персонажем цепочки хита всей книги» и не должна заменять полный вывод рецензии и градацию проблем.

### 10-тысячезнаковая среднесрочная верификация (версия для персонажа)

Если рецензия персонажа обслуживает стандарт Qidian, по умолчанию дополнительно проверяют способность этого персонажа непрерывно питать в первых `10` тыс. знаков, а не только то, цепляет ли первое появление. В отчёте нужно как минимум ответить:

1. Выполняет ли этот персонаж непрерывную функцию в первых `15` главах, а не скрывается после первого появления.
2. Запускает ли этот персонаж хотя бы один сдвиг отношений (союз, раскол, ответный укус, углубление недоразумения, смена стороны).
3. Приводил ли недостаток этого персонажа в ключевых выборах к реальной цене.
4. Если это ключевой персонаж, может ли он в середине продолжать порождать вопросы для следования, а не «после выполнения задачи функция обнуляется».

Если из четырёх пунктов отсутствуют два и более, по умолчанию признаётся «риск среднесрочного питания персонажа».

### Повторная проверка точек распространения-обсуждения персонажа

При рецензировании персонажа по умолчанию дополнительно оценивают, есть ли у него устойчивые точки распространения-обсуждения:

- **Точка выбора стороны**: расколются ли читатели по позициям в ключевом выборе;
- **Точка скриншота**: есть ли высоко узнаваемые действия, реплики, контрастные мгновения;
- **Точка вторичного творчества**: есть ли напряжение отношений, тайна идентичности, конфликт старых долгов, ценностное противоречие;
- **Точка возврата**: остаётся ли после ухода персонажа со сцены давление «читатели ждут его / её возвращения».

Если персонаж «настроен полностью, но обсуждений нет», по умолчанию в отчёте пометить «персонаж со слабой коммерческой распространяемостью» и рекомендовать в первую очередь добавить действие первого появления, напряжение отношений и сцены обращения недостатка против героя.

## Требования к подключению анализа конкурентов жанра (обязательно)

- Если текущая задача обслуживает какой-либо жанр, а в каталоге этого жанра `竞对分析/` уже есть отчёты анализа конкурентов, связанные с текущим проектом, текущей платформой или текущей дорожкой, перед рецензией их необходимо прочитать и учесть для сопоставления.
- Если целевая платформа — Qidian (起点中文网) или платформа не указана и по умолчанию применяется стандарт Qidian, а в каталоге текущего жанра ещё нет пригодного основного отчёта по конкурентам, перед рецензией следует в первую очередь вызвать `общий-анализ-конкурирующих-произведений`, чтобы как минимум восполнить **пул кандидатов Топ-10, `3–5` основных образцов и экспресс-обзор четырёхслойного глубокого разбора**; если из-за ограничений задачи в этом раунде восполнить нельзя, слепую зону необходимо заметно зафиксировать, а верхний предел оценки и уверенность этого раунда понизить.
- Отчёт рецензии не должен давать только внутренне согласованные выводы; необходимо явно оценить, по каким измерениям текущий персонаж уже опережает, равен или отстаёт от конкурентов, и какой путь превосходства нужно восполнить в первую очередь.
- Если текущий персонаж заметно слабее конкурентов в ключевых сильных сторонах, уже подтверждённых конкурентами, это необходимо прямо признать конкурентным риском; рецензия персонажа по умолчанию исполняется по критерию «жёстко искать разрывы», нельзя ради успокоения автора вскользь упоминать пустое первое появление, отсутствие цены или отсутствие у сети отношений функции событий.
- Измерение конкурентов в комплексной оценке рецензии персонажа по умолчанию имеет вес `25%`; если не завершена количественная карточка разрыва, либо ключевые измерения по-прежнему заметно отстают и нет патча на `72` часа, комплексной оценке по умолчанию нельзя давать высокий уровень.

## Формулировка усвоения конкурентов в стиле Qidian (новое)

Когда рецензия персонажа обслуживает Qidian (起点中文网) или платформа не указана и по умолчанию применяется базовая линия Qidian, сопоставление с конкурентами по умолчанию раскладывается на следующие четыре слоя и переводится в суждения рецензии и рекомендации по патчам:

- **Слой рыночных данных**: по местам в списках, косвенным сигналам — средние подписки / первая подписка / коэффициент подписки, рекомендательным ресурсным позициям обратным ходом оценить, действительно ли этот персонаж поддерживает жанровую классификацию, ценность постоянной оплаты и долгосрочную коммерческую конкурентную позицию, а не только «данных много» с точки зрения автора.
- **Слой творческого содержания**: в первую очередь сопоставить зрелость основных образцов в рычагах персонажа, желаниях и цене, напряжении отношений, контрасте идентичности, границах способностей, языковом отпечатке, дуге роста и упаковке мотивации антагониста, превратить разрыв в патчи биографии на уровне пунктов и патчи первого появления на уровне основного текста.
- **Слой операционной стратегии**: в первую очередь сопоставить, как основные образцы с помощью ролей создают инженерию следования, точки обсуждения в комментариях к главам (本章说), точки выбора стороны, напряжение отношений и непрерывные награды, превратить разрыв в патчи: триггеры, нижние границы / переключатели, предпочтения следов, библиотека деталей для повторного разбора и давление возврата.
- **Слой обратной связи аудитории**: в первую очередь сопоставить обаяние персонажей, за которое часто хвалят в комментариях к главам (本章说) / круге друзей по книге / разделе отзывов, болезни «шаблонности», за которые ругают, точки чувствительности «старых белых» читателей (老白读者) к героям, лишённым ума / пустым / без цены, превратить разрыв в рекомендации «чего избегать» и «что усилить».

В контексте Qidian по умолчанию по возможности используются следующие термины, а не пустое «недостаточная конкурентоспособность персонажа»: `средние подписки (均订)`, `высокие подписки (高订)`, `первая подписка (首订)`, `дополнительная подписка (追订)`, `коэффициент подписки (收订比)`, `категорийный список месячных голосов (分类月票榜)`, `список бестселлеров (畅销榜)`, `список новинок (新书榜)`, `«Саньцзян» (三江)`, `комментарии к главам / к абзацам (本章说 / 段评)`, `круг друзей по книге (书友圈)`, `«старые белые» читатели (老白读者)`. Если точное значение получить нельзя, нужно записать косвенный сигнал, поддельные конкретные цифры недопустимы.

## Пригодность для сцены и передача автору (обязательно)

- При рецензировании биографии персонажа её нужно рассматривать как «рабочее руководство автора по роли», а не как красивую аннотацию для читателей.
- Необходимо явно оценить: состоятельны ли «персонаж за три секунды», движение действием, повторно используемый недостаток, пригодность сети отношений, привязка к механике жанра, а также согласованность «персонаж — ситуация — взгляд».
- Запрещено давать лишь концептуальные оценки; одновременно нужно выдавать патчи на уровне пунктов, примеры кадров появления, повторно используемые реплики / действия / болевые точки / компромат.

## Слой источника, гейт вердикта и зеркало шаблонных артефактов (новое)

- При рецензировании биографии персонажа по умолчанию продолжают проверять, выросла ли она в «сопровождаемый авторский артефакт», а не просто статичное описание персонажа: суждение о полном / сокращённом шаблоне, текущее состояние, записи поведения по главам, варианты языкового отпечатка по эмоциям, обзор отношений, библиотека повторно используемых материалов — всё это входит в объём рецензии.
- Проблемы по умолчанию помечаются слоем-источником: `[структурный слой персонажа] / [слой динамического состояния] / [слой рычагов основного текста]`. Структурный слой персонажа отвечает за биографию, мотивацию, границы, главную ось отношений; слой динамического состояния — за текущее состояние, записи поведения по главам, этапные изменения; слой рычагов основного текста — за кадр появления, языковой отпечаток, библиотеку материалов, действия и реплики, которые можно вставить обратно в основной текст.
- По умолчанию добавляют вердикт о принятии в библиотеку `Green / Yellow / Red`: `Green` = четыре базовые графы, мотивация и цена, события отношений, динамическое состояние и библиотека материалов полны; `Yellow` = основа состоятельна, но динамические поля / библиотека материалов / патч первого появления всё ещё слабы; `Red` = отсутствуют графы, способности всемогущие, цены нет, сеть отношений без функции событий, первое появление без силы захвата либо нет давления возврата при уходе со сцены.
- Если биография персонажа не может прямо поддержать «как писать первые три главы, чем снова разогреть при возврате, как недостаток оборачивается против ключевого выбора», по умолчанию нельзя признавать зрелым источником-арбитром.

1. **Вывод экспресс-отсева** (10 секунд): сначала дать быстрое суждение о том, «запоминается ли, можно ли следовать, питает ли» персонаж, и блокирующие пункты.
2. **Вывод глубокой оценки** (3 минуты): затем дать мотивацию и цену, границы способностей, события отношений, награду за первое появление, давление возврата, суждение о разрыве с конкурентами.
3. **Вывод градации**: дать `Green/Yellow/Red` + градацию потенциала по стандарту Qidian (например, `S/A/B/C`) и указать основания.
4. **Цепочка минимальных патчей**: дать «какие `3` места править сначала (пункт / кадр / реплика), какое действие в каждом».
5. **Действия на 72 часа**: дать порядок доработки на уровне персонажа, ожидаемые пункты повышения и условия повторной рецензии.

Если задача не по стандарту Qidian, всё равно выводить по тому же скелету; поля конкурентов или платформы можно пометить «в этом раунде неприменимо», но шаги скелета удалять нельзя.

## Минимальная поставка

- Может указать, полны, ясны и пригодны ли для обратной записи четыре базовые графы — биография, характер, внешность, прочее — и какие места относятся к структурным пробелам.
- Может указать самые ключевые проблемные позиции по идентичности, мотивации, границам, отношениям, рычагам, дуге и индексу.
- Может объяснить, какие проблемы относятся к высокому риску, а какие можно оптимизировать позже.
- Может дать минимальный патч, пригодный для обратной записи, а не только абстрактную оценку.
- Может дать как минимум `1–3` патча на уровне пунктов, которые можно прямо записать обратно в биографию, как минимум `1` абзац кадра появления, который можно прямо вставить обратно в основной текст, как минимум `3` реплики, которые можно прямо использовать повторно, и как минимум `1` патч награды за первое появление / первые три главы.

## Правило независимости повторной рецензии (обязательно)

- В каждом раунде рецензии биографии персонажа текущую версию необходимо заново, независимо, строго и всесторонне рецензировать; нельзя ставить высокую оценку напрямую по принципу «заметный прогресс» только потому, что проблемы прошлого раунда исправлены.
- Проверка исправления проблем прошлого раунда обязательна, но это лишь базовый пункт; по-прежнему необходимо заново проверять, состоятельны ли принадлежность идентичности, мотивация и цена, границы способностей, сеть отношений, рычаги письма, психологическая дуга и отображение индексов.
- Если в этом раунде обнаружены новый риск OOC, новый пробел цены, новая точка отказа сети отношений или новый разрыв индекса, их необходимо честно записать в отчёт этого раунда, нельзя пропускать ради сохранения «непрерывного роста оценки».
- Оценка этого раунда может даваться только на основе фактического качества текущей версии при полной рецензии этого раунда, нельзя автоматически повышать по оценке прошлого раунда, числу исправленных проблем или масштабу правок.

## Жёсткие правила

- Запрещено оценивать только «есть ли у персонажа обаяние»
- Если исполняется по стандарту Qidian, запрещено пропускать `пул кандидатов Топ-10 → 3–5 основных образцов → четырёхслойное сопоставление` и сразу давать высокую оценку или суждение о высоком уровне.
- Нужно прийти к доказательствам, структуре и действиям по обратной записи
- Нужно объяснить, почему читателю стоит продолжать следить за этим персонажем и почему его не забудут при длинной серийной публикации
- При обнаружении у ключевого персонажа отсутствия цены, всемогущих способностей или сети отношений без функции событий оценивать как минимум как высокий риск
- Запрещено писать проблемы персонажей пустыми прилагательными; нужно превращать в проверяемые доказательства, конкретные пункты, действия, которые можно прямо записать обратно
- Запрещено писать персонажа как «доску настроек с полным послужным списком, но пустым первым появлением»; если в первых трёх главах нет действия или награды, действительно заставляющих читателя хотеть следовать, это необходимо явно записать как точку кровотечения
## Правила автоматического обнаружения шаблонов стиля / блюпринта

Если в корневом каталоге обслуживаемого проекта есть `Agents.md`, перед рецензированием биографии персонажа необходимо:

1. Прочитать `Agents.md` в корне проекта; если там объявлена `主输出平台`, при поиске трёх видов шаблонов в первую очередь подбирать шаблоны, у которых «适用平台» совпадает с основной платформой вывода, при отсутствии совпадений откатываться к шаблонам того же вида с «适用平台：默认»
2. Если в `Agents.md` зарегистрирован «шаблон исследования письма» — прочитать файл шаблона по соответствующему пути и использовать его ограничения по персонажам как базовую линию рецензии проектирования персонажей по умолчанию для «жанр × платформа»
3. Если в `Agents.md` зарегистрирован «шаблон стиля автора» — прочитать файл шаблона по соответствующему пути и дополнительно провести «рецензию стилевого соответствия» (см. ниже)
4. Если в `Agents.md` зарегистрирован «шаблон образца произведения» — прочитать файл шаблона по соответствующему пути и использовать закономерность переключения POV и распределение плотности диалога как справочное ограничение ритма появления персонажей
5. Если в корневом каталоге проекта нет `Agents.md` или в нём не зарегистрирован соответствующий шаблон — пропустить рецензию стилевого соответствия, не выдавая ошибок и не блокируя

### Рецензия стилевого соответствия (действует при наличии шаблона стиля автора)

**Пункты проверки**:

- **Соответствие длины предложения**: соответствует ли «предпочтение длины предложения» в ДНК выражения персонажа базовой линии длины предложения шаблона стиля автора? Если персонаж — тип коротких быстрых предложений, а шаблон автора — длинных неспешных, пометить «трение персонаж – стиль автора» — возможно, автор не сможет написать ритм этого персонажа.
- **Пересечение запретных слов**: пересекаются ли «запретные слова / конструкции, которых никогда не произнесёт» персонаж с «табу на конструкции / табу на лексику» шаблона стиля автора? Если пересекаются, значит голос персонажа совпадает с голосом автора по умолчанию — это может быть хорошо (персонаж не наткнётся на стену табу автора), а может быть плохо (все персонажи звучат как сам автор).
- **Соответствие тегов диалога**: соответствует ли способ диалога персонажа настройкам стиля диалога шаблона автора (предпочтение тегов, плотность перебиваний)? Если шаблон автора — «школа тегов-действий 70 %», а персонажу нужно продвигаться массой чистого диалога без тегов, пометить «способ диалога персонажа может вступать в трение со способом автора по умолчанию».
- **Соответствие способа выражения эмоций**: соответствует ли способ выражения эмоций персонажа (телесный / внешнее действие / прямое называние) распределению выражения эмоций шаблона автора? Если персонаж — тип прямого называния эмоций, а в шаблоне автора прямое называние < 5 %, пометить «способ выражения эмоций персонажа выходит за зону комфорта автора».

**Вывод рецензии**: в разделе «глубина персонажа» отчёта дописать подраздел «оценка стилевого соответствия», перечислить точки трения и рекомендации по соответствию.
## Глубокая рецензия уровня Nuwa (новое)

> Подробная методология — в `общий-проектирование-биографии-персонажей/references/nuwa-внедрение-глубокой-ментальной-модели-персонажа.md`. При рецензировании персонажа после завершения структурного аудита и оценки по стандарту Qidian по умолчанию добавляются следующие глубинные измерения Nuwa. Если персонаж останавливается на «настройки полные» и не имеет работающей когнитивной операционной системы, нельзя признавать его высокозавершённым.

### Рецензия ментальных моделей

При рецензировании биографии персонажа по умолчанию проверяют следующие измерения ментальных моделей:

- **Существуют ли ментальные модели и можно ли их распознать**: есть ли у ключевых / важных персонажей 2–5 чётких ментальных моделей (не просто «ярлыки характера» или «фон»)? Можно ли в биографии найти работающие когнитивные правила вроде «доверие надо заслужить, его не дают»?
- **Согласованность между сценами**: есть ли у каждой ментальной модели доказательства в ≥2 разных типах сцен? Если в биографии какое-то «убеждение» проявляется лишь в одной сцене, это всего лишь реплика сцены, а не ментальная модель.
- **Порождающая сила**: можно ли с помощью ментальных моделей, данных в биографии, вывести возможные реакции персонажа в ненаписанных сценах? Если нельзя, значит модель слишком пустая.
- **Исключительность**: способны ли ментальные модели этого персонажа отличить его от других персонажей истории? Если «картина мира» всех персонажей написана как «добрый / справедливый / хочет стать сильнее», значит исключительности нет → риск гомогенизации персонажей.
- **Отсутствие «моделей-заблуждений»**: есть ли у ключевых персонажей как минимум одна ментальная модель «типа заблуждения» (ложное убеждение, которое будет исправлено по ходу дуги)? Если нет, у дуги роста может не быть двигателя.
- **Столкновение моделей**: есть ли между ментальными моделями разных ключевых персонажей различия, способные сталкиваться? Если у двух противостоящих ролей одни и те же глубинные допущения, конфликт — лишь поверхностная шумиха.

**Вывод рецензии**: в разделе «глубина персонажа» отчёта явно оценить состоятельность ментальных моделей, пометить недостающие пункты и рекомендации по патчам.

### Рецензия ДНК выражения

При рецензировании биографии персонажа по умолчанию проверяют следующие измерения языкового отпечатка:

- **Измерим ли «языковой паспорт»**: не остаются ли «присказки / речевые привычки» в биографии расплывчатыми ярлыками вроде «говорит холодно», «любит подкалывать»? Даны ли измеримые измерения: предпочтение длины предложения, использование вопросительных предложений, тон уверенности, запретные слова?
- **Дифференциация голоса по собеседникам**: меняется ли голос ключевых персонажей по отношению к разным собеседникам? Если с вышестоящим / равным / подчинённым / близким / врагом он говорит совершенно одинаково → риск монотонности голоса.
- **Эмоциональные варианты**: описано ли в биографии изменение языка одного и того же персонажа при гневе / страхе / маскировке / близости?
- **Тест с закрытым именем**: если закрыть имя и читать образцы диалога или присказки из биографии, можно ли узнать, кто это? Если нет → языковой отпечаток не состоятелен.
- **Проверка запретных слов**: ясно ли в биографии написано, чего этот персонаж никогда не говорит? Если нет → языковой отпечаток неполон.

**Вывод рецензии**: в разделе «библиотека повторно используемых материалов для письма» отчёта явно оценить зрелость ДНК выражения, пометить недостающие измерения и минимальные патчи.

### Рецензия противоречия и напряжения

- **Сущностное напряжение**: есть ли у ключевых персонажей хотя бы 1 пара внутренних ценностных конфликтов? Если персонаж в биографии «един внутри и снаружи, тверд в убеждениях, никогда не колеблется» → риск картонного персонажа, прямо пометить как недостаток глубины.
- **Областные противоречия**: ведёт ли себя персонаж в разных областях / отношениях по единым нормам поведения? Если реакции во всех сценах можно обобщить одним ярлыком → риск уплощения.
- **Стыковка противоречия с дугой**: записано ли сущностное напряжение в ключевые шаги психологической дуги? Есть ли в кульминации дуги узел «лобового столкновения» напряжения?
- **Обнаружение ошибочной обработки противоречия**: нет ли в биографии следов «придумывания примиряющего объяснения, замазывающего противоречие»? Нет ли упрощения «выбрать одну сторону, проигнорировать другую»? Если есть → противоречие потрачено впустую.

**Вывод рецензии**: в разделе «психологическая дуга» отчёта явно оценить глубину противоречия; если сущностное напряжение отсутствует или противоречие примирено и замазано, записать как высокий риск.

### Рецензия честных границ

- **Наличие слепых зон**: есть ли у ключевых персонажей ≥3 честные границы? Ясно ли в биографии написано, чего персонаж не видит, чего не понимает, чего не может сделать?
- **Связь с сюжетом**: связана ли хотя бы 1 честная граница напрямую с основной сюжетной линией? Если ни одна слепая зона не вызывает последствий в основном тексте → слепые зоны — лишь украшение.
- **Обнаружение всемогущего героя**: нет ли в биографии следов «всё видит насквозь, всё может сделать»? Если границы способностей размыты, а все слабости «можно преодолеть» → риск всемогущего, пометить прямо.

**Вывод рецензии**: в разделе «границы способностей» отчёта явно оценить честные границы; если у ключевого персонажа честных границ <2 или все они не связаны с основной линией, записать как структурный пробел.

### Рецензия эвристик решений

- **Наличие правил**: есть ли у ключевого персонажа ≥5 правил решений вида «если X, то Y»? Реализуемы ли «нижняя граница / переключатели» в биографии?
- **Проверка ошибочных правил**: является ли хотя бы 1 эвристика решений «ошибочным правилом», которое в критический момент приведёт персонажа к неверному суждению? Если все правила — «верный выбор», персонаж слишком умён и ему не хватает достоверности.
- **Подкрепление примерами**: подкреплена ли каждая эвристика решений конкретным сюжетным узлом?

**Вывод рецензии**: в разделе «мотивация / границы» отчёта явно оценить полноту эвристик решений.

### Сводная оценка глубины Nuwa (новое измерение оценки)

Помимо имеющейся комплексной оценки, по умолчанию добавляется балл глубины Nuwa (максимум 10 баллов, вес 15 % в комплексной оценке):

| Подизмерение | Максимум | Критерий оценки |
| --- | --- | --- |
| Ментальные модели | 3 | Существуют, распознаются, между сценами, исключительны, есть «модель-заблуждение» |
| ДНК выражения | 2 | Измеримая, есть дифференциация голоса по собеседникам, есть эмоциональные варианты, узнаётся при закрытом имени |
| Напряжение противоречия | 2 | Есть сущностное напряжение, есть областные противоречия, стыкуется с дугой |
| Честные границы | 2 | Существуют, связаны с основной линией, есть план запуска, не декоративны |
| Эвристики решений | 1 | Существуют, есть ошибочное правило, подкреплены примерами |

Балл глубины Nuwa <5 → у персонажа есть настройки, но нет когнитивной операционной системы, отчёт обязан пометить «недостаточная глубина Nuwa» и назвать 2 измерения, которые нужно добавить в первую очередь.
