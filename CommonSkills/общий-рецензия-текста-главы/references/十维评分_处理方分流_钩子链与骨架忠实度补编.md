# Двенадцатимерная двухосевая оценка_распределение по обработчикам_дополнение о цепи хуков и верности каркасу

> Усвоена общая рамка внешних `reviewer-skill`, `review-checklist`, `quality-standards` и `review-report-template`, нужная для того, чтобы стабилизировать рецензирование глав как «двенадцатимерная двухосевая оценка + распределение по обработчикам + пометка источника + проверка цепи хуков + оценка верности каркасу».
>
> **Предыстория переработки**: из «десятимерной оценки приёмов» расширено до «двенадцатимерной двухосевой оценки (10 измерений приёмов + 2 измерения удержания)», чтобы устранить системное рассогласование между внутренней рецензией приёмов и платформенными стандартами удержания. Подробнее см. `CommonSkills/写作研究/网文留存模型.md`.

## 1. Минимальный пакет входных данных рецензии

В идеале прочитать как минимум:

- Рецензируемый текст главы
- Контрольную карточку / планирование сцен этой главы (включая поля быстрого запуска удержания, если есть)
- Черновой каркас (если есть)
- Конец предыдущей главы или план предыдущей главы (для проверки цепи хуков)
- Поля текущего состояния задействованных персонажей
- Активные интриги / активные предзнаменования / известный фон решений
- Поле жанра (для определения акцентов рецензии)
- **Основная платформа вывода** (для распределения динамических весов, определяется через Agents.md или указывается пользователем)

## 2. Базовая линия двенадцатимерной двухосевой оценки

Каждое измерение `1–5` баллов, ось приёмов `10` измерений, максимум `50` баллов, ось удержания `2` измерения, максимум `10` баллов.

### Ось приёмов (измерения 1–10)

1. Повествовательная логика (ядро)
2. Согласованность персонажей (ядро)
3. Связность
4. Исполнение планирования сцен
5. Ритм и напряжение
6. Качество диалога
7. Качество описания
8. Удаление привкуса ИИ
9. Хуки и интрига
10. Объём и плотность

### Ось удержания (измерения 11–12, новое)

11. **Плотность эмоциональных стимулов (ось удержания)** — есть ли ощутимое эмоциональное колебание (爽 / мука / сладость / интрига / щемящее / разворот) на каждые 500 знаков; чередуются ли эмоции на протяжении 3 глав подряд, а не один фоновый тон. См. детальные правила оценки §5.1 `网文留存模型.md`.
12. **Движущая сила следования (ось удержания)** — сила «обязательно перевернуть страницу» хука в конце главы + ощущение «стоило потраченного времени» от награды в середине. См. детальные правила оценки §5.2 `网文留存模型.md`.

### Единая шкала баллов (для обеих осей)

- `5`: отлично, явных проблем в основном нет
- `4`: хорошо, есть небольшие изъяны, не вредящие чтению
- `3`: удовлетворительно, читается, но есть явное пространство для улучшения
- `2`: есть большие проблемы, нужна правка
- `1`: серьёзно не годится, соответствующие разряды следует переписать

## 2.5. Формула двухосевой оценки

### Расчёт промежуточных баллов

```text
Исходный балл приёмов = сумма измерений 1–10 (макс. 50)
Балл приёмов = round(исходный балл приёмов / 50 × 10, 1)  → максимум 10.0

Исходный балл удержания = измерение 11 + измерение 12 (макс. 10)
Вычет за красные лампы удержания = −1 балл за каждую красную лампу (вычитается с 10 баллов, пока не исчерпается)
Балл удержания = max(исходный балл удержания — вычет за красные лампы удержания, 0)  → максимум 10.0
```

### Динамически взвешенный комплексный балл

Выбор весов по основной платформе вывода:

| Основная платформа вывода | W_приёмов | W_удержания |
| --------- | ----- | ----- |
| Бесплатные платформы вроде Qimao/Fanqie | 0.35 | 0.65 |
| Платные платформы вроде Qidian/Zongheng | 0.55 | 0.45 |
| Издательство/Douban | 0.75 | 0.25 |
| Zhihu Salt Selection | 0.50 | 0.50 |
| Не настроено / общий режим | 0.50 | 0.50 |

```text
Комплексная оценка = балл приёмов × W_приёмов + балл удержания × W_удержания
```

### Порог допуска (обе оси достигают одновременно)

- ✅ Балл приёмов ≥ 7.0 **и** балл удержания ≥ 6.0 → обе оси достигнуты, можно допускать
- ⚠️ Балл приёмов ≥ 7.0, но балл удержания < 6.0 → Yellow, приёмы годны, но риск удержания, приоритетно исправлять пункты удержания
- ⚠️ Балл приёмов < 7.0, но балл удержания ≥ 6.0 → Yellow, удержание годно, но приёмов недостаточно, можно переходно
- ❌ Балл приёмов < 6.0 или балл удержания < 5.0 → Red, обе оси не достигнуты, доработка

## 3. Пометка источника проблем

Для каждой проблемы нужно пометить:

- `[骨架层]`: планирование / каркас сам по себе ошибочен, нужно вернуться к вышестоящему слою и перестроить
- `[扩展层]`: каркас верен, но развёртывание в тексте уклонилось или отсутствует
- `[表达层]`: структура в основном состоятельна, проблема главным образом в формулировках, ритме, удалении привкуса, метках, плотности описания

## 4. Распределение по обработчикам

### Проблемы, передаваемые writer

- Разрыв причинной цепи
- Поведение персонажа противоречит установкам
- Ошибки линии времени / линии пространства
- Отсутствие несущего бит-а или нарушенный порядок
- Единственная обязанность не выполнена
- Эмоциональная дуга не исполнена
- Основное событие пропущено или сильно сжато
- Хук предыдущей главы остался без отклика и без причины
- У конца этой главы нет настоящей движущей силы
- Нужно изменить «что писать»

### Проблемы, передаваемые polisher

- Удаление привкуса ИИ
- Метки диалога, интонация, тонкая настройка голоса
- Сжатие описания
- Микронастройка ритма (без изменения структуры)
- Проблемы длины абзацев и равномерности конструкций
- Вычурные выражения, заполняющие фразы, «карусель синонимов»
- Нужно изменить «как писать»

## 5. Особые рычаги при десятимерной рецензии

### Измерение 4: исполнение планирования сцен

В первую очередь проверить:

- Все ли основные события плана представлены
- Выполнена ли цель сцены
- Реализован ли эмоциональный тон
- Все ли несущие бит-ы на месте и в правильном порядке
- Есть ли у слияния / удаления гибких бит-ов повествовательная причина
- Выполнена ли единственная обязанность этой главы
- Не остался ли язык плана

### Измерение 5: ритм и напряжение

В первую очередь проверить:

- Создаёт ли привлекательность первые `20%` начала
- Есть ли изменения ритма, а не ровный уровень всей главы
- Есть ли подготовка к кульминации
- Есть ли в конце настоящая движущая сила перелистывания
- Соответствует ли фактический ритм запланированному лёгкому / среднему / тяжёлому
- Состоятельны ли вход / выход эмоциональной дуги

### Измерение 9: хуки и интрига

В первую очередь проверить:

- Есть ли эффективная цепкость в первых трёх абзацах
- Остаётся ли в конце нераскрытый вопрос или незавершённое действие
- Получила ли отклик старая интрига
- Не повторяется ли тип хука в последних нескольких главах
- Отвечает ли начало этой главы на хук выхода предыдущей главы
- Правдоподобно ли хук выхода этой главы тянет следующую главу

## 6. Формат проверки цепи хуков

| Пункт | Содержание |
| --- | --- |
| Хук выхода предыдущей главы | Тип + направление |
| Отклик на входе этой главы | да / нет / частично; прямой / косвенный / отложенный |
| Хук выхода этой главы | Тип + направление |
| Ожидаемый отклик следующей главы | Как ожидается, что следующая глава примет эстафету |
| Повтор типа хука | Повторяется ли в последних 3 главах |
| Разрыв цепи хуков | Есть / нет; если есть — написать причину |

## 7. Оценка верности каркасу

Как минимум выделить отдельно:

- Присутствие несущих бит-ов: да / нет
- Сохранение порядка бит-ов: да / нет
- Остатки языка плана: есть / нет
- Структурные отклонения: разумны ли отклонения
- Верность каркасу: высокая / средняя / низкая

### Сигналы автоматического повторного определения

- Отсутствует несущий бит
- Несущие бит-ы без причины переставлены
- Текст свёл на нет основные обязанности каркаса
- Остатки языка плана более чем в `2` местах

## 7.5. Три поперечных предупреждения (новое — обнаружение «смертельного перекрёста»)

> Каждое измерение приёмов с точки зрения удержания даёт **U-образную перевёрнутую кривую** — после превышения оптимального порога каждый дополнительный балл качества приёмов, наоборот, снижает удержание на балл. Три поперечных предупреждения не входят в расчёт общего балла, но отмечают риск и влияют на итоговый вердикт.

### Показатели предупреждений

**Предупреждение A: предупреждение о чрезмерной оптимизации**
Срабатывает при совпадении ≥ 2 из следующих сигналов:
- Во всём тексте нет ни одного «несовершенного» места, текст как «заводские настройки»
- У каждого поведения персонажа есть достаточное объяснение, нет умолчаний
- Причинные связи слишком ясны, после прочтения 30% можно предсказать финал
- Удаление привкуса сделано слишком идеально, нет личного отпечатка автора

Эффект запуска: отметить риск «приёмы за пределами предела», оценка удержания автоматически снижается на 1 балл.

**Предупреждение B: предупреждение о плотности глаголов**
Срабатывает при совпадении ≥ 1 из следующих сигналов:
- Плотность глаголов в конфликтных абзацах < 40% (подробнее см. §18 чек-листа)
- В эмоциональной кульминации использована конструкция «он очень X» вместо соматизированного действия
- Есть паттерн «стоял и всё обдумал» (внутренняя обработка > 300 знаков подряд, затем действие)
- Число прилагательных / наречий / абстрактных существительных превышает число глаголов

Эффект запуска: отметить риск «недостаток двигателя картинки», оценка удержания автоматически снижается на 1 балл.

**Предупреждение C: предупреждение об избытке определённости**
Срабатывает при совпадении ≥ 2 из следующих сигналов:
- Причинные связи предельно ясны, читателю не нужно рассуждать
- В конце главы не оставлено неопределённости «может быть, я ошибся»
- Поведение персонажей полностью предсказуемо
- После прочтения главы читатель может точно сказать всё содержание следующей главы

Эффект запуска: отметить риск «недостаточная движущая сила следования», оценка удержания автоматически снижается на 1 балл.

### Сводные правила трёх предупреждений

| Число сработавших предупреждений | Влияние | Влияние на итоговый вердикт |
| --------- | ---- | ----------- |
| 0 | Нет влияния | Вердикт по двум осям в обычном порядке |
| 1 | Балл удержания −1 | Может запустить Yellow |
| ≥ 2 | Балл удержания −1 за каждое | Автоматически Yellow, пометить «риск парадигмы: синдром превышения приёмов» |
| ≥ 3 | Балл удержания — всего −3 | Автоматически Red, необходима доработка с корректировкой писательской парадигмы |

## 8. Вердикт готовности (двухосевая версия + три предупреждения)

### Предусловия двух осей

Перед вердиктом готовности сначала вычислить базовые баллы двух осей и вычеты за три предупреждения:

```text
Балл приёмов = сумма измерений 1–10 / 50 × 10 (максимум 10.0)
Балл удержания = (измерение 11 + измерение 12) — вычет за красные лампы удержания — вычет за три предупреждения (максимум 10.0)
Вычет за три предупреждения = предупреждение A(1) + предупреждение B(1) + предупреждение C(1), предел 3 балла
```

После выбора весов по основной платформе вывода вычислить комплексную оценку. Подробнее см. §2.5 формулу двухосевой оценки.

### Green (обе оси достигнуты + комплексная оценка крепка)

- Балл приёмов ≥ 7.0 **и** балл удержания ≥ 6.0 (обе оси достигнуты одновременно)
- Комплексная оценка (взвешенная по платформенным весам) ≥ соответствующей платформенной линии контроля качества
- Нет отдельных пунктов ≤ 2
- Красные линии не запущены
- Верное исполнение каркаса состоялось

### Yellow (одна ось достигнута, комплексная оценка проходит)

- Балл приёмов ≥ 7.0, но балл удержания < 6.0 → ⚠️ Yellow, пометить «приёмы годны, но риск удержания»
- Балл приёмов < 7.0, но балл удержания ≥ 6.0 → ⚠️ Yellow, пометить «удержание годно, но приёмов недостаточно»
- Исходный балл приёмов 25–34 (приёмы примерно 5.0–6.8/10)
- Или есть отдельный пункт = 2
- Или лёгкое нарушение ритма
- Или локальное отклонение от каркаса, но исправимое

**Стратегия обработки Yellow**: проблемы приёмов → вернуть в полировку / удаление привкуса ИИ; проблемы удержания → вернуть в контрольную карточку / творчество. Когда присутствуют проблемы обоих видов, приоритетно исправлять удержание.

### Red (одна или обе оси не достигнуты)

- Балл приёмов < 6.0 или балл удержания < 5.0 (любая ось на дне — Red)
- Исходный балл приёмов < 25
- Или основное измерение ≤ 1
- Или запущена красная линия

### Красные линии автоматического Red

- Персонаж знает то, чего знать не мог
- Разрыв причинной цепи
- Отсутствие несущего бит-а приводит к разрыву повествования
- Эмоциональная дуга совсем не исполнена
- Хук предыдущей главы совсем без отклика и без причины
- Остатки языка плана более чем в `2` местах
- **Красных ламп удержания ≥ 3** (новое — даже если балл приёмов едва проходит, 3 и более красных ламп удержания прямо означают Red)

## 9. Критерий поправок весов по жанрам

Корректировка весов влияет только на строгость, не меняет максимум по отдельному измерению:

- Уся: строже к ясности действия, согласованности рыцарства
- Сянься: строже к согласованности системы, чувству масштаба
- Детектив: строже к контролю информации, честности введения в заблуждение, хукам и интриге
- Любовный роман: строже к эмоциональной правдивости, подтексту
- Научная фантастика: строже к ясности концепций, согласованности

## 10. Минимальные поля отчёта (двухосевая версия)

Рецензионный отчёт по главе содержит как минимум:

- Основная информация
- Общий балл и вывод (включая балл приёмов / балл удержания / комплексную оценку / число красных ламп удержания)
- **Блок двухосевой оценки** (оценка приёмов + оценка удержания + платформенные веса + комплексный вердикт, подаётся отдельно)
- Вердикт готовности (включая сигналы вердикта / красные карточки / блокирующие пункты)
- Двенадцатимерная оценка (10 измерений приёмов + 2 измерения удержания)
- Перечень красных ламп удержания (с пометкой каждой совпавшей красной лампы по пунктам)
- Как минимум два достоинства
- Проблемы структуры / логики (writer)
- Проблемы выражения (polisher)
- Сводка задач по правкам (с пометкой оси, к которой относится проблема)
- Проверка цепи хуков
- Оценка верности каркасу
- Проверка эмоциональной дуги
- Заметки по связности
- Запись повторной рецензии (при повторной рецензии)

## 11. Напоминание о перекрёстной повторной проверке измерений

Некоторые проблемы нужно отмечать сразу по нескольким плоскостям влияния:

- Персонаж вдруг знает то, чего знать не должен → повествовательная логика + согласованность персонажей
- Большой кусок бесфункционального описания → качество описания + ритм и напряжение + объём и плотность
- Вываливание информации в диалоге → качество диалога + удаление привкуса ИИ
- Забытая старая интрига → связность + хуки и интрига

## Красные линии

- Нельзя давать только читательское ощущение без позиции и исполнимых предложений
- Нельзя не различать writer / polisher
- Нельзя не отмечать слой источника проблемы
- Нельзя пропускать цепь хуков и верность каркасу лишь потому, что статья «в целом неплоха»
- Нельзя делать повторную рецензию «только проверка старых ям, без взгляда на новые»

> Достаточность доказательств: средняя — измерения аудита InkOS — это описание системного проектирования, конкретная реализация (правила обнаружения и формулы оценки по каждому измерению) находится в исходном коде, а не в открытой документации
> Уровень достоверности: средний — перечень измерений может служить справочным сопоставлением, но не рекомендуется напрямую включать непроверенные измерения в этот Skill

InkOS имеет встроенную систему аудита «непрерывность + качество», заявляющую проверку каждого чернового текста главы по 33–37 измерениям. В её README и SKILL.md явно перечислены измерения, включая:

### Публично заявленные измерения аудита

| Измерение InkOS | Соответствующее измерение этого файла (двенадцатимерная двухосевая) | Пояснение сопоставления |
| --- | --- | --- |
| Память персонажей (character memory) | Изм. 2 согласованность персонажей | Высокое перекрытие — оба проверяют, помнит ли / забыл ли персонаж пережитое |
| Непрерывность предметов (material continuity) | Изм. 3 связность | Этот файл уже охватывает в связности (реквизит, состояние, положение) |
| Возврат предзнаменований (hook recovery) | Изм. 9 хуки и интрига | Уже охватывается проверкой цепи хуков в этом файле |
| Отклонение от плана (outline deviation) | Подразумевается в «верности каркасу» | Этот файл охватывает через «оценку верности каркасу» (§ двенадцатимерная) |
| Повествовательный ритм (narrative rhythm) | Изм. 5 ритм и напряжение | Высокое перекрытие |
| Эмоциональная дуга (emotional arc) | Изм. 11 плотность эмоциональных стимулов (ось удержания) | Эмоциональная дуга InkOS подчёркивает непрерывные эмоциональные изменения между главами, близко к поведенческому ощущению «оси удержания» |
| Качество диалога (dialogue quality) | Изм. 6 качество диалога | Прямое соответствие |
| Согласованность мировоззрения (world-building) | Подразумевается во многих измерениях | InkOS рассматривает мировоззрение как самостоятельное измерение аудита, этот файл охватывает комплексно через логику / связность / описание |

### Справочные направления дополнительных измерений

Следующее InkOS упоминает, но в двенадцати измерениях этого файла явно не названо; можно рассмотреть включение в последующих версиях:

| Направление измерения | Пояснение | Приоритет |
| --- | --- | --- |
| **Обнаружение следов ИИ** (AIGC detection) | У InkOS 11 детерминированных правил (нулевая стоимость LLM) + необязательная проверка LLM для обнаружения ИИ-контента | В этом Skill уже есть измерение «удаление привкуса ИИ», повторно проект не заводится |
| **Соответствие цветовой метки / стиля** | Проверка, соответствует ли стиль текста заявленной цветовой метке веб-романа (горячая кровь / абсурдный юмор / решительный в расправе и т. п.) | P2 — можно ориентироваться на измерение согласованности цветовых меток `общий-дистилляция-авторского-стиля` |
| **Чередование эмоций между главами** | Чередуются ли эмоции на протяжении 3 глав подряд, а не один фоновый тон | Уже частично охвачено проверкой «чередование эмоций на 3 главах подряд» измерения 11 оси удержания в §2 |

> Примечание: фактическая реализация аудита InkOS глубоко привязана к её коду (проверка Zod schema, applyRuntimeStateDelta, immutable-запись и т. п.), это инженерные решения реализации, а не методология письма, и их не следует напрямую переносить в правила письма этого Skill.
