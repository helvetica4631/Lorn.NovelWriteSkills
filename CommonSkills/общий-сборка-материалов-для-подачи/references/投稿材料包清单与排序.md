# Перечень пакета материалов для подачи и порядок

## Основной принцип

Порядок пакета материалов для подачи — не ради удобства автора, а чтобы редактор мог по самому лёгкому пути завершить суждение:

1. Что это за книга;
2. Почему её стоит читать дальше;
3. Исполнит ли книга обещания;
4. Способен ли автор продолжать писать.

## Часто необходимые файлы (формальный пакет для подачи)

1. Название / целевое название для публикации
2. Торговая точка одной фразой
3. `内投版简介` (аннотация для внутренней подачи)
4. `内投版正文` (основной текст для внутренней подачи; не менее `30000` знаков непрерывного основного текста)
5. `内投版总大纲` (общий план для внутренней подачи; минимум `5000` знаков)
6. `内投版第 1 卷卷纲` (план `1`-го тома для внутренней подачи)

> Пояснение: `组包自检` (самопроверка сборки), `当前版本索引` (индекс текущей версии), `版本说明` (описание версии), `模板字段覆盖表` (таблица покрытия полей шаблона) относятся к авторским внутренним файлам, **не входят в формальный пакет для редактора**.

## Рекомендуемый порядок (по умолчанию для Qidian / платформ серийной публикации)

1. **Название + торговая точка одной фразой**: сначала дать редактору понять, что это за книга.
2. **`内投版简介`**: затем дать редактору оценить, есть ли причина кликнуть и читать дальше.
3. **`内投版正文`**: затем доказать, что парадная дверь действительно захватывает.
4. **`内投版总大纲`**: затем доказать, что это не рукопись, умеющая только начинать, а есть настоящий скелет долгой линии.
5. **`内投版第 1 卷卷纲`**: затем доказать, что обещание первого тома детализировано до исполнимого уровня, а не просто пустые возгласы «дальше будет ещё интереснее».

## Авторские внутренние сопутствующие файлы (не отправляются вместе с рукописью)

- `组包自检`
- `当前版本索引 / 版本说明`
- `模板字段覆盖表`

## Какую задачу решает каждый материал

- **Название / торговая точка одной фразой**: решает «какой это жанр, ясна ли торговая точка».
- **Аннотация**: решает «почему я готов открыть и читать дальше».
- **Основной текст**: решает «действительно ли это обещание приземлено в начале».
- **Общий план**: решает «способен ли он поддержать долгую линию всей книги, а не разовую акцию».
- **План 1-го тома**: решает «приземлены ли на исполнимый уровень обещание первого тома, ритм первых `10` глав и передача эстафеты в конце тома».
- **Авторские внутренние сопутствующие файлы**: решают лишь потребности автора в сверке, отслеживании и возврате на доработку, не относятся к материалам для чтения редактором.

## Необязательные усиливающие файлы

- Индекс текущей версии / описание версии
- Таблица покрытия полей шаблона
- Пояснение об адаптации к платформе
- Резюме по точкам удовлетворения / интриге / матрице дел-единиц
- Пояснение о ритме письма автора и способности обновляться
- Дополнительная карточка героя / персонажей
- Дополнительная карточка правил / настроек
- Резюме имеющихся выводов платформенной оценки

## Нерекомендуемый порядок

- Сначала швырнуть длинный план, затем дополнять аннотацию и образцы глав
- Сначала положить пояснения автора, потом читаемые материалы
- Сначала положить энциклопедию настроек, потом основной текст
- Выложить спереди персонажей, настройки, общий план, и редактор надолго не видит парадную дверь
- Втиснуть весь комплект материалов для подачи в один Markdown-файл, держась на именах файлов и номерах версий, без каталога версий и индекса текущей версии
- Подмешать в материалы для редактора авторские суждения вроде `组包自检`, `当前最强 / 最弱一环`, `当前结论`, `建议现在内投`
