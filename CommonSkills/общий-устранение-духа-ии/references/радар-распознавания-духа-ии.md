# Радар распознавания «духа ИИ»

## Подтверждение за 30 секунд перед началом

Если пользователь не уточнил, сначала одной фразой подтвердить:

- Объём обработки: вся глава / отдельная сцена / несколько абзацев
- Целевая интенсивность: лёгкая (структуру не трогать) / средняя (допустимы небольшие перестановки внутри абзаца) / тяжёлая (переписать абзац целиком с эквивалентной информацией)
- «Гвозди», которые нужно сохранить: хук-фраза конца главы, ключевые поля доказательств, ключевые реплики

## Определение «духа ИИ» (в согласовании с исследовательской рамкой)

Под «духом ИИ» понимают явление, когда текст проявляет механистичность, шаблонность и недостаток человеческих черт; типичные симптомы:

- Язык: пышность без содержания, высокая частота универсальных слов / универсальных конструкций, книжная интонация подавляет ощущение разговорности
- Сюжет: пассивное развитие, слабая причинная цепочка, пресный кульминационный момент, отсутствие или чрезмерная натянутость предзнаменований
- Персонажи: ярлыки, отсутствие арки, недостаточная мотивация поступков, механистичное выражение чувств
- Диалог: прямолинейность без подтекста, однородность, слишком гладкий ритм без пауз- Точка зрения: утечка всеведущего взгляда, автор за персонажа объявляет эмоцию («ему было очень страшно», «ноги предательски задрожали», «подсознание подсказало ему») вместо подачи через ощущения персонажа — это обрушение точки зрения, недуг «духа ИИ» высокого приоритета- Ощущение реальности: пространство и процедуры вынуты, остаются лишь абстрактные слова вроде «гнетущий, жуткий, удушающий», а читатель ничего не чувствует, не осязает и не видит, что можно было бы приземлить
- Ощущение сериала: внутриглавное движение, должное быть в тексте сериала, превращено в эссеистичное медленное адажио — возникает потеря скорости по схеме «начало с событием, середина уплыла, хук вспомнили лишь в конце»

## Быстрое суждение по слоям-источникам (новое)

- `病灶识别层` (слой распознавания недуга): клише, возвышенный тон, корпоративный жаргон, самоссылки на главы, тон путеводителя, остатки вёрстки, расплывчатые атрибуции.
- `句群重构层` (слой перестройки групп фраз): однородные группы фраз, формульные фразы, объяснительный тон, разрыв «действие → последствие», усреднённые абзацы, переходные склеивающие слова.
- `人声回补层` (слой возвращения человеческого голоса): слабый голос персонажей, корысть и предубеждения, шероховатости, давление на месте, температурный перепад отношений, избирательное наблюдение.

По умолчанию сначала определить, в каком слое главная фальшь, и затем решать: сначала удалить клише, сначала разобрать группы фраз или сначала вернуть то, что делает текст «похожим на человека».

## Минимальный диагностический артефакт (новое)

```markdown
【病灶识别层】最重症状： (【Слой распознавания недуга】самый тяжёлый симптом:)
【句群重构层】最重症状： (【Слой перестройки групп фраз】самый тяжёлый симптом:)
【人声回补层】最重症状： (【Слой возвращения человеческого голоса】самый тяжёлый симптом:)
【本轮优先下刀层】： (【Слой первоочередного вмешательства в этом раунде】:)
```

## Специализированное обнаружение конструкций

### Часто встречающаяся конструкция ИИ: «不是X。是Y» (не X. А Y)

В тексте, сгенерированном ИИ, частота этой конструкции ≈2 раза на тысячу знаков — намного выше частоты в человеческом письме (0,3–0,6 раза на тысячу знаков). ИИ склонен использовать эту структуру как «точное наименование эмоции + самокоррекцию» — например «她不怕。她是在担心……» (Она не боится. Она беспокоится о…) — внутренний монолог реального человека под давлением рваный, скачущий, редко так стройно самоисправляется.

**Метод обнаружения**: просканировать весь текст по `不是[^。]{2,30}，是[^。]{2,30}`. Если частота >0,8 раза на тысячу знаков, срабатывает тревога.

**Методы разбора**:
1. Удалить часть «不是» (не), оставив только содержимое после «是» (есть) (потери минимальны, эффект самый заметный)
2. Разбить фразу на разговорные осколки: например «不是怕。是心跳声会被听见» (Не страх. Просто стук сердца услышат) заменить на «心跳太响了。屋里的人会听见» (Сердце бьётся слишком громко. Люди в комнате услышат)
3. Если фраза несёт главное эмоциональное ударение (не более 2 раз на главу): оставить, но убрать тире, заменить паузой через точку

### Частые логические связки ИИ (новое, источник: исследовательский отчёт по противодействию детектору Zhuque AI)

Эти слова встречаются в тексте, сгенерированном ИИ, заметно чаще, чем в человеческом письме (статистика из аналитических отчётов нескольких детекторов и данных сообщества авторов). При устранении «духа ИИ» искать по всему тексту и держать в пределах «не более 2 раз на тысячу знаков»:

| Частый триггер | Направление замены | Приоритет обнаружения |
|-----------|---------|-----------|
| 然而 (однако) | → «可» (но), «但» (но) или просто опустить, разорвать фразу действием | ★★★ |
| 此外/除此之外 (кроме того / помимо этого) | → просто удалить либо «还有» (ещё), «再说» (к тому же) | ★★★ |
| 因此/因而 (поэтому / вследствие этого) | → «所以» (так что), «结果» (в итоге) или подразумеваемая причинность | ★★★ |
| 值得注意的是 (стоит отметить) | → просто удалить либо заменить конкретным описанием | ★★★ |
| 不可否认的是 (нельзя отрицать, что) | → «当然» (конечно), «说实话» (честно говоря) | ★★☆ |
| 总的来说/总而言之 (в общем / подводя итог) | → просто удалить, дать абзацу закончиться естественно | ★★★ |
| 换句话说/换言之 (иными словами) | → заменить абстрактное объяснение конкретным примером | ★★☆ |
| 毫无疑问 (без сомнения) | → «显然» (очевидно) или прямое утверждение | ★★☆ |
| 一定程度上 (в определённой степени) | → удалить либо указать конкретную степень | ★☆☆ |
| 不仅…而且… (не только…, но и…) | → разбить на две фразы или оставить только одну часть | ★★☆ |

> Пояснение приоритета обнаружения: ★★★ = высокочастотные триггеры ИИ, каждое появление — штрафной пункт; ★★☆ = средний риск, при плотном появлении срабатывает тревога; ★☆☆ = лёгкий риск, служит вспомогательной справкой.

### Симметричные фразы и параллельные структуры (новое)

ИИ предпочитает уравновешенные конструкции «длина первой половины фразы ≈ длина второй половины», а также параллельные структуры вроде «不仅…而且…» (не только…, но и…), «不是A而是B» (не A, а B). Просканировать весь текст и подсчитать плотность симметричных фраз: если она превышает 15% всех фраз, срабатывает тревога. Способ разбора: превратить не менее половины симметричных фраз в структуры неравной длины.

## Обнаружение отпечатков, характерных для модели DeepSeek (новое)

У серий DeepSeek-R1/V3 при генерации веб-новелл есть особые стилистические паттерны; даже после обработки по устранению «духа ИИ» могут оставаться следующие черты. После обычного устранения дополнительно прогнать проверку на отпечатки DS:

| Признак | Метод обнаружения | Направление разбора |
|------|---------|---------|
| Нагромождение точных чисел | Просмотреть числа во всей главе — не встречаются ли в начале главы густо точные подсчёты | Оставить 1–2 ключевые цифры, остальные размыть |
| Слишком плотные изящные метафоры | Подсчитать плотность метафор: > 2 на тысячу знаков — превышение | Удалить половину, оставить только ту, что напрямую связана с эмоцией |

## Самоссылки на главы и тон сериального путеводителя (недуг высокого приоритета)

По умолчанию считать это «утечкой звука с рабочего стола автора», которую следует разбирать в первую очередь:

- 这几章…… (эти несколько глав…)
- 前几章…… (первые несколько глав…)
- 前面几章…… (предыдущие несколько глав…)
- 前面这几章…… (эти предыдущие несколько глав…)
- 后几章…… (последние несколько глав…)
- 后面几章…… (последующие несколько глав…)
- 后面这几章…… (эти последующие несколько глав…)
- 整章…… (вся глава…)
- 这整章…… (вся эта глава…)
- 这一整章…… (вся эта одна глава…)
- 上一章…… (предыдущая глава…)
- 下一章…… (следующая глава…)
- 本章 / 这章主要…… (эта глава главным образом…)
- 后文会…… (дальше будет…)
- 我们会看到…… (мы увидим…)
- 读者会发现…… (читатель обнаружит…)

Принципы обработки:

- «Обзор нескольких глав» заменить на последствия, которые персонаж сейчас переживает: отголоски, раны, остывшие отношения, оставшиеся предметы или изменения обстановки.
- «Анонс следующей главы» заменить на незавершённое действие, закинутую новую переменную, конкретную цену или новое окно опасности.
- «Подведение итогов автором за читателя» заменить действиями внутри сцены, ощущениями, сбоем в диалоге и видимыми последствиями.

- 在当今时代 (в наше время)

- 在……的背景下 (на фоне…)
- 值得注意的是 (стоит отметить)
- 需要指出的是 (необходимо указать, что)
- 不言而喻 (само собой разумеется)
- 毋庸置疑 (не подлежит сомнению)
- 从某种意义上说 (в некотором смысле)

- 接下来让我们 (далее давайте)

- 这是个本质区别 (это принципиальное различие)
- 更好的策略是 (лучшая стратегия —)

## Тревоги по разбору конструкций (расширенная версия)

- Чрезмерное противопоставление: «не A, а B, не C, а D…»
- Чрезмерное перечисление: «既……又……不仅……而且……同时……并且……» (и…, и… не только…, но и… одновременно… и…)
- Чрезмерный параллелизм: «от A до B, от B до C…»
- Ровная трёхчастность: «要么……要么……要么……» (либо…, либо…, либо…)
- Частое употребление «前者 / 后者» (первое / второе)

## Тревоги по конструкциям

- Подряд 3 фразы одинаковой длины
- Подряд 2 параллельные фразы
- Повторяющееся «这是……这是……这是……» (это… это… это…)
- Слишком одинаковая длина абзацев
- Слишком густые подзаголовки / пункты / эмодзи, из-за чего текст похож на слайд
- Подряд много фраз объясняют настроение / атмосферу, и нет подхвата действием, предметом, речью, интерфейсом или звуком
- Начало стало гладким, но не цепляет, середина стала красивой, но без награды

## Жёсткие показатели фраз и абзацев (версия для основного текста романа)

- Фразы: в основном 15–25 знаков; свыше 25 знаков — в первую очередь разбивать на 2–3 фразы
- Абзацы: для чтения с телефона уместно 3–5 строк; длинные абзацы разбивать
- Не нанизывать слишком много самостоятельных частей через запятые; где можно поставить точку, ставить точку

## Сигналы «духа ИИ» на уровне структуры (сюжет / персонажи / диалог)

- Пассивное развитие сюжета: абзац в основном объясняет / описывает пейзаж / определяет термины, но нет «действие → последствие»
- Слишком тонкая причинная цепочка: у ключевого поворота нет пускового условия «почему именно сейчас»
- Кульминация разбавлена деталями: когда нужно напряжение, начинают нагромождать внешность / детали пейзажа, кривая эмоций выравнивается
- Отсутствие или вставка предзнаменований «в лоб»: ранее нет мелких нитей, на которые можно сослаться; либо поясняющей фразой насильно подсказывают «это будет очень важно»
- Персонажи-ярлыки: персонажа напрямую клеймят словами «добрый / холодный / умный», без наблюдаемых привычек, промахов и противоречий
- Разрыв мотивации: у поступков персонажа нет цены, нет того, чего он боится, нет границы, которую он удерживает
- Прямолинейный диалог без подтекста: персонаж выговаривает все мысли, нет уклонения, прощупывания, перебивания, смутности
- Однородный / чрезмерно книжный диалог: люди разных статусов пользуются одним синтаксисом и словарём
- Чрезмерно «безупречные и правильные» персонажи: профессионал никогда не отвлекается, не делает мелких ошибок, его никогда не прерывают извне
- Чрезмерно «безопасная и чистая» сцена: пространство как образцовая квартира, нет скрытых рисков, давления обратного отсчёта или неподконтрольных посторонних наблюдателей
- Разрыв стежков реальности: исходные стежки жизни — пропускной режим, заявки, групповые чаты, принтер, квитанции, запах дыма, лампочки в подъезде — смыты
- Награда в середине сглажена: в оригинале уже были улики, изъяны, изменения отношений, результаты проб правил, а после переписывания всё спрятано в красивые фразы

## Предварительный фильтр Green / Yellow / Red (новое)

- `Green`: в основном ложные фразы, ложная склейка, ложный тон; структура и человеческий голос сносны, подходит сразу для переписывания по устранению «духа ИИ».
- `Yellow`: недуг охватывает два слоя, например группы фраз очень фальшивы и голоса персонажей тоже сливаются; при устранении нужно параллельно следить за повторной проверкой ответственности.
- `Red`: текст не только похож на ИИ, но и уже повредил структурную ответственность, награду в середине, хук конца главы или голоса персонажей; без одновременной повторной проверки при правке очень легко стать всё пустее.

## Новые диагностические сигналы (заимствованы у Kevin с Zhihu)

Следующие диагностические сигналы взяты из статьи пользователя Zhihu Kevin «Как убрать «дух ИИ» из текста, написанного ИИ?» и включены как новые диагностические пункты в SKILL.md; этот файл дополняет их быстрыми пунктами проверки.

### Слишком полная структура (болезнь «полного плана»)

- Не «обслужены ли поровну» все части основного текста (фон → причина → метод → итог, ничего не упущено)?
- Может ли читатель после 300 знаков сказать, «что эта статья больше всего хочет подчеркнуть»? Если нет — структура слишком полна.
- Метод обнаружения: одной фразой обобщить «суждение» основного текста (а не «содержание») — если можно обобщить лишь распределение содержимого, но не позицию суждения, срабатывает тревога.

### Плоский список (нет приоритета)

- Нет ли в тексте более 2 перечислительных структур «X видов/штук/способов/пунктов/методов/шагов»?
- Есть ли у каждого пункта списка подсказка приоритета («самое важное», «самое опасное», «можно пропустить в первую очередь»)?
- Если списки идут подряд без маркеров приоритета → признать «плоскостностью списков».

### Слишком безопасное мнение (слишком плотные уравновешивающие фразы)

- Подсчитать долю уравновешивающих фраз вроде «с одной стороны… с другой стороны…», «и… и…», «в целом», «нельзя просто сказать».
- Если уравновешивающих фраз больше, чем прямых суждений → признать риск безопасного мнения.
- Быстрая самопроверка: есть ли хоть одна фраза, с которой читатель мог бы поспорить? Если нет — слишком безопасно.

### Пример не приземлён (синдром фальшивого кейса)

- Есть ли в каждом «например / приведу пример / к примеру / у меня есть знакомый» конкретное время, конкретный персонаж, конкретное действие, конкретное последствие?
- Если два кейса подряд не имеют хотя бы двух из этих четырёх элементов → синдром фальшивого кейса.
- Быстрая самопроверка: подходит ли этот пример для публикации с любого аккаунта? → Если да, это фальшивый кейс.

### Любовь к возвышению (поднимают, не прояснив основ)

- Не перескакивает ли конец абзаца часто к абстрактным уровням — эпохи / перемен / ценностей / смысла?
- Если удалить одну-две «возвышающие фразы» в конце абзаца, уменьшится ли количество информации? Если нет — возвышение лишнее.

### Концовочные клише (фиксированная схема: итог + возвышение + призыв)

- Не повторяет ли заключительный абзац лишь содержание, сказанное ранее?
- Если удалить заключительный абзац, остаётся ли весь текст состоятельным? Если да — концовка клишированная.

## Стратегия предотвращения у источника (заимствовано из системы агентов письма InkOS)

> Источник: [Narcooo/inkos](https://github.com/Narcooo/inkos) — система творческих агентов для длинных и коротких романов, сценариев и IP-контента (v1.6.2)
> Достаточность доказательств: средняя — эта стратегия — системный дизайнерский выбор InkOS, а не независимо проверенная методология письма
> Уверенность: средняя — логика разумна, но нет контрольного сравнения с чисто «постобработочным» путём

Основное содержание этого файла сосредоточено на **последующей диагностике и устранении** (после написания сканировать, распознавать, разбирать). InkOS предлагает взаимодополняющую **стратегию предотвращения у источника**: вшить правила устранения «духа ИИ» в сам этап генерации, сокращая следы ИИ у источника, а не полагаясь лишь на последующее переписывание.

### Три элемента предотвращения у источника

| Элемент | Пояснение | Связь с этим Skill |
| --- | --- | --- |
| **Список слов-«утомителей» лексики** | Во встроенном слое prompt агента-писателя держать список частых кластеров слов ИИ, активно избегая их при генерации | Пересекается с диагностическими правилами этого файла — «Список запрещённых слов», «Частые логические связки ИИ» — можно рассмотреть проекцию на prompt писателя |
| **Запрещённые конструкции** | В слое prompt объявить запрещённые шаблоны конструкций (симметричные фразы, уравновешивающие фразы, универсальные конструкции и т. д.) | Соответствует пунктам обнаружения этого файла — «Специализированное обнаружение конструкций», «Симметричные фразы и параллельные структуры», «Тревоги по разбору конструкций» — пункты последующего обнаружения можно вынести вперёд как ограничения генерации |
| **Впрыск стилевого отпечатка** | Внести базовую линию целевого стиля (распределение длины фраз, сенсорные предпочтения, плотность диалога и т. д.) как ограничение генерации в prompt писателя, а не только проверять на этапе аудита | Согласуется с цепочкой потребления «шаблона стиля автора» Skill `общий-дистилляция-авторского-стиля` — результат дистилляции может прямо служить источником впрыска |

### Суждение о подходящих сценариях

- **Высокотемповое пакетное написание глав** (ежедневно несколько глав): предотвращение у источника ＞ последующее устранение, потому что временными затратами на устранение «духа ИИ» в каждой главе по отдельности нельзя пренебречь
- **Тщательная доводка одной главы** (например начало, ключевая поворотная глава): последующее устранение + предотвращение у источника дополняют друг друга, сначала впрыснуть ограничения, затем тщательно разбирать
- **Уже есть готовый черновик**: возможен только путь последующего устранения, но после правки можно переписать следующую главу по стратегии предотвращения у источника

### Связь с этим рабочим процессом

Существующий процесс этого Skill — «после написания диагностика → разбор». Стратегия InkOS по предотвращению у источника означает:

1. Для новых глав можно в prompt писателя `общий-генерация-контрольной-карточки-главы` или `общий-создание-основного-текста` встроить три типа ограничений: «список слов-утомителей + запрещённые конструкции + базовая линия стиля».
2. Для уже написанных глав продолжать использовать существующий процесс диагностики → устранения этого Skill.
3. Если `Agents.md` или `общий-дистилляция-авторского-стиля` уже выдали шаблон стиля, этот шаблон может прямо служить источником впрыска стилевого отпечатка. См. `общий-дистилляция-авторского-стиля/references/карточка-якорей-впрыска-стиля.md`.

> Дополнение: команда InkOS `revise --mode anti-detect` предоставляет специальный режим переписывания против детекции; его система аудита обнаруживает следы ИИ по 33+ измерениям, включая статистику частых слов, монотонность конструкций, чрезмерные итоги и др.
