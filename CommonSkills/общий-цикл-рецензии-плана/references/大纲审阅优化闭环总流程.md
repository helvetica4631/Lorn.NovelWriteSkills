# Общий процесс замкнутого цикла рецензирования и оптимизации плана (справочно)

Этот документ — сопутствующий справочник к `общий-цикл-рецензии-плана/SKILL.md`, он даёт дополнительные подробности выполнения шагов, пояснения принципов и условия остановки. **Авторитетное определение процесса — в SKILL.md**, этот документ не повторяет способы вызова skill и объявления ролей в шагах.

## Поддерживаемый вход

- OUTLINE_FILE: путь к файлу целевого плана
- Тип объекта: общий план / часть / том / одиночное дело
- RELATED_CONTEXT_FILES[] (необязательно)

Если пользователь не предоставил указанные параметры полностью:

- В первую очередь выводить тип объекта по имени файла, структуре каталогов и контексту
- Можно параллельно вывести номер или название плана для сопоставления с основным отчётом
- Если путь не поддаётся разбору, файл отсутствует или нет действительно блокирующей ошибки, нельзя останавливаться и задавать вопросы из-за деталей именования

## Дополнения к выполнению шагов

### Шаг 0: дополнительные пояснения по инициализации

#### Маршрутизация по объектам

- **Уровень общего плана** (小说总大纲.md / пакет общего плана): для рецензирования вызывается `общий-рецензия-общего-плана`; для правки вызывается `общий-проектирование-общего-плана`
- **Уровень части/тома/одиночного дела** (план тома / список глав и т. п.): для рецензирования вызывается `общий-рецензия-плана-тома`; для правки вызывается `общий-проектирование-плана-тома`

#### Требования ко входу

Перед началом обязательно дополнить:

1. Путь к файлу целевого плана
2. Тип объекта: общий план / часть / том / одиночное дело
3. Цель этого раунда: комплексные оценки двух независимых рецензирований подряд строго больше 9,2

Если в каталоге текущего жанра уже есть `竞对分析/`:

1. В этом раунде сверяться со списком конкурентов (рекомендуется 1–3 книги)
2. Для каждого конкурента как минимум 1 пункт «сильная сторона, которую можно позаимствовать» и 1 пункт «наша отстающая позиция»

### Шаг 1: дополнительные пояснения по первому раунду рецензирования

Обязательный контракт этапа рецензирования:

- Обязательно выдать полный отчёт рецензирования
- В отчёте обязательно: точки блокировки / риски, конкретные предложения по правке, идеи для рывка к 9,2+, комплексная оценка
- Если есть материалы анализа конкурентов, в отчёте обязательно: заимствуемые у конкурентов моменты, наши отстающие точки, приоритетные действия по оптимизации
- Если есть материалы анализа конкурентов, в отчёте дополнительно обязательно: единый количественный модуль конкурентов (сведение пула кандидатов Top 10 + экспресс-обзор четырёхслойной разборки 3–5 основных подавляющих образцов + единая количественная карточка + сводное суждение / пояснение потолка)
- Из отчёта должно быть чётко видно, «почему порог не пройден / почему уже пройден»
- В первом раунде сначала обязательно выдать полную версию отчёта рецензирования и записать её по пути основного отчёта
- Нельзя сначала в чате давать устные советы, а потом решать, писать ли отчёт

### Шаг 2: дополнительные пояснения по считыванию комплексной оценки

Комплексная оценка берётся как значение после округления до двух знаков. 9,2 не считается пройденным, нужно строго больше 9,2.

Если пункт по конкурентам хотя бы в одном раунде ниже 7,0/10, то даже при комплексной оценке, внешне превышающей 9,2, закрывать нельзя; обязательно продолжать доработку.

### Шаг 3: дополнительные пояснения по правке плана

Обязательный контракт этапа правки:

- Необходимо записывать прямо в файл целевого плана, нельзя давать вариант-совет только в чате
- Правка обязана покрыть основные пункты снижения оценки прошлого раунда
- Правка обязана одновременно усвоить проблемы, предложения по правке и «идеи для рывка к комплексной оценке 9,2+» из последнего отчёта рецензирования
- Если есть материалы анализа конкурентов, правка обязана приземлить как минимум 1 «действие заимствования у конкурентов» и закрыть 1 «отстающую позицию относительно конкурентов»
- Если есть материалы анализа конкурентов и пункт по конкурентам всё ещё ниже 7,0/10, по умолчанию нельзя считать, что в этом раунде достигнуто устойчивое прохождение порога
- Нельзя вносить новых серьёзных конфликтов формулировок

### Шаг 4: дополнительные пояснения по повторному рецензированию

Повторное рецензирование должно быть **полным, строгим, независимым новым рецензированием текущей исправленной редакции**, а не проверкой лишь того, исправлены ли старые проблемы.

Запрещённые действия:
- Подменять независимую оценку утверждением «по сравнению с прошлым раундом есть прогресс»
- Покупать высокий балл снижением критериев рецензирования
- Пропускать звено заново найденных новых проблем

### Шаг 5: дополнительные пояснения по управлению циклом

В каждом раунде доработки записывать как минимум:

- Текущий раунд
- Текущая комплексная оценка
- Какие проблемы исправлены по сравнению с прошлым раундом
- Какие проблемы всё ещё не решены
- Переходить ли в следующий раунд
- Если в этом раунде оценка впервые строго больше 9,2: пометить «порог впервые пройден, переход к раунду проверки устойчивости», принудительно добавить один раунд правки и независимого повторного рецензирования
- Если два раунда подряд строго больше 9,2: пометить «порог устойчиво пройден, закрытие разрешено»

### Шаг 6: дополнительные пояснения по квитанции о завершении

Перед выводом обязательно по пунктам проверить:
1. Является ли целевой план последней исправленной версией
2. Является ли основной отчёт рецензирования последней версией повторного рецензирования
3. > 9,2 ли оценка в двух раундах подряд
4. Если есть измерение конкурентов, в количественной карточке конкурентов нет ключевых заметных отстающих позиций

## Стратегия основного отчёта рецензирования

- В рамках одной задачи поддерживается только один основной отчёт.
- Если в первом раунде его нет — создаётся новый; после создания все последующие повторные рецензирования обязаны перезаписывать и обновлять тот же путь.
- Запрещено заводить для одной задачи параллельные отчёты, вызывающие расхождение формулировок.
- В первую очередь искать в `审阅意见/` существующий отчёт, соответствующий типу объекта плана, названию или номеру.
- Если найдено несколько отчётов-кандидатов, по умолчанию брать с самой свежей датой в качестве текущего основного отчёта.

Режимов записи в первом раунде допускается только два:
- Найден существующий основной отчёт: `overwrite`
- Существующий основной отчёт не найден: `create`

## Условия остановки

- Завершать разрешено только при **комплексных оценках двух независимых рецензирований подряд, строго больших 9,2**
- 9,2 не считается пройденным, нужно продолжать правку и повторное рецензирование
- После первого превышения оценкой строго 9,2 нельзя сразу закрывать; обязательно выполнить ещё один раунд построчной шлифовки на основе отчёта этого раунда + независимого строгого повторного рецензирования (повторно выполнить полное строгое рецензирование исправленной редакции, а не только перепроверять старые проблемы); если и оценка этого повторного рецензирования строго больше 9,2 (то есть два раунда подряд пройдены), тогда разрешён выход

## Гейт сходимости цикла

Цикл «проверка→правка→повторное рецензирование» по умолчанию выполняется не более 3 раундов (не считая первого рецензирования). Если после 3 раундов порог не достигнут:

1. Приостановить цикл, оценить, нужно ли менять модель, корректировать формулировки промптов или дополнять источники-арбитры
2. Если оценка 3-го раунда, напротив, ниже 2-го, принудительно остановить
3. Для признания плато необходимо, чтобы **разница оценок в двух парах подряд была < 0,15**: если разница оценки раунда N и раунда N-1 < 0,15, нельзя сразу останавливать — **обязательно выполнить ещё один раунд «шлифовка + независимое повторное рецензирование»** и получить оценку раунда N+1. Только если одновременно выполняются |Score(N)−Score(N-1)| < 0,15 **и** |Score(N+1)−Score(N)| < 0,15, считается, что наступило плато, и принудительно останавливаем. Если разница при повторном рецензировании ≥ 0,15, плато не признаётся, продолжается обычный цикл доработки
4. Нельзя просто повторять цикл «правка → рецензирование»

«Дополнительный раунд проверки устойчивости после первого прохождения порога» не входит в лимит 3 раундов — раунд проверки — необходимый дополнительный шаг ради достигнутого порога, а не продолжение доработки из-за недостижения.
