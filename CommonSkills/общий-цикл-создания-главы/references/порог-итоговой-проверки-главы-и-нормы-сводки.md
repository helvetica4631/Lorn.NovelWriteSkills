# Порог итоговой рецензии главы и нормы сводки

## Единственное условие признания `9.2+`

- Только если в последнем `REVIEW_REPORT_FILE` явно записано `Комплексная оценка: X.X/10`
- и `X.X > 9.2` (строго больше, сама `9.2` не считается пройденной)
- `8.8 / 8.9 / 9.0 / 9.1 / 9.2` всегда считаются не достигшими порога
- **Одноразовое прохождение порога не означает, что можно закрывать**; полный цикл доработки: ① первая итоговая рецензия → ② доводка на основе первого отчёта рецензии → ③ независимая повторная рецензия (заново выполнить полную рецензию исправленной версии, а не только проверять, исправлены ли старые проблемы) → ④ закрывать и выходить можно только когда две оценки подряд строго больше 9.2
- Независимая повторная рецензия второго раунда обязана быть **полной, строгой, независимой повторной рецензией именно текущей исправленной версии**: нужно и проверить, существенно ли исправлены проблемы предыдущего раунда, и заново выявить новые проблемы этого раунда; нельзя принимать «по сравнению с прошлым разом есть прогресс» за первый критерий суждения

## Первая цепочка рецензии: шаги не пропускать

- Шаги 5 / 6 / 7 / 8 / 9 обязательно сначала выполнить полностью один раз.
- Первое исполнение шагов 5, 6, 7, 8, 9 нельзя пропускать на основании какой-либо исторической оценки, предполагаемой оценки или «кажется, уже достаточно хорошо».
- Только после первого завершения шага 9 разрешено переходить к шагу 9.5 для маршрутизации по оценке.

## Правила доработки

- Шаги 5 / 6 / 7 / 8 / 9 нужно выполнить полностью хотя бы один раз, и только после этого разрешено решать по порогу 9.2, добавлять ли подцикл
- Суждение по порогу действует только после завершения шага 9
- Если порог не достигнут, продолжать выполнять `8 → 9 → суждение по порогу`
- **Если оценка первого шага 9 строго больше 9.2, всё равно нельзя прямо переходить к шагу 10**; нужно выполнить ещё один раунд `8 (поэтапная доводка по отчёту рецензии) → 9 (независимая строгая повторная рецензия — заново выполнить полную рецензию исправленной версии, а не только перепроверять старые проблемы)`, и только если оценка повторной рецензии по-прежнему строго больше 9.2 (то есть оба раунда подряд пройдены), разрешено выйти из цикла доработки
- Пока два раунда подряд не пройдены, нельзя переходить к шагам 10, 11, 12

## Правила числа знаков и свежести

- Каждый раз, когда основной текст после шага 2 был изменён, обязательно заново прогонять скрипт подсчёта знаков.
- Окончательное достижение порога числа знаков определяется по последним `Len / CJK / BodyCJK / MeetsMinCJK / WithinRange`.
- ⚠️ Внимание: раньше это поле называлось `Meets3500`, теперь заменено на `MeetsMinCJK`; реально проверяется `MinCJK`, что не равно жёстко заданному 3500. Достижение нормы нужно определять единственно по тому, попадает ли `BodyCJK` в диапазон числа знаков по умолчанию для платформы.
- Контроль доступа основного текста определяется по диапазону числа знаков по умолчанию платформы из SKILL.md `общий-вывод-*` (для основной платформы вывода), решает только `BodyCJK`; `Len` и другие подсчёты знаков служат лишь справкой.
- Если в отчёте, журнале или сводке написано «статистика без пробелов», «NoWhitespaceLen» или другой самодельный подсчёт знаков и по ним судят о достижении нормы, это считается провалом контроля доступа: обязательно заново прогнать скрипт для доработки и обновить связанные артефакты.
- Последний основной текст, последний отчёт рецензии, последнее число знаков, последний журнал и итоговая сводка должны быть взаимно согласованы; если любой устарел, завершать нельзя.

## Правила вывода сводки

- Выводить только резюме, не выводить основной текст
- Сводка должна быть согласована с последним основным текстом, последним отчётом, последним числом знаков и последним журналом
- Пакетная сводка обязана явно выводить поля агрегированного контроля доступа: `gatePassRate`, `rotationOverloadCount`, `midPayoffCoverage`, `tailDriverCoverage`
- Если агрегированный контроль не достигнут (не выполнен порог по любому пункту), в сводке нельзя писать «завершено», можно писать только «частично завершено / ожидает доработки»

## Трёхслойное отображение сводки и итоговой рецензии (новое)

- `Слой согласованности свежести`: основной текст, отчёт, число знаков, журнал и сводка — одна и та же последняя версия ли.
- `Слой вердикта порога`: по-настоящему ли пройдены `9.2+` одной главы, агрегированный контроль пакета и поля числа знаков из скрипта.
- `Слой завершающего вывода`: честно ли сводка выводит «завершено / нельзя пропускать / ожидает доработки», а не празднует раньше времени.

## Вердикт о пропуске пакета (слой сводки)

Сводка пакета может выводить «можно пропустить / завершено» только при одновременном выполнении следующих условий:

- gatePassRate >= 0.90
- rotationOverloadCount < 2
- midPayoffCoverage = 1.00
- tailDriverCoverage = 1.00

При невыполнении любого условия сводка обязана вывести «нельзя пропустить / ожидает доработки» и в разделе «Что делать дальше» перечислить приоритетные действия-патчи.

## Поля согласованности

Журнал должен отслеживать как минимум:

- `chapterFresh`
- `reportFresh`
- `wordCountFresh`
- `summaryFresh`

Если любое из них `false`, нельзя выводить итоговую сводку.

## Минимальный артефакт итоговой рецензии (новое)

```markdown
[Слой согласованности свежести] chapterFresh / reportFresh / wordCountFresh / summaryFresh
[Слой вердикта порога] 9.2+ одной главы / агрегированный контроль пакета / контроль BodyCJK
[Слой завершающего вывода] завершено / нельзя пропускать / ожидает доработки
【Текущая оценка】Green / Yellow / Red
```

## Вердикт итоговой рецензии Green / Yellow / Red (новое)

- `Green`: свежесть согласована, порог пройден полностью, формулировка сводки честна — можно закрывать.
- `Yellow`: оценка или число знаков в основном на месте, но по свежести или агрегированному контролю ещё есть пункты для дополнения, не стоит писать «завершено».
- `Red`: устаревшие артефакты, порог не пройден или сводка забегает вперёд — обязательно доработка, нельзя прикрывать сводкой факт незамкнутого цикла.
