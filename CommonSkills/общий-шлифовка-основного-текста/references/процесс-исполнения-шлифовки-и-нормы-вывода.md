# Процесс исполнения шлифовки основного текста и нормы вывода

Этот файл закрепляет **общие рамки исполнения** задач шлифовки основного текста, применим к доводке глав, локальной очистке, локальному переписыванию и предпубликационной шлифовке для всех жанров.

## Область применения

- Доводка всей главы при наличии полного черновика
- Локальная очистка существующих сцен и абзацев
- Усиление ритма без изменения основного сюжета
- Общая основа процесса при совместном вызове с жанровым Skill

## Входные данные по умолчанию

Если пользователь специально не оговаривает, по умолчанию считать:

- Есть полный черновик главы
- Разрешена прямая запись обратно в исходный файл
- Приоритет — повысить чувство дочитывания, затем фактуру фраз
- Сначала сохранить факты, структуру, функции, затем заниматься стилем

## Вывод по умолчанию

- Прямо записывать в целевой файл, а не останавливаться на советах в чате
- Если пользователь явно требует «сначала показать один отрывок / сначала посмотреть план / не записывать обратно», переходить к выводу-примеру
- По завершении задачи кратко пояснить, что именно было главным образом усилено:
  - Цепкость начала главы
- награда в середине
- Хук в конце главы
  - Диалог / действие / эмоции / атмосфера / ритм

## Стандартный порядок исполнения

1. **Подтвердить объём и интенсивность**
   - Вся глава / сцена / абзац
   - Лёгкая / средняя / тяжёлая шлифовка
   - Какую информацию, фразы, обращения, номера нельзя трогать
2. **Откалибровать источники вердикта**
   - Отношения персонажей
   - Временной порядок
   - Причинная цепочка
   - Улики, правила, процедуры, границы сеттинга
3. **В первую очередь чинить цепь дочитывания**
   - Быстро ли в начале главы выбрасывается аномалия, конфликт, интрига или давление
   - Есть ли в середине существенное продвижение, прореха, ответный удар, открытие, эмоциональная награда
   - Оставлен ли в конце главы конкретный хук, а не пустое завершение
4. **Затем чинить носитель персонажей и сцены**
   - Узнаваемость диалога
   - Непрерывность действий
   - Близость психологии к телу
   - Давление в сцене и состоятельность пространства
5. **Наконец фразовая доводка**
   - Очистить пояснительный тон, шаблонный тон, итоговый тон
   - Оптимизировать ритм длинных и коротких фраз и дыхание абзацев
   - Унифицировать повествовательную точку зрения и интонацию
6. **Запись обратно после повторной проверки**
   - Сверить, сохранены ли функциональные точки исходной главы
   - Проверить, нет ли ошибочных правок, пропущенных правок, излишней шлифовки, ухода от темы

## Шлюз по объёму (обязательно)

- Достаточность объёма основного текста определять только по `BodyCJK / MeetsMinCJK / WithinRange` из `scripts/count-chapter.ps1`.
- `Len` — справочная длина, не заменяет `BodyCJK`.
- `去空白统计` (подсчёт без пробелов), `NoWhitespaceLen`, счётчик знаков редактора или ручная прикидка могут быть лишь справочной информацией, нельзя записывать их как вывод шлюза «достигнуто / не достигнуто».
- Если после шлифовки в этом раунде нужно проставить в журнал, сводку или рецензионный отчёт данные об объёме, обязательно ссылаться напрямую на поля скрипта: `Len / CJK / BodyCJK / MeetsMinCJK / WithinRange / MeetsAll`.

## Требования к обработке целой главы

Когда задача — шлифовка основного текста всей главы, в первую очередь придерживаться:

- Не полировать абзацы изолированно, а по ритму всей главы смотреть цепкость, продвижение и хуки
- Не выбирать только красивые фразы, а в первую очередь заниматься 1–3 ключевыми проблемами, сильнее всего влияющими на дочитывание
- Усилить хотя бы одну ключевую читательскую выгоду: цепкость / награда / хук / вживание / напряжение

## Требования к локальной обработке

Когда задача касается лишь нескольких абзацев:

- Сначала определить функциональное положение этих абзацев во всей главе
- Нельзя, чтобы после локального приглаживания интонация расходилась с предыдущим и следующим текстом
- Если локальная проблема по сути структурная, это нужно ясно указать, не шлифовать насильно

## Нормы записи обратно в файл

- По умолчанию сохранять существующую структуру авторских рабочих файлов / исходного Markdown
- Если в одном файле одновременно есть:
  - `章节正文` (основной текст главы)
  - `## 作者有话说` (слово автора)
  - `## 章节后记` (послесловие к главе)
  - `## 润色说明` (пояснение к шлифовке)
  считать нормальной структурой исходного черновика, не принимать за загрязнение
- Зачистку «чистового текста» для платформы проводить на последующем этапе экспорта, в этом процессе не удалять по ошибке содержимое на стороне автора

## Рекомендации по сводке выдачи

После завершения шлифовки основного текста в внешнем пояснении в первую очередь писать:

- Какую главу / какой абзац отшлифовали
- Какие основные проблемы исправлены в этот раз
- Какие зацепки главным образом усилены
- Записано ли обратно прямо в исходный файл

## Красные линии

- Нельзя превращать общую шлифовку основного текста в поверхностную риторику лишь с заменой синонимов
- Нельзя пропускать «цепь дочитывания» и сразу нагромождать красивые фразы
- Нельзя отказываться от записи обратно по умолчанию ради вывода отчёта
- Нельзя смешивать структуру исходного черновика и структуру опубликованного читательского варианта
