# Лучшие практики для сборника рассказов: от вдохновения до распространения на нескольких платформах (вход через Prompt жанра + версия, управляемая гейтами)

> Область применения: все каталоги жанров этого репозитория (например, `женская-романтика/`, `городской-саспенс/`, `городская-магия-и-сверхспособности/` и т. п.).
>
> Основной принцип: **пользователь напрямую вызывает Prompt из каталога жанра (`/слеш-команда`) и передаёт контекст через `#ссылки`.**

---

## 1. Сначала единая архитектура вызова (для сборника рассказов тоже)

Работа идёт по такой цепочке:

`задача пользователя -> /команда жанра -> маршрутизация жанрового Skill -> основа общего Skill`

Это означает:

- Вход со стороны пользователя — `/команда` (например, `/竞对分析`, `/设计大纲`, `/创建小说正文`).
- Контекст передаётся через `#файл` или `#каталог` (например, `#小说总大纲.md`).
- В диалоге не пишут «выполни `женская-романтика/.github/prompts/xxx.prompt.md`».

---

## 2. Ключевые отличия сборника рассказов от длинного романа

Главная трудность сборника рассказов — не «хорошо написать отдельный рассказ», а «**каждый рассказ самостоятелен + у всего сборника единая узнаваемость**».

Нужно одновременно выполнить два уровня:

1. **Уровень рассказа**: каждый рассказ состоятелен сам по себе (конфликт, награда, послевкусие концовки завершены).
2. **Уровень сборника**: тема, эмоциональный спектр, жанровое обещание и границы стиля создают единое ощущение.

Одной фразой: **сборник рассказов — не россыпь папок, а система произведения с логикой компоновки.**

---

## 3. Сначала ответ на ключевой спор: можно ли до оформления темы сборника делать карточки рассказов / персонажей / настройки?

**Вывод: можно делать лёгкую версию, но не следует делать тяжёлую окончательную версию.**

### 3.1 Почему нельзя слишком рано вкладываться

- Тема сборника, связи между рассказами и маршрут чтения на раннем этапе меняются.
- Если слишком рано переписывать подробные описания карточек рассказов, биографии персонажей и документы настроек, то при последующей корректировке плана возникнут большие переделки, расхождения в формулировках и несовпадение порядка рассказов.
- Трудность сборника рассказов — в «единой узнаваемости», а не в «нагромождении содержания»: чрезмерное моделирование, наоборот, связывает руки.

### 3.2 Оптимальный способ: двухступенчатое моделирование

1. **До темы сборника (лёгкая основа)**: оставляй только минимально жизнеспособную информацию
   - Пул рассказов: конфликт одной фразой, уникальная награда, стратегия концовки (3–5 строк)
   - Персонажи: если персонаж проходит через несколько рассказов, записывай лишь основное желание + главный конфликт (не полную биографию)
   - Настройки: если правило сквозное, записывай лишь 3–5 жёстких границ (не подробный разбор)

2. **После утверждения темы сборника и порядка рассказов (тяжёлая окончательная версия)**: только тогда делай крупномасштабное моделирование
   - Развернуть полные карточки рассказов (награда в середине, культурные детали, поздние развороты)
   - Дополнить биографии персонажей (сеть отношений, психологическая арка, рост через несколько рассказов)
   - Доработать настройки истории (условия потери силы, цепочка доказательств, процедурное трение)

## 4. Оптимальный процесс: 8 этапов, 7 гейтов (версия для сборника рассказов)

0. Слой макроанализа рынка: макроанализ рынка (даёт рыночные доказательства для инициализации проекта)
1. Этап инициализации проекта: на основе макроанализа рынка выполняются калибровка платформы на уровне сборника, проектирование эмоционального спектра, подбор модулей шаблонов
2. Этап конкурентов и дистилляции произведений (необязательно, проверка и уточнение после инициализации): анализ конкурентов — найти соперников; дистилляционное исследование — разобрать соперников
3. Дистилляция стиля: дистилляция авторского стиля (до начала создания текста, необязательно)
4. Этап запуска: позиционирование жанра + проектирование каркаса позиционирования жанра
4. Этап выбора тем: проектирование пула рассказов (карточки заглавий)
5. Этап архитектуры: общий план сборника + список рассказов
6. Этап производства: создание рассказов по одному + рецензия каждого с возвратом на доработку
7. Этап компоновки: упорядочивание рассказов + правка согласованности всего сборника
8. Этап выпуска: сборка пакета для подачи + распространение на нескольких платформах + возврат данных

### Слой макроанализа рынка (предшествует инициализации проекта, обязателен)

До инициализации проекта необходимо сначала завершить макроуровневый анализ рынка. Результат этого слоя напрямую становится входом для решений в инициализации.

Вызови `общий-глубокое-исследование` для макроуровневого исследования трендов, анализа экосистемы и изучения портрета читателя по целевой платформе × жанру, чтобы ответить на вопрос «что сейчас происходит на рынке в этом направлении».

- **Области исследования**: исследование трендов жанра + исследование экосистемы платформ + исследование читателей / рынка
- **Особое внимание для сборника рассказов**: различия предпочтений читателей рассказов и читателей длинных романов, экосистема платформ для сборников рассказов (Zhihu Yanxuan, Douban, Xiaohongshu, сборники рассказов издательств и т. п.)
- **Вывод**: отчёт об исследовании сохраняется в каталог `исследования-письма/`
- **Рекомендуется как обязательный**: при написании нового сборника рассказов настоятельно рекомендуется выполнять.

Уже имеющиеся макроисследования можно использовать повторно в новом проекте, не нужно каждый раз исследовать заново.

### Этап инициализации проекта (обязателен перед началом работы, принимает макроанализ рынка)

После завершения макроанализа рынка и до проектирования плана сначала вызови `общий-инициализация-проекта` для стратегического планирования на уровне проекта. **В процессе инициализации главным основанием для решений служит результат макроанализа рынка**. Версия для сборника рассказов особо следит за: калибровкой позиционирования на уровне всего сборника, а не отдельного рассказа, проектированием эмоционального спектра, способом адаптации модулей шаблонов к формату рассказа.

Если в процессе инициализации обнаруживается нехватка данных о конкурентах, `общий-инициализация-проекта` автоматически вызовет `общий-анализ-конкурирующих-произведений`, чтобы дополнить перечень разрывов с конкурентами (в этом случае анализ конкурентов выступает дополнением и позже может быть проведён отдельно и глубже).

> Пример входной команды: `/小说项目初始化 --platform 七猫 --genre 女频爱情` (или напрямую быстрая команда `/init`)

### Этап конкурентов и дистилляции произведений (необязателен после инициализации, проверка и уточнение)

После завершения инициализации проекта направление и решение определены. Теперь можно вызвать анализ конкурентов и дистилляционное исследование как проверку и уточнение позиционирования:

#### Анализ конкурентов (найти соперников)

Вызови `общий-анализ-конкурирующих-произведений`, чтобы зафиксировать конкурентов-рассказы на платформе — сборники рассказов издательств, колонки Zhihu Yanxuan, сборники рассказов Douban, сборники рассказов Xiaohongshu и т. п. Следи за: способом компоновки рассказов, средним объёмом рассказа, распределением эмоционального спектра, обратной связью в комментариях читателей.

- **Пример команды**: `/竞对分析 --platform 知乎 --genre 女频爱情短篇`
- **Вывод**: по каждому конкуренту отдельный отчёт, сохраняемый в каталог `竞对分析/`.

#### Дистилляционное исследование (разобрать соперников)

Для сильных образцов, выявленных при анализе конкурентов, вызови `общий-дистилляция-исследований-письма` или `общий-дистилляция-чертежа-произведения`, чтобы извлечь переиспользуемую «ДНК компоновки» и отпечатки шаблонов.

- **Дистилляция писательских исследований**: извлекает исполнимые ограничения из отчётов о писательских исследованиях уровня «жанр × платформа» и выдаёт шаблон писательского исследования.
- **Дистилляция образца произведения**: выделяет «ДНК компоновки» удачного сборника рассказов и выдаёт шаблон образца произведения. Например: `蒸馏知乎盐选女频短篇合集作为蓝本`.

**Связь трёх слоёв**: макроанализ рынка отвечает на вопрос «стоит ли входить в эту нишу» — это решение о направлении до инициализации; анализ конкурентов отвечает на вопрос «какие на рынке сейчас пустоты и кто соперники» — это проверка и уточнение после инициализации; дистилляционное исследование отвечает на вопрос «какие закономерности у хороших произведений и как их использовать». Три слоя поэтапно сужают, но анализ конкурентов и дистилляционное исследование не влияют на сами решения о направлении в инициализации.

### Дистилляция стиля (подготовка письма перед созданием текста, необязательно)

- **Дистилляция авторского стиля** (`общий-дистилляция-авторского-стиля`): выделяет «ДНК письма» писателя и выдаёт шаблон авторского стиля. Например: `蒸馏桐华，分析《那些回不去的年少时光》`.

В отличие от дистилляции образца произведения на этапе исследования конкурентов и дистилляции, дистилляция авторского стиля не служит коммерческим решениям, а служит только конкретному исполнению письма. Достаточно выполнить её перед началом создания текста.

### Гейт S1 (макроанализ рынка -> инициализация -> исследование конкурентов / запуск)

- Макроанализ рынка завершён, отчёт об исследовании сохранён в каталог `исследования-письма/`
- Все семь измерений решений в «синей книге инициализации проекта» завершены и ссылаются на макроанализ рынка
- Тему сборника можно пересказать одной фразой
- Рыночное позиционирование на целевой платформе ясно
- Чётко определено «зачем читателю читать подряд несколько рассказов до конца»

### Гейт S2 (выбор тем -> архитектура)

- Сформировано не менее 8–20 кандидатных карточек заглавий рассказов (в зависимости от планируемого объёма)
- В каждой карточке заглавия есть: главный конфликт, уникальная награда, хук концовки
- Между заглавиями нет сильных повторов

### Гейт S3 (архитектура -> производство)

- Есть общий план сборника (тема, стиль, запреты, связи между рассказами)
- Есть очередь приоритетов рассказов (какие писать первыми)
- Входные зависимости каждого рассказа чёткие (персонажи / настройки / границы улик)

### Гейт S4 (производство -> компоновка)

- Каждый рассказ прошёл хотя бы один цикл «рецензия -> возврат на доработку»
- В рассказе выполнено: захват внимания начала, ключевая награда, послевкусие концовки
- Именование файлов, метки и метаданные полны

### Гейт S5 (компоновка -> выпуск)

- У порядка рассказов есть явный маршрут чтения (запуск -> изменение -> завершение)
- Тон и ценностное обещание сборника согласованы
- Правила переключения между версией для подачи и версией для платформы определены

## 5. Подготовка среды перед началом (рабочий каталог романа)

> Рабочий каталог здесь — каталог «этого сборника рассказов», а не корневой каталог этого проекта.
### 5.1 Создание рабочего каталога сборника рассказов

Пример: `D:\小说项目\她不再回头-短篇集\`

### 5.2 Создание junction в этом каталоге (Windows)

Перейдя в каталог, выполни:

- `mklink /j .github путь к каталогу .github соответствующего жанра в этом проекте`
- `mklink /j исследования-письма путь к каталогу исследования-письма соответствующего жанра в этом проекте`
- `mklink /j scripts путь к каталогу scripts этого проекта`

### 5.3 Рекомендуемая структура каталога сборника рассказов (внутри рабочего каталога)

- `小说总大纲.md` (позиционирование всего сборника)
- `分卷大纲/` (можно переименовать в `分辑大纲/`)
- `短篇清单/` (карточки заглавий, приоритеты)
- `小说正文/` (по одному файлу на рассказ)
- `审阅意见/` (рецензии на отдельные рассказы + рецензии на весь сборник)
- `竞对分析/`
- `投稿组包/`

## 5.4 Открыть в VS Code и создать конфигурационный файл

Откройте VS Code и откройте рабочий каталог сборника рассказов выше. **Первое действие после входа в VS Code** — создать или отредактировать `Agents.md` в корне рабочего каталога и зарегистрировать основную платформу вывода:

```markdown
## 主输出平台
起点中文网
```

(Если в файле уже есть другие записи, допиши запись об основной платформе вывода в конец того же файла.)

Эта запись автоматически обнаруживается ключевыми Skill — `общий-создание-основного-текста`, `общий-цикл-создания-главы`, `общий-шлифовка-основного-текста`, `общий-усиление-хука-конца-главы` и др.; Skill по соглашению об именах загружают соответствующий `общий-вывод-{платформа}` и объединяют специальные правила платформы (количественные стандарты начала, плотность наград и хуков, такт темпа глав, гейты платформы) с общими правилами создания. Если `Agents.md` не существует или основная платформа не зарегистрирована, все ключевые Skill возвращаются к платформонезависимому общему режиму по умолчанию и не привязываются к конкретной платформе.

После этого можно переходить к первому шагу рабочего процесса — слою рыночной разведки (дистилляция / анализ конкурентов).

## 6. Шаблон вызова и минимальный список входных данных (/команда + #ссылки)

### 6.1 Общий шаблон вызова (можно копировать прямо)

> /【название команды】
>
> Цель: одной фразой, что нужно завершить в этом раунде.
>
> Прочитай следующий контекст:
>
> - #файлА
> - #файлБ
>
> Ограничения этого раунда:
>
> - Что обязательно сохранить (например, тему сборника, связи между рассказами, настройки ключевых персонажей)
> - Чего нельзя делать (например, не добавлять факты, не менять порядок рассказов, не выходить за границы жанра)
>
> Требования к выводу:
>
> - В какой файл или каталог записать
> - Сколько версий нужно (например, основная + короткая)
> - В чате отвечать только сводкой, полный текст не вставлять

### 6.2 Минимальный список входных данных (чтобы не «недокормить»)

Каждый раз давай как минимум три из следующих четырёх видов информации:

1. **Объект**: какой сборник рассказов, какие рассказы обрабатывать.
2. **Основание**: #общий план сборника, #карточки рассказов, #текст, #персонажи, #рецензии.
3. **Цель**: что нужно улучшить в этом раунде (захват внимания, дочитывание, темп между рассказами, адаптация под платформу и т. п.).
4. **Ограничения**: что нельзя трогать (тема сборника, порядок рассказов, основной конфликт, порог объёма).

### 6.3 Рабочий каталог и техническая подготовка

> «Рабочий каталог» здесь — не корневой каталог этого проекта, а собственный каталог вашего сборника рассказов, например: `她不再回头-短篇集/`.

#### 6.3.1 Создание рабочего каталога сборника рассказов

Пример каталога: `D:\小说项目\她不再回头-短篇集\`

#### 6.3.2 Создание junction в рабочем каталоге сборника (Windows)

Перейдя в `她不再回头-短篇集/`, выполни следующие 4 команды:

```powershell
mklink /j .github 本项目中对应题材下的.github目录路径
mklink /j CommonSkills 本项目中的CommonSkills目录路径
mklink /j исследования-письма 本项目中对应题材下的исследования-письма目录路径

```

Например, если текущий жанр — женская романтика, то `.github` и `исследования-письма` должны указывать на соответствующие каталоги в `женская-романтика/`.

## 7. Копируемые примеры по этапам (сборник рассказов о женской романтике)

### 7.0 Слой макроанализа рынка: /深度研究

> /深度研究

>
> Ограничения: при исследовании сборника рассказов особо учитывай различия предпочтений «аудитории рассказов» и «аудитории длинных романов».
>
> Вывод: отчёт об исследовании записать в #исследования-письма/, в чате отвечать только ключевыми находками.

> /小说项目初始化

### 7.3 Исследовательский этап: /设计题材定位框架

> /设计题材定位框架

>
> Прочитай:
>
> - #项目初始化/项目初始化蓝皮书.md
> - #исследования-письма/ (включая отчёты макроанализа рынка, помогающие оценить нишу жанра и портрет читателя)

>

> - Если по сводке позиционирования посторонний человек не может объяснить, «что самого особенного в этом сборнике», это считается незавершённым
>
> Вывод: текст каркаса позиционирования записать в #小说总大纲.md или по соответствующему пути проекта и дать сводку не более чем в 6 строк.

> - тексты показательных рассказов (3–5 полных текстов)
> - краткое описание плана сборника (порядок рассказов, связи между рассказами, линия роста всего сборника)
> - чек-лист самопроверки сборки (формат, именование, проверка повторов)
>
> Вывод: оформить в #投稿组包/ и дать подтверждение готовности к подаче и предупреждение о рисках.

## 8. Частые ошибки в сборниках рассказов и их исправление

1. **Внимание только к точкам удовлетворения отдельных рассказов без единства сборника**
   - Исправление: каждые 3–5 рассказов проводить рецензию на уровне всего сборника, чтобы предотвратить дрейф стиля.

2. **Повторы в пуле тем (один и тот же конфликт пишется снова и снова)**
   - Исправление: в карточках заглавий обязательно ставить «метку типа конфликта», чтобы избегать сильных повторов.

3. **Каждый рассказ похож на начало длинного романа, не хватает сил на завершение рассказа**
   - Исправление: заранее определить стратегию концовки (разворот / недосказанность / возвращение к началу / зависание).

4. **При распространении один и тот же текст подаётся везде без дифференциации**
   - Исправление: зафиксировать порядок «материнский текст -> адаптация под платформу -> вывод» и проверять каждую платформу отдельно.

5. **Потеря контроля над «холодными и горячими линиями» между рассказами или разрыв непрерывности**
   - Исправление: вести реестр сквозных персонажей / улик, отмечать для каждого рассказа повторение в начале + закладку в конце, чтобы какой-то рассказ не «проседал» и читатель не забывал.

## 9. Операционный возврат и итерации (версия для сборника рассказов)

После выхода сборника рассказов нужно выстроить непрерывный цикл обратной связи, чтобы накапливать данные для следующего сборника или оптимизации платформ.

### 9.1 Сбор обратной связи читателей с нескольких платформ

Собирай по платформам:

- **Доля дочитывания**: какая доля читателей дочитывает каждый рассказ (отражает ощущение длины рассказа)
- **Накал комментариев**: какие рассказы вызывают обсуждение и в чём суть обсуждения
- **Репосты и закладки**: какие рассказы обладают сильной распространяемостью (отражает репрезентативность)
- **Оценки читателей**: частотные слова, эмоциональная окраска, предложения по улучшению

### 9.2 Выявление сильных и слабых рассказов и закономерностей

Найти:

- **Сильные рассказы**: доля дочитывания > 80 %, много комментариев, много репостов -> проанализировать факторы успеха
- **Слабые рассказы**: доля дочитывания < 60 % -> проанализировать причины неудачи (слабый конфликт? неудовлетворительная концовка? отрыв от темы сборника?)
- **Неожиданные хиты**: рассказы, которые получили высокое внимание вопреки плану -> можно использовать как ориентир для следующего сборника

### 9.3 Запись обратно и итерация следующего сборника

На основе данных:

- Выбор жанра для следующего сборника (чего ожидают читатели?)
- Проектирование рассказов (корректировка в сторону сильных рассказов)
- Персонажи и настройки (сохранить популярные элементы)
- Стратегия платформ (на какой платформе лучшая обратная связь, куда направлять ресурсы)

## 11. Быстрый перенос на другие жанры

Рамки этого руководства можно переиспользовать для сборников рассказов других жанров (сборник рассказов городского саспенса, сборник рассказов «Сверхспособности и мистика», сборник рассказов женской романтики и т. п.). При переносе достаточно сделать индивидуальные правки в следующих местах:

### 11.1 Ограничения жанра и запреты

| Измерение ограничений | Что менять |
| --- | --- |
| **Тип конфликта** | Примеры карточек рассказов в разделе 7.3: заменить типичными для жанра шаблонами конфликтов |
| **Запретные элементы** | Описание технической подготовки в разделах 6.2 и 6.3: добавить красные линии модерации, свойственные жанру |
| **Стратегия компоновки** | Раздел 7.6 (предварительная компоновка порядка рассказов) и раздел 7.11 (последующая очистка материнского текста) нужно скорректировать по жанру в два этапа |
| **Границы стиля** | Описание call architecture в разделе 1: дополнить стандартами «языкового стиля жанра, степени реализма, степени жестокости» |

### 11.2 Правки в проектировании карточек рассказов

- Пример в разделе 7.3: использовать для иллюстрации анализа конкурентов произведения из топ-N списка жанра
- Критерий оценки: заменить определением признаков «сильного конфликта» этого жанра
- Предварительная компоновка в разделе 7.6: перестроить логику распределения «первого, поворотного, завершающего рассказов» по жанру

### 11.3 Корректировка стратегии распространения по платформам

- Акценты очистки материнского текста в разделе 7.11: скорректировать по жанру «информационную плотность / силу эмоций / долю объяснений»
- Выбор платформ в разделе 7.12: упорядочить по популярности жанра на разных платформах
- Ключевые слова обратной связи в разделе 9: заранее задать частотные направления пользовательских комментариев по жанру на разных платформах

### 11.4 Тонкая настройка акцентов рецензии

- Критерий «компактности рассказа» в разделе 7.10: скорректировать по среднему объёму рассказа в жанре
- Критерий «порядка и маршрута рассказов» в разделе 7.6: уточнить по жанру темп запуска и распределение середины
- Ошибки в разделе 8: дополнить типичными ловушками жанра (например, логические дыры в сборниках саспенса, конфликты настроек в сборниках сверхспособностей)

## 12. Заключение

Суть сборника рассказов — не «много рассказов», а «система произведения с узнаваемостью».

Достаточно держаться двух пунктов:

1. **Вход всегда через `/команду`, контекст всегда через `#ссылки`.**
2. **Цикл качества отдельного рассказа + цикл согласованности всего сборника работают одновременно.**

Тогда вы сможете превратить сборник рассказов из «кучи материала» в целостный продукт, который можно непрерывно улучшать, распространять и подавать на платформы.
