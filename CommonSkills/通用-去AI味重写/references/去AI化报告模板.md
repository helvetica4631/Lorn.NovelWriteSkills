# Шаблон отчёта об устранении «духа ИИ» (обязательный архивный вывод)

> Этот файл — полный шаблон, **обязательный к прочтению на шаге 11** `通用-去AI味重写` (общий Skill переписывания для устранения «духа ИИ»). После каждого выполнения задачи по устранению «духа ИИ» (включая режим полного процесса и режим быстрого канала без исключений) необходимо по этому шаблону сформировать **отчёт об устранении «духа ИИ» по данной главе** и сохранить на диск в **каталог `去AI化报告/` в корне проекта романа, по одному независимому файлу на главу**.
>
> Количественные данные, подсчёты сверки и журнал исполнения в этом шаблоне обязательно должны происходить из реального исполнения; **если какой-либо блок невозможно заполнить реальными данными, нельзя отделываться «—»**, нужно указать причину невыполнения и вернуться в процесс для дополнительного выполнения.

## 0. Правила сохранения на диск (согласованы с жёсткими ограничениями шага 11 в SKILL.md)

- **Путь**: `去AI化报告/` в корне проекта романа, запрещено записывать в `小说正文/`, `审阅意见/` или любые их подкаталоги.
- **Структура подкаталогов** (по томам, один файл на главу):

  ```text
  小说项目根/ (корень проекта романа)
  ├── 去AI化报告/
  │   ├── 第X部/ (при наличии структуры по частям)
  │   │   └── 第Y卷_{卷名}/
  │   │       ├── 去AI化报告_第1章_2026-08-26.md
  │   │       └── 去AI化报告_第2章_2026-08-26.md
  │   ├── 第Y卷_{卷名}/ (если тома есть, а частей нет)
  │   └── 去AI化报告_第1章_2026-08-26.md (без структуры томов — прямо в корне)
  ```

- **Именование**: `去AI化报告_{章节标识}_{YYYY-MM-DD}.md` (например, `去AI化报告_第3章_2026-08-26.md`). При обработке нескольких глав за раз **выдавать по одному файлу на каждую главу**, нельзя объединять в «главы 3–5».
- **Версия**: многократное выполнение для одной главы в один день — перезаписать одноимённый файл этого дня и указать в заявлении о недопущении небрежности «версия N / переделанная версия»; выполнение в другой день — сохранить новым файлом с новой датой.
- **Момент**: сохранять на диск **немедленно** по завершении работы по устранению «духа» в каждой главе, нельзя накапливать и дописывать пакетом.

## 2. Заполнение и определение провала (обязательные условия этого шаблона)

При любом из следующих случаев работа по устранению «духа ИИ» в этом раунде **признаётся проваленной**, архивировать и сдавать нельзя, необходимо выполнить дополнительно и заново сохранить на диск:

1. **Файл отчёта не выдан**: при каждом выполнении этого Skill (оба режима без исключений) обязательно выдавать отчёт по главе в `去AI化报告/`; любые причины (мало правок / только локальная обработка / только обратная связь в чате) не служат основанием пропустить.
2. **Отписка**: отчёт выдан после лишь поверхностного сканирования без выполнения содержательных процессов (например, не прогнано статистическое противодействие, не проведена построчная сверка структуры, не прочитано вслух); вся таблица заполнена «—» или списаны плейсхолдеры шаблона; количественные данные взяты с потолка или не соответствуют фактическому основному тексту; выводы по чтению вслух на нескольких страницах одинаковы и без доказательств.
3. **Подделка данных**: резюме «до правки» в журнале правок невозможно найти в оригинале; статистические числа не соответствуют фактическому основному тексту (например, число знаков до обработки не совпадает с фактическим исходником).
4. **Отчёт не выдан немедленно**: по завершении каждой главы на диск не сохранено, накоплено и дописано пакетом.
5. **Нарушение пути**: отчёт записан в `小说正文/`, `审阅意见/` либо не сохранён по принципу «один файл на главу» (появилась объединённая архивная запись вида «главы 3–5»).
