# Типичные проблемы «духа ИИ» в научной фантастике и стратегии исправления

> Источник: усвоено из `写作研究/小说写作中避免 AI 味的策略与技巧研究.md` (§2.4, §3.1–3.3)
> Достаточность доказательств: достаточная | Уверенность: высокая

## Специфические проблемы «духа ИИ» в научной фантастике

### 1. Логические прорехи научных сеттингов
- **Проявление**: ИИ генерирует псевдоглубокие понятия вроде «薛定谔的历史» (история Шрёдингера), «熵减重生» (возрождение через убыль энтропии); термины нагромождены, но между сеттингами есть логические противоречия
- **Исправление**: у каждого научного сеттинга должен быть хотя бы один проверяемый технический якорь (проверяемый через действия/наблюдения персонажа); запрещено объяснять словом «квантовый» более одного независимого сеттинга

### 2. Поверхностность технических описаний
- **Проявление**: много профессиональных терминов, но нет углублённого описания технических принципов и сценариев применения
- **Исправление**: технические термины появляются только в сценах, где персонаж их воспринимает и может ими оперировать; после каждого появления термина обязательно должен следовать конкретный воспринимаемый эффект

### 3. Отсутствие гуманитарной мысли
- **Проявление**: ИИ нагромождает научные понятия, но не размышляет об отношениях технологии и человеческой природы
- **Исправление**: каждый технический сеттинг должен быть привязан хотя бы к одной цене для персонажа или этической дилемме — «кто лишился чего из-за этой технологии?»

### 4. Уплощение мира будущего
- **Проявление**: общество будущего упрощено до «высокотехнологичной оболочки + нынешней общественной структуры», игнорируется глубокое влияние технологии на общество/культуру/человеческие отношения
- **Исправление**: при введении каждой ключевой технологии одновременно показывать, как она изменила хотя бы один вид повседневных общественных отношений (работа/семья/обмен/доверие)

## Общие проблемы «духа ИИ» для всех жанров (относится ко всем Skill)

### Замысел сюжета
- **Шаблонная структура**: ИИ склонен к линейной структуре «начало → встреча с проблемой → решение проблемы → happy ending»
  - Исправление: в середине принудительно вставить одну «ошибочную оценку с точки зрения читателя — пусть читатель решит, что понял, но на деле всё иначе»
- **Пассивное развитие**: ИИ умеет только описание среды + внутренний монолог, не умеет активно двигать сюжет
  - Исправление: в каждой главе не менее двух раз действие «персонаж сам делает необратимый выбор»
- **Слабая причинность**: ИИ видит лишь прямую причинность, игнорирует косвенное влияние и долгосрочные последствия
  - Исправление: после каждого крупного решения в следующей главе показывать хотя бы одно непредвиденное косвенное последствие
- **Пресная кульминация**: ИИ в кульминации нагромождает детали вместо сжатия напряжения
  - Исправление: в кульминационном абзаце удалить все необязательные описания деталей, оставить только действие + диалог + телесную реакцию

### Создание персонажей
- **Плоский характер**: есть только ярлык (добрый/холодный) без внутреннего противоречия
  - Исправление: у каждого ключевого персонажа должно быть противоречие «публичная позиция vs тайные истинные мысли»
- **Отсутствие арки персонажа**: персонаж остаётся неизменным на протяжении всего произведения
  - Исправление: в конце каждого тома персонаж теряет хотя бы одно (убеждение/отношения/способность/информационное преимущество)
- **Шаблонный образ**: ИИ склонен копировать распространённые типажи
  - Исправление: дать каждому персонажу «странную мелкую привычку» (например, главный герой-программист каждую неделю вручную делает резервную копию, исследователь ИИ боится высоты)

### Проектирование диалогов
- **Объяснительный диалог**: то, что говорит персонаж, служит для объяснения фона читателю
  - Исправление: диалог в первую очередь служит цели «что персонаж хочет выудить из собеседника»
- **Одинаковый тон**: все персонажи говорят в одном стиле
  - Исправление: дать каждому персонажу «слова, которые нельзя говорить» (запретные слова / избегаемые темы / предпочтение определённых конструкций)

## Правила контроля плотности технической информации (обязательно｜источник: исследование по избеганию «духа ИИ» §4.1)

Типичная проблема письма ИИ: потеря контроля плотности информации — либо сплошь пустая атмосфера, либо нагромождение технических терминов. Следующие правила служат для точного контроля:

- **Верхний предел доли технической информации**: чисто техническое объяснение — не более 15% общего объёма на тысячу знаков
- **Постепенное развёртывание**: запрещено с самого начала нагромождать понятия вроде квантовой запутанности / убыли энтропии сознания; сначала закреплять технический эффект воспринимаемым опытом персонажа, потом дополнять технический принцип диалогом/действием
- **Приоритет функциональной ориентации**: объясняя технологию, в первую очередь писать «что она умеет, как влияет на сюжет», а не «каков её принцип»

## Сводная таблица быстрых исправлений

| Проблема | Быстрый способ исправления |
|---|---|
| Злоупотребление компенсаторными словами («似乎» — казалось, «或许» — возможно, «仿佛» — словно) | Удалить компенсаторные слова, пусть суждение лежит в точке зрения персонажа |
| Обобщающая фраза впереди | Сначала писать действие/сцену, потом при необходимости добавить одну фразу-обобщение |
| Избыточные связки («因此» — поэтому, «然而» — однако, «不过» — впрочем) | Убрать связки, пусть причинность естественно проступает из порядка действий |
| Ровная длина фраз | Вмешать одну предельно короткую фразу (3–5 знаков), нарушить ритм |
