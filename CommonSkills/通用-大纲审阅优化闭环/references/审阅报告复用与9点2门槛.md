# Повторное использование отчёта рецензирования и порог 9,2

## Стратегия основного отчёта рецензирования

- В рамках одной задачи поддерживается только один основной отчёт
- Если в первом раунде его нет — создать новый
- После успешного создания основного отчёта все последующие повторные рецензирования обязаны перезаписывать и обновлять тот же путь
- Запрещено заводить для одной задачи параллельные отчёты, вызывающие расхождение формулировок

Режимов записи в первом раунде допускается только два:

- Найден существующий основной отчёт: `overwrite`
- Существующий основной отчёт не найден: `create`

## Правила нахождения отчёта

В первую очередь искать в `审阅意见/` существующий отчёт, соответствующий типу объекта плана, названию или номеру.

Если найдено несколько отчётов-кандидатов:

- По умолчанию брать с **самой свежей датой** в качестве текущего основного отчёта
- После фиксации основного отчёта все последующие раунды этой задачи обязаны перезаписывать и обновлять тот же путь
- Нельзя ради сохранения истории заводить параллельные отчёты «вторая версия / третья версия / исправленная версия»

## Порог оценки

- Условие остановки: **комплексные оценки двух независимых рецензирований подряд строго больше 9,2**
- Полный процесс между двумя раундами: **первый раунд рецензирования → построчная шлифовка на основе отчёта первого раунда → дополнительное независимое повторное рецензирование (над исправленной редакцией заново выполняется полное, строгое, независимое рецензирование)**
- `9.2`: не считается пройденным
- `9.3+`: только один раз считается пройденным порогом, но и после единичного прохождения нужно добавить раунд правки и независимого повторного рецензирования
- Закрыть и выйти разрешено, только если оценки обоих независимых повторных рецензирований строго больше 9,2
- Второе независимое повторное рецензирование должно быть **заново выполненным полным рецензированием текущей исправленной редакции**: нужно и проверить, существенно ли исправлены проблемы прошлого раунда, и заново найти новые проблемы, внесённые в этом раунде; нельзя подменять независимую оценку утверждением «по сравнению с прошлым раундом есть прогресс», нельзя пропускать звено поиска новых проблем

## Управление циклом

В каждом раунде записывать как минимум:

- Текущий раунд
- Текущая комплексная оценка
- Какие проблемы исправлены по сравнению с прошлым раундом
- Какие проблемы всё ещё не решены
- Переходить ли в следующий раунд
- Если в этом раунде оценка впервые строго больше 9,2: пометить «порог впервые пройден, переход к раунду проверки устойчивости», принудительно добавить один раунд правки и независимого повторного рецензирования
- Если два раунда подряд строго больше 9,2: пометить «порог устойчиво пройден, закрытие разрешено»

## Запрещённые действия

- Ослаблять стандарты оценки ради скорейшего завершения
- Прикрывать неисправленные пункты пустыми формулировками
- Завышать оценку без существенных улучшений
- Менять критерии рецензирования от раунда к раунду, из-за чего оценка выходит из-под контроля

## Минимальная квитанция в диалоге

В каждом раунде достаточно кратко указать:

- Текущий раунд
- Какой план прочитан / изменён
- Какой отчёт рецензирования перезаписан
- Комплексная оценка этого раунда
- Переходить ли в следующий раунд

Если используется как квитанция закрытия SOP, дополнительно как минимум нужно указать:

- Способ записи основного отчёта в этом раунде: перезапись / создание
- Достигнуты ли комплексные оценки двух независимых рецензирований подряд строго больше 9,2 (устойчивое прохождение порога)
