## Результат 1: Agents.md (обязательный результат, основной результат)

- **Путь**: `项目根目录/Agents.md`
- **Характер**: **обязательный результат**. Единственный критерий того, что этот Skill действительно завершён.
- **Содержание**: регистрация основной платформы вывода + настройки POV + путь к синей книге инициализации проекта (подробности см. в SKILL.md, «Модуль 8: создание файла конфигурации проекта Agents.md»)
- **Потребители**: автоматически находится ключевыми Skill `通用-创建小说正文`, `通用-章节创作闭环`, `通用-正文润色`, `通用-多平台输出编排` и др.

> Если `Agents.md` не создан, этот Skill считается незавершённым. Все нижестоящие Skill не могут автоматически адаптироваться к правилам платформы.

## Результат 2: синяя книга инициализации проекта (подробное обоснование решений)

Основания решений всех модулей сводятся в один единый файл: **`项目初始化/项目初始化蓝皮书.md`**.

### Структура файла (обязательно)

```text
# Синяя книга инициализации проекта

## 1. Выводы по калибровке рынка (четырёхчастная структура: процесс анализа → перечень оснований для решений → итоговое решение → вход для нижестоящих)
## 2. Привязка коммерческой логики (четырёхчастная структура)
## 3. Позиционирование эмоций читателя (четырёхчастная структура)
## 4. Каркас метасеттинга (четырёхчастная структура)
## 5. Схема сочетания паттернов-套路 (четырёхчастная структура)
## 6. Расстановка точек коммерциализации (четырёхчастная структура)
## 7. Выводы проверки осуществимости (четырёхчастная структура)
## 8. Перечень разрывов с конкурентами (матрица данных: по строке на каждого конкурента, сравнение по пяти измерениям)
## 9. Перечень элементов романа, которые лучше всего привлекают читателей и приносят больше всего денег (основной результат, четырёхчастная структура вывода, подробности см. `references/核心产出要素清单规格.md`)
## 10. Честные границы (сводная таблица всех неопределённых пунктов + общая оценка уверенности + декларация пробелов информации + декларация «против здравого смысла»)
```

### Стандарт исполнения каждой главы

- **① Процесс анализа**: цепочка рассуждений не менее 300 знаков. Ссылка не менее чем на 2 источника данных. Сравнение не менее чем с 1 отвергнутой альтернативой.
- **② Перечень оснований для решений**: перечислить 3–5 ключевых оснований, к каждому указать файл-источник и уровень уверенности.
- **③ Итоговое решение**: одной фразой сказать «что выбрано, от чего отказались, почему».
- **④ Вход для нижестоящих**: чётко указать, как это решение будет использоваться нижестоящими Skill.
- **Исключение для главы 9**: исполняется в формате таблиц/матриц, предписанном `references/核心产出要素清单规格.md`; четырёхчастная структура не нужна (цепочка анализа первых 8 глав — уже её «процесс анализа»).

### Три красные линии

- ❌ **Не допускается распределённый вывод по нескольким файлам**. Все главы пишутся в один файл.
- ❌ **Не допускается цепочка рассуждений менее 300 знаков в одной главе**. Глава из одного списка без анализа считается незавершённой.
- ❌ **Не допускается решение без указания источника**. Каждое решение должно указывать, из какого отчёта, какого конкурента или какого исследования оно взято.

### Как эту синюю книгу используют нижестоящие Skill

Путь к синей книге зарегистрирован через поле `## 项目初始化蓝皮书` файла `Agents.md`. Нижестоящие проектировочные Skill автоматически находят этот путь в `Agents.md`, загружают синюю книгу и по мере необходимости используют из неё главы:

| Нижестоящий Skill | Какие главы синей книги используются |
| --- | --- |
| `通用-设计总大纲` | Глава 1 (рыночное позиционирование), глава 4 (мир / система сил), глава 5 (сочетание паттернов), глава 9 (перечень элементов) |
| `通用-设计分卷大纲` | Глава 5 (реализация схемы сочетания паттернов), глава 9 (требования к ритму из перечня элементов) |
| `通用-设计人物传记` | Глава 4 (каркас персонажей), глава 9 (ключевые моменты инженерии персонажей) |
| `通用-设计故事设定` | Глава 4 (мир / система сил), глава 9 (ключевые моменты дизайна золотого пальца / правил) |
| `通用-撰写内容简介` | Глава 3 (обещание читателю / эмоциональная главная ось), глава 9 (слой позиционирования / стратегия хуков аннотации) |
| `通用-设计标题` | Глава 9 (направление названия) |
| `通用-生成章节控制卡` | Глава 3 (предустановка воронки из 7 барьеров), глава 6 (точки коммерциализации), глава 9 (требования к ритму) |
| `通用-平台签约评估框架` | Глава 7 (выводы проверки осуществимости), глава 8 (перечень разрывов с конкурентами) |

## Контрольные точки

### После завершения /init (решения по семи измерениям приняты)

- [ ] Решения по всем 7 модулям завершены?
- [ ] Результаты каждого модуля записаны в каталог `项目初始化/`?
- [ ] Выводы модулей 1–3 (слой жёстких ограничений) согласованы и без внутренних противоречий?
- [ ] Весь модуль 4 (метасеттинг) служит основной эмоции?
- [ ] В модуле 5 (адаптация паттернов) есть неизменное ядро логики + чёткое отображение адаптации?
- [ ] Модуль 6 (точки коммерциализации) покрывает два измерения: оплата + IP?
- [ ] Модуль 7 (проверка осуществимости): все четыре барьера пройдены?
- [ ] Перечень предупреждений о рисках составлен и снабжён стратегиями реагирования?
- [ ] **Модуль 8 (Agents.md) создан и заполнен с корректными названием платформы и настройками POV?**
- [ ] Внешние зависимые Skill вызваны согласно требованиям?

### Ретроспективная проверка инициализации (/init-check)

При ретроспективной проверке инициализации уже существующего проекта проверяются следующие вопросы:

- **Действителен ли ещё `Agents.md` в корневом каталоге проекта?** (По-прежнему ли верна основная платформа вывода?)
- На каком уровне сейчас слабое звено проекта? (слой жёстких ограничений / слой повествовательной основы / слой коммерческого исполнения / **слой регистрации проекта**)
- Не устарела ли адаптация к платформе? (правила платформы / популярность жанра могли измениться)
- Нужно ли обновить сочетание паттернов? (конкуренты могли применить более новые приёмы)
- Остаются ли в силе точки коммерциализации? (подтверждение данными: конверсия в оплату / время чтения и т. п.)
- Нет ли риска логического краха повествовательной основы? (система сил / отношения между силами / согласованность персонажей)
