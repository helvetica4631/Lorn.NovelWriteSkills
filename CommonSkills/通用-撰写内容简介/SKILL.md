## Аннотация как начало: принцип изоморфности аннотации и начала (новое)

> **Модель решения читателя при просмотре аннотации совпадает с моделью при просмотре начала — только аннотация является последним барьером «перед открытием».**

Основная логика аннотации и начала **изоморфна**:

| Измерение | Начало | Аннотация |
|------|------|------|
| Основная задача | За 3–5 секунд завладеть читателем | За 3–5 секунд заставить читателя «открыть» |
| Суть сделки | Менять знаки на внимание | Менять ещё более короткие знаки на действие «нажать» |
| Когнитивный разрыв | Создавать «если не читать дальше — потеряешь» | Создавать «если не открыть — потеряешь» |
| Демонстрация торговой точки | Дать читателю почувствовать ключевое достоинство этой главы | Дать читателю почувствовать ключевое достоинство всей книги |
| Аномалия межличностных отношений | Аномальные отношения цепляют больше всего | Аномалия отношений в аннотации тоже вызывает любопытство читателя |
| Информационный разрыв | Крючок — то, чего читатель не знает | Приоткрытая наполовину дверь эффективнее распахнутой настежь |
| Правило трёх фраз | Первые три фразы: вопрос + эмоция + вживание | Первые три фразы тоже должны совершить вопрос + эмоцию + вживание |
| Принцип среза | Брать мгновение высокого давления, а не обобщающее повествование | Брать сцену основного конфликта, а не нагромождение настроек |

> **Основной вывод**: хорошая аннотация = сжатая версия хорошего начала + обещание в масштабе всей книги. Самые частые недостатки плохой аннотации те же, что у плохого начала — превращение в описание настроек, обобщающее повествование, отсутствие когнитивного разрыва.

> **Связь с теорией порога терпения** (источник: `写作技法_黄金三章与黄金一章含金量提升研究.md` § 1.3, `网文留存模型.md`): терпение читателя = начальное ожидание − скорость расхода содержимого × время. Название книги определяет первую точку начального ожидания, аннотация — **вторую**: в последние 3–5 секунд «перед открытием» читатель по аннотации ещё раз калибрует «стоит ли тратить время на эту книгу». Сильная аннотация — высокое начальное ожидание, и окно терпения читателя к основному тексту дольше; слабая аннотация — терпимость к ошибкам в первом абзаце основного текста крайне низка.

### Позиция аннотации в системе хуков и трёхслойной воронке (новое — усвоение исследований письма 2026)

Проверенная сообществом **пятислойная система хуков** (источник: `社区验证的写作能力域框架.md` → пятислойная система хуков, обобщено Юньтяньхэ из сообщества Qimao #32138) определяет хук аннотации как слой ② всей книги:

| Слой | Определение | Обязанность этого Skill |
| --- | --- | --- |
| **① Хук названия** | Привлечь потенциальных читателей к клику | Выдаётся `通用-设计标题` |
| **② Хук аннотации/тегов** | Вызвать интерес к чтению — фон настроек + нынешнее положение + цель главной линии + противоречие и конфликт + хук торговой точки + развернутый финал | ✅ **Прямо выдаётся этим Skill** |
| **③ Хук начала** | Вызвать желание читать по главам — неожиданное событие + результат, соответствующий эмоциональному ожиданию | Принимается `通用-强化章节开头` |
| **④ Хук главной линии** | Движет общую историю, плотно привязан к основной достопримечательности, есть пространство для перетягивания | Принимается Skill проектирования плана |
| **⑤ Малый хук главы** | Концовка каждой главы двигает чтение по главам | Принимается `通用-强化章末钩子` |

Это полностью соответствует **трёхслойной воронке**:

```text
Слой 1: золотое название + золотая аннотация (3–5 секунд)    ← хук названия + хук аннотации (здесь поле боя этого Skill)
    ↓ Отфильтровывает неинтересующихся читателей, привлекает целевых
Слой 2: золотой абзац / золотая глава (150–300 знаков / первые 3 абзаца)  ← хук начала
    ↓ Создаёт когнитивный разрыв до того, как читатель пролистнёт
Слой 3: золотые три главы (6000–9000 знаков)      ← хук главной линии + малые хуки глав
    ↓ Завершает замкнутый цикл «подавление → накопление → первое высвобождение точки удовлетворения»
```

**Практический смысл**:
- Аннотация — не самостоятельный копирайтинг, а вторая входная дверь системы хуков всей книги — наверху она принимает обещание хука названия, внизу раскрывает пространство исполнения хука начала
- Главная миссия аннотации — не «ясно рассказать историю», а **за 3–5 секунд создать достаточно сильный импульс открыть**, чтобы читатель согласился перейти на второй слой (пробное чтение)
- Если хук названия не удался (читатель не зашёл), блестящая аннотация бесполезна; если аннотация не удалась (читатель зашёл и обнаружил несоответствие ожиданиям), то как бы хорошо ни было написано начало, читатель уже вошёл в пробное чтение с «разрывом ожиданий»

## Самопроверка GEO-дружественности аннотации (новое)

> В эпоху ИИ-поиска аннотация — не только «витрина» для читателей-людей, но и важнейший материал для цитирования, когда ИИ отвечает на вопрос «порекомендуй роман». После написания аннотации дополнительно сверить по следующему списку.

- [ ] **Блок метаданных в начале**: аннотация содержит структурированный блок из четырёх полей (название/жанр/торговая точка одной фразой/целевая аудитория), ИИ может прямо извлечь
- [ ] **Утвердительное изложение основного конфликта**: основной конфликт подан утвердительным предложением (а не чисто риторическим вопросом), ИИ может извлечь из него фактические описания
- [ ] **Естественное повторение ключевых слов**: жанровые ключевые слова названия естественно встречаются в тексте как минимум 1 раз, усиливая семантическую связь для ИИ
- [ ] **Формула целевой аудитории**: содержит формулу «подходит читателям, которым нравится ____» — изоморфна логике рекомендаций ИИ
- [ ] **Метка актуальности**: у серийных произведений отмечен статус и время начала (фильтр актуальности ИИ)
- [ ] **Независимая выдержка**: после удаления риторических вопросов и слов эмоций оставшаяся чистая информация по-прежнему способна самостоятельно составить читаемое описание

6. **Только для платформ, зарегистрированных в `Agents.md`, сжать язык по платформенной длине, усилить хук и распространяемые фразы**; для незарегистрированных платформ версии адаптации не генерировать.
7. Затем сохранить в файл по правилам независимого файла и обработать стратегию версий.
8. **В конце выполнить «самопроверку сути сделки»**: если читатель пролистнёт здесь, что он потеряет? Если ответ — «абзац фоновой справки» или «существительные настроек», вернуть на доработку и переписать.

## Справка по температуре модели по умолчанию (новое)

Для создания аннотации нужны умеренная креативность и языковое разнообразие, для аудита аннотации — устойчивая согласованная способность суждения.

| Этап | Рекомендуемая температура | Пояснение |
|---|---|---|
| Написание / переписывание аннотации | 0.55 | Нужна креативность, но не стоит уходить в сторону |
| Аудит существующей аннотации | 0.3 | Низкая креативность, сохранять устойчивость суждений |

## Общие напоминания по аннотации (новое — усвоение избранных материалов о начале с Zhihu)

- **Суть сделки**: после написания аннотации спросить себя — «если читатель пролистнёт здесь, что он потеряет?» Если ответ — «абзац фоновой справки» или «существительные настроек», вернуть на доработку.
- **Двигатель информационного разрыва**: аннотации не нужно ясно рассказывать историю, достаточно, чтобы у читателя возник конкретный вопрос («а потом?», «почему?», «кто это сделал?»). Этот вопрос и есть двигатель открытия.
- **Ощущение аномальности межличностных отношений**: аномальность отношений в аннотации («влюбиться во врага», «жена обнаружила тайну мужа») от природы несёт вопрос и эффективнее нагромождения событий.
- Аннотация по умолчанию в первую очередь сдаёт положение и эмоциональный консенсус, затем уже дополняет существительные настроек; если читатель сначала видит кучу имён собственных и не видит дилеммы персонажа — это сигнал провала.
- Основную торговую точку лучше сжимать в один главный хук «кто что теряет сейчас, что обязан делать, почему будет увязать всё глубже», а не в равномерное перечисление нескольких торговых точек.
- Если постоянное притяжение произведения построено на линии роста, линии отношений или смене личности, в аннотации хотя бы одна из них должна быстро ощущаться.
- Первые `1–2` фразы по умолчанию дополнительно несут задачу `30-секундной классификации`: чтобы редактор и читатель быстро поняли, что это за книга, в каком текущем тупике главный герой и что они получат, читая дальше.
- Если после прочтения аннотации по-прежнему ощущаются только существительные мироустройства, но не ощущаются положение персонажа, нынешнее давление и постоянное обещание, по умолчанию обрабатывать как «превращение в описание настроек» и вернуть на доработку.
## Базовая логика экономики внимания аннотации (новое — усвоение колонки Zhihu «Исследование китайской веб-литературы» № 36)

### Суть заработка — не в «хорошо написано», а в «перехвате внимания»

Суть заработка на написании романов никогда не «написать хорошее произведение», а **получить внимание → удержать внимание → монетизировать внимание**. Аннотация — самое передовое оружие в звене «получение внимания».

> Бутылка минералки в супермаркете стоит 2 юаня, в пустыне умирающему от жажды её продадут за 2000 юаней — и он заплатит. Вода не изменилась, изменилась интенсивность внимания этого человека в данный момент. Ваша аннотация — та самая бутылка воды в информационном потоке читателя: нужно, чтобы в миг, когда читатель скользнул взглядом, ему показалось «если сейчас не открою — потеряю».

### Позиция аннотации в цепочке внимания

```
Читатель листает вашу книгу (3 с) → смотрит название (1 с) → смотрит аннотацию (3–5 с)
  ↓ не открыл → ATLANTIS (трафик обнуляется)
  ↓ открыл → входит в пробное чтение
```

Ежедневно появляются десятки тысяч новых веб-романов, внимание читателей раздроблено играми, короткими видео, короткими сериалами, соцсетями. Ваша аннотация — лишь один из тысяч вариантов. В такой среде **у вас нет права требовать, чтобы читатель «терпеливо дочитал аннотацию, а потом решил»**.

### Три закона проектирования аннотации, ведомого вниманием

**Закон 1: название должно быть «прямым»**
В названии не нужно играть в глубокомыслие и изящество — у читателя нет времени гадать, что вы хотели сказать. Название обязано прямо сказать читателю: что это за жанр, какие точки удовлетворения, в чём основной конфликт. 《重生之xxxx》, 《系统让我xxxx》, 《xxxx打脸xxxx》 — пошло, но работает. Это и уважение к вашему труду: столько трудились над книгой, неужели не хотите оформить для неё хорошую витрину?

**Закон 2: первые 3 фразы аннотации создают «пик внимания»**
Кривая внимания достигает пика в первые 3 фразы, затем быстро затухает. Именно на пике нужно бросить самый сильный хук — конфликт, интригу, аномалию межличностных отношений. Не прятать самое сильное в середину или конец аннотации.

**Закон 3: обновлениями удерживать внимание (стадия серийной публикации)**
При стабильной частоте обновлений у читателей формируется мышечная память — в тот момент времени, если не зайти, кажется, будто чего-то не хватает. Аннотация отвечает только за «первое привлечение новых», а стабильность обновлений — за «превращение новых читателей в постоянных».

> **Практическая подсказка**: если вам лень даже хорошо написать аннотацию, значит, вы недостаточно уважаете своё произведение. Отложите литературную спесь и изучайте, как перехватывать внимание — это уважение к вашим десяткам и сотням тысяч знаков труда.
>
> Источник: колонка Zhihu «Исследование китайской веб-литературы» № 36 «Три слова „писать романы“ стоят миллион, многие этого не замечают», «Таверна Гули Мутуя»
> Уровень уверенности: высокий — метод экономики внимания — универсальная базовая логика, не привязана к конкретной платформе; эти законы основаны на универсальном экономическом принципе «субъективности ценности»

### Дополнение с точки зрения GEO: смена входа внимания в эпоху ИИ-поиска (новое)

Три закона экономики внимания в эпоху ИИ-поиска требуют дополнить одним ключевым изменением: **«вход внимания» читателя переходит от «самостоятельного поиска по рейтингам» к «рекомендации ИИ на основе структурированной информации»**.

Прежняя цепочка:
```
Читатель сам ищет → листает до названия → смотрит аннотацию → открывает пробное чтение
```

Новая цепочка в эпоху ИИ-поиска:
```
Читатель задаёт вопрос ИИ → ИИ рекомендует вашу книгу из структурированной информации → читатель открывает сразу
```

**Значение для проектирования аннотации**:
- Аннотация — не только «последний барьер перед открытием», но и «структурированный материал, по которому ИИ решает, рекомендовать ли»
- «Прямое название» (закон 1) в ИИ-поиске получает дополнительную ценность: название с жанровыми ключевыми словами легче семантически сопоставляется ИИ
- «Пик внимания в первых 3 фразах» (закон 2) так же важен для ИИ: при RAG-переранжировании ИИ в первую очередь берёт фрагменты с самой высокой плотностью информации и самой ясной структурой — это очень согласуется с потребностью в пике внимания у людей
- Формула «подходит читателям, которым нравится ____» в аннотации влияет на рекомендации ИИ даже больше, чем на читателей-людей

> Подробный анализ см. `../../写作研究/读者市场_GEO小说项目生成式引擎优化策略研究.md`.

## Формулировки вывода по умолчанию

- По умолчанию выдавать как минимум 1 основную версию аннотации, готовую к прямому использованию.
- В многоплатформенных сценариях по умолчанию дополнительно давать пояснение различий в длине или различий платформ, но **выдавать только версии адаптации для платформ, зарегистрированных в `Agents.md`**, для незарегистрированных платформ не выдавать.
- Если `Agents.md` не существует или в нём не объявлено ни одной платформы, выдавать только универсальную основную версию аннотации без различия платформ, пропустив все шаги платформенной адаптации.
- Если в заголовке аннотации, пояснении в тексте, метке версии или имени файла для сохранения нужно название произведения, единообразно использовать целевое название для публикации, соответствующее объекту этой сдачи.

## Иерархия каталогов сохранения в файл (обязательно)

- Рабочий каталог этого Skill по умолчанию фиксирован: `小说简介/`.
- Аннотации серии всей книги, части, тома единообразно сохраняются прямо в корень `小说简介/`.
- Аннотации глав разделяются по структуре романа: если у произведения есть части — единообразно в `小说简介/第X部/第Y卷/`; если частей нет — единообразно в `小说简介/第X卷/`.
- Имена файлов по-прежнему подчиняются правилам даты и номера версии, нельзя разбрасывать аннотации глав по побочным каталогам вроде `章节目录/简介/`.

## Минимальная поставка

- Как минимум 1 основная версия аннотации.
- Если задействовано несколько платформ, как минимум объяснить различия адаптации длинной / средней / короткой версий, но **число версий платформенной адаптации ограничено списком платформ, зарегистрированных в `Agents.md`**, для незарегистрированных платформ не сдавать.
- Уже в первых 1–2 фразах редактор и читатель быстро ощущают основную торговую точку, а не дочитывают весь абзац и по-прежнему видят только существительные настроек.
- Читатель обязан знать: кто, в какую передрягу попал, почему будет увязать всё глубже.

## Жёсткие правила

- Запрещено нагромождать существительные мироустройства без положения и конфликта.
- **Запрещена аннотация «формой плана»**: нагромождение лишь пунктов настроек и фоновой информации без одного конкретного ощутимого мгновения высокого давления — самая частая неудача аннотации, это тот же корень болезни, что и «обобщающее повествование» в начале. Аннотация обязана быть «срезом».
- Запрещено выдавать все развороты спойлером.
- Запрещено писать лишь пустые лозунги вроде «шестерёнки судьбы начали вращаться».
- Запрещено, чтобы аннотация обещала ложную торговую точку, которую основной текст вообще не вытянет.
- **Запрещено, чтобы аннотация лишь «классифицировала жанр», не делая «обещания торговой точки»**: если после прочтения аннотации читатель может сказать лишь «а, это роман про попаданца/саспенс», но не может сказать «что в этой книге конкретно необычного», значит, аннотация выполнила лишь функцию классификации, но не демонстрацию торговой точки. Хорошая аннотация при классификации должна давать «привлекательную точку, которой нет у других». Источник: `写作技法_黄金三章与黄金一章含金量提升研究.md` § 2.2 «„Демонстрация торговой точки“ приоритетнее всех приёмов».
- **Запрещено, чтобы обещание аннотации расходилось с обещанием названия**: название уже «заманило» читателя, аннотация обязана сразу дать читателю подтвердить «эта книга именно то, что я только что зашёл посмотреть» — а не выдавать историю совсем другого направления, чем в названии. После написания аннотации сверить с названием: если они никак не связаны, вернуть на доработку и переписать. Источник: там же.
- **Запрещено, чтобы первые 3 фразы были сплошь описанием настроек**: первые 3 фразы обязаны нести как минимум две из трёх задач «вопрос + эмоция + вживание». Если после первых трёх фраз читатель всё ещё не знает, «о чём заботиться», вернуть на доработку.
- Аннотация несегментированного романа единообразно использует целевое название романа для публикации; аннотация романа по частям единообразно использует целевое название соответствующей части, нельзя продолжать подставлять общее название книги вместо аннотации части.
- **Запрещено выдавать версии аннотации для незарегистрированных платформ**: любая платформа, не зарегистрированная в `Agents.md`, не должна появляться в результате сдачи платформенных версий аннотации. Если `Agents.md` не существует или не объявлено ни одной платформы, выдавать только универсальную основную версию аннотации, пропустив все шаги платформенной адаптации.
- Если пользователь явно не требует только набросать, нельзя давать аннотацию только в чате без файла.
