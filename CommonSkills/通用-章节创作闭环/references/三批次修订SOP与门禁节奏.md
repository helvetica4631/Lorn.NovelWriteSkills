# SOP трёх пакетов правок и ритм контроля доступа

> Источник рамок: `修订体系.md` / `经验总结.md`.

## Порядок пакетов (необратим)

```text
A (персонажи / хуки / диалоги) → B (закладки / золотой палец / сокращение) → C (веб-романизация / реквизит / стиль) → итоговая рецензия
```

> Запрещено перескакивать пакеты: пока A не завершён, в B не переходить; пока B не завершён, в C не переходить.

## Быстрое определение слоя источника пакета (новое)

- `Слой исполнения шагов`: в каком из пакетов A / B / C мы находимся на самом деле и действительно ли выполнены базовые действия этого пакета.
- `Слой вердикта контроля доступа`: пройден ли жёсткий порог пакета, какие поля всё ещё не пройдены.
- `Слой диспетчеризации доработки`: если порог не пройден, что дополнить в следующем раунде в первую очередь, на какой шаг вернуться и разрешено ли продолжать продвижение.

Порядок по умолчанию: сначала судить `слой исполнения шагов`, затем `слой вердикта контроля доступа`, в конце выдать `слой диспетчеризации доработки`; не писать сперва «переходим к следующему пакету», а потом обнаруживать, что контроль предыдущего пакета не пройден.

## Контроль доступа пакета A

- Охват хуком первых 200 знаков: цель 100 %.
- Охват оставленным хуком в последних 200 знаках: цель 90 %+.
- Доля диалогов: 25 %–55 %.
- Мотивация второстепенных персонажей: у каждого постоянного второстепенного персонажа должен быть самостоятельный сигнал мотивации.

## Контроль доступа пакета B

- Перечень закладок полон (закладка / состояние / окно возврата).
- В дуге золотого пальца есть «эскалация + цена + триггер».
- Непрерывный объяснительный абзац в 200 знаков нужно разбивать.
- Высокочастотные избыточные слова и звукоподражания нужно ограничивать по частоте.

## Контроль доступа пакета C

- В конце главы обязательно должен быть один из хуков: интрига / выбор / кризис.
- Важный реквизит должен образовывать дугу откликов через главы.
- Убирать метаповествование и ИИ-универсальные конструкции.
- Единообразие терминов для одного понятия.

## Рекомендации по ритму исполнения

- Каждые 3–5 глав делать быструю рецензию (число знаков / доля диалогов / охват хуков).
- При доработке нескольких глав подряд сначала править «структурный контроль доступа», потом «языковую фактуру».
- Журнал правок обязан фиксировать: пакет этого раунда, непройденные пункты контроля, следующее действие-патч.

## Минимальный артефакт пакета (новое)

```markdown
[Текущий пакет] A / B / C
[Слой исполнения шагов] завершён / не завершён
[Слой вердикта контроля доступа] непройденные пункты:
[Слой диспетчеризации доработки] следующее действие-патч:
【Текущая оценка】Green / Yellow / Red
```

## Вердикт по пакету Green / Yellow / Red (новое)

- `Green`: действия текущего пакета реально выполнены, контроль доступа пройден, можно переходить к следующему пакету.
- `Yellow`: основная часть текущего пакета сделана, но остаются `1–2` пункта контроля, которые надо дополнить; продвигаться осторожно.
- `Red`: шаги пакета реально не прогнаны до конца, ключевой контроль не пройден или действие доработки не прописано — запрещено объявлять переход к следующему пакету.
