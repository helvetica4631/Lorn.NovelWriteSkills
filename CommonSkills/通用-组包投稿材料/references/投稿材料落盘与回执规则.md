# Правила сохранения материалов для подачи в файл и квитанции

## Принцип сохранения по умолчанию

- Если пользователь явно не требует «только набросать, файлы не сохранять», результат обязательно записывается в репозиторий.
- В первую очередь вести формальные файлы, которые можно прямо смотреть и продолжать итерировать; нельзя оставлять полный пакет для подачи только в окне чата.

## Путь по умолчанию для пакета внутренней подачи на Qidian

- Корневой каталог произведения: `投稿材料/起点内投/《作品名》/`
- Индекс текущей версии: `投稿材料/起点内投/《作品名》/当前版本索引.md`
- Каталог версии этого раунда: `投稿材料/起点内投/《作品名》/vYYYY-MM-DD-rN/`

## Структура каталога версии по умолчанию

По умолчанию пакет внутренней подачи на Qidian больше не записывается в один файл; каждый раунд пакета для подачи должен попадать в отдельный каталог версии, рекомендуется как минимум включить:

1. `00_版本说明.md` (описание версии; авторский внутренний файл, необязателен, но настоятельно рекомендуется)
2. `01_内投版简介.md`
3. `02_内投版正文_至少30000字.md`
4. `03_内投版总大纲_至少5000字.md`
5. `04_内投版第1卷卷纲.md`
6. `05_组包自检.md` (самопроверка сборки; авторский внутренний файл, не отправляется вместе с рукописью)
7. `06_模板字段覆盖表.md` (таблица покрытия полей шаблона; авторский внутренний файл; в стандарте Qidian настоятельно рекомендуется)

Из них следующие `4` файла считаются фиксированными **внешними сдаваемыми**:

1. `01_内投版简介.md`
2. `02_内投版正文_至少30000字.md`
3. `03_内投版总大纲_至少5000字.md`
4. `04_内投版第1卷卷纲.md`

Если целевая платформа — Qidian (起点中文网) или платформа не указана и применяется критерий Qidian по умолчанию, то вывод о соответствии шаблону и таблица покрытия полей также считаются ключевыми доказательствами процесса; при отсутствии этого содержимого процесс считается незавершённым.

Рекомендации по сохранению:

- В `00_版本说明.md` разрешено писать только авторскую внутреннюю информацию, например вывод о соответствии шаблону, источники материалов, список отсутствующих файлов и действия по дополнению; **нельзя включать во внешние сдаваемые файлы**.
- `05_组包自检.md` по умолчанию в первую очередь использует `references/组包自检模板与风险矩阵模板.md` и обязательно помечается «авторский внутренний файл / не отправляется вместе с рукописью».
- Если соответствующий жанровый Skill уже предоставил жанровый `起点内投材料落盘模板.md` (шаблон сохранения материалов для внутренней подачи на Qidian), то поверх общей структуры в первую очередь применять жанровый шаблон.

## Красные линии внешней сдачи

- В файлах `01`–`04` и в любых `99_汇总导出件.md` (сводный экспортный файл) запрещены предложения с авторской самооценкой, самовосхвалением, анализом сильнейшего и слабейшего, комментариями об остаточных рисках, вероятностными суждениями, рекомендациями по подаче или суждением вместо редактора.
- `00_版本说明.md`, `05_组包自检.md`, `06_模板字段覆盖表.md` могут существовать только как авторские внутренние файлы, **нельзя отправлять редактору как вложения**.
- Если пользователь требует дополнительно экспортировать сводный файл, сводный файл может объединять только четыре внешних сдаваемых файла, нельзя вклеивать в него содержимое внутренних файлов.

## Необязательные формы экспорта

Если пользователь явно требует дополнительно экспортировать для редактора «единое вложение / сводный файл», его можно добавить в текущий каталог версии:

- `99_汇总导出件.md`

Но это лишь **дополнительный экспортный файл**; авторские исходные файлы по-прежнему обязаны сохранять систему каталогов версий, нельзя откатываться к «версии сборки в одном файле» как форме по умолчанию, а сводный файл не должен содержать содержимое внутренних файлов `00 / 05 / 06`.

## Стратегия версий по умолчанию

- Каждый раунд пакета для подачи по умолчанию создаёт новый подкаталог версии, не смешиваясь с историческими версиями.
- В `当前版本索引.md` обязательно явно указывать: текущий рекомендуемый для чтения номер версии, путь к версии, состояние файлов (четыре готовы / не хватает файлов / на доработке), время создания и краткое описание изменений.
- Обновлять с перезаписью в том же каталоге версии только если пользователь явно требует «продолжать править эту версию» либо текущий каталог версии изначально является единым сопровождаемым основным каталогом; иначе по умолчанию создавать следующую версию.
- Если в этом раунде всё ещё не хватает файлов или нужна доработка, это нужно заметно записать в `当前版本索引.md` и `00_版本说明.md`, но такое описание остаётся только в авторских внутренних файлах.

## Минимальная квитанция со стороны диалога

По завершении как минимум сообщить:

- В какой корневой каталог произведения, в какой каталог версии записано
- Обновлён ли `当前版本索引.md`
- В этом раунде перезаписана текущая версия или создана следующая
- Полны ли четыре внешних сдаваемых файла
- Какие файлы относятся только к авторской внутренней стороне и не должны отправляться вместе с рукописью
- Усвоены ли в этом раунде имеющаяся платформенная оценка / выводы рецензии
- Какие файлы или блоки ещё предстоит дописать / вернуть на доработку

## Нижняя граница завершённости

- Если нет реального сохранения в файл, формально не считается завершённым
- Если не созданы чёткие корневой каталог произведения, каталог версии и индекс текущей версии, формально не считается завершённым
- Если не пояснены путь сохранения и стратегия версий, квитанция неполна
- Если не пояснено, какие файлы внешние сдаваемые, а какие авторские внутренние, закрытие неполно
