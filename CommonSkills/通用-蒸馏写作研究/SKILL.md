## Ключевое различие

| | Шаблон стиля автора | Шаблон блюпринта произведения | Шаблон исследования письма |
| --- | --- | --- | --- |
| Источник дистилляции | Исходный текст реального автора | Исходный текст одного полного романа | **Отчёты по исследованию письма (тексты выводов)** |
| Способ дистилляции | Статистический анализ (распределение длины предложений и т. п.) | Статистический анализ (типы хуков и т. п.) | **Извлечение правил (перевод выводов исследования в исполнимые ограничения)** |
| Область действия результата | Ограничения стиля | Структурные ограничения | **Ограничения жанр × платформа (базовая линия по умолчанию)** |
| Приоритет | Выше исследования письма | Выше исследования письма | **Ниже явных указаний пользователя, выше универсальных значений по умолчанию** |

> **Предварительное чтение**: перед дистилляцией рекомендуется сначала прочитать `../../写作研究/网文留存模型.md`, чтобы понять количественную рамку базовой линии удержания, и `../../写作研究/GEO小说项目核心参考.md`, чтобы понять базовую рамку GEO и принципы видимости в ИИ-поиске; это нужно, чтобы выявлять в отчётах ограничения, связанные с удержанием и GEO.
>
> **Основная идея**: конечная цель дистилляции — не выдать список правил, по которому нижестоящие ставят галочки, а чтобы нижестоящие **усвоили «почему» за каждым правилом** — столкнувшись с новой ситуацией, не охваченной правилами, они смогут самостоятельно вывести верное решение для письма. Подробности см. в `references/约束提取方法论.md`.

## «Почему» ограничения — от внешнего подобия к внутреннему (обязательно)

Основная методология извлечения ограничений подробно в `references/约束提取方法论.md`. Ниже — жёсткие правила, которые необходимо соблюдать:

1. **Атрибуция «почему»**: к каждому жёсткому гейту и сильному ограничению обязательно добавлять корневую причину по психологии читателя; без атрибуции в итоговый шаблон не записывать.
2. **Воспроизводимость между отчётами**: только ограничения, на один принцип которых указывают ≥ 2 независимых отчёта, могут быть повышены до «принципов» и записаны в § 5 «Слой принципов».
3. **Порождающая сила слоя принципов**: после завершения дистилляции обязательно провести тест «вывод для новой ситуации», проверяя, что принципы и в новых ситуациях направляют верные решения.

## Извлечение ограничений для подражания

Когда дистилляция служит сценарию подражания, обязательно добавлять измерения извлечения, связанные с окном рынка.

**Основная методология** подробно в `references/仿写约束提取指南.md`. Ниже — жёсткие правила, которые необходимо соблюдать:

1. **Обязательная пометка происхождения**: во всех ограничениях типа «сейчас в тренде / остывает / ещё есть место» в источнике обязательно указывать дату публикации отчёта (`[2026年Q1]` / `[2025年]` / `[时效不明]` — «время неясно»).
2. **Три вопроса об интеграции материала**: при слиянии ограничений из нескольких отчётов обязательно пройти проверку тремя вопросами «единство темы, согласованность стиля, логическая самосогласованность»; не прошедшие — отбрасываются или помечаются как конфликтующие.
3. **Место результата**: ограничения окна подражания записываются в § 5-B (после § 5 «Слой принципов»).

## Результат и регистрация

### Выходной файл

```text
蒸馏产物/写作研究模板/[题材名]-[平台名]-写作研究模板.md
```

Правила имени файла: `[题材名]` (название жанра) извлекается из заголовка отчёта, `[平台名]` (название платформы) извлекается из заголовка отчёта. При объединении нескольких отчётов в названии платформы пишется «综合» (комплексный). **Полную структуру шаблона** см. в `references/写作研究模板格式定义.md`.

### Регистрация в Agents.md

В `Agents.md` в корне целевого проекта добавить запись регистрации (заголовки и ключи записи остаются китайскими — по ним нижестоящие Skill находят шаблон):

```markdown
### 写作研究模板 (шаблон исследования письма)
- 名称 (название)：[题材名]-[平台名]
- 路径 (путь)：蒸馏产物/写作研究模板/[题材名]-[平台名]-写作研究模板.md
- 蒸馏日期 (дата дистилляции)：YYYY-MM-DD
- 素材来源 (источники материала)：[N] шт. (отчёты исследований/отчёты разведки/страницы сетевого поиска)
- 提取约束数 (число извлечённых ограничений)：[N] (письмо [N] + структура [N] + персонажи [N] + запреты [N])
- 适用平台 (применимые платформы)：[番茄 / 起点 / 七猫 / ...] или 默认 (по умолчанию)
```

**Логика регистрации платформы** (обязательно выполнять): если при дистилляции отчёт естественно указывает на какую-то платформу, автоматически записывается соответствующее название платформы; если это комплексное межплатформенное исследование, пишется `默认` или список, указанный пользователем; если в `Agents.md` ещё нет основной выходной платформы, а платформа этого раунда ясна, рекомендовать пользователю её указать.

| **Phase 2.5** | Подтверждение слияния | Вывести сводку слияния (число оставленных/конфликты/кандидаты в принципы/охват атрибуции), переход к Phase 3 только после подтверждения пользователя |

### Граф зависимостей ограничений

На этапе слияния (Phase 2) необходимо выстроить три вида связей: **родительско-дочерняя** (одно — операционализация другого), **взаимодополняющая** (то же правило с разных сторон), **потенциальный конфликт** (на практике могут быть взаимоисключающими). Пример формата см. `references/约束依赖与版本漂移.md`.

### Обнаружение дрейфа версий

При обновлении шаблона обязательно выполнять обнаружение дрейфа: опровергнутые / усиленные / впервые добавленные / не охваченные. Пример формата см. `references/约束依赖与版本漂移.md`.

## Правила арбитража конфликтов трёх шаблонов

Когда шаблон исследования письма, шаблон стиля автора и шаблон блюпринта произведения одновременно действуют на одно поле:

| Сценарий конфликта | Порядок приоритета | Логика решения |
| --- | --- | --- |
| Одно поле ограничено всеми тремя шаблонами | Стиль автора > блюпринт произведения > исследование письма | Первичная статистика > структурная проверка > общее исследование |
| «Жёсткий гейт» исследования письма vs стиль автора | Приоритет у жёсткого гейта | Жёсткий порог платформы (например «в первых 300 знаках должен быть конфликт») перекрывает всё |
| «Сильное ограничение» исследования письма vs стиль автора | Приоритет у стиля автора | Общие рекомендации, не являющиеся жёсткими гейтами, уступают первичной статистике стиля |
| Конфликт платформенной чувствительности | Специализация под целевую платформу > межплатформенное универсальное | Если целевая платформа — Qidian, ограничение `[起点]` приоритетнее `[通用]` |

**Жёсткое правило**: решение о конфликте обязательно явно записывается в отчёт дистилляции; рядом с перекрытыми ограничениями помечается источник и причина перекрытия; если по-прежнему не удаётся определить, конфликт сохраняется для решения пользователем.

## Пояснение о потреблении нижестоящими Skill

Шаблон исследования письма, выпущенный этим Skill, нижестоящие Skill автоматически находят и потребляют через раздел «写作研究模板» в `Agents.md` в корне проекта.

**Правила приоритета**:
- Шаблон исследования письма даёт **базовую линию ограничений по умолчанию по жанру × платформе**
- Если пользователь явно указал шаблон стиля автора или блюпринта → приоритет у указанного пользователем, он перекрывает ограничения исследования письма по тому же полю
- Если пользователь ничего не указал → ограничения шаблона исследования письма действуют как жёсткие
- Если нет и шаблона исследования письма → откат к встроенным в Skill универсальным значениям по умолчанию

## Аудит соответствия ограничениям

> Полную таблицу измерений аудита, способ расчёта, формат отчёта и замыкающие действия см. в `references/约束符合度审计.md`.

Конечный критерий проверки шаблона исследования письма: **действительно ли основной текст/планы, выданные нижестоящими Skill по этим ограничениям, соблюдают каждое правило шаблона**.

### Момент аудита

Запускается тогда и только тогда, когда одновременно выполняются условия:
1. В текущем проекте уже есть **шаблон исследования письма**, прошедший проверку качества Phase 4
2. Нижестоящий Skill уже выдал готовый продукт, доступный для проверки
3. Пользователь явно требует аудит

### Методология аудита

Основа — **построчная таблица сканирования**: каждое ограничение шаблона исследования письма поочерёдно сверяется с выданным содержимым. Аудит градуируется по жёсткости ограничения: жёсткие гейты должны проходить на 100%, при непрохождении любого признаётся несоответствие.
