### Расширяемость — слой жанра

> **Проблема**: общие пулы 01-05 обслуживают сюжетное питание текущего романа. Но когда вы начинаете новый жанр (например, от городского офиса к детективу-расследованию), эмоциональные якоря/ритм/персонажи разных жанров сильно различаются, и смешение в одном пуле создаёт взаимные помехи. Более принципиально: **логика классификации 01-05 сама по себе родом из жанра женской городской романтики и подходит не для всех жанров.**

Поэтому перед созданием жанровой подбиблиотеки обязательно сначала выполнить проверку **гейта структурной адаптации**: определить, действительна ли общая классификация пулов для этого жанра, какие пулы нужно заменить, какие добавить.

---

#### Гейт структурной адаптации (обязательная проверка перед созданием жанровой подбиблиотеки)

> **Основной принцип**: жанровая подбиблиотека — не простая копия общих 6 пулов. У каждого жанра должна быть собственная система пулов, соответствующая особенностям его повествования.

**Метод проверки**: по каждому пулу ответить на следующие вопросы и записать решение «сохранить/заменить/отключить/добавить»:

| # | Название пула | Вопрос проверки | Решение | Причина |
|---|--------|---------|------|------|
| 01 | Пул сюжетных эпизодов | Охватывает ли логика классификации A/B/C (офисные коммерческие войны/внутрисемейные распри/продвижение отношений) в общем пуле основные типы конфликтов этого жанра? | Сохранить/заменить подклассы/отключить | — |
| 02 | Пул знаковых сцен | Есть ли в этом жанре «яркие моменты, которыми читатели могут делиться по скриншотам»? Совпадает ли ритм их эмоционального нарастания с общим пулом? | Сохранить/отключить | — |
| 03 | Пул настроек персонажей | Выходят ли типы персонажей этого жанра за рамки «босс-президент/героиня/антагонист/второстепенные»? | Сохранить/заменить подклассы/отключить | — |

| 05 | Пул холодного юмора и острого языка | Нужны ли жанру в больших количествах перепалки/острый язык/афоризмы? | Сохранить/отключить | — |

**Правила исполнения**:
1. Перед созданием жанровой подбиблиотеки обязательно сначала вывести таблицу гейта структурной адаптации с решениями по каждому пулу
2. Таблица гейта обязательно записывается в раздел «Решения по структурной адаптации» файла `题材名_索引.md` для последующих пополняющих
3. Отключённые пулы просто пропускаются (пустые каталоги-заглушки в жанровой подбиблиотеке не создаются)
4. Если позже выяснится, что первоначальное суждение таблицы гейта необоснованно, её можно пересмотреть и обновить запись в индексе

#### Условия запуска (после расширения)

При возникновении **любой** из следующих ситуаций на одном уровне с `素材库/` следует создать подбиблиотеку материалов `题材名/`:

**Условия по количеству** (исходное правило, продолжает действовать):
- Текущий проект переключается на другой жанр (например, с «городской офисной прозы» на «космическую фантастику»)
- Доля записей «не относящихся к текущему жанру» в общих пулах превышает 30% (пул разбавлен)
- Общий объём материалов одного жанра превышает 200 записей и продолжает быстро расти

**Условия по структуре** (новое правило):
- После проверки гейта структурной адаптации выяснилось, что **≥ 2 пулов требуют замены подклассов**, и степень замены превышает 50% от общего числа подклассов — значит, ось классификации общих пулов сместилась, чинить её на общем слое нецелесообразно, нужно сразу создавать жанровую подбиблиотеку
- Нужно добавить **≥ 1 тип пула, которого в нынешней системе 01-05 совсем нет** (например, научной фантастике нужен «архив настроек истории») — значит, общий слой не предоставляет места классификации по этому измерению
- **Ключевая повествовательная движущая сила** жанра отличается от той, под которую проектировались общие пулы (например, общие пулы спроектированы под «эмоциональный двигатель», а новый жанр — под «двигатель разгадки» или «двигатель исследования мира») — значит, система индекса эмоциональных якорей не универсальна

#### Вывод необходимых типов пулов для жанра

> При создании жанровой подбиблиотеки не копировать нумерацию общих 01-05, а выводить из особенностей жанра, «какие пулы нужны этому жанру».

**Измерения вывода**:

| Особенность жанра | Необходимый тип пула |
|---------|-------------|
| Конфликт зависит от внешних событий/дел | → Библиотека движков событий/дел (можно отобразить на 01 сюжет → заменить подклассы) |
| Конфликт зависит от межличностных отношений/эмоционального напряжения | → Библиотека продвижения отношений, библиотека конфликтов в диалогах (можно отобразить на 01C/01B) |
| Яркие моменты зависят от эмоционального взрыва/переворота/«пощёчины» | → Пул знаковых сцен (сохранить 02) |
| Яркие моменты зависят от когнитивного шока/мига разгадки/потрясения настройками | → Пул знаковых сцен (сохранить 02, но логику классификации заменить на «яркие моменты разгадки», «раскрытие настроек» и т. п.) |
| Персонажи — ключевая движущая сила | → Пул настроек персонажей (сохранить 03) |
| Персонажи — носители мироустройства (например, способности, киберимпланты) | → Пул настроек персонажей (сохранить 03, но добавить измерения полей способностей/имплантов) |
| Есть технологическая/правовая/системная структура, которую нужно поддерживать | → **Архив настроек истории** (добавить 06) — хранит технические принципы, пункты правил, цепочки процедур, носители улик |
| Есть повествовательная потребность в пространстве/сцене/атмосфере | → **Библиотека пространственных сцен** (добавить 06/07) — хранит сенсорные описания типичных пространств, списки атмосферы, пространственные сценарии |
| Нужна странная/потусторонняя/сверхъестественная атмосфера | → **Библиотека жуткой атмосферы** (новая) — хранит описания атмосферы, аномальные предвестники, сенсорные детали |
| Нужны систематизированные трюки/приёмы/загадки | → **Библиотека приёмов-трюков** (новая) — хранит детективные трюки, проектирование загадок, ложные ходы и расстановку зацепок |
| Нужно много острого языка/афоризмов/холодного юмора для регулирования ритма | → Пул холодного юмора и острого языка (сохранить 05) |
| Острый язык для регулирования ритма не нужен (серьёзный/угнетающий/академический стиль) | → Пул холодного юмора и острого языка (отключить) |

**Правила нумерации новых пулов**:
- Общие 01-05 остаются системой общего слоя, добавление жанрового слоя их не меняет
- Нумерация новых пулов в жанровой подбиблиотеке продолжается **с 06** (независимо от того, сколько пулов в общем слое)
- Пропуск номеров допускается, отсутствие в жанровом слое некоторых из 01-05 допускается (отключённые пулы просто опускаются, пустой номер не сохраняется)
- Нумерация заново объявляется в `_索引.md` жанра и не ссылается на нумерацию общего слоя

#### Правила жанровой подбиблиотеки

1. **Входной файл**: в каждой жанровой подбиблиотеке обязательно должен быть `题材名_索引.md`, формат по образцу `00_素材库总索引.md`, дополнительно включает раздел «Решения по структурной адаптации» (запись таблицы проверки гейта)
2. **Нумерация без префикса**: подфайлы жанровой подбиблиотеки не используют буквенный префикс (например `A_职场商战桥段.md`) — называются прямо по смыслу (например `跃迁引擎事故.md`), чтобы избежать конфликта с системой нумерации общих пулов
3. **Сначала смотреть подбиблиотеку**: при письме сначала смотреть подбиблиотеку текущего жанра, затем откатываться к общим пулам. Общие эпизоды, которых нет в жанровой подбиблиотеке, восполняются из общих пулов
4. **Регистрация после создания**: после создания жанровой подбиблиотеки её обязательно зарегистрировать в «реестре подбиблиотек материалов» в конце `00_素材库总索引.md` (путь + дата создания + список охваченных пулов)
5. **Индекс эмоциональных якорей становится частным для жанра**: индекс эмоциональных якорей ведётся отдельно в `题材名_索引.md`, больше не размещается в общем индексе, чтобы избежать порчи из-за смешения якорей разных жанров
6. **Общие пулы только растут, не убывают**: новые и отключённые пулы жанровой подбиблиотеки влияют только на операции с материалами этого жанра, общие пулы 01-05 всегда сохраняются без изменений

### Углубляемость — разделение файлов

> **Проблема**: при постоянном добавлении записей в один файл (например, 80+ записей про офисные войны, 100+ про холодный юмор) рано или поздно возникают трудности с поиском и падение производительности редактирования из-за слишком длинного файла.

**Порог разделения**:

| Метрика | Запуск разделения | Рекомендуемое действие |
|----------|---------|---------|
| Число записей в одном файле | Более **100 записей** | Разбить на подкаталог |
| Число строк в одном файле | Более **500 строк** (без пустых строк и разделителей) | Разбить на подкаталог |
| Число подклассов в файле | Более **5 заголовков второго уровня `##`** | Каждый заголовок второго уровня вынести в отдельный файл |

**Нормы операции разделения**:

Возьмём для примера текущий `A_职场商战桥段.md` (≈80+ записей, четыре подкласса A01-A04):

```text
До разделения:                  После разделения:
01_情节桥段池/                  01_情节桥段池/
├── A_职场商战桥段.md   →       ├── A_价格博弈与竞标/
│                               │   ├── _index.md        # индекс этого каталога
│                               │   ├── 01_沉默战术.md
│                               │   └── ...
│                               ├── B_会议对决与职场博弈/
│                               │   ├── _index.md
│                               │   └── ...
│                               └── C_行业声誉与危机管理/
│                                   ├── _index.md
│                                   └── ...
```

**Жёсткие правила разделения**:
1. **Сохранить входной файл**: исходный файл сохраняется как входной, содержимое заменяется индексом списка файлов этого каталога (формат `_index.md`), префиксы номеров записей в подфайлах остаются прежними
2. **Формат `_index.md`**:

```markdown
# [Название пула]

> **Исходный файл**: `原文件名.md` (разделён на подкаталог, YYYY-MM-DD)
> **Всего записей**: [N]

| Подфайл | Содержание | Число записей |
|--------|------|--------|
| 01_沉默战术.md | Ценовые игры и торговые противостояния | 20+ |
| 02_会议对决.md | Игры на совещаниях и офисные противостояния | 15+ |
| ... | ... | ... |
```

3. **Глобальная нумерация не меняется**: номера записей внутри подфайлов (например `A01-07`) наследуют систему исходного файла, заново не нумеруются
4. **Названия подкаталогов**: аббревиатура исходного заголовка второго уровня, не более 8 китайских иероглифов
5. **После разделения обновить общий индекс**: операцию разделения зарегистрировать в таблице «записи об изменениях структуры файлов» в `00_素材库总索引.md`

### Искомость — индекс эмоциональных якорей

> **Проблема**: материалы разбросаны по многим файлам многих пулов; при написании какой-то главы нужна «одна приятная сцена с пощёчиной», но неизвестно, в каком она пуле и файле.

**Решение**: в конце `00_素材库总索引.md` вести **сквозную по пулам таблицу индекса эмоциональных якорей**.

**Формат таблицы индекса эмоциональных якорей**:

```markdown
## Индекс эмоциональных якорей (情绪锚索引)

| Эмоциональный якорь | Пример записи (пул/номер/название) | Пул | Количество |
|--------|-------------------------|----|------|
| 爽 (удовольствие)  | 01A｜A01-01 用对手漏洞反制 (ответ на слабое место соперника) | Пул сюжетных эпизодов — офисные войны | 30+ |
| 爽 (удовольствие)  | 02｜F01 签字离婚 (подпись о разводе) | Пул знаковых сцен | 20+ |
| 心理战 (психологическая война) | 01A｜A01-03 沉默战术 (тактика молчания) | Пул сюжетных эпизодов — офисные войны | 15+ |
| 悬疑 (саспенс)   | 04｜D01-01 旧书里的合同 (договор в старой книге) | Пул лёгких саспенс-переворотов | 50+ |
| 毒舌 (острый язык)   | 05｜E01-01 女主→男主 (героиня → герой) | Пул холодного юмора и острого языка | 100+ |
| ...    | ...                       | ... | ... |
```

**Правила построения и ведения**:
1. **Первичное построение**: после каждого крупного пополнения помощник сканирует поля `**情绪锚**：` (эмоциональный якорь) в файлах всех пулов, суммирует с удалением повторов и записывает в эту таблицу
2. **Условие попадания записи в индекс**: в индекс попадают только эмоциональные якоря с частотой ≥ 3 (редкие якоря не стоят ведения)
3. **Момент ведения**: при каждом сохранении пополнения в файл + обновлении общего индекса одновременно обновлять эту таблицу
4. **В сочетании с поиском grep**: при письме в VS Code нажать `Ctrl+Shift+F` и искать по ключевому слову эмоционального якоря — можно найти записи сквозь пулы:

```text
# Пример: поиск всех материалов с меткой «心理战» (психологическая война)
Ctrl+Shift+F → grep: "情绪锚.*心理战" → путь: 素材库/
```

5. **Точный поиск на уровне пути**: если нужно ограничиться пулом:

```text
# Искать «证据» (улики) только в пуле саспенса
grep: "证据形态" → путь: 素材库/04_轻悬疑反转池/
```

6. **Индекс не синхронизируется в реальном времени**: записи материалов постоянно растут, индекс достаточно обновлять пакетно при каждой операции пополнения, не нужно синхронизировать при добавлении каждой записи

### Нормы формата ввода записей

Все записи в пулах материалов обязаны следовать следующей структуре полей. **Записи с недостающими полями в библиотеку не принимаются**.

| Поле | Обязательно | Пояснение | Пример |
|------|------|------|------|
| **Заголовок** | Да | Лаконичное название этой записи материала | «Ответ на слабое место соперника» |
| **Количество знаков** | Да | Ориентировочный диапазон объёма текста при разворачивании материала | «3000–5000 знаков» |
| **Эмоциональный якорь** | Да | Основная эмоциональная метка (удовольствие/боль/драйв/саспенс/слёзы/тайное удовольствие/психологическая война и т. п.) | «Профессиональное превосходство» |
| **Краткое содержание** | Да | 1–3 абзаца с описанием контура сюжета/сцены/конфликта | «На тендере соперник использует данные предыдущего клиента Су Тан, чтобы атаковать её…» |
| **Логика проектирования** | Рекомендуется | Почему этот материал эффективен, ключевой замысел | «Молчание — самое сильное оружие переговоров: пусть соперник не выдержит первым» |
| **Подходящая грань истории** | Рекомендуется | Какой грани истории/M0/линии X соответствует | «X01 линия карьеры» |

В записи пула знаковых сцен **дополнительно обязательно** поле **афоризм** — «ключевая реплика или авторская ремарка, которой читателю захочется поделиться в ленте друзей по скриншоту».

### Перед пополнением обязательна диагностика нехватки

Перед любым действием по пополнению обязательно сначала прочитать `00_素材库总索引.md` и проверить направления нехватки:

1. **Сравнение плотности материалов**: сопоставить текущее число записей в пулах с «целевой плотностью материалов по томам», заявленной в общем индексе, найти пулы ниже целевой плотности
2. **Пробелы в направлениях покрытия**: в таблице «покрытие крупномасштабного поиска этого раунда» общего индекса записаны уже охваченные направления; неохваченные направления — пробелы поиска
3. **Проверка журнала поиска**: прочитать записи поиска в `搜索日志/`, подтвердить, делали ли уже поиск по какому-то направлению и каково качество
4. **Проверка пустых пулов**: проверить, не пусты ли файлы пулов или не хватает ли записей (например, текущий `03_人物设定池/` пуст)

Получив список нехватки, затем планировать порядок пополнения и стратегию поиска.

### Парадигма сетевого поиска

При пополнении материалов стратегия поиска различается по типу пула материалов:

| Тип пула | Рекомендуемое направление поиска | Сочетания ключевых слов |
|--------|-------------|-----------|
| Сюжетные эпизоды (01) | Искать по типу сцены/конфликта | "职场商战 经典谈判桥段 应对刁难 反转" |
| Знаковые сцены (02) | Искать по эмоциональному якорю | "打脸名场面 爽文 高光时刻 女主逆袭 社交传播" |
| Настройки персонажей (03) | Искать по образу/статусу | "霸总人设 经典性格 大佬细节描写 反派模板" |
| Саспенс-перевороты (04) | Искать по типу приёма | "轻悬疑 反转手法 真相揭露 伏笔回收 合同谜团" |
| Холодный юмор (05) | Искать по полу/статусу | "女主毒舌金句 怼人 冷幽默 女频嘴炮" |
| Разбор конкурентов | Искать по платформе + жанру | "起点 女频 总裁文 追妻火葬场 爆款 结构拆解" |

- Каждый поиск нужно записывать в `搜索日志/` (формат см. ниже)
- Каждый результат поиска должен быть очищен до стандартного формата материала, прежде чем попасть в библиотеку
- Нельзя прямо вставлять исходный текст результатов поиска в качестве записи материала (нарушение «норм формата ввода записей»)

### Общий индекс обязательно обновляется синхронно

После каждого сохранения пополненного материала в файл обязательно обновлять `00_素材库总索引.md`:

- Обновить счётчик «записей материалов» соответствующего пула
- В таблицу «покрытие поиска этого раунда» добавить направление поиска этого пополнения и число полученных записей
- Обновить «дату обновления» на сегодняшнюю

### Журнал поиска обязательно ведётся синхронно

После каждого выполнения сетевого поиска обязательно дописывать строку записи поиска в соответствующий файл в `搜索日志/` в следующем формате:

```text
| [№] | [Ключевые слова поиска] | [Инструмент поиска] | [Число полезных результатов] | [Примечание] |
```

Если объём поиска велик, можно создать в `搜索日志/` инкрементальный файл вроде `03_搜索素材汇总.md`, но обязательно объявить его в общем индексе.

### Гейт качества ввода записей

Каждая запись материала перед сохранением в файл обязана пройти следующую самопроверку:

- [ ] Поля полны (заполнены как минимум заголовок + количество знаков + эмоциональный якорь + краткое содержание)
- [ ] В кратком содержании есть ощущение картинки: не абстрактное понятие, а сцена, которую читатель может сразу представить
- [ ] Эмоциональный якорь чёток: читатель знает, какого эмоционального ожидания ему ждать после прочтения
- [ ] Есть различимость: не шаблонное описание «и так понятно», а с конкретными деталями/переворотом/афоризмом
- [ ] Не совпадает с уже имеющимися записями того же пула (проверить файлы того же пула)
- [ ] Эмоциональный якорь/оценка количества знаков разумны (отклонение оценки знаков не более 30%)

## References для дальнейшего чтения (гейт обязательного чтения)

**Перечисленные ниже файлы references обязательно читать по одному через инструмент `read_file`; нельзя пропускать ни один под предлогом «знания уже есть», «в прошлый раз уже читал» или «этот файл — всего лишь справка».** Каждая запись references выполняется принудительно по указанному для неё уровню обязательности чтения:

- Файлы с пометкой **обязательно читать**: их нужно прочитать, пропуск хотя бы одного считается нарушением процесса, начинать выполнение процесса нельзя.
- Файлы без пометки «обязательно»: их нужно прочитать, но после прочтения можно извлечь только фрагменты, прямо относящиеся к текущей задаче, построчное прочтение не требуется.
- Если файла по указанному пути не существует (например, внешний путь не подготовлен), в журнале обязательно явно записать `reference_missing_{refName}`, молча пропускать нельзя.

При срабатывании задач пополнения библиотеки материалов, помимо этого файла, **обязательно продолжить чтение**:

- `references/各池条目录入模板.md` — шаблоны ввода записей и примеры, специфичные для каждого пула
- `references/缺件诊断检查表.md` — полный список проверки диагностики нехватки и формат стандартизированного результата
- `references/搜索日志记录模板.md` — формат записи журнала поиска и определения полей
- `00_素材库总索引.md` — общий индекс библиотеки материалов (читается в каталоге выполнения)
- `CommonSkills/写作研究/写作技法_网文作者素材库构建完全指南.md` — справочная философия и методологический фон построения библиотеки материалов (загружать, когда пользователь ставит под сомнение или отклоняется от методологии)

**Разделы этого файла, затрагивающие архитектуру библиотеки материалов** (при выполнении повседневного пополнения без изменения архитектуры перечитывать не обязательно):
- `Расширяемость — слой жанра` (включая гейт структурной адаптации, вывод необходимых типов пулов жанра, гибкую структуру подбиблиотеки)

  - **Точка касания S6 (предпочтения при выборе образцов)**: когда автор раз за разом выбирает в библиотеке материалов один тип материалов (или прямо указывает направление), вести «запись выбора»; после ≥ 2 однотипных раз по четырёхчастной схеме задать 1 вопрос «почему ты всё время берёшь этот тип материалов? что ты хочешь, чтобы увидел читатель?» → ответ в библиотеку образцов (S6) + слой предпочтений материалов

## Процесс выполнения

### Шаг 1: диагностика нехватки

Если пользователь явно указал цель пополнения, перейти к шагу 2.

Если пользователь не указал, выполнить диагностику нехватки:

1. Прочитать `00_素材库总索引.md` в каталоге выполнения
2. Прочитать файлы всех пулов, проверить соответствие фактического числа записей заявленному в общем индексе
3. Проверить, не пусты ли такие пулы, как `03_人物设定池/`
4. Проверить в `搜索日志/` уже охваченные направления и пробелы
5. Вывести отчёт о нехватке (формат см. `references/缺件诊断检查表.md`), представить пользователю на подтверждение

### Шаг 2: подтверждение пользователем направления пополнения

После показа отчёта о нехватке подтвердить с пользователем:

```
Предложение по направлению пополнения:
├── Приоритетно пополнить: [название пула] — [конкретное недостающее направление]
├── Целевое число записей: [N]
├── Ключевые слова поиска: [предварительные ключевые слова поиска]
├── Охват эмоциональных якорей: [список типов эмоций]
└── Подтвердить / скорректировать?
```

### Шаг 3: целевой поиск

1. По подтверждённому направлению пополнения выполнить сетевой поиск
2. Очистить результаты поиска, выделить пригодные записи
3. После каждого выполненного поиска сразу записывать в журнал поиска

### Шаг 4: форматирование записей и сохранение в файл

1. Очищенные записи по стандартному формату записать в файл соответствующего пула
2. Ссылаться на номера уже имеющихся записей того же пула (если есть преемственность, например `A01-06 基于A01-01的变体` (вариант на основе A01-01))
3. Новые записи используют сквозную нумерацию внутри пула

### Шаг 5: обновление общего индекса

1. Обновить счётчик материалов в `00_素材库总索引.md`
2. В таблицу «покрытие поиска этого раунда» добавить направление поиска и результат этого пополнения
3. Обновить таблицу «индекс эмоциональных якорей» общего индекса (суммировать с удалением повторов эмоциональные якоря новых записей, с частотой ≥ 3 — в индекс)
4. Обновить «дату обновления» общего индекса

### Шаг 6: архивация журнала поиска

1. Если объём поиска в этот раз < 10: дописать в уже имеющийся файл журнала в `搜索日志/`
2. Если объём поиска в этот раз ≥ 10: создать `搜索日志/NN_增量搜索_YYYYMMDD.md` и одновременно объявить в общем индексе

### Шаг 7: итоговая сводка

Представить пользователю итоговую сводку по этому пополнению:

```text
## Сводка пополнения
- Целевой пул: [название пула]
- Пополнено записей: [N]
- Охваченные эмоциональные якоря: [список эмоциональных якорей]
- Раундов поиска: [N]
- Источники поиска: [сводка источников]
- Общий индекс обновлён: да/нет (включая обновление индекса эмоциональных якорей: да/нет)
- Журнал поиска архивирован: да/нет (путь)
- Изменения подбиблиотеки материалов: создана новая/без изменений
```

### Шаг 8: регистрация жанровой подбиблиотеки и регистрация структуры (только при создании нового)

Выполняется после создания жанровой подбиблиотеки по правилу «Расширяемость — слой жанра»:

**Предварительный шаг 8a: выполнить гейт структурной адаптации**
1. По «гейту структурной адаптации» по каждому пулу принять решение, вывести таблицу решений по структурной адаптации (сохранить/заменить/отключить/добавить)
2. Записать таблицу решений в раздел «Решения по структурной адаптации» файла `题材名_索引.md`
3. По таблице решений создать реальные каталоги — создавать только пулы «сохранить» и «добавить», отключённые пулы не занимают места

**Шаг 8b: регистрация в общем индексе**
1. Зарегистрировать одну строку в «реестре подбиблиотек материалов» в конце `00_素材库总索引.md`
2. Формат следующий:

```text
| [Название жанра] | [Название жанра]_索引.md | YYYY-MM-DD | сюжетные эпизоды/знаковые сцены/настройки персонажей/саспенс/[отключён]/разбор конкурентов/журнал поиска | 06_故事设定档案库(новый) |
```

**Шаг 8c: создание файла индекса жанра**
1. Создать `题材名_索引.md`, формат совпадает с `00_素材库总索引.md`
2. Дополнительно включить раздел «Решения по структурной адаптации» (запись таблицы проверки гейта)
3. Индекс эмоциональных якорей ведётся в этом файле отдельно, в общий индекс не попадает

## Различия типов пулов

### 01_情节桥段池 (A/B/C)

- Каждая запись обязана содержать чёткий эмоциональный якорь — эмоцию, которую читатель ожидает после прочтения этого отрывка
- Краткое содержание обязано включать конкретных персонажей, сцену, противника, конфликт, поворот
- Логика проектирования необязательна, но рекомендуется — объяснить, почему этот эпизод эффективен

### 02_名场面高光池 (F)

- Дополнительное обязательное поле: **афоризм**
- Знаковая сцена должна достигать эффекта уровня распространения «читателю хочется сделать скриншот и поделиться в ленте друзей»
- Приоритетно собирать три класса: «ответный удар-пощёчина», «слёзы чувств», «потрясение переворота»

### 03_人物设定池

- Сейчас это пустой пул, при первом наполнении использовать следующую структуру подклассов:

```text
03_人物设定池/
├── A_霸总人设.md
├── B_女主设定.md
├── C_反派模板.md
├── D_配角原型.md
└── E_人物关系动态模板.md
```

- Формат записи персонажа (отличается от сюжетных записей):

| Поле | Пояснение |
|------|------|
| **Метка образа** | Основная точка запоминания (например «даос, предельно чтущий даосские заповеди») |
| **Глубинное желание** | Основная потребность, движущая этим персонажем |
| **Ключевое противоречие** | Его/её основной конфликт с внешним миром или с собой |
| **Контрастные детали** | Контрастное поведение, делающее персонажа объёмным |
| **Особенности голоса** | Фирменная манера говорить, словесные привычки |
| **Подходящая грань истории** | Каким граням истории/линиям X может служить |

### 04_轻悬疑反转池 (D)

- Каждая запись должна содержать чёткую логическую цепочку «обнаружение → выведение → раскрытие»
- Детали должны включать конкретную форму улики (предмет/документ/фото/аудиозапись/аномалия поведения и т. п.)
- Переворот не может опираться на «совпадение», должна быть разумная предварительная подготовка

### 05_冷幽默毒舌池 (E)

- Каждая запись должна подходить под сцену статусных отношений целевого персонажа (в адрес героя/в адрес светлой лунной любви/в адрес злой второстепенной и т. п.)
- Критерий афоризма: умно, но не зло; остро, но не ранит; серьёзно доведённая до абсурда мысль
- Приоритетно собирать диалоговые наборы, которые можно «ударить тройкой» — не изолированную фразу, а диалоговую комбинацию с обменом репликами

### Разбор конкурентов

> В каталоге разбора конкурентов хранятся черновики анализа всего произведения, это **не** записи материалов, которые можно брать напрямую.
> Повторно используемые эпизоды, приёмы, афоризмы, извлечённые из разбора конкурентов, после очистки должны быть отнесены в соответствующие пулы материалов 01-05.
> Если нужно прямо создавать записи материалов, использовать Skill «通用-分析竞对作品».

- Записи имеют двухчастную структуру «абзац оригинала + разбор»
- Разбор должен включать: какой приём использовал автор, почему этот отрывок цепляет, что можно позаимствовать
- Не копировать целиком, а отбирать «фрагменты повторно используемых приёмов»
