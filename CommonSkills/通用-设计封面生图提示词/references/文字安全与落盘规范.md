# Безопасность текста и нормы сохранения в файл

## Фиксированные жёсткие ограничения

- Обложка по умолчанию — **вертикальная обложка романа**
- Рекомендуемое вертикальное соотношение по умолчанию: `3:4`
- Главный заголовок обложки должен использовать название книги, определённое по формулировке для публикации, и сохраняться в точности, нельзя самовольно переписывать, сокращать или переименовывать
- Главный заголовок должен быть самым крупным и самым заметным текстом на картинке
- Имя автора должно быть заметно меньше главного заголовка и появляться как вторичная информация
- Нельзя добавлять логотип платформы, логотип APP, водяные знаки, QR-коды, угловые рекламные слоганы
- Нельзя делать в стиле киноафиши, игнорируя читаемость обложки книги

## Формулировка названия книги на обложке (обязательно)

- Несегментированный роман: главный заголовок обложки всегда использует целевое название романа для публикации.
- Роман по частям: главный заголовок обложки всегда использует целевое название соответствующей части.
- Если в контексте одновременно встречаются общее название, название части, платформенное название для публикации и внутреннее рабочее название, ориентироваться на фактическое название для публикации на целевой платформе в этот раз.
- В основном промпте, пояснении по вёрстке и ограничениях безопасности текста в рамках одного комплекта вариантов `书名` (название книги) везде означает указанную выше формулировку главного заголовка обложки, переключаться туда-сюда нельзя.

## Правила имени автора по платформам

- Имя автора на китайских платформах по умолчанию: `产品经理独孤虾`
- Имя автора на английских платформах по умолчанию: `lornshrimp`
- Если пользователь явно не просит, самовольно переписывать указанные имена автора нельзя

## Правила безопасности текста (обязательно)

- На картинке разрешены **только запланированные текстовые элементы**
- По умолчанию запланированный текст обычно только: главный заголовок обложки (определяется по формулировке целевого названия для публикации) + имя автора
- Если пользователь явно дал `plannedText`, разрешён только этот дополнительный текст
- Слова жанра, слова эмоций, слова торговых точек, слова визуальной цели нужно переписывать как: сцена, предмет, состояние персонажа, свет и тень, требования композиции — их нельзя писать так, чтобы модель могла переписать их на картинку как лишние надписи
- Кроме запланированного текста, запрещено заключать описательные фразы в кавычки, названия-скобки, выделяющие знаки или выносить в отдельную строку и затем засовывать в основной промпт

## Опасные формулировки, в которые легко ошибочно попасть

- `突出“危险”“禁忌”“职业”`
- `画面写上“规则感”`
- `背景出现题材关键词`
- `传达“谁要先死”的感觉`

Всё перечисленное нужно переписывать как требования к изображению, а не как требования к тексту.

## Шаблоны безопасной переформулировки

- `整体气质偏冷、规则感强、职业化、异常压迫感明确，但这些信息只通过场景、物件和人物状态体现，不以额外文字出现`
- `除已规划文字外，不要出现任何其他汉字、英文单词、标语、标签、UI字样`
- `用场景与物件传达题材识别度，而不是增加额外文字元素`

## Шаблон написания основного промпта (обязательно)

### Китайские платформы

- Когда нет дополнительного запланированного текста для картинки:
  - `除主标题《目标投放名》与作者名外，画面中不要出现任何其他可读文字，包括汉字、英文、数字、标语、标签、界面字、背景字、漂浮字。`
- Когда есть дополнительный запланированный текст для картинки:
  - `除主标题《目标投放名》、作者名以及以下计划入画文字外，画面中不要出现任何其他可读文字：{plannedText 列表}。`

### Английские платформы

- Когда нет дополнительного запланированного текста для картинки:
  - `No readable text in the image except the exact target release title and the author name.`
- Когда есть дополнительный запланированный текст для картинки:
  - `No readable text in the image except the exact target release title, the author name, and these explicitly planned text elements: {plannedText list}.`

### Патч для абстрактных обобщающих фраз

Если в основном промпте появляются абстрактные обобщающие фразы о торговых точках, обязательно добавить одну фразу:

- `这些信息只通过画面呈现，不以额外文字出现。`

## Минимальные требования к формату вывода

Каждый вариант должен содержать как минимум:

1. Оценка платформы
2. Краткое описание направления обложки
3. Основной промпт
4. Negative Prompt
5. Пояснение по вёрстке

По умолчанию выдаются 2 варианта:

- `方案A`: ориентация на массовый хит платформы
- `方案B`: ориентация на дифференциацию / фактуру

## Минимальные пункты Negative Prompt

Negative Prompt каждого варианта должен охватывать как минимум:

- низкая чёткость / blurry / low detail
- искажённый текст-абракадабра
- любой дополнительный текст, кроме запланированного
- плавающий текст / текст на фоне / слоганы / надписи UI / тексты на ярлыках
- лишние персонажи
- лишние руки и пальцы
- разрушенные черты лица
- чрезмерная кровавость
- logo / watermark / QR code
- busy composition / cluttered background

## Требования к сохранению в файл по умолчанию

- Результат по умолчанию нужно оформить в файл Markdown и сохранить, а не оставлять лишь в показе в чате
- Каталог сохранения по умолчанию: `小说简介/`
- Рекомендуемое имя файла по умолчанию:
  - Одна платформа: `《目标投放名》{平台名}封面生图提示词_vYYYY-MM-DD-r1.md`
  - Несколько платформ: `《目标投放名》{平台A}与{平台B}封面生图提示词_vYYYY-MM-DD-r1.md`
- Если за тот же день уже есть файл с тем же именем, увеличить номер версии `rN`, старую версию не перезаписывать
- Если на этот раз только правится существующий вариант, тоже в первую очередь создавать новую редакцию, не перезаписывая старый черновик

## Принцип минимальных уточняющих вопросов

Уточняющие вопросы задавать только если следующую информацию совершенно невозможно определить из контекста или рабочего пространства:

1. Целевая платформа
2. Целевое название для публикации (если у произведения есть части — целевое название соответствующей части)
3. Визуальные элементы, которые обязательно должны присутствовать / которых обязательно нужно избегать

Кроме этого, в первую очередь сразу приступать к работе.

## Критерии успеха

- Тон платформы определён верно
- На миниатюре сохраняется узнаваемость
- Иерархия главного заголовка и имени автора ясна
- Кроме запланированного текста, нет случайно попавшего лишнего текста
- Основной промпт можно скопировать прямо в модель генерации изображений
- По умолчанию уже есть структура сдачи, пригодная для сохранения в файл
