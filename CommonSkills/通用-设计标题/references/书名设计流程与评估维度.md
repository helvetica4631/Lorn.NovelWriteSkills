# Процесс проектирования названия и измерения оценки

## Применимые задачи

- Проектировать заголовки для всего романа, части или тома.
- Проектировать многоплатформенные названия для одного произведения.
- Переделывать, переставлять, пересматривать существующие варианты названий.
- Из большого числа кандидатов сужать shortlist.

## Правила входных данных по умолчанию

В приоритете автоматически извлекать из текущей сессии, текущего редактируемого файла и материалов рабочей области; задавать минимально необходимые вопросы только когда продолжать действительно невозможно.

### Обязательный вход

- Название произведения (если уже есть)
- Уровень проектирования: `вся книга / часть / том`
- Целевая платформа: по умолчанию все платформы
- Число кандидатов: по умолчанию 10 на каждую платформу

### Необязательные параметры

- `scope`: `вся книга / часть / том`
- `platforms`: подмножество платформ
- `countPerPlatform`: число кандидатов на платформу
- `styleBias`: `коммерческий клик / репутационная фактура / издательская рецензия / зарубежное распространение`
- `outputMode`: `полный вариант / shortlist / финальная версия`
- `overwriteCurrentFile`: перезаписывать ли файл текущего варианта
- `withRubric`: включать ли Rubric оценки названия (по умолчанию включено)

## Обязательное предварительное чтение контекста

Перед началом проектирования обязательно прочитать или найти материалы рабочей области, непосредственно связанные с названием; нельзя придумывать названия с потолка.

Приоритетный порядок:

1. Платформенные исследовательские документы в `写作研究/`
2. `小说大纲/小说总大纲.md`
3. `小说大纲/故事多面体大纲.md`
4. `小说大纲/分卷故事面推进表.md`
5. `小说大纲/伏笔与呼应总纲.md`
6. `小说大纲/线索台账.md`, `嫌疑池台账.md`, `时间轴（总）.md`
7. Если уже есть файл варианта названий, обязательно прочитать его, сначала разобрать старые проблемы, затем переделывать

Если пользователь просит только заголовки одного тома или одной части, особое внимание на соответствующие материалы тома / части, не нужно заново разворачивать весь общий план.

## Размышления, которые обязательно завершить перед формальным выводом

### Контроль доступа глобальной дедупликации между платформами (обязательно выполнить перед выводом, нельзя пропускать)

Перед записью таблицы кандидатов в любой вывод обязательно сначала выполнить следующие шаги:

1. Свести заголовки-кандидаты всех платформ в один глобальный перечень.
2. Сопоставить по пунктам, найти полностью совпадающие заголовки между любыми двумя платформами.
3. Для каждого повтора заново сгенерировать другой заменяющий заголовок для повторно встретившейся платформы, пока в глобальном перечне не останется ни одного повтора.
4. Заменяющий заголовок не может быть лишь сменой знаков препинания, замены одного знака или перестановкой слов; он обязан происходить от другого материнского ядра или использовать другую форму именования.
5. После дедупликации итоговое число выводимых заголовков должно строго равняться числу платформ × числу кандидатов на платформу и не содержать никаких повторов.

> **Запрещено пропускать этот шаг**: даже если субъективно «кажется, что платформы уже различаются», всё равно обязательно механически выполнить сводное сопоставление, нельзя пропускать по впечатлению.

### Сначала схватить четыре основных слова

1. Слово тега жанра
2. Слово профессии / идентичности главного героя
3. Слово опасности / правила / аномалии
4. Слово тона, предпочитаемого целевой платформой

### Затем выделить материнское ядро заголовка

Выполнить как минимум следующие действия:

1. Выделить 3–5 материнских ядер заголовка произведения.
2. Определить, какие торговые точки годятся для названия, а какие только для аннотации или рекламной фразы.
3. Различить следующие типы материнского ядра:
   - Ядро мироустройства
   - Ядро реалистичной интриги
   - Ядро этики персонажей
   - Ядро катастрофического события
4. Для каждой платформы выбрать более подходящую основную ось именования, а не использовать для всей таблицы один шаблон замены слов.

## Основной опыт суждения о названии

### Сначала оценить «похоже ли на название книги»

Каждый кандидат сначала должен пройти этот барьер:

- Можно ли принять его за общее название длинного произведения?
- Может ли читатель естественно произнести и запомнить?
- Может ли охватить всю книгу, а не только один фрагмент?

Если больше похоже на любое из следующего, нужно понизить или отсеять:

- Рекламный текст
- Заголовок поста
- Заголовок главы
- Вводная фраза со взрывной точкой
- Лозунг одной фразой

### Один заголовок бьёт только по одной основной оси

- В одном заголовке допустима только одна основная ось, максимум — одна вспомогательная тень.
- Чрезмерная жадность обычно превращается в «всё написано, но не похоже на название книги».

### Длинный заголовок — не первородный грех, но он должен быть гладким, устойчивым и пересказуемым

В следующих случаях в приоритете сжимать:

- Не читается на одном дыхании
- Информационный центр тяжести разбалансирован
- Структура похожа на рекламный слоган
- Похоже на краткое содержание истории, а не на заголовок

### Нельзя добавлять основные торговые точки, которых нет в материалах

- Нельзя ради красивого названия выдумывать новые настройки, новые отношения персонажей, новые правила мира.
- Заголовок может лишь с высокой плотностью извлекать суть из существующих материалов.

## Частые направления именования

- Профессия / идентичность + аномалия
- Правило / запрет / предложение о цене
- Идентичность главного героя + кризис
- Предмет / ориентир + интрига
- Катастрофическое событие / место кризиса
