## Когда использовать

- Переписать главу любого жанра в англоязычную версию, лучше подходящую для WebNovel.
- Нужно усилить межкультурную читаемость, ясность причинно-следственной цепочки, темп для мобильных и англоязычные гейты платформы.
- Нужно дать жанровым обёрткам единый общий каркас платформы WebNovel.

## Случаи, когда не применяется

- Только дополнение границ жанра, без основы вывода на платформу.
- Только оркестрация нескольких платформ, сохранение в файлы и итоговая проверка, без обработки самого стиля платформы WebNovel.

## Обязанности слоя

- Поддерживать межжанровые общие правила платформы WebNovel.
- Единообразно держать структурные ограничения вывода в версии для WebNovel, англоязычные гейты, склонность в заголовках и гейты стиля.
- Вызывать встроенный облегчённый режим `通用-设计标题`, чтобы оптимизировать заголовок этой главы под платформу: длина заголовка не должна превышать линию риска обрезки на этой платформе, стиль заголовка должен соответствовать ожиданиям читателей этой платформы.

### Сценарии применения лица повествования для версии WebNovel (справка при создании / исправлении записи в таблице базовой линии)

**Базовая логика платформы**: WebNovel — англоязычная платформа веб-романов с крупнейшей в мире читательской аудиторией, читатели охватывают десятки культурных фонов. Межкультурная читаемость — предпосылка всего. Исследование рекомендует многолинейное повествование с возможностью переключения точки зрения каждые 2–3 главы.

**Почему WebNovel склоняется к третьему лицу?**
- **Межкультурная читаемость — первое ограничение WebNovel.** Культурно-специфические внутренние переживания в первом лице (например, «у меня в душе ёкнуло» (我心里咯噔一下), «в сердце поднялось что-то неописуемое» (一股说不清道不明的滋味涌上心头)) создают трудности понимания для читателей, для которых язык не родной. Прямую причинно-следственную цепочку третьего лица «он увидел / он почувствовал запах / он осознал» смогут уловить читатели всего мира.
- Структура информационного разрыва в третьем лице («читатель узнаёт синхронно с героем + изредка переключение точки зрения создаёт напряжение „читатель знает, а герой нет“») — универсальный во всём мире механизм, заставляющий читать дальше. Первому лицу для такого же эффекта нужен более сильный резонанс культурного контекста.
- Рекомендуемое исследованием многолинейное повествование (переключение точки зрения каждые 2–3 главы) в третьем лице всего естественнее — для переключения между главами с разными точками зрения достаточно одной метки «POV: [Character Name]», это не создаёт разрыва повествования.

**Когда на WebNovel можно использовать первое лицо?**
- Жанр romance — эмоции — общий язык человечества, эмоциональная связь в первом лице не нуждается в межкультурном декодировании.
- У романтики / триллера от первого лица на WebNovel уже есть зрелая аудитория, преимущество эмоциональной связи очевидно.
- **Предупреждение**: нельзя внезапно примешивать повествование от третьего лица. Единое лицо повествования на всю книгу — нижняя планка.

## Заглавная картинка главы и промпты для иллюстраций (обязательно для каждой главы)

При сохранении в файл платформенной версии каждой главы в конце файла (после `## 作者有话说` и `## 章节后记`) обязательно добавляй блок «заглавная картинка главы и промпты для иллюстраций», чтобы дать промпты, которые можно напрямую подавать в модели генерации изображений ИИ. В этом разделе выдаются только тексты промптов, сами картинки не выдаются.

### Структура вывода

Конец файла организуется в таком порядке:

1. **Промпт заглавной картинки (картинка начала главы / картинка заголовка главы)**: 1 штука, для карточки главы и показа начала главы на платформе; выбирается из ключевого яркого кадра или ядра образа этой главы.
2. **Промпты иллюстраций (картинки внутри текста)**: на каждую главу 0–2 картинки (по умолчанию 1; если в главе нет визуализируемого яркого кадра — не делать, лучше меньше, чем лишнее); к каждой картинке обязательно одновременно дать место вставки и промпт генерации.

### Правила места вставки иллюстраций (обязательно)

- Формат описания места каждой иллюстрации: `Insert at the end of paragraph N (starts with: "...")` — сначала номер абзаца, затем повторное уточнение по первым 8–15 английским словам этого абзаца, чтобы не было неоднозначности.
- **Иллюстрации всегда вставляются после конца абзаца (между абзацами), запрещено вставлять посреди абзаца, запрещено разбивать или переписывать абзацы ради иллюстрации.**
- Запрещены расплывчатые описания вроде "at a suitable point", "near the climax".

### Нулевое загрязнение текста (обязательно)

- В текст нельзя вставлять никаких заполнителей изображений, `[illustration]`, HTML-комментариев и прочих якорей или меток; текст платформенной версии остаётся чистым.
- Информация о месте иллюстраций пишется только в блоке промптов иллюстраций в конце файла; когда иллюстрации не вставляются, текст можно целиком скопировать для загрузки, и ничто не мешает.

### Требования к качеству промптов

- Промпты заглавной картинки и иллюстраций должны быть написаны **на английском** и обязаны быть полными, пригодными для прямого копирования промптами для генерации изображений ИИ (с субъектом, средой, светом, композицией, цветовой гаммой, стилем и негативными словами), нельзя писать абстрактные описания или советы по письму.
- Промпты должны быть тесно связаны с содержанием главы; запрещены универсальные шаблонные картинки; между несколькими главами одной партии нельзя повторно использовать один и тот же набор промптов.

## Формулировки вывода по умолчанию

- По умолчанию выдаётся одна версия производного от WebNovel англоязычного текста, которую можно сразу сохранять в файл или направлять на итоговую проверку платформы.
- По умолчанию сохраняются ключевая информация исходной главы, ясность причинно-следственной цепочки и межкультурная читаемость; ключевые факты не добавляются.

## Минимальная поставка

- Есть явные плавность английского, межкультурная читаемость и драйвер в конце главы.
- Сохранить ключевую цепочку событий исходной главы, причинно-следственную цепочку и темп дочитывания на мобильных.
- Читаться должно так, чтобы это не походило на дословный перевод и не на общий англоязычный текст, потерявший напряжение платформы.

## Самопроверка и правка после вывода (обязательно, пропускать нельзя)

Сразу после завершения переписывания и вывода обязательно выполнить самопроверку этого раздела; по найденным проблемам вносить исправления на месте, и только после подтверждения прохождения можно сохранять в файл. **Пропускать этот шаг ни по какой причине нельзя.**

**Пять самопроверок:**

0. **Объём в норме**: основной текст и `## 作者有话说` должны ориентироваться на «диапазон объёма по умолчанию на платформе» этого Skill (или значение, переопределяемое в `Agents.md` проекта). Пока основной текст не достиг рекомендуемой нижней границы, рекомендуется сначала вернуть на доработку и добрать объём. **Категорически запрещено набирать объём шаблонной добавкой слов или механическим расширением**; если обнаружено загрязнение шаблонными фразами, нагромождение объясняющей интонации или бессмысленные повторы, самопроверка считается проваленной даже при достаточном объёме, и текст нужно переписать.
1. **Нулевое добавление фактов**: в переписанной версии не появилось ключевых фактов, персонажей или настроек, которых нет в исходнике; если появились — удалить / восстановить.
2. **Ключевая цепочка событий полна**: причина → продвижение → кульминация → направление хука в конце главы — всё отражено в переписанной версии; при разрыве — восстановить.
3. **Стиль платформы соблюдён**: переписанная версия удовлетворяет всем пунктам «минимальной поставки» этого Skill (или требованиям к ключевому стилю платформы); если не хватает — править на месте.
4. **Нет загрязнения шаблонными фразами**: нет двух и более подряд групп фраз в объясняющей интонации / шаблонной интонации / из слов-«формулировок»; при срабатывании весь абзац возвращается на доработку.
5. **POV согласован**: POV переписанной версии согласуется с уже зафиксированным `platformPovContract`; при дрейфе — вернуть на доработку и исправить.

**Формат вывода (обязательно выдавать):**

- Всё в норме: `[自检通过] 五项均达标，可落盘。` (самопроверка пройдена: все пять пунктов в норме, можно сохранять в файл)
- Исправлено и в норме: `[自检修订完成] 已修订：<问题描述>，现五项均达标，可落盘。` (правка по самопроверке завершена: исправлено <описание проблемы>, теперь все пять пунктов в норме, можно сохранять)
- Не пройдено (сохранять нельзя): `[自检未通过] 命中：<问题描述>，需继续处理。` (самопроверка не пройдена: обнаружено <описание проблемы>, нужно продолжать обработку)

Если выведено «не пройдено», обязательно исправить и заново вывести заключение самопроверки; цикл повторяется, пока не будет выведено «пройдено» или «правка завершена», и только тогда можно сохранять в файл.

## Жёсткие правила

- Подсчёт знаков в заголовке главы обязательно ведётся по чистому заголовку: сначала удаляется номер главы вида `x.y.z ` в начале и следующий за ним пробел, затем считается только оставшийся текст заголовка.
- Длина чистого заголовка главы на платформе WebNovel не должна превышать **70 знаков**; но механически сжимать её не нужно: в первую очередь нужно подчиняться межкультурной читаемости платформы и ясности информации, в пределах лимита сохраняя полноту выражения заголовка.
- Категорически запрещено выводить мусорные группы фраз вида «абстрактное самоописание + шаблонный глагол + слово-формулировка»; при появлении похожих шаблонных оборотов вроде «对照项落在… / 先把同一句话拆碎 / 先把顺滑的解释拆开 / 只求能追溯（复核、对得上）» это нужно признать загрязнением и вернуть на доработку весь текст.
- Строго запрещено использовать или косвенно вызывать следующие скрипты для генерации, расширения, склейки или снижения повтора основного текста: `scripts/append_cn_unique_monologue.ps1`, `scripts/append_cn_unique_narration.ps1`, `scripts/append_cn_unique_thirdperson.ps1`, `scripts/rephrase_cn_body.ps1`, `scripts/rephrase_en_body.ps1`, `scripts/cn_lexicon_profile_transform.ps1`. Эти инструменты не должны попадать в цепочку производства основного текста платформы.
- В текст платформы добавляется «гейт нулевого загрязнения шаблонными фразами»: в основном тексте не должно быть двух и более подряд фраз со структурой «я / с моей стороны / в душе я… + 把/将… + 对齐/校准/锁死/拆开… + союз + слово-формулировка + 只求/不求/先把…»; при совпадении — провал, независимо от того, прошли ли объём и сходство.
- Подряд идущие главы платформы обязаны подчиняться зафиксированному `platformPovContract`; нельзя в этом Skill самовольно переводить прежнюю стабильную цепочку на новую цепочку POV.
- Если сработал несанкционированный переход POV или проверка POV провалена, нужно признать провал по `pov_drift_detected` / `pov_switch_without_approval` и вернуть на доработку весь текст.

- При срабатывании этого Skill обязательно одновременно загружать `题材名-输出WebNovel版` Skill соответствующего жанра.
- Правила, специфичные для жанра, нельзя записывать обратно в этот файл для параллельного ведения.
- При изменении общих правил платформы WebNovel в первую очередь меняй этот Skill, а не несколько жанровых входов.
- Нельзя прямо распространять формулировки жанра `都市悬疑` из справки по историческому переносу как межжанровые правила по умолчанию.
- Производный текст платформы по умолчанию сохраняется в рабочий каталог этого Skill `WebNovel/`.
- Каталог производного текста на уровне глав определяется структурой романа единообразно: если у произведения есть части, то он находится в `WebNovel/第X部/第Y卷/`; если частей нет — в `WebNovel/第X卷/`.
- Имя файла производного текста платформы по умолчанию без даты, следует существующему правилу синхронизации номера главы и заголовка платформы; дата используется только для сопутствующих производных материалов — отчётов рецензий, рецензий на книгу и т. п.
- Производный текст главы обязательно сохраняется в виде файла `.md`: если каталога соответствующей главы нет, перед выполнением нужно сначала создать полный путь каталога, затем записать переписанное содержимое главы в `.md`-файл в этом каталоге; нельзя только выдать черновик в чате и не записать в файл.
- Полный приоритет определения пути сохранения: ① явно указанный пользователем chapterPath → ② автоматический вывод по имени исходного файла и сведениям о части / томе → ③ если часть / том определить нельзя, приостановиться и спросить пользователя, нельзя выводить наугад и молча сохранять.
- После сохранения платформенной версии обязательно явно запустить скрипт-гейт по объёму: **проверка объёма основного текста обязательно выполняется через `scripts/count-chapter.ps1`**, нельзя подменять `Len`, `NoWhitespaceLen` или счётчиком знаков редактора. Параметры объёма определяются по приоритету: ① значение платформы, заданное в `Agents.md` проекта → ② «диапазон объёма по умолчанию на платформе» этого Skill. Гейт основного текста проверяется `scripts/count-chapter.ps1 -Path "FILE"` (для англоязычного текста в первую очередь смотреть поле `Len` как справку по общему числу знаков, а `BodyCJK` — для проверки на нулевое присутствие китайского); кроме того, весь текст проверяется `scripts/platform_validate.ps1` с соответствующими параметрами объёма; если нужно проверить отдельно только `## 作者有话说`, используй `scripts/count-afterword-words.ps1` (параметры берутся из соответствующего диапазона «слова от автора»); помимо строки-маркера `## 作者有话说`, обязательно проверять `scripts/check_no_cjk_except_marker.ps1` на нулевое присутствие китайского / CJK.
- На этапе генерации рекомендуется сначала достичь целевого объёма, и только затем разрешать сохранение в файл: ориентироваться на «диапазон объёма по умолчанию на платформе» этого Skill или значение, переопределяемое в `Agents.md` проекта.
- Пока безущербный перенос не завершён, нельзя удалять в исходном `输出WebNovel版.prompt.md` ещё не отображённое содержимое.
