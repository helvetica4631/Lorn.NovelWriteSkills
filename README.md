# Lorn.NovelWriteSkills

Библиотека ИИ-ресурсов для письма, ориентированная на **рабочий процесс создания длинных веб-романов / романов**. Это не репозиторий, где «как попало свалены промпты», а переиспользуемая система письма, выстроенная вокруг цепочки **проектирование жанра → построение плана → создание глав → рецензирование и шлифовка → многоплатформенная переработка → контроль качества (ворота) → рассылка и запись на диск**.

Проект организован в основном в формате Markdown:

- **Тела общих Skill (ядро возможностей)**
- **Жанровые Skill-обёртки**
- **Исполнительные Prompt / SOP**
- **Локальные Instructions**
- **Скрипты сопровождения на этапе письма**

Если вы хотите превратить ИИ из «собеседника для болтовни» в «настоящего партнёра по производству романов, чьи результаты можно записывать на диск, переиспользовать и аудировать», этот репозиторий построен именно в этом направлении. Он не только умеет писать, но и подчёркивает: **структурированность, переносимость, возможность финальной проверки и устойчивое развитие**.

## Для кого этот проект

- Для тех, кто хочет использовать ИИ как помощника в написании веб-романов, длинных сериальных произведений, детективов, фантастики, женской прозы или городских жанров
- Для тех, кто хочет превратить разрозненные промпты в **долговременно поддерживаемые ресурсы**
- Для тех, кто хочет перейти от «сгенерировать основной текст» к полному процессу «генерация + рецензирование + ворота + рассылка»
- Для тех, кто использует в VS Code / GitHub Copilot собственные рабочие процессы Prompt, Skill, Instruction
- Для тех, кто хочет готовить разные версии для разных платформ, а не жёстко копировать один черновик в 8 экземпляров

## Чем он отличается от обычных репозиториев промптов

Конечная точка многих репозиториев промптов — «фрагмент текста Prompt».

Этот проект больше похож на **рабочий стол писателя**:

1. **Чёткая многослойность**
   - `CommonSkills/`: накапливает тела возможностей, переиспользуемые между жанрами
   - `<каталог жанра>/.github/skills/`: жанровые обёртки, входы по умолчанию, границы жанра
   - `<каталог жанра>/.github/prompts/`: жанровые входы для задач, SOP, совместимые входы
   - `scripts/`: скрипты контроля качества на этапе письма — проверка сходства, форматирование, платформенные ворота

2. **Не только «умеет писать», но и «умеет закрывать»**
   - У создания глав есть замкнутый цикл
   - У рецензирования и переписывания есть замкнутый цикл
   - У многоплатформенного вывода есть журналы, ворота, проверка сходства и итоговая сводка

3. **Двухслойное моделирование жанра и платформы**
   - Сначала сохраняется основа жанра, затем выполняется адаптация под платформы
   - Подчёркивается стилевое различие между платформенными версиями, а не просто смена названия или пары фраз

4. **Упор на переиспользуемые ресурсы, а не на разовый результат чата**
   - Исследовательские файлы продолжают оседать в Skill
   - Prompt отвечает за вход
   - Skill отвечает за тело возможностей и носитель правил
   - Скрипты отвечают за проверку на этапе исполнения

Одной фразой:

> Это репозиторий, который переводит «писать роман с помощью ИИ» из вдохновенной работы на **инженерный процесс письма**.

## Обзор ключевых возможностей

### 0. Дистилляция и шаблоны (выполняется один раз при инициализации проекта)

- **Дистилляция авторского стиля**: извлекается «ДНК письма» писателя, создаётся переиспользуемый «шаблон авторского стиля» (базовая длина фразы, ритм абзацев, чувственные предпочтения, отпечатки метафор, список запретов)
- **Дистилляция образца произведения**: извлекается ДНК повествовательной архитектуры успешного романа, создаётся «шаблон образца произведения» (отпечатки способов начала глав, закономерности чередования крючков, интервалы между наградами, распределение ритма)
- **Дистилляция исследований письма**: из отчётов исследований письма уровня «жанр × платформа» извлекаются исполнимые ограничения, создаётся «шаблон исследований письма» как базовая линия ограничений по умолчанию для «жанр × платформа»
- Три вида шаблонов единообразно регистрируются в корневом `Agents.md`, и 9 нижестоящих Skill для письма / рецензирования / правки автоматически их обнаруживают и используют. Приоритет: шаблон, указанный пользователем > шаблон исследований письма > общие значения по умолчанию

### 1. Замысел и проектирование

- Позиционирование жанра
- Проектирование граней истории
- Биографии персонажей
- Настройки истории
- Общий план / план тома
- Движок событий и дел
- Реестр улик, завязок и возвратов
- Название книги, аннотация, промпты для обложки

### 2. Исполнение письма глав

- Создание основного текста
- Замкнутый цикл создания главы
- Генерация контрольной карточки главы
- Исполнение сценических единиц
- Исполнение конфликтов диалога
- Письмо о микропространстве / ограниченном пространстве
- Усиление начала главы
- Усиление крючка конца главы

### 3. Редактура и контроль качества

- Шлифовка основного текста
- Переписывание с удалением «машинного привкуса» (AI味)
- Шлифовка «слова автора»
- Рецензирование общего плана / тома / персонажей / настроек / глав
- Замкнутый цикл рецензирования и оптимизации плана

### 4. Многоплатформенный вывод и коммерческая подготовка

- Очистка мастер-черновика для многоплатформенного использования
- Многоплатформенная адаптация романа
- Оркестровка многоплатформенного вывода (включая восстановление журналов, скрипты ворот, проверку сходства, итоговую сводку)
- Рамка оценки подписания на платформе
- Сборка материалов для подачи
- Планы многоплатформенной рассылки
- 13 платформенных версий вывода: Fanqie, Qimao, Zhihu, Douban, версия для издательства, WeChat Official Accounts, Baidu Baijiahao, Xiaohongshu, Bilibili, Sina Weibo, My Fiction, GoodNovel, WebNovel

## Каталог и функции `распространение-романов`

`распространение-романов/` — это **каталог процесса платформенной рассылки**, а не жанровый каталог.

- В этом каталоге накапливаются планы рассылки, оркестровка исполнения, чек-листы и документы разбора итогов.
- Внутри этого каталога не требуется принудительно выполнять правило «взаимно-однозначного отображения Skill жанрового слоя».
- Управление каталогом и заявление об исключениях см. в `распространение-романов/.github/instructions/distribution-directory-boundary.instructions.md`.

### Краткое описание функций рассылки

В каталог `распространение-романов/` встроены Skill рассылки для 15 основных платформ: Baidu Baijiahao, Douban, Fanqie Novel, Toutiao, Qimao Novel, Qidian, WeChat Official Accounts, Xiaohongshu, Sina Weibo, Zhihu Novel, Zongheng, Bilibili, GoodNovel, My Fiction, WebNovel.

- Каждый платформенный Skill рассылки поддерживает автоматизированную загрузку, сохранение черновиков, отслеживание глав, журнал рассылки и обратную запись состояния.
- Skill рассылки совместимы с продвинутыми возможностями: параллельная рассылка на несколько платформ, восстановление с точки обрыва, отслеживание глав по уникальному ключу.
- Процесс рассылки тесно стыкуется с платформенной адаптацией и Skill вывода, поддерживая сквозное приземление от мастер-черновика до платформенного готового текста.

#### Рекомендуемое использование

- Написание глав можно запускать одной командой для последовательного написания нескольких глав.
- Многоплатформенный вывод рекомендуется запускать по одной главе на команду, но можно параллельно открывать несколько сессий, в каждой выводя по одной главе, что повышает эффективность и стабильность рассылки.

Подробнее см. `распространение-романов/README.md` и описания Skill отдельных платформ.

- Затем выполнить вывод по платформам
- Затем прогнать ворота — по числу знаков / качеству текста / сходству / борьбе с «водой»

## Как им пользоваться

### Способ первый: как личная / командная библиотека ресурсов письма

Вы можете организовать по такому же послойному принципу свои:

- Исследования жанров
- Исследования платформ
- Часто используемые Prompt
- Жанровые Skill
- Скрипты контроля качества

чтобы репозиторий по мере письма всё лучше «умел писать».

### Способ второй: прямо в рабочем процессе VS Code + GitHub Copilot

В репозитории принята структура `.github/prompts/`, `.github/skills/`, `.github/instructions/`, которая очень хорошо подходит для пользовательских рабочих процессов GitHub Copilot в VS Code.

Типичные способы:

- Использовать жанровый Prompt как вход для задачи
- Использовать жанровый Skill как жанровую маршрутизацию и дополнение границ
- Использовать общие Skill для общих между жанрами возможностей
- Использовать скрипты для ворот после написания и выборочных проверок

### Способ третий: только как «инженерный шаблон романа» для справки

Даже если вы не пользуетесь полным пользовательским рабочим процессом Copilot, этот репозиторий всё равно можно использовать как:

- Шаблон каталога романного проекта
- Образец SOP письма
- Библиотеку стратегий многоплатформенного вывода
- Набор скриптов контроля качества письма

для заимствования и вторичной переработки.

## Рекомендуемый порядок знакомства

Если вы впервые встречаетесь с этим репозиторием, рекомендуется смотреть в таком порядке:

1. Сначала `CommonSkills/README.md`
2. Затем один жанровый каталог (например, `городской-саспенс/` или `городская-магия-и-сверхспособности/`)
3. Затем `.github/prompts/` и `.github/skills/` этого жанра
4. Наконец, скрипты контроля качества и ворот в `scripts/`

Если вы хотите начать сразу с «генерации основного текста», в первую очередь обратите внимание на:

- `общий-создание-основного-текста`
- `общий-цикл-создания-главы`
- `общий-генерация-контрольной-карточки-главы`

Если вы хотите начать с «многоплатформенного вывода», в первую очередь обратите внимание на:

- `общий-очистка-мастер-черновика`
- `общий-адаптация-под-платформы`
- `общий-оркестрация-вывода-на-платформы`
- Соответствующие Skill / Prompt «вывод по платформам» (`输出*版`) в каждом жанровом каталоге

## Принципы проектирования проекта

Многие структуры этого репозитория выстроены вокруг следующих принципов:

- **Сначала выделить общее, затем дополнить жанровой спецификой**
- **Сначала накопить Skill, затем копировать и использовать**
- **Сначала платформизировать, затем снижать сходство**
- **Сначала писать как ресурс, затем писать как результат**
- **По возможности делать процесс пригодным для записи на диск, восстановления и проверки**

Иными словами, этот репозиторий стремится не к «написал один раз — порадовался», а к тому, чтобы:

> способность ИИ к письму накапливала сложный процент, как инженерный ресурс.
