# Рецензирование биографии персонажа (специальный Prompt)

## 🔗 Маршрутизация жанровых навыков (обязательно)

При формальном исполнении этого Prompt необходимо сначала загрузить: `общий-рецензия-биографии-персонажей`.

Если при рецензировании обнаруживается, что само позиционирование персонажа расфокусировано, можно вернуться и вызвать `общий-проектирование-биографии-персонажей` для исправления, но судьёй рецензирования по умолчанию в этом Prompt остаётся `общий-рецензия-биографии-персонажей` как первый вход.

> Общие правила и общие красные линии см.: `../agents/рецензент-романов.agent.md`. Этот файл сохраняет только «специальные для рецензирования биографий персонажей» цепочку чтения, требования записи в хранилище, минимальный вход и ограничения маршрутизации шаблонов.

## Целевое позиционирование (документ для автора)
- Биография персонажа — не «краткая биография», предназначенная для читателя, а **эталон согласованности автора + руководство по вызовам при письме**.
- Главный критерий оценки: личность / хронология / границы способностей поддаются сверке, мотив—цена способны двигать сюжет, сеть отношений способна порождать конфликты, сочетание профессии и способностей / тайных искусств узнаваемо, языковая и поведенческая «подпись» прямо ложится на кадр, и **уже в первых трёх главах достигается как минимум один вид награды из: профессиональное ощущение, информационный разрыв, цена или напряжение выживания**.
- Допустимо писать биографию просто, но не допускаются: всемогущие способности, продвижение без цены, нестыковки хронологии, сеть отношений, не способная запускать события, разрыв профессии и способностей.
- В жанре «городская магия и сверхспособности» дополнительно необходимо оценить: похож ли этот персонаж на «настоящего человека, выживающего в аномальном мире», а не на функциональную карточку или инструкцию персонажа с отложенным действием.

## Подтвердить перед началом (если чего-то нет — сначала спросить)
1) Путь к файлу целевой биографии персонажа (относительный путь в репозитории)
2) Позиция персонажа в истории: главный герой / напарник / антагонист / ключевой свидетель / проходная функциональная роль (если пользователь не дал, вам нужно вывести из биографии и записать)
3) Принадлежность к тому / единице-делу: название тома / номер дела / этап (если нет, написать «неизвестно» и отметить риск)
4) Стратегия вывода в этот раз: перезапись | добавление рецензии этого раунда (по умолчанию — добавление)
5) Ключевая глава первого появления / окно первых трёх глав (если пользователь не дал, вам нужно вывести из биографии, плана или главы появления и записать)

## Цепочка чтения (специально для биографий персонажей | сверху вниз)
В начале отчёта обязательно написать «подтверждение цепочки чтения»:

1) `/.github/prompts/проектирование-плана.prompt.md`
2) Общий план (если существует): [путь]
3) План тома, к которому относится (если существует / настоятельно рекомендуется): [путь]
4) Другие биографии персонажей, сильно связанные с ним (как минимум: близкие отношения / противоположные отношения / та же организация):
   - [путь]
5) Биография целевого персонажа (обязательно): [путь]
6) Главы ключевого первого появления / первого проявления цены / первого давления раскрытия личности (приоритет — первые три главы): [путь]

Отсутствие любого вышестоящего звена: обязательно написать «точка блокировки / замещающее основание / риск».

## Требования к исполнению рецензирования биографии персонажа

Следующее специальное для рецензирования биографий персонажей содержимое перенесено в Skill и references `общий-рецензия-биографии-персонажей`; при исполнении этого Prompt **обязательно одновременно загрузить и соблюдать**:

- `../skills/городская-магия-и-сверхспособности-рецензия-биографии-персонажей/SKILL.md`
- `../skills/городская-магия-и-сверхспособности-рецензия-биографии-персонажей/references/дополнение-к-жанровому-шаблону-рецензии-персонажей.md`

И обязательно исполнять совместно **основной каркас, маршрутизированный текущим жанровым Skill + дополнения жанровых шаблонов**; нельзя продолжать выводить старый «вариант со встроенными фрагментами шаблонов» или упрощённый отчёт вида «несколько комментариев о персонаже + немного рекомендаций».

## Нормы вывода и записи в хранилище (специально для биографий персонажей)

Рекомендуемый путь: `审阅意见/人物传记/人物传记审阅报告_人物名_YYYY-MM-DD.md`

### Обязанности, сохраняемые этим Prompt

- Подтвердить цель рецензии, функциональную позицию персонажа, принадлежность к тому и стратегию вывода
- Сохранить «подтверждение цепочки чтения» и ограничения пути записи в хранилище
- Обязательно требовать записывать выводы в отчёт, пригодный для записи обратно, а не в разрозненные комментарии в чате
- На уровне входа заранее закрепить минимальные пороги, которые нельзя пропускать при рецензировании: «первое появление / три главы / профессиональное ощущение / информационный разрыв / проявление цены»

### Минимальные требования к выводу

- Структура отчёта исполняется совместно по общему каркасу рецензирования биографий персонажей и `дополнение-к-жанровому-шаблону-рецензии-персонажей.md`
- Измерения рецензирования должны охватывать как минимум цепочку чтения, проверку основной информации, проверку первого появления и удержания в первых трёх главах, согласованность персонажа—ситуации—точки зрения, играбельность / пишемость, ярлыки и арку роста, библиотеку материалов, личность, мотив и цену, границы способностей, сеть отношений, секретные точки взрыва, полноту плана, удержание веб-романа и давление возвращения
- Оценка и рекомендации по исправлению обязаны исходить из фактической рецензии этого раза, нельзя ставить пустые оценки
- Отчёт обязан ясно написать **тип постоянного питания** этого персонажа (например: профессиональное ощущение / информационный разрыв / командная эстафета / проявление цены / напряжение выживания и т. п.)
- Отчёт обязан дать `1–3` пункта-патча уровня записи, прямо пригодных для записи обратно в биографию, как минимум `1` кадр появления, как минимум `3` реплики, прямо пригодные для переиспользования, а также как минимум `1` патч награды первого появления / первых трёх глав

Полный шаблон отчёта, пункты оценки, список проблем и формат записи обратно уровня примеров единообразно определяются общим каркасом рецензирования биографий персонажей и `дополнение-к-жанровому-шаблону-рецензии-персонажей.md`; входной Prompt больше не ведёт вторую параллельную копию шаблона, чтобы не допускать последующего расхождения.
