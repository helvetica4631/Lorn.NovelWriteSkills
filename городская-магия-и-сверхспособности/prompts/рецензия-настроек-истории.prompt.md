# Рецензирование сеттинга истории (специальный Prompt)

## 🔗 Маршрутизация жанровых навыков (обязательно)

При формальном исполнении этого Prompt необходимо сначала загрузить: `общий-рецензия-настроек-истории`.

Если результаты рецензии требуют записи обратно с исправлением, по умолчанию возвращаться в `общий-проектирование-настроек-истории` для принятия правок; если затрагиваются питание дел или система возвратов, можно по необходимости дополнительно вызывать `общий-проектирование-движка-событий-и-дел`, `общий-проектирование-реестра-улик-и-завязок`.

> Общие правила и общие красные линии см.: `../agents/рецензент-романов.agent.md`. Этот файл сохраняет только «специальные для рецензирования сеттинга истории» цепочку чтения, минимальный вход, требования записи в хранилище и ограничения маршрутизации шаблонов.

## Целевое позиционирование (документ для автора)
- Сеттинг истории — не «научно-популярная статья», а **переиспользуемое боевое руководство** автора: чтобы при написании основного текста можно было быстро вызывать правила, носители доказательств, процедурное трение и границы способностей.
- Главный критерий оценки: пригодность для повествования (способность двигать конфликт / опровержение приговора / страх / эскалацию) + подтверждаемость доказательствами (возможность свести к следам / цепочкам) + границы и цена (защита от всемогущества) + опыт использования автором (можно искать, цитировать, переиспользовать) + **в первых трёх главах достигается как минимум один вид награды из: профессиональное ощущение, информационный разрыв, смещение познания, развенчание страха или проявление цены**.

## Подтвердить перед началом (если чего-то нет — сначала спросить)
1) Путь к файлу целевого сеттинга (относительный путь в репозитории, обычно в `/故事设定/`)
2) Сюжетный модуль, которому в основном служит этот сеттинг: соответствующий том / единица-дело / ключевая точка опровержения приговора (если пользователь не дал, вы выводите из документа и записываете)
3) Нужен ли «строгий режим технической осуществимости»: да/нет (по умолчанию: приоритет пригодности для повествования, но грубые ошибки не допускаются)
4) Стратегия вывода в этот раз: перезапись | добавление рецензии этого раунда (по умолчанию — добавление)
5) Окно глав первого действия / первого оставленного следа / первого проявления цены (если пользователь не дал, вам нужно вывести из плана или сеттинга и записать)

## Цепочка чтения (специально для сеттинга | сверху вниз)
В начале отчёта обязательно написать «подтверждение цепочки чтения»:

1) `/.github/prompts/проектирование-плана.prompt.md`
2) Общий план / план тома (если существует): [путь]
3) Связанные биографии персонажей (особенно «кто может сделать / кто сделает / кто боится сделать»):
   - [путь]
4) Целевой сеттинг истории (обязательно): [путь]
5) Если сеттинг ссылается на другие файлы сеттинга (обязательно перечислить и включить в рецензию):
   - [путь]
6) Главы ключевого первого появления / первой проверки / первого проявления цены (приоритет — первые три главы): [путь]

Отсутствие любого вышестоящего звена: обязательно написать «точка блокировки / замещающее основание / риск».

## Требования к исполнению рецензирования сеттинга истории

Следующее специальное для сеттинга содержимое рецензирования перенесено в Skill и references `общий-рецензия-настроек-истории`; при исполнении этого Prompt **обязательно одновременно загрузить и соблюдать**:

- `../skills/городская-магия-и-сверхспособности-рецензия-настроек-истории/SKILL.md`
- `../skills/городская-магия-и-сверхспособности-рецензия-настроек-истории/references/дополнение-к-жанровому-шаблону-технической-рецензии.md`

И обязательно исполнять совместно **основной каркас, маршрутизированный текущим жанровым Skill + дополнения жанровых шаблонов**; нельзя продолжать выводить старый «вариант со встроенными фрагментами шаблонов» или упрощённый отчёт вида «несколько комментариев + немного рекомендаций».

## Нормы вывода и записи в хранилище (специально для сеттинга истории)

Рекомендуемый путь: `审阅意见/故事设定/设定审阅报告_文件名_YYYY-MM-DD.md`

### Обязанности, сохраняемые этим Prompt

- Подтвердить целевой файл сеттинга, сюжетный модуль, которому он служит, режим технической осуществимости и стратегию вывода
- Сохранить цепочку чтения, путь записи в хранилище и ограничение «обязательно реально сформировать отчёт»
- На уровне входа заранее закрепить минимальные пороги, которые нельзя пропускать при рецензировании: «первое появление / три главы / профессиональное ощущение / информационный разрыв / проявление цены»

### Минимальные требования к выводу

- Структура отчёта исполняется совместно по общему шаблону рецензирования сеттинга и `дополнение-к-жанровому-шаблону-технической-рецензии.md`
- Охватить как минимум цепочку чтения, проверку основной информации, проверку первого появления и первых трёх глав, согласованность персонаж—ситуация—точка зрения, карточки применения при письме, пункты правил, реальную осуществимость и процедурную разумность, длинную эскалацию, реальные «болевые точки» / эмоциональный резонанс, подтверждение доказательствами, процедурное трение, согласованность персонажей / организаций
- Отчёт обязан ясно написать **тип постоянного питания** этого сеттинга (например: профессиональность / информационный разрыв / смещение познания / развенчание страха / проявление цены)
- Отчёт обязан дать рекомендации по исправлению, прямо пригодные для записи обратно в документ сеттинга, а также как минимум `1–3` примера-переписывания уровня примеров и как минимум `1` рекомендацию по исправлению награды первого появления / первых трёх глав

Полный шаблон отчёта, пункты оценки, список проблем и формат записи обратно уровня примеров единообразно определяются общим шаблоном рецензирования сеттинга и `дополнение-к-жанровому-шаблону-технической-рецензии.md`; входной Prompt больше не ведёт вторую параллельную копию шаблона, чтобы не допускать последующего расхождения.
