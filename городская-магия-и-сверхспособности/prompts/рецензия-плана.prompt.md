# Рецензирование плана

## Маршрутизация жанровых навыков (обязательно)

При исполнении этого Prompt необходимо сначала определить уровень объекта рецензирования, затем вызвать соответствующий жанровый Skill:

- Общий план / план всей книги / стратегический уровень / загадка основной линии `M0` / важные побочные линии `X01-XNN` / матрица единиц-дел `C01-CNN` / межтомное планирование / замыкание финала → `общий-рецензия-общего-плана`
- Часть / том / единица-дело / список глав / ритм 5/15 / стратегия крючков / возможность разбиения на главы / эскалация цены для персонажей → `общий-рецензия-плана-тома`

Prompt не имеет права, минуя жанровый Skill, «голо» рецензировать.

Если задача одновременно охватывает общий план и часть / том:

1. Сначала вызвать `общий-рецензия-общего-плана`, зафиксировав проблемы стратегического уровня;
2. Затем вызвать `общий-рецензия-плана-тома`, проверив, состоятельно ли принятие на уровне исполнения;
3. Запрещено пропускать вышестоящее и сразу рецензировать нижестоящее.

## Обязанности, которые остаются только у этого Prompt

- Единый вход рецензирования планов жанра «городская магия и сверхспособности»
- Сохраняет разведение объектов, общие критерии суждения рецензирования, цепочку чтения, минимальный вход, запись отчёта в хранилище и ограничения минимальной квитанции
- Маршрутизирует специфичные для уровня пункты проверки, дополнения отчёта, акценты оценки и стратегию минимальных патчей в соответствующий жанровый Skill

## Общие критерии суждения рецензирования (сохраняются на уровне входа)

### Приоритет авторской направленности

- План — не текст, предназначенный читателю напрямую; главный критерий оценки: способен ли он надёжнее направлять автора в написании глав для сериала.
- При рецензировании в первую очередь смотреть на: исполнимость, возможность разбиения на главы, можно ли реально прописать доказательства / правила / время / цену, а не на литературные достоинства плана.
- Допускается простой текст, но не допускаются пустые слова, лозунги, нагромождение понятий, узлы без носителей доказательств, правила, которые не удаётся применить, неисполнимая хронология.

### Запись в хранилище по умолчанию

- Если пользователь явно не потребовал «только обсуждать, файлы не писать», отчёт рецензии по умолчанию записывается в `审阅意见/`.
- Если уже есть соответствующий главный отчёт, по умолчанию обновлять с перезаписью последний действующий главный отчёт; если нет — создать новый.
- На стороне чата достаточно кратко сообщить целевой файл, файл отчёта, оценку и нужно ли продолжать доработку; пересказывать весь текст отчёта не следует.

### Минимальный вход

- Путь к файлу целевого плана
- Тип объекта рецензирования: общий план / часть / том / единица-дело
- Стратегия вывода в этот раз: перезапись｜добавление рецензии этого раунда (если не указано, по умолчанию добавлять или перезаписывать главный отчёт — выбирать по существующей цепочке)

### Нижняя граница цепочки чтения

- Сначала прочитать `проектирование-плана.prompt.md` и связанные материалы исследований / обзоров.
- Объекты «часть / том / единица-дело»: сначала прочитать вышестоящий общий план, при необходимости затем — принадлежащую часть и связанные реестры.
- Если вышестоящее отсутствует, в отчёте обязательно явно указать: точку блокировки, временное замещающее основание, риски, возникающие из-за этого.

### Платформа, вживание, длинная линия и борьба с духом ИИ

- При рецензировании нельзя смотреть только на логическую самосогласованность, нужно ещё смотреть на: платформенную адаптацию, реальную основу, чувственные якоря, дисциплину перспективы, профессиональные / правила-爽-точки, выносливость на длинной дистанции и борьбу с духом ИИ.
- Для объектов общего плана по умолчанию ещё нужно судить: главную платформенную формулировку, реальную основу, цену правил, чувственные мотивы, нарастание способностей и баланс цены, обещание начала и интерфейсы с нижестоящим.
- Для объектов «часть / том / единица-дело» по умолчанию ещё нужно судить: цепочку продолжения чтения первых 5 глав, реализацию в середине, профессиональную необходимость, тройную связку правила / доказательства / цена, давление контрольной карточки вниз и подхват в конце тома.
- Отчёт обязан указать: какие места больше всего похожи на пустую высокую концепцию / резюме в духе ИИ и в какие события, действия, доказательства, якоря реальности, последствия правил или цену для персонажей их следует переписать.

## Фиксированный порядок разведения

1. Сначала определить уровень объекта рецензирования.
2. Сначала вышестоящее, потом нижестоящее: общий план приоритетнее части / тома; если вышестоящее отсутствует, сначала в отчёте записать точку блокировки и риски.
3. Если объект охватывает уровень общего плана и уровень тома, сначала вызвать `общий-рецензия-общего-плана`, затем `общий-рецензия-плана-тома`.
4. Затем вызвать соответствующий жанровый Skill для продолжения исполнения.
5. Отчёт записывается в `审阅意见/`, на стороне чата — лишь минимальная квитанция.
