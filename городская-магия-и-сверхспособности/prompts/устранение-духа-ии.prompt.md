## 🔗 Маршрутизация жанровых навыков (обязательно)

При срабатывании этого Prompt необходимо сначала вызвать: `общий-устранение-духа-ии`.

Текущий Prompt и текущая цепочка по умолчанию единообразно используют стандартное имя `общий-устранение-духа-ии`.

Все задачи вроде «устранить дух ИИ во всей главе / очистить локальный шаблонный тон / очеловечивающая переработка без потери информации / защита фактуры реальности / защита границ правил и цены» следует в первую очередь вести через этот skill.

## Обязанности, которые остаются только у этого Prompt

- Распознавать «устранение духа ИИ» как вход задачи, для которой в первую очередь обязательно загрузить `общий-устранение-духа-ии`
- Требовать менять реальные файлы в рабочей области, а не только показывать пример в чате
- Требовать при неясном объёме сначала одной фразой подтвердить границы
- Требовать, чтобы окно чата по умолчанию возвращало только краткую проверяемую сводку правок, не вставляя всю главу

### ⚙️ Жёсткие требования к обновлению файла (дополнительные указания для ИИ-ассистента)

- Предпосылка по умолчанию: вы открыли в VS Code файл с основным текстом какой-то главы или файл Markdown с каким-то фрагментом; этот файл и есть цель операции «устранения духа ИИ» в этом раунде.
- **Запрещено давать в диалоге лишь целый абзац или целую главу «текста после устранения духа ИИ», не изменяя файл**.
- Если пользователь явно указал всю главу, нужно полностью переписать основную часть текста и записать обратно; если указан только фрагмент — заменять только соответствующий фрагмент.
- Если объём не указан, нужно сначала одной фразой подтвердить границы обработки: объём, интенсивность, «гвозди», которые обязательно сохранить.
- Если в файле есть специальные разделы «послесловие к главе», «заметки о письме» или «журнал правок», можно по необходимости добавить краткую запись, поясняющую направление правок в этом раунде.
- Только если пользователь явно требует «только обсуждение и демонстрацию, файл не трогать», разрешается показывать лишь примерные абзацы.

## 🧾 Шаблон вывода пояснения правок (краткий, проверяемый)

Если пользователь явно не требует построчного сопоставления целиком, не вставляйте в окно чата всю главу целиком. По умолчанию давать только «сводку правок», при необходимости — 1–3 коротких сопоставления.

**Сводка правок** (рекомендуется 5–10 строк):
- Охват: вся глава / сцена X / с абзаца N.
- Первый проход (содержание): какие нормы выровнены (имена / хронология / поля доказательств / сеттинг).
- Второй проход (стиль): удалено клише — X мест; разбито длинных фраз — Y; заменено книжных слов — Z; обработано сбоев в диалогах — N.
- Третий проход (детали): унификация знаков препинания / кавычек; разбиение абзацев; проверка пробелов между китайским, английским и цифрами.
- Защита крючка: крючок конца главы сохранён в (позиция / последняя фраза) и стал более конкретным / напряжённым (без раскрытия развязки раньше времени).

**Выборочное сопоставление (необязательно)**: показывать только 1–3 коротких сопоставления «исходная фраза → после правки», чтобы доказать равнозначность информации.

## 📤 Требования к формату вывода

### Сдача оптимизированного текста
- Использовать инструмент правки файлов рабочей области VS Code и прямо менять исходный файл (например, `apply_patch`)
- Сохранять исходную структуру файла (заголовок, нумерация глав, разделители абзацев)
- Выполнять точную замену по абзацам, обеспечивая полноту информации

### Пояснение правок (необязательно)
При необходимости можно дополнить в послесловии к главе:
- Обзор главных точек оптимизации (например: устранён шаблонный тон, усилена смена ритма)
- Применение ключевых приёмов (например: короткие фразы создают напряжение, детали через чувства)
- Пояснения по особой обработке (например: причина сохранения технически точных числовых значений)

**Внимание**: пояснение правок должно быть кратким и ясным, избегать чрезмерных объяснений, пусть оптимизированный текст говорит сам за себя.
