# Вход шлифовки основного текста

## 🔗 Маршрутизация жанровых навыков (обязательно)

При срабатывании этого Prompt необходимо сначала вызвать: `общий-шлифовка-основного-текста`.

Если пользователю нужно лишь локальное специализированное усиление, маршрутизация идёт по следующим стандартным входам:

- Усиление начала главы: `общий-усиление-начала-главы`
- Крючок в конце главы: `общий-усиление-хука-конца-главы`
- Слово от автора: `общий-шлифовка-слова-автора`
- Мультиплатформенная основа: `общий-очистка-мастер-черновика`
- Переписывание шаблонной интонации: `общий-устранение-духа-ии`

Этот файл — **единственный сохраняемый** в рабочей области вход «шлифовка основного текста / доводка основного текста / доводка главы».

Подробные правила шлифовки, проектные ограничения и расширенные приёмы передаются следующим местам:

- `.github/skills/городская-магия-и-сверхспособности-шлифовка-основного-текста/SKILL.md`
- `.github/skills/городская-магия-и-сверхспособности-шлифовка-основного-текста/references/migrated-polish-rules.md`
- `.github/skills/городская-магия-и-сверхспособности-шлифовка-основного-текста/references/polish-chapter-checklist.md`
- `.github/skills/городская-магия-и-сверхспособности-шлифовка-основного-текста/references/line-level-polish-actions.md`
- `.github/skills/городская-магия-и-сверхспособности-шлифовка-основного-текста/references/project-specific-polish-rules.md`
- `.github/skills/городская-магия-и-сверхспособности-шлифовка-основного-текста/references/extended-polish-playbook.md`
- `.github/skills/городская-магия-и-сверхспособности-шлифовка-основного-текста/references/extended-reference-routing.md`

## Режим обработки по умолчанию

- Цель по умолчанию: основной текст главы
- Охват по умолчанию: формальная шлифовка всей главы с записью обратно в файл
- По умолчанию заголовок не меняется
- По умолчанию сохраняется нулевая потеря информации: новых ключевых фактов не добавлять, нумерацию главы и базовую структуру не менять
- По умолчанию «удаление ИИ-привкуса» автоматически не подключается, если пользователь явно не потребует или если главная проблема текста — не шаблонная интонация / фальшивый человеческий голос / испарение «швов реальности»

## Что необходимо соблюдать после срабатывания

1. В первую очередь исполнять по процессу `общий-шлифовка-основного-текста`.
2. При формальном исполнении нельзя лишь выкладывать в диалоге целую отшлифованную главу, нужно напрямую изменять целевой файл.
3. Если пользователь явно хочет лишь усилить начало, маршрутизация идёт в:
   - `.github/skills/городская-магия-и-сверхспособности-усиление-начала-главы/SKILL.md`
4. Если пользователь явно хочет лишь усилить крючок в конце главы, маршрутизация идёт в:
   - `.github/skills/городская-магия-и-сверхспособности-усиление-хука-конца-главы/SKILL.md`
5. Если пользователь явно хочет лишь фрагмент `## 作者有话说` («Слово от автора»), маршрутизация идёт в:
   - `.github/skills/городская-магия-и-сверхспособности-шлифовка-слова-автора/SKILL.md`
6. Если пользователь готовит основу для мультиплатформенной переписи, маршрутизация идёт в:
   - `.github/skills/городская-магия-и-сверхспособности-очистка-мастер-черновика/SKILL.md`
7. Если пользователь явно требует исполнять «по канону прежней полной версии Prompt в репозитории», нужно дополнительно прочитать `extended-polish-playbook.md` и `project-specific-polish-rules.md`.
8. Если в основном тексте, эпиграфе главы или `## 作者有话说` («Слово от автора») встречаются внутренние номера авторской стороны (например, `M0`, `X01`, `C01`, `C03@V2`, `L01.2`, `CL01.03`, `SUS01.02`, `FB01`), при шлифовке их нужно переписать в понятное читателю естественное повествование или реальные номера внутри мира, авторские номера реестра сохранять нельзя.
9. Если в файле уже есть `## 章节后记` («Послесловие к главе») или `## 润色说明` («Пояснение к шлифовке»), их следует обновить на месте; если изменения велики, а раздела с пояснением в файле ещё нет, при необходимости можно добавить `## 润色说明`.

## Требования к выводу

- В ответе достаточно кратко указать:
  - какой файл изменён
  - вся глава или часть
  - что в основном усилено за этот проход
- В чате не нужно повторно вставлять целую готовую главу, если пользователь явно не просил «только показать пример, без записи обратно в файл».

## Формулировки, пригодные для прямого запуска

- «Шлифовка основного текста»
- «Доводка основного текста»
- «Доводка главы»
- «Помоги отшлифовать основной текст этой главы»
- «Доведи всю главу и запиши обратно в файл»
- «Сделай эту главу чуть глаже, но заголовок не меняй»
- «Шлифовка основного текста, обработай как формальную»
- «Шлифуй по канону прежней полной версии Prompt»

## Примечание по сопровождению

- Этот Prompt сохраняет лишь «вход для обнаружения + маршрутизацию по умолчанию + требование записи обратно».
- Стандарты шлифовки, проектные правила, чек-листы, шаблоны вывода и длинные расширенные приёмы единообразно сопровождаются в Skill и его references.
- Если позже понадобится дополнить правила, в первую очередь дополняйте Skill или references, а не возвращайте длинные правила во вход, чтобы снова не возникло двойного сопровождения.
