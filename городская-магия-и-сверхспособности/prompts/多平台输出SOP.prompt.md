# SOP вывода на несколько платформ

## Маршрутизация жанровых навыков (обязательно)

При срабатывании этого Prompt необходимо сначала вызвать: `通用-多平台输出编排`.

И порядок исполнения всей цепочки по умолчанию обязан быть чётко таким:

1. Сначала вызвать `通用-提纯多平台母稿`
2. Затем вызвать `通用-多平台小说适配`
3. В конце по платформам вызвать соответствующие `通用-输出*版`

Этот вход не имеет права «голым» гнать платформенную цепочку и не имеет права пропускать очистку жанровой мастер-рукописи, фиксацию жанровой основы и разведение различий платформ.

## Гейт полноты вызовов (обязательно)

Чтобы «обязательные вызовы Skill» не были устной договорённостью, при срабатывании этого Prompt необходимо выводить аудит вызовов:

- `requiredCalledSkills`: список вызовов, которые следовало выполнить в этот раз
- `calledSkills`: список фактически выполненных вызовов в этот раз (с порядком)
- `missingCalledSkills`: список должных, но не вызванных

И удовлетворять следующему минимальному покрытию:

- Для каждой главы обязательно вызывать `通用-提纯多平台母稿`
- Для каждой главы обязательно вызывать `通用-多平台小说适配`
- Для каждой пары «глава × целевая платформа» обязательно вызывать соответствующий `通用-输出*版`

Пока `missingCalledSkills` не пуст, задача этого раза обязательно признаётся незавершённой, переходить к «сводке завершения» нельзя.

## Обязанности, которые этот Prompt по-прежнему обязан сохранять

Хотя этот Prompt уже мигрирован в «слой входа + слой маршрутизации», он **не может стать настолько тонким, чтобы остались одни слова «смотрите в Skill»**. Он по-прежнему обязан сохранять следующую информацию, чтобы пользователь, рецензент и исполнитель с первого взгляда видели минимальные жёсткие ограничения этой цепочки:

- Это единый вход вывода на несколько платформ жанра «городская магия и сверхспособности»
- Набор платформ по умолчанию, минимальный вход и минимальные условия переспроса
- Сначала обязательно зафиксировать жанровую основу, затем делать платформенную адаптацию, затем снижать сходство
- Обязательно вести журнал исполнения, поддерживать продолжение с контрольной точки, выполнять финальную проверку независимо по главам
- На стороне чата разрешается выводить только сводку записи, нельзя выводить основной текст
- Настоящие детальные нормы, шлюзы, шаблоны финальной проверки и правила жанровой достоверности нужно продолжать читать в `通用-多平台输出编排`, `通用-多平台小说适配` и объявленных ими references

## Минимальный вход

Поддерживаются следующие формы входа:

- `chapterPath`
- `chapterPaths[]`
- При необходимости можно принять и вставку основного текста, но дозапрашивать минимально необходимые поля разрешено только когда нельзя вывести из пути

Необязательные параметры:

- `platforms` (если не указан — читать набор платформ по умолчанию из `平台POV基线表` в корне проекта; если этого файла нет, обязательно предложить пользователю создать его и остановиться, продолжать выполнение нельзя)

## Правила набора платформ по умолчанию

Когда в команде пользователя не указан `platforms`:

1. Обязательно прочитать `平台POV基线表` в корне проекта и взять перечисленные в нём платформы как набор платформ вывода по умолчанию в этот раз.
2. Если в корне проекта нет `平台POV基线表`, обязательно предложить пользователю создать этот файл (по одному названию платформы на строку, строки с `#` в начале — комментарии), затем **немедленно остановиться**.
3. Названия платформ обязаны совпадать с суффиксом имени соответствующего Skill `通用-输出*版`.

## Жёсткие ограничения уровня входа для путей и нумерации

Эти правила, даже если основная часть перенесена в Skill, обязаны сохраняться на уровне входа, чтобы при исполнении не допускать повторных ошибочных суждений:

- `chapterNo` в первую очередь разбирать из префикса номера в имени исходного файла главы
- `chapterIndex` брать как последний сегмент `chapterNo`
- `{каталог тома}` по умолчанию брать как имя каталога, в котором лежит исходный файл
- `{каталог части}` по умолчанию брать как имя родительского каталога `{каталога тома}`

Переспрашивать разрешено только в следующих случаях, причём обязательно собрав все недостающие пункты в один вопрос:

- Не удаётся разобрать `chapterNo`
- Не удаётся стабильно вывести `分部目录 / 分卷目录`
- Пользователь вставил основной текст напрямую и не предоставил вышеуказанные необходимые поля

Если за раз вводится несколько глав, необходимо объединить в один совместный переспрос, запрещено переспрашивать по главам по очереди.

## Ритм исполнения (слой входа по-прежнему обязан чётко задавать)

- После начала исполнения необходимо по возможности пройти всё на одном дыхании: прочитать исходную главу → поглавно и поплатформенно сгенерировать и записать на диск → финальная проверка каждой главы → вывод сводки
- Запрещено останавливаться ради «отчёта о ходе работ» и ждать, пока пользователь скажет «продолжай»
- Прерывание допускается только в следующих сценариях: не удаётся разобрать `chapterNo`, не удаётся стабильно вывести `каталог части / каталог тома`, пользователь дал только основной текст и нужных полей нет, настоящая ошибка исполнения не позволяет продвинуться дальше
- Стратегия по умолчанию — автоматически выводить и продолжать, нельзя прерываться ради «подтверждения платформенных предпочтений», «подтверждения порядка», «подтверждения продолжения»
- При нескольких главах сначала обязательно составить список пакетных задач
- Порядок исполнения обязан быть «главы — внешний цикл, платформы — внутренний»
- По умолчанию одновременно продвигать не более 2 задач-глав, на каждую главу не более 2 платформенных веток, глобально активных платформенных веток не более 4; при перегрузке среды обязательно автоматически понижать
- Каждая глава перед переходом к следующей обязана завершить запись всех целевых платформ этой главы, шлюзы, сканирование качества текста и финальную проверку сходства
- Гранулярность восстановления с контрольной точки обязана доходить до узла «глава × платформа»; узлы, прошедшие шлюз, нужно прямо пропускать, нельзя переделывать всю партию

## 🚨 Жёсткое ограничение режима ИИ (первая красная линия)

Версии для нескольких платформ **обязаны и могут генерироваться только способом вызова модели ИИ**, строго запрещено генерировать или переписывать содержимое входной главы каким-либо скриптом.

### Явные жёсткие правила

1. **Генерация основного текста скриптом строго запрещена** (первая красная линия)
   - Запрещено использовать любые скрипты для пакетной генерации, преобразования, переписывания, добивки знаков или перезаписи основного текста главы
   - Запрещено использовать скриптовую переписку как запасной вариант ради «экономии стоимости вызовов / обхода лимита токенов»
   - Единственная обязанность скриптов: помогать строить список задач, вести журнал, выводить пути к файлам, сканировать шлюзы качества, **нельзя касаться генерации основного текста**

2. **Генерация версий для нескольких платформ обязана вызывать ИИ**
   - Каждая версия «глава × платформа» обязана независимо генерироваться вызовом модели ИИ
   - Запрещено переиспользовать, латать, преобразовывать или превращать в скрипт любую уже сгенерированную версию
   - Запрещено использовать псевдо-ИИ-способы — подстановку в шаблон, замену регулярными выражениями, сопоставление по правилам

3. **Единственное разрешённое действие при недоступности ИИ**
   - Когда вызов ИИ даёт сбой, исчерпана квота, сервис недоступен — **единственное разрешённое действие**: вывести сигнал `blocked_ai_unavailable`
   - Немедленно остановить весь процесс производства основного текста
   - Запрещены любые деградационные варианты «скриптовая переписка как запасной вариант / ручное исправление / частичная генерация»
   - Дождаться восстановления ИИ и выполнять заново, продолжать нельзя

4. **Дисциплина токенов**
   - Запрещено использовать скриптовую переписку основного текста ради «экономии вызовов / обхода лимита»
   - Запрещено после разделённой генерации склеивать скриптом, запрещено сначала предобрабатывать скриптом, а затем ИИ «спасать»
   - Обязательно ясно указывать «сколько токенов должно быть израсходовано в этом раунде» и «сколько фактически израсходовано», нельзя подменять скриптом, скрывая перерасход

5. **Требования к журналу исполнения**
   - Для каждой главы на каждой платформе обязательно явно записывать: вызывался ли ИИ, время вызова, число знаков на входе, число знаков на выходе, ограничен ли по токенам
   - При появлении `blocked_ai_unavailable` обязательно отметить в журнале и остановить весь последующий платформенный вывод этой главы
   - Запрещено выдавать скриптовую версию за сгенерированную ИИ, запрещено скрывать факт использования скрипта

### Итог одной фразой

ИИ есть ИИ, скрипт есть скрипт. Генерировать версии — ИИ, остальное — скрипты. ИИ умер — остановились, нельзя позволять скрипту «как-нибудь залатать».

## Общие жёсткие ограничения (краткая версия уровня входа)

Даже если детальные нормы перенесены в Skill, этот Prompt всё равно обязан явно указывать следующие общие жёсткие ограничения:

1. **Сначала платформизировать, затем снижать сходство**: нельзя сначала сделать нейтральный общий вариант, а затем рассылать по платформам.
2. **Основная информация не теряется**: цепочка событий, цели и цена персонажей, изменения отношений, ключевые закладки, крючок конца главы, жанровая основа обязаны сохраняться.
3. **Платформенный стиль обязан быть заметен**: если закрыть название платформы, всё равно должно быть видно, что вариант больше похож на эту платформу, а не на обобщённый.
4. **Строго запрещено шумовое снижение сходства**: нельзя вставлять мусорные символы, случайные строки, воду, повторяющиеся фразы без информации, нагромождение символов или возмущающие пустые строки для разбавления сходства.
5. **Структура вывода ограничена**: в файл разрешается писать только «основной текст + `## 作者有话说`».
6. **Обязательно вести журнал исполнения**: журнал — часть процесса, опускать нельзя; незавершённые задачи должны допускать продолжение.
7. **Обязательна финальная проверка по языкам**: китайская и английская группы проверяются отдельно, сравнение сходства между языками не проводится.
8. **В чате отвечать только сводкой**: нельзя выводить основной текст, черновики дедукции, пояснения сопоставления или длинные цитаты.
9. **Антиводность и качество текста — предварительные шлюзы**: следы шума — `PAD_TO_GATE`, токены вида UID, символы области частного использования, символы замены и т. п. — должны быть обнулены, только тогда допускается финальная проверка сходства.
10. **Заголовок обязан иметь двойное избегание столкновений**: нельзя совпадать с названием исходной главы, а также у разных платформ одной главы не должно быть одинаковых названий.

## Напоминание о жанровой достоверности (слой входа обязан показывать)

В жанре «городская магия и сверхспособности» платформенная переработка не имеет права смыть следующий скелет:

- Фольклорная достоверность и якоря реальности
- Цепочка правил тайных искусств / сверхспособностей и цепочка цены
- Профессиональные действия и реальное трение
- Давление городского пространства
- Загадка основной линии и отношение питания единиц-дел

Когда платформенные шлюзы пройдены, но жанровое ощущение поблекло, обязательно в первую очередь вернуть: якоря реальности, цену правил, профессиональные действия, выражение фольклорных функций, опасные пространства и крючок конца главы.

## Минимально видимые ограничения для нескольких глав и журнала

Этот Prompt больше не раскладывает все поля JSON журнала, но слой входа по-прежнему обязан сообщить исполнителю:

- В рабочей области обязательно вести журнал исполнения вывода на несколько платформ
- И для одной главы, и для нескольких глав всё должно допускать восстановление
- Многоглавая партия ведёт только один общий журнал партии
- По записи каждой главы должно быть видно текущую контрольную точку, завершённые платформы, сбойные узлы и следующее действие
- Пока партия не завершена целиком, нельзя записывать общий статус как completed
- В `gates` журнала как минимум должно быть можно проверить: шлюз по числу знаков, шлюз слова от автора, шлюз антиводности / языка, качество текста, единство стиля

Детальные нормы полей журнала, структура контрольных точек, написание путей к отчётам шлюзов платформ и шаблон сводки читать и исполнять единообразно в `通用-多平台输出编排` и объявленных им references.

## Выдача по умолчанию

- Файлы целевых платформ записаны на диск по соответствию каталогов
- Каждый платформенный файл прошёл соответствующий шлюз
- Каждая глава прошла сканирование качества текста
- Каждая глава прошла проверку сходства по языкам
- Чат отвечает только «сводкой записи + путь + вывод по шлюзам / финальной проверке»

## Основное содержимое, уже перенесённое в Skill, но которое необходимо продолжать читать и исполнять

Следующее содержимое перенесено в `异能志怪-多平台输出编排`, `异能志怪-多平台小说适配` и объявленные ими references; этот Prompt больше не копирует параллельно полный текст, но **при исполнении необходимо продолжать читать и выполнять**:

- Детальные нормы очередного исполнения одной / нескольких глав
- Границы параллелизма и диспетчеризация на уровне глав / платформ
- Каталог журнала, `logKey`, контрольные точки и правила продолжения
- Платформенные шлюзы, антиводность, сканирование качества текста, шлюз заголовков
- Нормы проверки сходства по языкам и шаблон сводки
- Очистка жанровой мастер-рукописи, платформенная адаптация и порядок сохранения жанровой основы
- Для платформенных Skill вывода: соответствие каталогов, стратегия заголовков, требования к числу знаков и слову от автора

## Напоминание одной фразой

Этот Prompt и сейчас остаётся **слоем входа**, но он обязан быть «входом с зубами»:

- Пользователь видит здесь минимальный вход и минимальные условия прерывания
- Исполнитель видит здесь непреодолимый порядок и общие жёсткие ограничения
- Настоящий детальный основной текст исполнения, структуру журнала, скрипты шлюзов и жанровые нормы адаптации читать дальше в соответствующих Skill и там исполнять
