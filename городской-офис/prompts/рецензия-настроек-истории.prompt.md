# общий-рецензия-настроек-истории (специальный Prompt)

## Связанные навыки (специализированные для сеттинга)

[`общий-рецензия-настроек-истории`｜рецензирование сеттинга истории](../skills/общий-рецензия-настроек-истории/SKILL.md)

Для любой задачи «осмотр сеттинга истории / аудит пунктов правил / аудит возможности превращения в доказательства / аудит процедурного трения / предложения по записи сеттинга обратно» следует в первую очередь вызывать этот skill.

> Общие правила и общие красные линии см.: `../agents/рецензент-романов.agent.md`. Этот файл содержит лишь чек-лист, шаблоны и правила внесения в библиотеку, «специальные для рецензирования сеттинга истории».

## Целевое позиционирование (документ для автора)
- Сеттинг истории — не «научно-популярная статья», а **многоразовое боевое руководство** автора: чтобы при написании основного текста можно было быстро вызывать правила, носители доказательств и процедурное трение.
- Главный критерий оценки: нарративная применимость (способность двигать конфликт / переворот дела / страх) + возможность превращения в доказательства (способность приземляться в следы / цепочки) + граница и цена (против всемогущества) + опыт использования автором (индексируемость, цитируемость, повторная применимость) + **в первых трёх главах появления способность выдать микроаномалию, процедурную «обиду» или малую награду в знакомом городском пространстве**.

## Подтвердить перед началом (если чего-то нет — сначала спросить)
1) Путь к файлу целевого сеттинга (относительный путь в репозитории, обычно в `/故事设定/`)
2) Сюжетный модуль, которому в основном служит этот сеттинг: соответствующий том / единица-событие / ключевая точка переворота дела (если пользователь не дал, нужно вывести из документа и написать)
3) Нужен ли «строгий режим технической осуществимости»: да/нет (по умолчанию: приоритет пригодности для повествования, но грубые ошибки не допускаются)
4) Стратегия вывода в этот раз: перезапись | добавление рецензии этого раунда (по умолчанию — добавление)
5) Окно глав первого применения / первой проверки / первого провала (если пользователь не дал, нужно вывести из плана или сеттинга и написать)

## Цепочка чтения (специально для сеттинга | сверху вниз)
В начале отчёта обязательно написать «подтверждение цепочки чтения»:

1) `/.github/prompts/проектирование-плана.prompt.md`
2) Общий план / план тома (если есть): [путь]
3) Связанные биографии персонажей (особенно «кто может делать / кто будет делать / кто боится делать»):
	 - [путь]
4) Целевой сеттинг истории (обязательно): [путь]
5) Если сеттинг ссылается на другие файлы сеттинга (обязательно перечислить и включить в рецензию):
	 - [путь]
6) Главы ключевого первого появления / первой проверки / первого проявления цены (приоритет — первые три главы): [путь]

Отсутствие любого вышестоящего звена: обязательно написать «точка блокировки / замещающее основание / риск».

## Требования к исполнению рецензирования сеттинга истории

Следующее специальное содержимое рецензирования сеттинга перенесено в references `городской-офис-рецензия-настроек-истории`; при исполнении этого Prompt **необходимо одновременно загрузить и соблюдать**:

- `../skills/городской-офис-рецензия-настроек-истории/SKILL.md`
- `../skills/городской-офис-рецензия-настроек-истории/references/дополнение-к-жанровому-шаблону-технической-рецензии.md`

И необходимо исполнять совместно **по основному каркасу, выведенному маршрутизацией текущего жанрового Skill, и дополнению жанровыми шаблонами**; нельзя выдавать упрощённый отчёт «несколько реплик + немного советов», а также нельзя во входном Prompt вести второй параллельный каркас.

## Нормы вывода и записи в хранилище (специально для сеттинга истории)

Рекомендуемый путь: `审阅意见/故事设定/设定审阅报告_文件名_YYYY-MM-DD.md`

### Обязанности, сохраняемые этим Prompt

- Подтвердить целевой файл сеттинга, сюжетный модуль, которому он служит, режим технической осуществимости и стратегию вывода
- Сохранить цепочку чтения, путь записи в хранилище и ограничение «обязательно реально сформировать отчёт»
- На уровне входа сначала закрепить минимальные пороги, которые нельзя пропустить при рецензировании: «первое появление / три главы / микроаномалия / ситуация «в упор»»

### Минимальные требования к выводу

- Структура отчёта исполняется совместно по общему шаблону рецензирования сеттинга и `дополнение-к-жанровому-шаблону-технической-рецензии.md`
- Охватить как минимум цепочку чтения, проверку основной информации, проверку первого появления и первых трёх глав, согласованность персонаж—ситуация—точка зрения, карточки применения при письме, пункты правил, реальную осуществимость и процедурную разумность, длинную эскалацию, реальные «болевые точки» / эмоциональный резонанс, подтверждение доказательствами, процедурное трение, согласованность персонажей / организаций
- В отчёте необходимо чётко написать **тип постоянного питания** этого сеттинга (например: интеллектуальный прорыв / институциональный контрудар / пробивающий страх / распространение и обсуждение и т. п.)
- В отчёте необходимо дать предложения по исправлению, которые можно напрямую записать обратно в документ сеттинга, и как минимум `1` предложение по исправлению награды первого появления / первых трёх глав

Полный шаблон отчёта, пункты оценки, список проблем и формат записи обратно уровня примеров единообразно определяются общим шаблоном рецензирования сеттинга и `дополнение-к-жанровому-шаблону-технической-рецензии.md`; входной Prompt больше не ведёт вторую параллельную копию шаблона, чтобы не допускать последующего расхождения.
