# SOP рецензии и оптимизации плана

## Маршрутизация жанровых навыков (обязательно)

При срабатывании этого Prompt необходимо сначала вызвать: `общий-цикл-рецензии-плана`.

Этот вход не имеет права выдавать «однократную рецензию» за «замкнутый цикл рецензии и правки» и не имеет права пропускать жанровые Skill рецензии / проектирования, «голо» рецензируя или правя.

## Обязанности, которые остаются только у этого Prompt

- Единый вход замкнутого цикла рецензии и оптимизации плана
- Сохраняет минимальный вход, обнаруживаемость объекта, якоря порядка исполнения, порог оценки и ограничения минимальной квитанции
- Маршрутизирует основную логику цикла в `общий-цикл-рецензии-плана`

## Минимальный вход

- Путь к целевому файлу плана
- Тип объекта: общий план / часть / том / единица-событие

## Якоря исполнения, которые слой входа обязан сохранять

Даже если основной процесс перенесён в Skill, этот вход обязан сохранять следующую **не подлежащую потере** информацию, чтобы при исполнении не деградировать до «рецензии один раз» или «только рекомендаций»:

1. Сначала обязательно определить, существует ли уже главный отчёт рецензии, соответствующий целевому плану; если существует — зафиксировать этот отчёт и постоянно **обновлять с перезаписью**, если нет — сначала создать.
2. Рецензия первого раунда обязана сначала выдать **полную версию отчёта рецензии** и записать в `审阅意见/`; в отчёте должна ясно читаться строка: `- 综合评分：X.X/10`.
3. Пока последняя интегральная оценка `<= 9,2`, обязательно переходить к этапу правки; правка обязана опираться на проблемы, рекомендации по правке и «идеи оптимизации для прорыва интегральной оценки 9,2+» из отчёта предыдущего раунда и **прямо записываться обратно в целевой файл плана**.
4. После каждой правки обязательно рецензировать заново и записывать результат в **тот же главный отчёт рецензии**, нельзя заводить ответвление отчётов «второй / третьей / исправленной версии».
5. Завершать разрешено только если последняя интегральная оценка **строго больше 9,2**; сам `9,2` не считается пройденным.

## Обнаружение объекта и определение отчёта

- Если пользователь не указал тип объекта, в первую очередь выводить по имени файла и структуре каталогов.
- При необходимости можно одновременно выводить номер или название плана для сопоставления главного отчёта рецензии.
- Если в `审阅意见/` сопоставлено несколько отчётов по тому же объекту, тому же номеру или тому же названию, по умолчанию брать отчёт с **самой свежей датой** как текущий главный.
- Кроме случаев, когда путь не удаётся разобрать, файл отсутствует или возникает настоящая блокирующая ошибка, нельзя прерывать цикл переспросами из-за деталей именования.

## Фиксированный порядок исполнения (версия, сохраняемая во входе)

1. Определить, существует ли главный отчёт рецензии для целевого плана
2. Если существует — зафиксировать и обновлять с перезаписью; если нет — создать новый главный отчёт
3. Вызвать `общий-цикл-рецензии-плана`
4. По типу объекта маршрутизировать в жанровую цепочку рецензии / проектирования:
   - Слой общего плана: `общий-рецензия-общего-плана` ↔ `общий-проектирование-общего-плана`
   - Уровень части / тома / единицы-события: `общий-рецензия-плана-тома` ↔ `общий-проектирование-плана-тома`
5. После рецензии первого раунда прочитать последнюю интегральную оценку
6. Если `интегральная оценка <= 9,2`, править целевой план по последнему отчёту и записывать обратно в исходный файл
7. Повторная рецензия и обновление с перезаписью того же главного отчёта рецензии
8. Повторять 5–7 до тех пор, пока `интегральная оценка > 9,2`

Дополнительное напоминание: для объекта общего плана по умолчанию идёт «`общий-рецензия-общего-плана` ↔ `общий-проектирование-общего-плана`», для объектов тома / единицы-события по умолчанию идёт «`общий-рецензия-плана-тома` ↔ `общий-проектирование-плана-тома`»; нельзя смешивать предложения по правкам двух уровней в одном проходе и беспорядочно записывать их обратно.

## Минимальные ограничения исполнения

- Отчёт рецензии обязан постоянно обновляться с перезаписью как главный отчёт одной и той же задачи
- Правка обязана прямо записываться обратно в целевой файл плана
- Остановиться разрешено только если последняя интегральная оценка **строго больше 9,2**
- `9,2` не считается пройденным

## Выдача по умолчанию

- Последний целевой файл плана записан обратно
- Главный отчёт рецензии обновлён с перезаписью
- Чат отвечает только минимальной квитанцией: раунд, оценка, целевой файл, файл отчёта, продолжать ли

## Поля минимальной квитанции в чате

Окну чата не нужно пересказывать весь отчёт или весь план, но как минимум нужно указать:

1. Целевой файл плана
2. Файл главного отчёта рецензии
3. Способ записи отчёта в этом раунде: обновление с перезаписью / создание нового
4. Текущая интегральная оценка
5. Продолжать ли доработку
6. Достигнута ли в итоге `интегральная оценка > 9,2`

## Основное содержимое, перенесённое в Skill

Следующее содержимое перенесено в `городской-офис-цикл-рецензии-плана` и его общее ядро, и больше не ведётся параллельно в этом Prompt:

- Запись раундов, отслеживание исправленных / неисправленных проблем
- Более полное определение главного отчёта, обновление с перезаписью и детальные нормы контроля порога
- Детальные нормы замкнутого цикла «рецензия → правка → повторная рецензия → повторное суждение» с записью на диск
- Требования разведения объектов жанра и согласованности жанровых источников суждения

## Напоминание одной фразой

Этот Prompt сейчас — **слой входа**, но его нельзя ослаблять до одной фразы «вызови Skill»; слой входа обязан сохранять достаточные якоря исполнения, а настоящие детали цикла читать и исполнять дальше в соответствующих Skill.
