# Лёгкий входной Prompt шлифовки основного текста «Названия произведения» жанра «Городская офисная проза»

## Связанные навыки (специализированные для шлифовки основного текста)

[`общий-шлифовка-основного-текста`｜шлифовка основного текста](../skills/общий-шлифовка-основного-текста/SKILL.md)

Для любой задачи «доводка целой главы / перешлифовка полного чернового варианта главы / усиление ощущения продолжения чтения / прямая запись основного текста обратно / усиление начала главы, середины, конца при нулевой потере информации» необходимо в первую очередь загрузить и соблюдать этот skill.

Если цель пользователя сужается, можно дополнительно вызвать соответствующий специализированный skill:

- Исправить лишь `## 作者有话说` («Слово от автора»): вызвать `общий-шлифовка-слова-автора`
- Усилить лишь цепкость входа в первые 150–300 знаков: вызвать `общий-усиление-начала-главы`
- Усилить лишь удар «следующую главу нельзя не прочесть» в конце главы: вызвать `общий-усиление-хука-конца-главы`
- Перед мультиплатформенным выводом сначала очистить китайскую основу: вызвать `общий-очистка-мастер-черновика`
- Если цель в основном удаление ИИ-привкуса, а не шлифовка уровня общей приёмки: вызвать `общий-устранение-духа-ии`

## Обязанности, которые сохраняются за этим Prompt

- Служит лёгким входом `/шлифовка-основного-текста`, отвечает за маршрутизацию задачи в `общий-шлифовка-основного-текста`.
- Ограничивает: эта задача — «формальная шлифовка» или «только демонстрация небольшого фрагмента». Если пользователь явно не требует лишь демонстрации, по умолчанию это формальная шлифовка с прямым изменением файла.
- Ограничивает: объект сопровождения по умолчанию — **рабочий файл автора / исходный Markdown**; наличие в одном файле `章节正文`, `## 作者有话说` («Слово от автора»), `## 章节后记` («Послесловие к главе»), `## 润色说明` («Пояснение к шлифовке») — нормальная структура, нельзя ошибочно считать её грязной.
- Ограничивает: окно чата ведёт лишь краткий отчёт: какой файл обновлён, целиком или локальной заменой, обновлены ли заодно послесловие / пояснение к шлифовке, без необоснованной вставки в чат всего текста главы.

## Минимальное подтверждение перед началом работы

Если пользователь не разъяснил, в первую очередь выяснить следующее:

1. Путь к файлу целевой главы
2. Охват обработки: целая глава / некая сцена / несколько абзацев
3. Акцент этого прохода: цепкость начала / награда в середине / крючок в конце главы / диалоги / вовлечение / удаление ИИ-привкуса / комплексная доводка
4. Разрешена ли запись обратно в файл напрямую (по умолчанию разрешена; исключение — только когда пользователь явно сказал «сначала показать пример, файл не менять»)

## Минимальные требования к исполнению

- Сначала обязательно войти в `общий-шлифовка-основного-текста` и по файлам процесса и чек-листам определить уровень и приоритет шлифовки этого прохода.
- При необходимости обязательно дочитывать перенесённые references, а не браться за письмо, опираясь лишь на этот короткий Prompt.
- Обязательно защищать речевой канон персонажей, ограниченную точку зрения, цепочку доказательств, процедурное сопротивление, поля времени / номеров и награды внутри главы.
- Обязательно записывать результат формальной шлифовки в целевой файл основного текста, а не оставлять его выводом в чате.
- После завершения обязательно давать краткую, поддающуюся проверке сводку правок.
