# Рецензирование плана

## Маршрутизация жанровых навыков (обязательно)

При исполнении этого Prompt необходимо сначала определить уровень объекта рецензирования, затем вызвать соответствующий жанровый Skill:

- Общий план / общая таблица / грани истории / общий план зацепок / общая хронология → `通用-审阅总大纲`
- Часть / том / список глав / исполняемая версия единицы-события / артефакты ритма и крючков → `通用-审阅分卷大纲`

Prompt не имеет права, минуя жанровый Skill, «голо» рецензировать.

## Обязанности, которые остаются только у этого Prompt

- Служит единым входом рецензирования плана в жанре «Городская офисная проза»
- Сохраняет разведение объектов, общие критерии суждения рецензирования, цепочку чтения, минимальный вход, запись отчёта в хранилище и ограничения минимальной квитанции
- Маршрутизирует специфичные для уровня пункты проверки, дополнения отчёта, акценты оценки и стратегию минимальных патчей в соответствующий жанровый Skill

## Общие критерии суждения рецензирования (сохраняются на уровне входа)

### Приоритет авторской направленности

- План — не текст, предназначенный читателю напрямую; главный критерий оценки: способен ли он надёжнее направлять автора в написании глав для сериала.
- В рецензии в первую очередь смотреть: исполнимость, возможность разбиения на главы, можно ли реалистично написать доказательства / процедуры / время / цену, а не литературность плана.
- Допускается простой текст, но не допускаются пустые слова, лозунги, нагромождение понятий, узлы без носителя доказательств, невозможная к приземлению хронология.

### Запись в хранилище по умолчанию

- Если пользователь явно не потребовал «только обсуждать, файлы не писать», отчёт рецензии по умолчанию записывается в `审阅意见/`.
- Если уже есть соответствующий главный отчёт, по умолчанию обновлять с перезаписью последний действующий главный отчёт; если нет — создать новый.
- На стороне чата достаточно кратко сообщить целевой файл, файл отчёта, оценку и нужно ли продолжать доработку; пересказывать весь текст отчёта не следует.

### Минимальный вход

- Путь к файлу целевого плана
- Тип объекта рецензии: общий план / часть / том / единица-событие/узел
- Стратегия вывода в этот раз: перезапись｜добавление рецензии этого раунда (если не указано, по умолчанию добавлять или перезаписывать главный отчёт — выбирать по существующей цепочке)

### Нижняя граница цепочки чтения

- Сначала прочитать `设计大纲.prompt.md` и связанные материалы исследований / обзоров.
- Объекты части / тома / единицы-события/узла: сначала прочитать вышестоящий общий план, при необходимости — затем соответствующую часть и связанные реестры.
- Если вышестоящее отсутствует, в отчёте обязательно явно указать: точку блокировки, временное замещающее основание, риски, возникающие из-за этого.

### Платформа, выносливость и против ИИ-привкуса

- При рецензии нельзя смотреть только на логическую самосогласованность, нужно также смотреть: платформенную адаптацию, обещание начала, выносливость длинной формы, награды внутри глав, опорные точки реальности и борьбу с ИИ-привкусом.
- Для объекта общего плана по умолчанию дополнительно нужно судить: точку запоминания редактором за 1 минуту, обещание первого тома, материнскую библиотеку процедур, окно доказательств замыкания причинности, нет ли обрыва питания в сериях средних томов, согласованы ли направления обещания начала и финала.
- Для объектов части / тома / единицы-события/узла по умолчанию дополнительно нужно судить: цепочку продолжения чтения первых 5 глав, плотность наград в середине тома, долю свежих конфликтов, усталость от крючков, повторные покупки в конце тома и адаптацию платформенного разбиения на главы.
- В отчёте нужно указать: какие места больше всего похожи на высококонцептуальные пустые слова / ИИ-подобные резюме, и во что их следует переписать: какие события, доказательства, действия, процедурное трение или цену персонажа.
- Для объектов общего плана / тома по умолчанию дополнительно нужно судить: действительно ли грани истории подключены к общему плану / тому, а не просто красиво выглядят выводы исследовательского слоя.

## Фиксированный порядок разведения

1. Сначала определить уровень объекта рецензирования.
2. Сначала вышестоящее, потом нижестоящее: общий план приоритетнее части / тома; если вышестоящее отсутствует, сначала в отчёте записать точку блокировки и риски.
3. Если объект охватывает уровни общего плана и тома, сначала вызвать `通用-审阅总大纲`, затем `通用-审阅分卷大纲`, но не наоборот.
4. Затем вызвать соответствующий жанровый Skill для продолжения исполнения.
5. Отчёт записывается в `审阅意见/`, на стороне чата — лишь минимальная квитанция.

## Основное содержимое, перенесённое в Skill

Следующее содержимое перенесено в `都市职场-审阅总大纲`, `都市职场-审阅分卷大纲` и их references, больше не ведётся параллельно в этом Prompt:

- Четырёхэтапное нарастание механизма на уровне общего плана, питание единиц-событий, точка запоминания редактором, материнская библиотека процедур, окно доказательств замыкания причинности, обещание начала, выносливость длинной формы, «болезнь ИИ-плана» и минимальный патч уровня общего плана
- Список преемственности уровня части / тома, ритм 5/15, цепочка продолжения чтения первых пяти глав, награды в середине главы, доля свежих конфликтов, усталость от крючков, повторные покупки в конце тома, адаптация платформенного разбиения на главы, замыкание единиц-событий и минимальный патч уровня тома
- Дополнения отчёта, специфичные для уровня, суждения о платформенной адаптации, диагностика борьбы с духом ИИ и минимальные требования к записи обратно
