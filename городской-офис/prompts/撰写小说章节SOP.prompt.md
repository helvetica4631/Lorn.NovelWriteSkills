# SOP написания главы романа

## Маршрутизация жанровых навыков (обязательно)

При срабатывании этого Prompt необходимо сначала вызвать: `通用-章节创作闭环`.

Если у текущей партии глав уже есть чёткий план тома / список глав, по умолчанию `通用-生成章节控制卡` следует считать обязательным вышестоящим слоем перед строительством основного текста, а не необязательным дополнением.

Этот вход не вправе выдавать «написание одного лишь чернового варианта» за «полный SOP главы» и не вправе в обход жанровой цепочки напрямую вызывать общую основу создания основного текста.

## Обязанности, которые остаются только у этого Prompt

- Служит единым входом замкнутого цикла создания главы
- Сохраняет платформу по умолчанию / каталог основного текста по умолчанию, обнаруживаемость пакетного режима, минимальное условие завершения и ограничения на итоговую сводку
- Направляет основной ход исполнения в `通用-章节创作闭环`

## Жёсткие ограничения, которые вход обязан сохранять

### Платформа и каталог основного текста по умолчанию

- Целевая платформа определяется основной платформой вывода в Agents.md в корне проекта.
- Если пользователь явно не указал каталог другой платформы, основной текст по умолчанию размещается в `小说正文/` в корне рабочей области.
- Если пользователь указал лишь номер главы, заголовок, сведения о томе / части и явно не задал `CHAPTER_FILE`, при исполнении путь к основному тексту следует в первую очередь выводить в соответствующий каталог `小说正文/`, а не принимать каталоги Fanqie, Zhihu, WeChat Official Accounts, GoodNovel, My Fiction, WebNovel или издательства за место размещения по умолчанию.
- Написание основного текста, шлифовка, удаление ИИ-привкуса, рецензия, читательские продукты и итоговая сводка в этом SOP по умолчанию работают с исходным основным текстом главы в `小说正文/`; версии для других платформ по умолчанию передаются последующей мультиплатформенной цепочке.
- Номера вроде `C01`, `FB-01`, `SL-02`, `R3`, `M0`, используемые лишь для авторского реестра / управления планом, нельзя напрямую вписывать в основной текст главы, эпиграф главы или `## 作者有话说` («Слово от автора»); если читатель должен их воспринять, их нужно переписать в реально существующее внутри сюжета повествование или выражение через доказательства.

### Поддерживаемые входы и обнаруживаемость пакетного режима

- Вход одной главы по умолчанию: `OUTLINE_FILE + CHAPTER_FILE`.
- Для нескольких глав подряд можно подать: `CHAPTER_FILES[]`, `OUTLINE_FILES[]`, `CHAPTER_BATCH[]`, `BATCH_ID`.
- Если передан `CHAPTER_BATCH[]`, за основу берётся он; если передан лишь `CHAPTER_FILES[]`, по умолчанию главы замыкаются по очереди, при необходимости повторно используя один и тот же `OUTLINE_FILE` или соответствующий элемент `OUTLINE_FILES[]`.
- Пакетный режим — не режим со сниженным стандартом: для каждой главы по-прежнему нужно выдать `CHAPTER_FILE`, `REVIEW_REPORT_FILE`, `READER_NOTE_FILE`, `BOOK_REVIEW_FILE`, а оценки и журналы замыкаются отдельно по каждой главе.

### Исполнительская роль и единственный выход завершения

- Этот Prompt — вход исполнителя, а не планировщика; после срабатывания шаги нужно реально пройти до конца, а не выводить лишь план, промежуточный отчёт, список черновиков или «что будет сделано дальше».
- Если нет жёсткой нехватки параметров (например, `OUTLINE_FILE` не существует или `CHAPTER_FILE` невозможно надёжно вывести), нельзя останавливаться на полпути в ожидании ответа пользователя «продолжай».
- Заявлять о завершении можно лишь тогда, когда основной текст, итоговый отчёт рецензии, читательские заметки, отзыв на главу и журнал полностью замкнуты.
- Любое изменение основного текста после шага 2 требует повторного подсчёта объёма и обновления затронутой цепочки рецензии, оценочных суждений и итоговой сводки.
- Пакетный режим должен замыкаться по главам; нельзя подменять поглавную проверку устным обобщением всей партии; пока хоть одна глава не замкнута, всю партию нельзя помечать завершённой.
- В чате в конце разрешено выводить только сводку о завершении задачи из шага 12, но не основной текст главы.

## Минимальный вход

- `OUTLINE_FILE`
- `CHAPTER_FILE`
- `RELATED_CONTEXT_FILES[]` (необязательно)
- `CHAPTER_FILES[] / OUTLINE_FILES[] / CHAPTER_BATCH[] / BATCH_ID` (необязательно, для пакетного режима)

## Основное содержимое, перенесённое в Skill

- Полный замкнутый цикл главы по шагам 0→12 и шлюзы продвижения между этапами
- Вывод путей по умолчанию, именование артефактов, резервная классификация и расположение реестра непрерывности по умолчанию
- Пакетный режим, поэтапный конвейер, изоляция сбоев и продолжение по журналу
- Порог `9.2+`, цикл доработки, обязательное правило «первую цепочку рецензии нельзя пропускать»
- Определение завершения для одной главы / партии, шаблон сводки и поля согласованности
- Цепочка письма жанра «Городская офисная проза», непрерывность процессуальных доказательств, городское давление и ограждения окон развязки
- Правила моста строительства: контрольная карта вносится в основной текст, затем разбивается на сценические единицы / конфликты диалога / кадры микропространства
- Жанровые соглашения о путях читательских заметок и отзывов на главы, порядок генерации и правила пересоздания устаревших
- Очерёдность и границы защиты `作者有话说` («Слово от автора»), удаления ИИ-привкуса и рецензии глав во второй половине замкнутого цикла

## Выдача по умолчанию

- `CHAPTER_FILE`
- `REVIEW_REPORT_FILE`
- `READER_NOTE_FILE`
- `BOOK_REVIEW_FILE`
- В чате в конце возвращается лишь сводка о завершении в стиле шага 12

## Напоминание одной фразой

Этот Prompt теперь — **слой входа**; но он по-прежнему обязан закрепить цель по умолчанию, выход завершения и нижнюю границу, запрещающую ложное признание завершённости. Настоящий SOP создания главы, пакетный режим, механизм журналов и ограждения непрерывности жанра «Городская офисная проза» нужно читать в соответствующих Skill и исполнять там.
