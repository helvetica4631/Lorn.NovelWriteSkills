# городской-офис-оркестрация-вывода-на-платформы

## Соответствующий общий Skill

- `общий-оркестрация-вывода-на-платформы`

## Обязанности слоя

- Сохранять жанровое входное имя «городской-офис-оркестрация-вывода-на-платформы».
- Маршрутизировать общую оркестрацию SOP мультиплатформенного вывода в `общий-оркестрация-вывода-на-платформы`.
- Дополнять фиксацию основы жанра перед рассылкой по платформам: аномальные доказательства, процедурное трение, реальная цена, городское ощущение давления и долгие закулисные факты нельзя вымывать до нейтрального детективного черновика.

## Справочник частых триггерных слов / формулировок пользователя

- Разошли эту главу «Городской офисной прозы» на несколько платформ
- Запусти SOP многоплатформенного вывода «Городской офисной прозы»
- Сделай платформенное переписывание и сохранение для этих глав разом
- Массовая раздача с жанровой достоверностью

## Порядок комбинированных вызовов по умолчанию

1. Сначала загрузить и использовать `общий-оркестрация-вывода-на-платформы`
2. Сначала вызвать `городской-офис-очистка-мастер-черновика`
3. Затем вызвать `городской-офис-адаптация-под-платформы`
4. В конце по платформам вызвать соответствующие `городской-офис-вывод-*`

## Правила наследования исполнения (обязательно)

- При срабатывании этого навыка, помимо патчей жанровой достоверности, обязательно полностью наследовать и исполнять «15-шаговый замкнутый цикл исполнения» `общий-оркестрация-вывода-на-платформы`, не удаляя, не изменяя, не пропуская шаги и не понижая уровень.
- Если пользователь ставит задачу в виде «какая часть, какой том, какая глава», целевое положение по умолчанию обязательно определять в `小说正文/`, не требуя от пользователя повторно указывать путь.
- Если пользователь не указал платформы, набор платформ по умолчанию обязан динамически определяться по текущим доступным платформам вывода (сейчас 13, новые платформы в будущем включаются автоматически).
- Сходство, объём знаков, борьба с «водой» и ворота бессмысленных символов — всё жёсткие ворота; при провале любых обязательно доработка до достижения порога.
- Пока не завершены «запись на диск по всем указанным платформам + достижение порога всех ворот + журнал, допускающий возобновление», нельзя останавливать процесс.
- Необходимо наследовать и выполнять «ворота полноты вызовов» общего слоя: в каждой главе этого жанра обязательно вызывать `городской-офис-очистка-мастер-черновика` и `городской-офис-адаптация-под-платформы`, а для каждой пары «глава × целевая платформа» — соответствующий `городской-офис-вывод-*`; если в журнале вызовов есть пробел, задача не может считаться завершённой.

## Обязательные требования

- При срабатывании этого навыка в первую очередь обязательно принудительно загрузить текущий жанровый Skill и `общий-оркестрация-вывода-на-платформы`.
- При срабатывании этого навыка в первую очередь обязательно принудительно загрузить текущий жанровый Skill и `общий-оркестрация-вывода-на-платформы` и строго исполнять по 15-шаговому замкнутому циклу общего слоя.
- Нельзя в обход жанровой цепочки раздавать исходный черновик по платформам.
- Основу жанра нужно сначала зафиксировать, затем делать платформизацию и снижение сходства.
- Ни одна платформенная версия не должна вымывать «Городскую офисную прозу» до чистого уголовного розыска, чистого общественного комментария или нейтрального триллерного черновика.
- Даже если ворота платформы пройдены, если якоря реальности, цепочка аномальных доказательств, процедурное трение, номерной формат, городское ощущение давления или питание долгих закулисных фактов основной линии вымыты, обязательно возвращать на доработку.
- Гранулярность продолжения должна доходить до узлов «глава × платформа»; жанровый слой не должен стирать результаты жанровой достоверности, уже прошедшие на других платформах, из-за провала на одной платформе.
