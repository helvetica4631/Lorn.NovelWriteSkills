## Соответствующий общий Skill

- `通用-设计事件案件引擎`

## Обязанности слоя

- Сохранять стандартное входное имя «都市职场-设计事件案件引擎».
- Маршрутизировать общий каркас проектирования движка событий / конфликтов в `通用-设计事件案件引擎`.
- Дополнять в жанре «Городская офисная проза»: **институциональные конфликты (увольнения / PIP / перевод с понижением зарплаты / роль «крайнего» / присвоение чужих заслуг)**, процессное сопротивление (согласование / полномочия / учёт рабочего времени / показатели KPI), носители доказательств (почта / IM / протоколы совещаний / расписки / учёт трудозатрат) и требования к выплате точек 爽 «контрмеры по правилам».

## Обязательные требования

- При срабатывании этого навыка в первую очередь обязательно принудительно загрузить текущий жанровый Skill и `通用-设计事件案件引擎`.
- Нельзя в обход `通用-设计事件案件引擎` восстанавливать в этом файле целый параллельный набор общих правил.
- В жанре «Городская офисная проза» слово «дело» (案件) в имени этого Skill сохранено лишь для совместимости со старым входом; фактически всё исполняется как: **единица-событие / узел защиты прав / узел проекта / узел институционального конфликта**, без детективной уголовной логики.
- Движок событий обязан отвечать: кто на какой должности / в каких полномочиях что сделал → какой процесс / формулировку это запустило → какие доказательства / расписки получил персонаж → какую цену заплатил → в какой главе выплачена точка 爽 (контрудар / переворот / продвижение узла арбитража) → какой отголосок.
- Текущая жанровая цепочка единообразно использует это стандартное входное имя.
- Конфликт в первую очередь должен вырастать из реальных офисных механизмов, а не падать с неба из чисто абстрактного заговора.

## Справочник частых триггерных слов / формулировок пользователя

- Помоги спроектировать эту единицу-событие
- Как эта единица-событие питает основную линию
- Как сделать первую аномалию / первую странную деталь
- Как расширять и как сужать пул атрибуции ответственности
- Как сделать введение в заблуждение опровержимым
- Куда класть носитель доказательства
- Какой отголосок оставить после завершения события

## Когда использовать

Когда задача относится к любому из следующих случаев, загрузить и следовать этому Skill:

- Проектирование единиц-событий / узлов институциональных конфликтов / материнских плат событий для тома или последовательных глав.
- Рассмотреть, действительно ли какая-то единица-событие питает основную линию, а не создаёт лишь атмосферную суету.
- Спроектировать полный движок «сигнал аномалии → расследование / противостояние → цепочка улик → ложный ход и опровержение → цена → последствия».
- Нужно согласовать единицу-событие с журналом улик, журналом пула атрибуции ответственности и журналом зацепок и возвратов.

## Запреты

- Не писать жанровый каркас как параллельную копию `通用-设计事件案件引擎`.
- Не опускать требование загрузки соответствующего общего Skill.
- Нельзя писать трение городской реальности как абстрактные тематические лозунги, не опуская его в цепочку событий и цепочку доказательств.
