# 都市职场-设计人物传记

Это жанровая обёртка и совместимый вход. При срабатывании этого навыка **в первую очередь обязательно принудительно загрузить** текущий жанровый Skill и `通用-设计人物传记`; текущий жанровый Skill отвечает за норму и границы суждения жанра «Городская офисная проза», а `通用-设计人物传记` — за общий каркас и общий процесс проектирования биографий персонажей.

Писать биографию персонажа как файл Canon, который автор может долго использовать, а не как красивый, но трудно приземляемый текст описания персонажа.

## Когда использовать

Вызывать этот skill в следующих ситуациях:

- Вам нужно создать новый `人物传记/人物名.md` (биография персонажа / имя).
- Вам нужно переписать старую биографию в версию, которую «можно писать, можно рецензировать, можно согласовать с планом».
- Вам нужно добавить персонажу писательские зацепки, психологическую дугу, сеть отношений и отображение индекса.
- Вам нужно исправить проблему «у персонажа много ярлыков, но их трудно написать в основном тексте».

Не использовать ошибочно в следующих ситуациях:

- Пишется только временный персонаж одной главы, и он не будет использоваться повторно.
- Нужно лишь небольшое описание персонажа для фрагмента основного текста.
- Делается только читательский текст-знакомство с персонажем.

## Цели проектирования

Годная биография персонажа обязана одновременно выполнять пять задач:

1. **Личность поддаётся сверке**: имя, принадлежность к организации, положение в отношениях, временной этап не конфликтуют.
2. **Мотив способен вести сюжет**: чего хочет, что боится потерять, какую цену готов заплатить — должно быть написано реалистично.
3. **У способностей есть границы**: что умеет, чего не умеет, почему не всемогущ.
4. **Можно использовать в основном тексте**: реплики, действия, триггеры, предпочтения в оставлении следов, шаблоны контрмер можно прямо писать в основной текст.
5. **Можно вернуться к вышестоящему**: можно согласовать с общим планом, планами томов, ключевыми событиями и возвратами предзнаменований.

## Разделение с входным Prompt

- Входной Prompt `../prompts/撰写人物传记.prompt.md` продолжает отвечать за общие правила: авторское позиционирование, стратегию записи файла, общие красные линии качества, соглашение о путях рабочего пространства.
- Этот Skill отвечает только за **специальные правила биографий персонажей**, вынося из входного Prompt шаблон персонажа, психологическую дугу, писательские зацепки и структуру индекса.

## Порядок выполнения по умолчанию

1. Сначала по входному Prompt подтвердить целевой файл биографии персонажа и стратегию записи.
2. Определить уровень персонажа: ключевой / важный / второстепенный.
3. Загрузить `references/人物传记模板与写作抓手.md`, сначала построить структуру.
4. Загрузить `references/创新人物设计与心理弧线规范.md`, дополнить двигатель персонажа, тревогу эпохи, будничное отчуждение и психологические дуги по типам.
5. Загрузить `references/心理弧线与索引规则.md`, дополнить психологические шаги и критерии индекса.
6. Загрузить `references/三级大纲索引模板.md`, записать индексы общего плана / части / тома как структуру с обратными ссылками.
7. Записать обратно файл биографии, обеспечив как минимум семь блоков: «личность, мотив, границы, отношения, зацепка, психологическая дуга, индекс».

## Жёсткие правила

- Биография — не рекламный текст, запрещено писать лишь абстрактные похвалы и порицания.
- Каждую ключевую черту по возможности приземлять в: поведенческая деталь → носитель / привычка → проверяемое последствие.
- У ключевого персонажа обязательно набор из трёх: изъян, тайна, одержимость.
- Ключевую тайну в первую очередь делать подтверждаемой доказательствами, а не чисто психологической.
- Сеть отношений обязана порождать события, не может быть лишь «отношения хорошие / плохие».
- Писательские зацепки должны быть короткими, копируемыми, способными приземляться в кадр.
- Нельзя в обход `通用-设计人物传记` писать другой параллельный набор общих правил.
## References для дальнейшего чтения (гейт обязательного чтения)

**Перечисленные ниже файлы references обязательно читать по одному через инструмент `read_file`; нельзя пропускать ни один под предлогом «знания уже есть», «в прошлый раз уже читал» или «этот файл — всего лишь справка».** Каждая запись references выполняется принудительно по указанному для неё уровню обязательности чтения:

- Файлы с пометкой **обязательно читать**: их нужно прочитать, пропуск хотя бы одного считается нарушением процесса, начинать выполнение процесса нельзя.
- Файлы без пометки «обязательно»: их нужно прочитать, но после прочтения можно извлечь только фрагменты, прямо относящиеся к текущей задаче, построчное прочтение не требуется.
- Если файла по указанному пути не существует (например, внешний путь не подготовлен), в журнале обязательно явно записать `reference_missing_{refName}`, молча пропускать нельзя.
