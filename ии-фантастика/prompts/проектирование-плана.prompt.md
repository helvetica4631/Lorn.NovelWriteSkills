# Проектирование плана

## Маршрутизация жанровых навыков (обязательно)

При исполнении этого Prompt необходимо сначала определить уровень задачи, затем вызвать соответствующий жанровый Skill:

- Общий план / общая таблица / грани истории / общий план зацепок / общая хронология → `общий-проектирование-общего-плана`
- Часть / том / список глав / таблица запуска тома / сюжетные точки / расстановка точек 爽 / разбор единиц-дел внутри тома → `общий-проектирование-плана-тома`

Prompt не вправе в обход жанрового Skill напрямую использовать общую основу проектирования плана.

## Обязанности, которые остаются только у этого Prompt

- Служит единым входом проектирования плана в жанре «ИИ-фантастика»
- Сохраняет разделение по объектам, общий арбитражный канон, минимальный ввод, запись обратно в файл и ограничения на минимальную квитанцию
- Направляет шаблоны, правила, приёмку и артефакты уровня глав, специфичные для уровня, в соответствующий жанровый Skill

## Общий арбитражный канон (сохраняется на уровне входа)

### Приоритет авторской направленности

- План прежде всего служит тому, чтобы «автор мог писать, разбивать на главы, записывать обратно и проверять», а не быть рекламным текстом для прямого чтения читателем.
- Цели читательского опыта (продолжение чтения, точки 爽, крючки, выносливость) обязательно записываются как исполнимые автором «обещание → реализация → новый разрыв / новая цена», а не просто лозунги.
- Ключевые узлы в первую очередь записывать так: кто что сделал → какой носитель цифровых следов оставил → какие проверяемые последствия вызвал.
- Усиленные сведения о гранях истории, оценке подписания контракта и платформенном позиционировании по умолчанию должны и дальше явно приниматься на уровне общего плана / тома, а не оставаться в вышестоящих аналитических файлах.

### Запись обратно по умолчанию

- Если пользователь явно не требует «только обсудить, без записи в файлы», по умолчанию запись напрямую в Markdown-файл в целевом `小说大纲/`.
- Если пользователь не пояснил, перезапись это или дополнение, по умолчанию применяется консервативная стратегия: точная вставка / замена в исходной структуре, при необходимости добавление раздела «правки этого прохода».
- Если задача — создать файл плана некоего уровня, его нужно создать и записать в `小说大纲/` по существующей системе именования.

### Минимальный вход

- Путь к файлу целевого плана или выводимые с уверенностью целевой уровень и объект
- Уровень задачи: общий план / часть / том / список глав / единиц-дел
- Если текущий объект явно зависит от вышестоящего: путь к вышестоящему плану или связанному реестру

### Нижняя граница исследования и глубокого размышления

- Если задача затрагивает жанровое позиционирование, платформенную адаптацию, стратегию начала, выносливость длинной формы, сопряжение с общественными темами, инновационные комбинации и т. п., прежде чем писать, в первую очередь следует сверяться с соответствующими документами в `写作研究/` и `调研报告/`.
- Если нет доступа в сеть или инструменты недоступны, можно опираться лишь на имеющиеся в рабочей области исследовательские материалы и допущения здравого смысла, а неопределённые пункты помечать как требующие проверки.
- В файлах плана CANON в первую очередь сохраняются исполнимые выводы; длинные ссылки и длинные выдержки лучше помещать в файлы `NON_CANON_...` в `调研报告/`.

## Фиксированный порядок разведения

1. Сначала определить уровень объекта.
2. Сначала вышестоящее, затем нижестоящее: общий план приоритетнее части / тома; если вышестоящее отсутствует, сначала дополнить минимально пригодный каркас.
3. Затем вызвать соответствующий жанровый Skill и продолжить исполнение.
4. В конце напрямую записать в целевой файл и в чате лишь кратко подтвердить объём правок и способ записи.

## Основное содержимое, перенесённое в Skill

Следующее содержимое перенесено в `ии-фантастика-проектирование-общего-плана`, `ии-фантастика-проектирование-плана-тома` и их references, больше не ведётся параллельно в этом Prompt:

- Грани истории уровня общего плана / основная загадка / матрица единиц-дел / специфичные для общего плана шаблоны и приёмка
- Список преемственности уровня части / тома, шаблон плана тома, список глав, таблица запуска тома, таблица расстановки точек 爽 и микросценарии глав
- Система нумерации каждого уровня, требования к конкретизации, требования к масштабу, правила заголовков и специфичные для уровня стандарты качества
- Для жанра «ИИ-фантастика»: технические опорные точки, система правил, носители цифровых следов, цепкость начала, платформенная адаптация и приёмы написания плана против ИИ-привкуса

## Напоминание одной фразой

Этот Prompt теперь — **слой входа + слой общего арбитража**; настоящие специфичные для уровней правила, шаблоны, артефакты и критерии приёмки нужно по-прежнему читать в соответствующих жанровых Skill и references и исполнять там.
