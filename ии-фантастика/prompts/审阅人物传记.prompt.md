# ИИ-фантастика — рецензирование биографий персонажей (специальный Prompt)

## Связанные навыки (специализированные для биографий персонажей)

[`通用-审阅人物传记`｜рецензирование биографий персонажей](../skills/通用-审阅人物传记/SKILL.md)

Для любой задачи «осмотр биографии персонажа / предложения по записи биографии обратно / аудит мотивации, цены и границ способностей / аудит крючков для письма» следует в первую очередь вызывать этот skill.

> Общие правила и общие красные линии см.: `../agents/小说审阅者.agent.md`. Этот файл содержит лишь чек-лист, шаблоны и правила внесения в библиотеку, «специальные для рецензирования биографий персонажей».

## Целевое позиционирование (документ для автора)
- Биография персонажа — не «краткая биография», предназначенная для читателя, а **эталон согласованности автора + руководство по вызовам при письме**.
- Главный критерий оценки: личность / хронология / границы способностей поддаются сверке, пара «мотивация — цена» способна двигать сюжет, сеть отношений порождает конфликты, речевая и поведенческая «подпись» напрямую переносится в кадр, и **уже в первых трёх главах появления читатель может запомнить, заподозрить, встать на сторону или захотеть следить дальше**.
- Допускается простая биография, но не допускаются: всемогущие способности, продвижение без цены, дыры в хронологии, сеть отношений, не способная запускать события.
- В жанре «ИИ-фантастика» дополнительно нужно судить: прибит ли этот персонаж к реальной городской системе, цепочке технических событий и цепочке системной логики, а не является ли он парящей карточкой персонажа.

## Подтвердить перед началом (если чего-то нет — сначала спросить)
1) Путь к файлу целевой биографии персонажа (относительный путь в репозитории)
2) Положение персонажа в истории: главный герой / напарник / антагонист / ключевой источник данных / проходная функциональная позиция (если пользователь не указал, нужно вывести из биографии и написать)
3) Принадлежность к тому / единице-делу: название тома / номер дела / этап (если нет — писать «неизвестно» и отметить риск)
4) Стратегия вывода в этот раз: перезапись | добавление рецензии этого раунда (по умолчанию — добавление)
5) Ключевая глава первого появления / окно первых трёх глав (если пользователь не дал, вам нужно вывести из биографии, плана или главы появления и записать)

## Цепочка чтения (специально для биографий персонажей | сверху вниз)
В начале отчёта обязательно написать «подтверждение цепочки чтения»:

1) `/.github/prompts/设计大纲.prompt.md`
2) Общий план (если существует): [путь]
3) План тома, к которому относится (если есть / настоятельно рекомендуется): [путь]
4) Биографии других персонажей, сильно связанных с ним (как минимум: близкие отношения / противостояние / одна организация):
	 - [путь]
5) Биография целевого персонажа (обязательно): [путь]
6) Главы ключевого первого появления / первого испытания давлением / первого попадания под подозрение (первые три главы указывать в приоритете): [путь]

Отсутствие любого вышестоящего звена: обязательно написать «точка блокировки / замещающее основание / риск».

## Нормы вывода и записи в хранилище (специально для биографий персонажей)

Рекомендуемый путь: `审阅意见/人物传记/人物传记审阅报告_人物名_YYYY-MM-DD.md`

### Обязанности, сохраняемые этим Prompt

- Подтвердить цель рецензии, функциональную позицию персонажа, принадлежность к тому и стратегию вывода
- Сохранить «подтверждение цепочки чтения» и ограничения пути записи в хранилище
- Обязательно требовать записывать выводы в отчёт, пригодный для записи обратно, а не в разрозненные комментарии в чате
- На уровне входа сначала закрепить минимальные пороги, которые нельзя пропустить при рецензировании: «первое появление / первые три главы / выбор стороны при подозрении / ситуация «в упор»»

### Минимальные требования к выводу

- Структура отчёта исполняется совместно по общему каркасу рецензирования биографий персонажей и `题材人物审阅模板补充.md`
- Измерения рецензирования должны охватывать как минимум цепочку чтения, проверку основной информации, проверку первого появления и удержания в первых трёх главах, согласованность персонажа—ситуации—точки зрения, играбельность / пишемость, ярлыки и арку роста, библиотеку материалов, личность, мотив и цену, границы способностей, сеть отношений, секретные точки взрыва, полноту плана, удержание веб-романа и давление возвращения
- Оценка и рекомендации по исправлению обязаны исходить из фактической рецензии этого раза, нельзя ставить пустые оценки
- В отчёте необходимо чётко написать **тип постоянного питания** этого персонажа (например: профессиональное превосходство / напряжение отношений / точка 爽 контрудара / ценностное «встать на сторону» и т. п.)
- Отчёт обязан дать `1–3` пункта-патча уровня записи, прямо пригодных для записи обратно в биографию, как минимум `1` кадр появления, как минимум `3` реплики, прямо пригодные для переиспользования, а также как минимум `1` патч награды первого появления / первых трёх глав
