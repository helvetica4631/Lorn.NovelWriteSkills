# ии-фантастика-адаптация-под-платформы (Мультиплатформенная адаптация — ИИ-фантастика)

Это жанровая обёртка и совместимый вход. При срабатывании этого навыка **в первую очередь обязательно принудительно загрузить** текущий жанровый Skill и `общий-адаптация-под-платформы`; текущий жанровый Skill отвечает за жанровую рамку и границы на стороне платформы, `общий-адаптация-под-платформы` — за общий каркас и общий процесс.

## Соответствующий общий Skill

- `общий-адаптация-под-платформы`

## Обязанности слоя

- Сохранять старое входное имя и обнаружимость по жанру.
- Маршрутизировать задачи мультиплатформенной адаптации в жанре ИИ-фантастики в `общий-адаптация-под-платформы`.
- Не поддерживать в этом файле повторно библиотеку межплатформенных общих методов, уже перенесённую в общий слой.

## Справочник частых триггерных слов / формулировок пользователя

- Сначала сделай стратегию мультиплатформенной адаптации ИИ-фантастики
- Как развести эту главу для разных платформ
- Не делай сразу лёгкую правку, сначала скажи мне о платформенных различиях
- Версии для этих платформ начали «сталкиваться»
- Сохрани основу ИИ-фантастики, затем делай платформенное переписывание

## Границы с другими Skill / Prompt

- `../prompts/оркестрация-вывода-на-платформы-sop.prompt.md` продолжает отвечать за оркестрацию, сохранение в файл, контроль сходства по системному контролю доступа.
- Подпромпты отдельных платформ продолжают отвечать за жёсткие ограничения своей платформы.
- Эта обёртка отвечает только за подключение задач к общей библиотеке методов адаптации.

## Когда использовать

- Когда нужно развести стилевые различия между платформами: Fanqie, Qimao, Zhihu, Douban, издательство, WeChat Official Accounts, Baidu Baijiahao, Xiaohongshu, Bilibili, Sina Weibo, Zongheng, Toutiao, My Fiction, GoodNovel, WebNovel и т. п.
- Когда нужно сначала прогнать до переписывания, а не сразу писать «универсальный платформенный» вариант.
- Когда версии на платформах «столкнулись» и нужно починить по приоритету платформенного стиля.

## Обязательные требования

- Нельзя в обход `общий-адаптация-под-платформы` писать параллельный набор правил.
- Нельзя в этом файле восстанавливать содержимое диспетчеризации references, уже перенесённое в общий слой.
- Если нужно изменить межплатформенные общие правила, правьте общий skill напрямую.
