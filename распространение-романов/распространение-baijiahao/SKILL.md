# Загрузка указанных глав в Baidu Baijiahao с сохранением черновика

Используется, чтобы загрузить указанную вами 1 или несколько глав под соответствующий аккаунт Baidu Baijiahao и сохранить все как черновики.


<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (Baidu Baijiahao) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `百度百家号/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `百度百家号/`

> **О путях**: все пути вида `百度百家号/` в нижеследующих разделах (например, `百度百家号/README.md`, `百度百家号/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `百度百家号/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `百度百家号/`.
- Вы уже записали в `百度百家号/README.md` аккаунт, пароль, псевдоним автора, название романа, ID книги и прочую информацию.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход → определение режима «создание / изменение» → заполнение заголовка и текста → настройка базовой информации → сохранение черновика → запись ID главы обратно.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт Baijiahao или необходимые метаданные.
- Цель — не «сохранить черновик», а «опубликовать напрямую».

## Требования ко входным данным (обязательно)

### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `百度百家号/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не берётся напрямую из имени файла**: его необходимо извлечь из содержимого файла главы, нормализовать и затем внести в поле заголовка на странице.

### 1.1) Правила извлечения и сборки заголовка главы (обязательно)

- Из файла главы обязательно извлечь: номер главы (арабскими цифрами), заголовок главы, основной текст, «слово от автора».
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как исходный номер главы, а `三分钟` — как «заголовок главы».
- Хотя при итоговой загрузке в Baijiahao используется абсолютная нумерация глав, абсолютный номер можно вычислять только на основе последнего сегмента номера главы по правилам этого Skill; нельзя переносить в поле заголовка трёхуровневую нумерацию вроде `1.1.3`, `2.4.17` как есть; итоговая запись допустима только в формате вроде `第95章 三分钟`.
- Номер главы и заголовок главы в Baijiahao используют **одно поле заголовка**.
- Итоговое вносимое значение — полная строка: `第{绝对章节号}章 {章节标题}`.
- Между `章号` (номером главы) и `标题` (заголовком) обязательно сохранять **1 пробел**, например: `第1章 天降奇缘`.
- Если извлечённая строка заголовка содержит лишь текст заголовка (например, `天降奇缘`), необходимо автоматически собрать `第{绝对章节号}章 天降奇缘`.

### 2) Источник метаданных

- Обязательно прочитать `百度百家号/README.md` и извлечь как минимум следующее:
  - имя пользователя Baijiahao
  - пароль Baijiahao
  - псевдоним автора (для подтверждения оригинальности)
  - ID книги Baijiahao (выбрать значение, соответствующее текущей главе, по «правилу определения ID книги»)
  - название романа (кандидат на название книги; итоговое название колонки определяется по «правилу определения названия книги»)
### 2.1) Проверка платформы (обязательно)

После чтения `百度百家号/README.md` необходимо проверить, равен ли его первый заголовок первого уровня `# 百度百家号分发配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"百度百家号分发配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «百度百家号分发配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)
### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `百度百家号/分发记录.md`:
  - если файла нет, сначала создать его, затем выполнять распространение.
  - используется для запроса соответствия «глава -> ID главы» и определения для главы «режима создания» или «режима изменения».

### 4) Правило определения названия книги (обязательно)

- «Название романа» в каталоге Baijiahao — это название книги романа.
- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава.

### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.

## Процесс выполнения (строго по порядку)

### Шаг 1: чтение локальных входных данных

1. Прочитать и разобрать `百度百家号/README.md`.
2. Убедиться, что получены: аккаунт, пароль, псевдоним автора, целевой ID книги (выбранный по «правилу определения ID книги»), название романа, а также по «правилу определения названия книги» получено целевое название книги для текущей главы (для сопоставления колонки).
3. Прочитать `百度百家号/分发记录.md` и построить соответствие «уникальный ключ главы -> ID главы» (рекомендуемый уникальный ключ: `百家号书籍ID|分部名|绝对章号|章名`; если частей нет, название части фиксированно `NA`).
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: номер тома, номер главы (арабскими цифрами), заголовок главы, основной текст, «слово от автора».

### Шаг 1.5: вычисление абсолютного номера главы (без деления на тома)

1. Нумерация глав везде использует «абсолютный номер главы», локальная нумерация внутри тома не применяется.
2. Способ вычисления:
   - прочитать из `分发记录.md` все записанные главы под тем же целевым ID книги;
   - отсортировав по `绝对章号`, вычислить абсолютный порядковый номер текущей главы.
3. Для сценария публикации в Baijiahao без деления на тома номер главы использует абсолютный номер, формула расчёта:
   - `абсолютный номер главы = сумма числа глав предыдущих томов + относительный номер этой главы в её томе`.
4. Пример:
   - если в томе 1 — 90 глав, а в томе 2 — 100 глав:
   - том 1, глава 5 → абсолютный номер главы: глава 5;
   - том 2, глава 5 → абсолютный номер главы: глава 95;
   - том 3, глава 5 → абсолютный номер главы: глава 195.
5. Если `分发记录.md` не существует или в нём нет истории записей, вычислять по приведённой формуле из известной структуры томов и глав; если число глав предыдущих томов определить нельзя, сначала нужно восполнить реестр и только потом публиковать.

### Шаг 2: вход в кабинет Baidu Baijiahao

1. **Обязательно открыть новую вкладку браузера** и в этой новой вкладке перейти по адресу:
   - `https://baijiahao.baidu.com/builder/rc/incomecenter`
2. Эта новая вкладка используется только для текущего процесса загрузки в Baidu Baijiahao; вкладку, в которой вы сейчас решаете другие задачи, повторно не использовать.
3. Если появляется состояние «не выполнен вход»:
   - нажать «登录/注册百家号» (Войти / зарегистрироваться в Baijiahao);
   - во всплывающем слое выбрать «百度账号登录» (вход по аккаунту Baidu);
   - ввести имя пользователя и пароль из `README.md` и завершить вход.
4. После входа оставаться в авторском кабинете Baijiahao.

### Шаг 3: разведение режимов создания / изменения

1. Перед началом каждой главы сначала проверить `百度百家号/分发记录.md`:
   - если уже есть `章节Id`: идти по **режиму изменения**.
   - если нет `章节Id`: идти по **режиму создания**.

2. Режим создания:
   - перейти по адресу:
   - `https://baijiahao.baidu.com/builder/rc/edit?type=pay_read&sub_type=add_chapter&pay_read_type=news_special_column&pay_read_action=add&is_pay_training_camp=&set_id={书籍Id}`

3. Режим изменения:
   - перейти по адресу:
   - `https://baijiahao.baidu.com/builder/rc/edit?type=pay_read&article_id={章节Id}&is_pay_training_camp=&set_id={书籍Id}&sub_type=add_chapter&pay_read_action=update&pay_read_type=news_special_column&pay_read_status=draft`

### Шаг 4: заполнение заголовка и текста

1. В поле заголовка внести: `第{绝对章节号}章 {章节标题}`.
2. В область редактирования текста вставить основной текст этой главы.
3. Необходимо гарантировать, что текст взят из указанного вами файла главы, без перепутывания глав.

### Шаг 5: настройка базовой информации (обязательно)

#### 5.1 Выбранная колонка (обязательная проверка)

- В области «基础信息» (базовая информация) подтвердить «已选专栏» (выбранная колонка).
- Необходимо гарантировать, что название выбранной колонки совпадает с целевым названием книги, полученным по «правилу определения названия книги».
- При несовпадении необходимо остановить сохранение и сначала исправить выбор колонки.

#### 5.2 «Включить главу в рекомендации» (обязательно)

- Пункт «本章节进推荐» (включить главу в рекомендации) обязательно отметить.

#### 5.3 Настройка платности (обязательно)

- В «付费设置» (настройка платности) обязательно выбрать «本章节免费» (глава бесплатна).

#### 5.4 Подтверждение оригинальности (обязательно)

- В «原创证明» (подтверждение оригинальности) обязательно выбрать «个人原创» (личное оригинальное произведение).

#### 5.5 Расширенные настройки (обязательно)

- В «拓展设置» (расширенные настройки) обязательно отметить «支持用户打赏» (поддержка донатов от пользователей).

### Шаг 6: сохранение черновика

1. Нажать «存草稿» (сохранить черновик).
2. Дождаться сообщения страницы об успешном сохранении (или эквивалентного сообщения об успехе).

### Шаг 7: извлечение ID главы для новой главы

1. Для новой главы после сохранения будет получен новый URL вида:
   - `https://baijiahao.baidu.com/builder/rc/edit?type=pay_read&article_id={章节Id}&sub_type=add_chapter&set_id={书籍Id}&pay_read_type=news_special_column&pay_read_action=update&pay_read_status=draft`
2. Извлечь из URL `article_id` как новый ID главы.
3. Записать «уникальный ключ главы + ID главы + время обновления» обратно в `百度百家号/分发记录.md`:
   - если записи нет: добавить новую;
   - если запись уже есть: обновить `章节Id` (если изменился) и время обновления.

### Шаг 8: цикл по нескольким главам

- При создании или изменении других глав строго повторять шаги 3–8.
- Для каждой главы обязательно заново проверять: это создание или изменение, выполнены ли все обязательные пункты базовой информации.


### Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и расширенных полей платформы (например, «слово автора» / текст настроек публикации);
   - предпроверка ограничений платформы (например, число знаков в заголовке, число знаков в слове автора, обязательные пункты публикации);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `{каталог платформы}/.cache/content_parts/no_part/v{номер тома}/*.txt`, `{каталог платформы}/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (по записи — создание или изменение);
   2) заполнить заголовок;
   3) заполнить основной текст;
   4) заполнить расширенные поля платформы (например, слово автора / настройки публикации);
   5) сохранить черновик;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по `5–10` глав:
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- Так даже при ограничении частоты, колебаниях состояния входа или смене вёрстки страницы пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Для неблокирующих напоминаний, многократно появляющихся на платформе (напоминание о числе знаков, обучающие слои, окна-подсказки), при первом появлении можно убрать шум и продолжить основной процесс.
- Только когда всплывающее окно реально блокирует критический путь «ввод / сохранение / отправка», повышать до обработки как сбой или ручного вмешательства.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / расширенные поля платформы / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs`:
   - без частей: `/parts/v/{номер тома}/{номер главы}`
   - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии.
- Этот способ — средство ускорения; он не заменяет требования каждого платформенного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.
## Ключевые границы и жёсткие правила

- Загружать можно только главы, явно указанные пользователем, без самовольного расширения объёма.
- На шаге 2 для входа в кабинет Baijiahao обязательно использовать **новую вкладку**; запрещено занимать исходную вкладку, которой пользуется пользователь.
- Вход в авторский кабинет фиксирован: `https://baijiahao.baidu.com/builder/rc/incomecenter`.
- Цепочка действий входа фиксирована: «登录/注册百家号» → «百度账号登录» → ввод аккаунта и пароля.
- URL создания и изменения должны разводиться автоматически по журналу распространения, смешивать их запрещено.
- Заголовок обязан использовать объединённый формат: `第X章 标题文本` (`X` — абсолютный номер главы, между номером главы и заголовком 1 пробел).
- Нумерация глав Baijiahao определяется и проверяется по абсолютному номеру главы.
- Пять пунктов «基础信息» должны выполняться: совпадение выбранной колонки + включение главы в рекомендации + бесплатная глава + личное авторство + поддержка расширенных настроек.
- Итоговое действие сохранения каждой главы обязано быть «存草稿».
- После сохранения новой главы обязательно извлечь `article_id` из нового URL и записать его обратно в `百度百家号/分发记录.md`.
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.

## Обработка сбоев и откатов

- Сбой входа: сообщить об ошибке аккаунта / пароля и остановиться, не продолжая последующие главы.
- При вторичной проверке (капча / SMS-проверка / контроль риска): обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную пройдёт проверку и явно сообщит «вход завершён»; до получения этой обратной связи любые последующие шаги выполнять нельзя.
- Отсутствие элемента страницы (например, изменение поля в области «基础信息»): записать шаг сбоя и остановить эту главу.
- Выбранная колонка не совпадает с целевым названием книги: остановить сохранение, сначала скорректировать колонку, затем продолжить.
- Сбой «存草稿»: отметить главу как сбойную; если после повторной попытки сбой остаётся — сохранить запись о сбое и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой записи `分发记录.md`: процесс помечается как «частичный сбой (запись не записана на диск)» и предлагается ручная дозапись.

## Накопленный практический опыт (Baidu Baijiahao)

### Заполнение заголовка (ключевое)

- Область заголовка — абзац `contenteditable` (`ref=e193`), а не стандартный `<input>`. Инструмент `type_in_page` для этого элемента ненадёжен.
- **Надёжный способ**: через Playwright найти `locator('text=请输入标题').locator('..')` → `click()` → `Control+A` (выделить всё) → `keyboard.type(текст заголовка, {delay: 0})`.
- Формат заголовка фиксирован: `第{绝对章节号}章 {章节标题}`, между номером главы и заголовком **1 пробел**.
- Счётчик знаков заголовка (`N/64`) можно использовать, чтобы проверить, что заполнение удалось.

### Заполнение основного текста (ключевое, буфер обмена запрещён)

- **Запрещено использовать буфер обмена**: буфер легко перезаписывается другими операциями, ненадёжен.
- **Обязательно использовать локальный HTTP-сервер основного текста** (`scripts/bjh_body_server.mjs`):
  ```powershell
  # Запустить сервер (асинхронно, держать запущенным на время загрузки)
  node scripts/bjh_body_server.mjs --dir "百度百家号/第1卷" --port 8765
  ```
- Интерфейс сервера:
  - `GET /ch/{номер главы}` → основной текст простым текстом (строка заголовка автоматически убрана)
  - `GET /ch/{номер главы}/title` → заголовок простым текстом
  - `GET /health` → проверка работоспособности + список доступных номеров глав
- В Playwright получать основной текст через `fetch` и сразу внедрять в iframe:
  ```javascript
  const chNum = 36;
  const resp = await fetch(`http://127.0.0.1:8765/ch/${chNum}`);
  const bodyText = await resp.text();

  const iframe = page.frameLocator('iframe').first();
  const bodyEl = iframe.locator('body').first();
  // После очистки задавать textContent через evaluate (безопаснее, чем innerHTML)
  await bodyEl.evaluate(el => { el.textContent = ''; });
  await bodyEl.evaluate((el, text) => { el.textContent = text; }, bodyText);
  ```
- Это решение полностью устраняет риск гонки буфера обмена: основной текст идёт из файловой системы Node.js → HTTP → внедрение в Playwright, минуя буфер обмена ОС.

### Ускорение пакетной предобработки

- Перед открытием браузера разом выполнить: извлечение номера главы, вычисление абсолютного номера главы, предварительное определение режима создания / изменения.
- **Не нужно** предобрабатывать файлы основного текста во временный каталог — сервер основного текста читает исходные файлы глав напрямую и в реальном времени убирает строку заголовка.
- Размер шрифта «19» автоматически наследуется от предыдущей главы, на каждой главе задавать не нужно.

- Пять обязательных настроек: глава бесплатна, глава в рекомендациях, личное авторство, поддержка донатов, совпадение выбранной колонки.
- **Порядок настройки**: сначала нажать `text=本章节免费` (по умолчанию стоит «本章节付费», глава платная), затем `text=个人原创`.
- «支持用户打赏» и «本章节进推荐» по умолчанию обычно уже отмечены, но всё равно нужно перепроверять на каждой главе.
- Название колонки может отображаться в сокращённом виде (например, «陆深被写进案卷» вместо «刑警陆深被写进案卷»); ориентироваться нужно на согласованность `set_id` и счётчик «已添加N篇» («добавлено N статей»).

### Сохранение черновика (момент и проверка)

- После заполнения основного текста дождаться, пока подсказка автосохранения страницы сменится на «已保存» («сохранено»), и только затем нажимать кнопку «存草稿».
- Локатор кнопки сохранения: `button:has-text("存草稿")`.
- После успешного сохранения URL меняется с `pay_read_action=add` на `pay_read_action=update&pay_read_status=draft`, и одновременно появляется параметр `article_id=`.
- Извлечение `article_id` из `page.url()` — самый стабильный источник для записи обратно в журнал распространения.

### Полный шаблон Playwright для одной главы

Рекомендуется объединять все операции над главой в один вызов `run_playwright_code`, чтобы сократить обмен между инструментами:

```javascript
const CH = 36; // текущий абсолютный номер главы
const TITLE = '第36章 排班写"休息、不在岗"，为何仍无法排除安全主管进入NVR机房';

// 1. Получить основной текст с сервера основного текста
const resp = await fetch(`http://127.0.0.1:8765/ch/${CH}`);
const bodyText = await resp.text();

// 2. Заполнить заголовок
const titleArea = page.locator('text=请输入标题').locator('..');
await titleArea.click();
await page.keyboard.press('Control+a');
await page.keyboard.type(TITLE, {delay: 0});
await page.waitForTimeout(300);

// 3. Заполнить основной текст (внедрение в iframe)
const iframe = page.frameLocator('iframe').first();
const bodyEl = iframe.locator('body').first();
await bodyEl.evaluate(el => { el.textContent = ''; });
await bodyEl.evaluate((el, text) => { el.textContent = text; }, bodyText);
await page.waitForTimeout(500);

// 4. Базовые настройки
await page.click('text=本章节免费');
await page.waitForTimeout(200);
await page.click('text=个人原创');
await page.waitForTimeout(200);

// 5. Сохранить черновик
await page.click('button:has-text("存草稿")');
await page.waitForTimeout(3000);

// 6. Вернуть article_id
return page.url();
```

- После завершения каждой главы сразу записывать запись в журнал распространения, не дожидаясь завершения всех глав для пакетной записи.

### Типичные сбои и исправления

| Симптом сбоя | Причина | Исправление |
|:--|:--|:--|
| «标题不能为空» («заголовок не может быть пустым») | `type_in_page` фактически не внёс заголовок | Перейти на ввод заголовка клавиатурой Playwright |
| Сохранение черновика не реагирует | Страница не завершила автосохранение | Дождаться состояния «已保存» и только потом нажимать |
| После вставки текста разметка искажена | Буфер перезаписан или асинхронный сбой `Control+V` | Перейти на HTTP-сервер основного текста + внедрение через `textContent` |
| Основной текст не внесён | `textContent` в `evaluate` заблокирован CSP или редактором | Деградировать до `innerHTML`: `el.innerHTML = text.replace(/\n/g, '<br>')`, затем вручную вызвать событие `input` редактора |

### Рекомендации по размеру партии

- **5 глав на партию** — оптимальный баланс: быстро, малая площадь сбоев, низкая стоимость отката.
- После каждой партии выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав выполнена запись ID главы обратно.
