# Загрузка указанных глав романа в Douban Reading с сохранением черновика

Используется, чтобы загрузить указанную вами 1 или несколько глав в соответствующее произведение Douban Reading и сохранить все как черновики.

<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (Douban) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `豆瓣/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `豆瓣/`

> **О путях**: все пути вида `豆瓣/` в нижеследующих разделах (например, `豆瓣/README.md`, `豆瓣/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `豆瓣/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `豆瓣/`.
- Вы уже записали в `豆瓣/README.md` аккаунт, пароль, ID книги Douban, название книги и названия томов.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход → заполнение номера и названия главы → вставка основного текста → добавление слова автора → сохранение черновика.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт Douban или ID книги.
- Цель — не «сохранить черновик», а «сразу опубликовать».

## Требования ко входным данным (обязательно)

> Рекомендуется выполнить предпроверку в порядке «файлы глав → конфигурация платформы → журнал распространения → определение названия книги / ID книги → недостающие шаблоны», и только затем переходить к работе в браузере.

### I. Локальные входные данные и базовые источники

#### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `豆瓣/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не определяется именем файла**, его необходимо извлечь из основного текста файла главы.

#### 1.1) Правила извлечения заголовка главы (обязательно)

- Заголовок главы берётся из содержимого файла главы, обычно это строка заголовка Markdown в 1-й строке (начинается с `# `).
- Эта строка заголовка иногда содержит номер главы, иногда только текст заголовка; допустимы оба варианта.
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как «номер главы», а `三分钟` — как «заголовок главы».
- Douban — платформа с делением на тома, при загрузке используется только номер главы внутри тома; нельзя переносить в поле заголовка трёхуровневую нумерацию вроде `1.1.3`, `2.4.17` как есть; итоговая запись допустима только в формате вроде `第3章 三分钟`.
- Douban требует объединять номер главы и заголовок в одном поле, формат — `第X章 标题文本` (между номером главы и заголовком обязательно сохранять один пробел).

#### 2) Источник метаданных

- Обязательно прочитать `豆瓣/README.md` и извлечь как минимум следующее:
  - имя пользователя Douban
  - пароль Douban
   - ID книги романа на Douban (только цифры, например `11997642`; выбрать значение, соответствующее текущей главе, по «правилу определения ID книги»)
   - название романа (название книги, для текущей цели загрузки)
  - название каждого тома
#### 2.1) Проверка платформы (обязательно)

После чтения `豆瓣/README.md` необходимо проверить, равен ли его первый заголовок первого уровня `# 豆瓣阅读分发配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"豆瓣阅读分发配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «豆瓣阅读分发配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)
#### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `豆瓣/分发记录.md`:
   - если файла нет, сначала создать его, затем выполнять распространение.
   - используется для запроса соответствия «глава -> ID главы» и определения для главы «режима создания» или «режима изменения».

### II. Определение названия книги / ID книги

#### 4) Правило определения названия книги (обязательно)

- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава; нельзя ошибочно использовать общее название.

#### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.

### III. Шаблоны на случай отсутствия файлов при первом запуске

#### 5) Шаблон `分发记录.md` (при первом создании использовать напрямую)

Если `豆瓣/分发记录.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# 豆瓣阅读分发记录

> Назначение: фиксирует соответствие «уникальный ключ главы -> ID главы Douban», чтобы процесс распространения мог определять «режим создания / режим изменения».

## Описание полей

- `章节唯一键` (уникальный ключ главы): фиксированный формат `豆瓣书籍ID|分部名|卷号|章号|章名` (если частей нет, в поле названия части пишется `NA`)
- `豆瓣书籍ID` (ID книги Douban): соответствует ID книги в `豆瓣/README.md`
- `章节Id` (ID главы): числовой сегмент в URL страницы главы Douban
- `最近操作` (последняя операция): `新建` (создание) или `修改` (изменение)
- `更新时间` (время обновления): `YYYY-MM-DD HH:mm:ss`
- `备注` (примечание): необязательно

## Таблица записей

|章节唯一键|豆瓣书籍ID|章节Id|最近操作|更新时间|备注|
|:--|--:|--:|:--|:--|:--|
```

## Процесс выполнения (строго по порядку)

> Рекомендуется выполнять в порядке «чтение локальных входных данных и определение режима → вход в кабинет → разведение создания / изменения → заполнение заголовка / основного текста / слова автора → сохранение и запись обратно → цикл по нескольким главам».
### 0. Самопроверка перед выполнением (обязательно, при каждом диалоге распространения)

> Следующая самопроверка предотвращает отклонение от существующего SOP из-за «выполнения по впечатлению». При любой аномалии страницы, выборе инструмента или развилке процесса сначала сверьтесь с соответствующим разделом этого документа, и только затем действуйте.

1. **Выбор инструмента**: если речь о канале данных (пакетная передача основного текста / слова автора), сначала сверьтесь с [VI.1.F Ускорение канала данных](#f-数据通道提效可选) и убедитесь, покрывает ли текущую потребность уже имеющийся `scripts/content_parts_server.mjs`; **запрещено создавать временный скрипт, если уже есть покрывающий инструмент**.
2. **Определение всплывающих окон**: при появлении слоя / всплывающего окна на странице редактирования сначала сопоставьте с [Практическим опытом I: обучающий слой панели инструментов и настоящая проверка безопасности](#2026-05-20-实跑修正如何区分工具栏教学浮层与真实安全验证) и только затем решайте, приостанавливаться ли; **запрещено без обращения к документу сразу считать это проверкой безопасности**.
3. **Определение ограничения частоты / сбоя**: при появлении «你发得太快» («вы публикуете слишком быстро») или аномалии сохранения сначала сверьтесь с соответствующими разделами [Практического опыта II](#二创建与保存阶段的页面反馈) и [Практического опыта III](#三长批量分发策略) и действуйте по уже имеющейся стратегии.
4. **Аномалия входа**: при появлении капчи / слайдера / подсказки контроля риска обязательно немедленно приостановиться и ждать, пока пользователь вручную завершит проверку; до получения обратной связи «вход завершён» продолжать нельзя.
### I. Чтение локальных входных данных и определение режима

1. Прочитать и разобрать `豆瓣/README.md`.
2. Убедиться, что получены: аккаунт, пароль, целевой ID книги (выбранный по «правилу определения ID книги»), целевое название романа, целевое название тома.
3. Прочитать `豆瓣/分发记录.md` и построить соответствие «уникальный ключ главы -> ID главы» (рекомендуемый уникальный ключ: `豆瓣书籍ID|分部名|卷号|章号|章名`; если частей нет, название части фиксированно `NA`).
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: номер тома, название тома, номер главы (арабскими цифрами), заголовок главы, основной текст, слово автора.
   - Заголовок главы при этом обязательно извлекать из содержимого файла по «правилу извлечения заголовка главы (обязательно)», подменять его именем файла нельзя.

### II. Вход и переход в авторский кабинет

1. **Обязательно открыть новую вкладку браузера** и в этой новой вкладке перейти по адресу:
   - `https://read.douban.com/submit/agent`
2. Эта новая вкладка используется только для текущего процесса загрузки в Douban; вкладку, в которой вы сейчас решаете другие задачи, повторно не использовать.
3. Если появляется состояние «не выполнен вход»:
   - по умолчанию страница показывает интерфейс «手机号验证码登录» (вход по коду на телефон)
   - **обязательно нажать ссылку «豆瓣登录»** (вход через Douban)
   - после перехода страницы в правом верхнем углу найти и нажать «短信登录/注册» (вход / регистрация по SMS)
   - затем переключиться на вкладку «密码登录» (вход по паролю)
   - выполнить вход, используя имя пользователя и пароль из `README.md`
4. Если после входа по паролю страница выдаёт подсказку «为保证账号安全，请使用验证码» («для безопасности аккаунта используйте код подтверждения») или аналогичную:
   - обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成» (вход завершён)
   - до получения обратной связи «登录完成» не продолжать никакие дальнейшие шаги и не имитировать состояние успеха

### III. Переход на страницу главы целевой книги (разведение создания / изменения)

1. Перед переходом сначала проверить в `豆瓣/分发记录.md`, есть ли уже у этой главы `章节Id`.
2. Если у этой главы **нет** ID главы (режим создания), перейти по адресу:
   - `https://read.douban.com/article_v2/chapter/create?column_id={豆瓣书籍ID}`
   - после загрузки страницы URL автоматически перенаправляется на `https://read.douban.com/article_v2/chapter/{章节Id}/`
   - из URL после перенаправления извлечь часть `{章节Id}` (только цифры между двумя косыми чертами)
3. Если у этой главы **уже есть** ID главы (режим изменения), перейти по адресу:
   - `https://read.douban.com/article_v2/chapter/{章节Id}`
4. `{豆瓣书籍ID}` обязательно берётся из `README.md` и должен быть строкой цифр.
5. Интерфейс редактирования Douban не показывает информацию о книге и названии тома, поэтому проверку книги на странице выполнить нельзя; корректность ID книги подтверждается только через `column_id` в URL или сам путь URL, поэтому перед шагом 2 убедитесь, что ID книги в `README.md` верен.

### IV. Редактирование содержимого главы

#### 4) Заполнение области заголовка главы

Douban требует вводить в одно поле «номер главы + пробел + заголовок главы».

1. Получить арабский номер этой главы (например, `1`).
2. Получить заголовок этой главы (из содержимого файла, обычно из строки заголовка `# ` в 1-й строке); использовать имя файла нельзя.
3. Собрать по формату `第X章 标题文本` и внести в поле заголовка:
   - пример: `第1章 天降奇缘`
   - между номером главы и заголовком **обязательно сохранять один пробел**
4. Убедиться, что формат правильный, и только затем отправлять.

#### 5) Заполнение основного текста

1. Ввести основной текст главы в текстовое поле основного текста.
2. Необходимо гарантировать, что текст взят из указанного вами файла главы, без перепутывания глав.

#### 6) Добавление слова автора

1. В правой верхней части страницы найти кнопку или меню «工具» (инструменты).
2. Нажать в нём пункт «作者的话» (слово автора).
3. После нажатия в правом верхнем углу страницы появится всплывающее поле ввода.
4. Во всплывающем поле ввода **сначала выделить всё и очистить старое содержимое**, затем ввести содержимое «слова автора» этой главы, чтобы не склеивать его с прежним текстом.
5. После ввода обязательно проверить счётчик (если страница показывает ограничение по числу знаков):
   - при превышении лимита — сжать до лимита платформы по принципу «крючок в приоритете» и только затем сохранять.
   - при отсутствии превышения — сохранить смысл исходного текста.
6. Нажать во всплывающем слое кнопку «确定» (подтвердить), чтобы убедиться, что слово автора записано.

### V. Сохранение главы и запись обратно

1. Нажать на странице кнопку «保存» (сохранить).
2. Дождаться сообщения страницы об успешном сохранении (или эквивалентного сообщения об успехе).
3. После успешного сохранения извлечь `章节Id` из текущего URL (если режим создания, то URL в этот момент должен быть `https://read.douban.com/article_v2/chapter/{章节Id}/`).
4. Записать «уникальный ключ главы + ID главы + время обновления» обратно в `豆瓣/分发记录.md`:
   - если записи нет: добавить новую.
   - если запись уже есть: обновить только `章节Id` (если изменился) и время обновления.
   - **Обратите внимание на экранирование в таблице Markdown**: если внутри `章节唯一键` есть `|`, при записи в таблицу его необходимо экранировать как `\|`, иначе будет нарушено число столбцов таблицы и запись станет неразбираемой.

> Правило формирования уникального ключа главы (обязательно):
> - Порядок полей: `豆瓣书籍ID|分部名|卷号|章号|章名`
> - При этом:
>   - `豆瓣书籍ID` берётся из `README.md`
>   - `分部名` — название книги текущей части; если частей нет — `NA`
>   - `卷号`, `章号` должны быть арабскими цифрами
> - Это правило нужно для полного избежания конфликтов «одинаковый номер главы в одном томе» в многочастных романах.

### VI. Цикл по нескольким главам

- Для каждой указанной главы строго повторять шаги 3–7, пока не будут завершены все главы.
- Перед началом каждой главы обязательно один раз запрашивать `分发记录.md` для определения режима создания / изменения, нельзя наследовать режим предыдущей главы.

### VI.1 Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и слова автора;
   - предпроверка превышения лимита слова автора (при `>300` сначала сжать);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `豆瓣/.cache/content_parts/no_part/v{номер тома}/*.txt`, `豆瓣/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (создание `create?column_id=` или изменение `chapter/{id}`);
   2) заполнить заголовок (`第X章 标题`);
   3) заполнить основной текст;
   4) заполнить слово автора;
   5) сохранить;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по `5–10` глав:
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- Так даже при ограничении частоты, колебаниях состояния входа или смене вёрстки страницы пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Если на этапе сохранения появляется напоминание о числе знаков:
   - при первом разе отметить «不再提醒» (больше не напоминать) и нажать «我知道了» (понятно);
   - для последующих глав такие помехи обычно сокращаются.
- Если на странице редактирования появляется обучающий слой «切换工具栏模式» (переключение режима панели инструментов): считать его неблокирующим элементом, основной процесс не прерывать.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / слово автора / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs` (универсальный сервис content parts):
   - пусть браузер через scoped-интерфейс читает заголовок / основной текст / слово автора:
     - без частей: `/parts/v/{номер тома}/{номер главы}`
     - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
     - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии;
   - сократить повторную передачу длинного основного текста в чате или скриптах.
- Этот способ — средство ускорения; он не заменяет требования данного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.

## Ключевые границы и жёсткие правила

> Ниже приведены ограждения, которые при выполнении нельзя ослаблять; при конфликте с временным поведением страницы ориентироваться на правила здесь и на нижеследующий «Накопленный практический опыт» для перепроверки.


### I. Область и правила разведения

- Загружать можно только главы, явно указанные пользователем, без самовольного расширения объёма.
- Перед входом в шаг 3 для каждой главы обязательно сначала запросить `豆瓣/分发记录.md`.
- Перед входом в шаг 3 для каждой главы обязательно убедиться, что ID книги Douban в `README.md` верен (интерфейс редактирования Douban не позволяет проверить информацию о книге на странице).
- Два вида адресов — `create?column_id={书籍ID}` и `chapter/{章节Id}` — обязаны разводиться автоматически по записи, смешивать их запрещено.

### II. Вход и использование страницы

- На шаге 2 для входа в авторский кабинет обязательно использовать **новую вкладку**; запрещено занимать исходную вкладку, которой пользуется пользователь.
- Процесс входа обязан выполняться в порядке «手机号验证码 (код на телефон) → 豆瓣登录 (вход через Douban) → 短信登录/注册 (вход / регистрация по SMS) → 密码登录 (вход по паролю)».
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.

### III. Заголовок, основной текст и слово автора

- Заголовок главы обязан браться из содержимого файла главы (обычно из строки заголовка `# ` в 1-й строке), использовать имя файла вместо заголовка нельзя.
- Формат ввода заголовка главы обязан быть `第X章 标题文本` (между номером главы и заголовком **обязательно сохранять один пробел**), пропускать пробел нельзя.
- Номер главы обязан быть арабской цифрой, китайские числительные писать нельзя.
- Douban — платформа с делением на тома, номер главы обязан использовать относительный номер внутри тома, без накопления между томами.
- «作者的话» (слово автора) обязано вноситься по пути «工具 → 作者的话 → ввод во всплывающем слое → 确定».
- Перед внесением слова автора обязательно сначала очистить поле редактирования, затем вставить текст этой главы.
- Слово автора перед подтверждением обязано укладываться в лимит платформы по числу знаков.

### IV. Сохранение и запись

- После успешного «保存» каждой главы обязательно записать актуальный `章节Id` обратно в `豆瓣/分发记录.md`.
- Итоговое действие — «保存»; после сохранения состояние — черновик.

## Обработка сбоев и откатов

- Сбой входа: сообщить об ошибке аккаунта / пароля и остановиться, не продолжая последующие главы.
- Вход по паролю перехвачен и заменён входом по коду подтверждения: обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成»; до получения этой обратной связи любые последующие шаги выполнять нельзя.
- На странице редактирования появилась вторичная проверка безопасности (пазл / слайдер): обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成»; до получения этой обратной связи любые последующие шаги выполнять нельзя.
- Отсутствие элемента страницы (например, изменение кнопки): записать текущий шаг сбоя и остановить эту главу; перед переходом к следующей главе сначала убедиться, что страница пригодна для действий.
- Сбой сохранения: отметить главу как сбойную; если после повторной попытки сбой остаётся — сохранить запись о сбое и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой сохранения слова автора: не сохранять эту главу пока, повторить цепочку «редактирование слова автора → 确定 → сохранение»; если сбой остаётся — записать причину и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой записи `分发记录.md`: хотя эта глава, возможно, уже сохранена, статус процесса обязательно пометить как «частичный сбой (запись не записана на диск)» и немедленно предложить ручную дозапись; молчаливый успех запрещён.

## Накопленный практический опыт (на основе реальных загрузок)

> Рекомендуется читать в порядке «распознавание страницы редактирования → отклик страницы → стратегия для длинных партий → вспомогательные средства автоматизации»: первые две категории касаются стабильности работы с одной главой, последние две — длинного непрерывного распространения партиями.

### I. Распознавание страницы редактирования и исключение ложных срабатываний

#### 【Важно】Как точно распознать поля заголовка и основного текста

- 【2026-05-20 явное дополнение пользователя (наивысший приоритет)】
   - Место ввода заголовка: `textarea` (под `h1.title`), placeholder — «标题» (заголовок).
   - Место ввода основного текста: `div.public-DraftStyleDefault-block.public-DraftStyleDefault-ltr` (блок редактирования Draft, под `DraftEditor-root`).
   - При выполнении обязательно сначала писать в `textarea(标题)`, затем в `Draft div(正文)`; обратный порядок запрещён.

- Основная область редактора Douban разделена на верхнюю и нижнюю части, **единственный якорь — placeholder**:
   - верхнее поле ввода предназначено для заголовка, его placeholder — явно «标题» (заголовок).
   - нижнее поле ввода предназначено для основного текста, его placeholder — явно «写点什么吧» (напишите что-нибудь).
   - поле заголовка однострочное, поле основного текста многострочное и поддерживает панель форматирования.
   - при автоматических / ручных действиях ориентироваться обязательно на placeholder: сначала найти поле «标题» и внести заголовок главы, затем найти поле «写点什么吧» и внести основной текст.
   - при любом изменении страницы в первую очередь проверять содержимое placeholder, при необходимости обновлять логику поиска элементов в скрипте автоматизации.
- Типичные заблуждения:
   - не вносить основной текст по ошибке в поле заголовка (весь текст главы окажется в заголовке, а основной текст останется пустым).
   - не вносить заголовок по ошибке в поле основного текста (у главы не будет заголовка, что повлияет на оглавление и отображение).
- При автоматических / ручных действиях обязательно сначала найти поле заголовка (вверху страницы, однострочное), затем поле основного текста (большая область редактирования), **перед каждой вставкой подтверждать положение фокуса**.
- Рекомендации:
   - скрипту автоматизации находить элементы точно по placeholder, порядку тегов input или class/id.
   - при ручных действиях сначала щёлкнуть в поле заголовка, ввести заголовок, переключиться Enter или Tab в поле основного текста, затем вставить основной текст.
   - после вставки функциями «撤销 / 重做» (отменить / повторить) можно убедиться, что содержимое попало в нужную область.

При изменении структуры страницы в первую очередь вручную проверить порядок полей ввода и placeholder, при необходимости обновить логику автоматического поиска элементов.

#### 【2026-05-20 коррекция по реальному прогону】Как отличить обучающий слой панели инструментов от настоящей проверки безопасности

- Внизу страницы редактирования может появиться полноширинный обучающий слой «切换工具栏模式» (переключение режима панели инструментов); это не пазл / слайдер-проверка, он не блокирует ввод основного текста, меню в правом верхнем углу и сохранение.
- Признаки распознавания:
   - слой находится внизу страницы, заголовок явно «切换工具栏模式».
   - внутри слоя есть описание режима панели инструментов, стрелки листания влево и вправо и кнопка закрытия `X` в правом нижнем углу.
   - вверху страницы «保存 / 发表 / 菜单» (сохранить / опубликовать / меню) и область основного текста по-прежнему нормально доступны для нажатия, ввода и сохранения.
- Способ обработки:
   - можно прямо проигнорировать этот слой, продолжить заполнять основной текст, слово автора и сохранять.
   - если беспокоит перекрытие, можно сначала нажать `X` в правом нижнем углу для закрытия, затем продолжить процесс.
- Приостанавливаться как «вторичная проверка безопасности» нужно только тогда, когда на странице реально появляется неотключаемое взаимодействие с капчей, блокирующее область основного текста, меню или кнопку сохранения; обучающий слой нельзя ошибочно принимать за проверку безопасности.
- Если во вспомогательном снимке появляются слова вроде «安全验证 / 拖动下方拼图完成验证» (проверка безопасности / перетащите пазл ниже для проверки), но на видимой странице на самом деле отображается обучающий слой панели инструментов, необходимо перепроверить по видимому интерфейсу и реальной интерактивности, и только затем решать, приостанавливаться ли.

### II. Отклик страницы на этапах создания и сохранения

#### 【2026-05-20 коррекция по реальному прогону】Что делать, если на странице создания появляется «你发得太快»

- Если после перехода на `https://read.douban.com/article_v2/chapter/create?column_id={书籍ID}` в области основного текста страницы не появился редактор, а показано «你发得太快，读者看不过来啦，请明天再继续» («вы публикуете слишком быстро, читатели не успевают читать, продолжите завтра»), следует считать это ограничением платформы на число публикаций за день.
- Это не недействительность входа, не капча и не ошибка поиска поля ввода; обновление страницы и повторные попытки обычно бесполезны.
- Признаки распознавания:
   - заголовок страницы обычно по-прежнему «创建文章 | 豆瓣阅读» (создать статью | Douban Reading);
   - в основном тексте страницы напрямую появляются «你发得太快，读者看不过来啦，请明天再继续» и «返回作者中心» (вернуться в авторский центр);
   - поле заголовка `textarea[placeholder="标题"]`, которое должно было появиться, не отрисовывается.
- Правильный способ обработки:
   - немедленно прекратить дальнейшие попытки «создания главы»;
   - сначала записать обратно в `豆瓣/分发记录.md` ID глав, успешно сохранённых за этот день;
   - оставшиеся незагруженные главы пометить как «отложены из-за ограничения платформы», продолжить на следующий день.
- Если нужно продолжить дозагрузку, на следующий день продолжать с первой главы в `分发记录.md`, у которой не записан `章节Id`, а не перезапускать всю партию с начала.
- В этом реальном прогоне после непрерывного завершения до главы 21 при попытке создать главу 22 сработало это ограничение; значит, не следует по умолчанию считать, что длинная пакетная задача может бесконечно создавать главы подряд в течение одного дня.

#### 【2026-05-20 коррекция по реальному прогону】Что делать, если при сохранении появляется напоминание о числе знаков

- При нажатии «保存» страница может показать напоминание о числе знаков; это не сбой сохранения и не проверка безопасности.
- Правильный порядок обработки:
   - сначала отметить «不再提醒»;
   - затем нажать «我知道了».
- Так можно закрыть последующие повторные напоминания того же рода, сократить лишние взаимодействия при сохранении каждой главы и повысить эффективность пакетной загрузки.
- Если в этот раз не отметить «不再提醒», при сохранении последующих глав подобные подсказки могут появляться снова и снова, нарушая ритм непрерывного распространения.

### III. Стратегия длинного пакетного распространения

#### 【2026-05-20 коррекция по реальному прогону】Перед длинным пакетным распространением выполнить предпроверку превышения лимита «слова автора»

- При длинной пакетной загрузке не ждите, пока после открытия слоя «作者的话» обнаружится превышение лимита знаков: это прервёт ритм и легко приведёт к искажению текста при непрерывных операциях.
- Рекомендуемый подход:
   - перед фактической загрузкой пакетно подсчитать длину «слова автора» для целевого диапазона глав;
   - сжать главы с `>300` централизованно и только затем переходить к пакетному заполнению в браузере.
- В предпроверке `глав 3–40` в этом раунде главами с превышением оказались: `第12章`, `第24章`, `第26章`, `第28章`.
- Если текущий процесс использует `豆瓣/.cache/content_parts/no_part/v{номер тома}/*.txt` или `豆瓣/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` как входной кэш автоматизации, можно в первую очередь пакетно проверять `*_author.txt`; если кэш не используется, ориентироваться по-прежнему на «слово автора» в исходных файлах глав.

#### 【2026-05-20 коррекция по реальному прогону】Длинная пакетная загрузка обязана записывать `分发记录.md` по частям

- Не ждать завершения всей партии, чтобы записать `豆瓣/分发记录.md` одним разом.
- Рекомендуемая стратегия: после каждых `5–10` успешно завершённых глав сразу записывать соответствие `уникальный ключ главы -> ID главы` этой малой партии обратно в таблицу записей.
- Преимущества такого подхода:
   - если посреди процесса случится ограничение платформы, аномалия состояния браузера, смена вёрстки страницы или ручное прерывание, завершённые главы не потеряют `章节Id`;
   - при продолжении на следующий день можно прямо начинать с первой главы в `分发记录.md`, у которой ещё не записан `章节Id`;
   - можно избежать скрытого разрыва «на веб-странице сохранено успешно, но локальная запись не записана на диск».
- В этом реальном прогоне именно потому, что сначала были записаны обратно `главы 3–7`, затем `главы 8–21`, при срабатывании ограничения на главе 22 локальное состояние осталось целостным.

### IV. Вспомогательные средства автоматизации (по желанию)

#### 【2026-05-20 коррекция по реальному прогону】Роль и применение `scripts/content_parts_server.mjs` (универсальный сервис content parts)

- `scripts/content_parts_server.mjs` — это **вспомогательный скрипт автоматизации**, который выставляет разбитые по главам заголовок, основной текст и слово автора из `.cache/content_parts/` каталога платформы в виде локального JSON-интерфейса для чтения процессом автоматизации браузера.
- Его роль: **помощь при пакетной автоматической загрузке**, а не обязательный шаг ручной загрузки.
- Подходящие сценарии:
   - нужно непрерывно загружать пакетом несколько глав;
   - не хочется многократно передавать целую главу основного текста в чате или скриптах автоматизации;
   - подтверждено, что содержимое `豆瓣/.cache/content_parts/` синхронизировано с текущими загружаемыми главами.
- Неподходящие сценарии:
   - чисто ручная загрузка;
   - `豆瓣/.cache/content_parts/` — старый кэш, ещё не отражающий последние изменения глав;
   - невозможно подтвердить, что разбитый текст совпадает с целевыми файлами глав в `豆瓣/`.
- Границы использования:
   - скрипт отвечает лишь за канал данных основного текста и не заменяет обязательные правила этого Skill;
   - суждения о заголовке главы, номере главы, ID книги, номере тома, записи обратно и т. п. по-прежнему обязаны выполняться по формальным правилам `README.md`, `分发记录.md` и целевого файла главы;
   - если исходная глава только что изменялась, сначала нужно заново синхронизировать `豆瓣/.cache/content_parts/`, иначе следует читать файл главы напрямую, не доверяя кэшу вслепую.
- Соглашение об интерфейсе:
   - проверка работоспособности: `/health`
   - данные главы (рекомендуется, роман без частей): `/parts/v/{номер тома}/{номер главы}`
   - данные главы (рекомендуется, роман с частями): `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - данные главы (по желанию, плоский вариант, только для одной партии): `/parts/{номер главы}`
   - возвращаемые поля: `chapterNo`, `title`, `body`, `author`
- О порте:
   - по умолчанию используется `8765`;
   - если порт занят, его можно сменить на другой через переменную окружения `CONTENT_PARTS_PORT`.
   - Подкаталог кэша `.cache/content_parts` жёстко прописан в скрипте, по умолчанию читается `小说正文/.cache/content_parts`.
   - Для сценария распространения в Douban явно задайте: `DISTRIBUTION_PLATFORM_DIR=豆瓣` (скрипт автоматически дополнит до `豆瓣/.cache/content_parts`).
   - Для переиспользования на других платформах можно переключить каталог платформы переменной окружения `DISTRIBUTION_PLATFORM_DIR` (например, `番茄小说`), скрипт автоматически дополнит до `{каталог платформы}/.cache/content_parts`.
- Вывод по реальному прогону:
   - в этом раунде пакетного распространения 21 главы скрипт заметно снизил затраты на многократную передачу длинного основного текста процессом автоматизации браузера;
   - поэтому рекомендуется записать его в этот Skill как необязательное вспомогательное средство для «длинной пакетной автоматической загрузки», но явно пометить как **необязательное**, а не **жёсткую зависимость**.

#### 【Соглашение об обязанностях каталогов】Границы между `scripts/` и каталогом кэша данных

- Каталог `scripts/` предназначен только для хранения самих многократно используемых скриптов (например, `content_parts_server.mjs`); не рекомендуется помещать туда временные данные глав, порождаемые каждым раундом распространения.
- Кэш разбиения глав, временные соответствия и промежуточные продукты в процессе распространения рекомендуется единообразно размещать в специальном временном подкаталоге каталога `豆瓣/` (например, `豆瓣/.cache/content_parts/`).
- Сервис content parts фиксированно использует `.cache/content_parts` как подкаталог кэша; только при переиспользовании на других платформах каталог платформы переключается через `DISTRIBUTION_PLATFORM_DIR`.
- Чтобы избежать конфликта «одинаковый номер главы в разных частях / разных томах», в первую очередь использовать пути scoped-интерфейса с номером части / тома; не рекомендуется долго опираться на плоский `/parts/{номер главы}`.
