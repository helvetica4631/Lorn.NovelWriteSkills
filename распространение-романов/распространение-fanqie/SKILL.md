# Загрузка указанных глав романа в Fanqie Novel с сохранением черновика

Используется, чтобы загрузить указанную вами 1 или несколько глав в соответствующее произведение Fanqie Novel и сохранить все как черновики.


<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (Fanqie Novel) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `番茄小说/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `番茄小说/`

> **О путях**: все пути вида `番茄小说/` в нижеследующих разделах (например, `番茄小说/README.md`, `番茄小说/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `番茄小说/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `番茄小说/`.
- Вы уже записали в `番茄小说/README.md` аккаунт, пароль, ID книги Fanqie, название книги и названия томов.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход → заполнение номера и названия главы → вставка основного текста → добавление слова от автора → сохранение черновика.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт Fanqie или ID книги.
- Цель — не «сохранить черновик», а «сразу опубликовать».

## Требования ко входным данным (обязательно)

### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `番茄小说/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не определяется именем файла**, его необходимо извлечь из основного текста файла главы.

### 1.1) Правила извлечения заголовка главы (обязательно)

- Заголовок главы берётся из содержимого файла главы, обычно это строка заголовка Markdown в 1-й строке (начинается с `# `).
- Эта строка заголовка иногда содержит номер главы, иногда только текст заголовка; допустимы оба варианта.
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как исходный номер главы, а `三分钟` — как «заголовок главы».
- При заполнении поля «章节标题» (заголовок главы) на Fanqie допускается использовать только текст заголовка `三分钟`; если на странице есть отдельное поле номера главы или позже потребуется вычисление абсолютного номера, также можно использовать только последний сегмент номера `3`, нельзя загружать `1.1.3` как есть.
- При заполнении поля «章节标题» на Fanqie следует использовать извлечённый текст заголовка, нельзя напрямую использовать имя файла.

### 2) Источник метаданных

- Обязательно прочитать `番茄小说/README.md` и извлечь как минимум следующее:
  - имя пользователя Fanqie Novel
  - пароль Fanqie Novel
   - ID книги романа (только цифры, например `7605776437705985086`; выбрать значение, соответствующее текущей главе, по «правилу определения ID книги»)
   - название романа (название книги, для текущей цели загрузки)
  - название каждого тома
### 2.1) Проверка платформы (обязательно)

После чтения `番茄小说/README.md` необходимо проверить, равен ли его первый заголовок первого уровня `# 番茄распространение-романов配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"番茄распространение-романов配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «番茄распространение-романов配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)
### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `番茄小说/分发记录.md`:
   - если файла нет, сначала создать его, затем выполнять распространение.
   - используется для запроса соответствия «глава -> ID главы» и определения для главы «режима создания» или «режима изменения».

### 4) Правило определения названия книги (обязательно)

- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава; нельзя ошибочно использовать общее название.

### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.

### 5) Шаблон `分发记录.md` (при первом создании использовать напрямую)

Если `番茄小说/分发记录.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# 番茄распространение-романов记录

> Назначение: фиксирует соответствие «уникальный ключ главы -> ID главы Fanqie», чтобы процесс распространения мог определять «режим создания / режим изменения».

## Описание полей

- `章节唯一键` (уникальный ключ главы): фиксированный формат `书籍ID|分部名|卷号|章号|章名` (если частей нет, в поле названия части пишется `NA`)
- `书籍ID` (ID книги): соответствует ID книги в `番茄小说/README.md`
- `章节Id` (ID главы): число после `publish/` в URL страницы публикации Fanqie
- `最近操作` (последняя операция): `新建` (создание) или `修改` (изменение)
- `更新时间` (время обновления): `YYYY-MM-DD HH:mm:ss`
- `备注` (примечание): необязательно

## Таблица записей

|章节唯一键|书籍ID|章节Id|最近操作|更新时间|备注|
|:--|--:|--:|:--|:--|:--|
```
### 6) Шаблон `README.md` (при первом создании использовать напрямую)

Если `番茄小说/README.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# 番茄распространение-романов配置

> Назначение: хранит аккаунт Fanqie Novel, информацию о книгах и соответствие названий томов. Процесс распространения будет читать этот файл.

## Информация об аккаунте

- Имя пользователя: `your_username`
- Пароль: `your_password`

## Информация о книге

### Роман без частей

| Название романа | ID книги |
|:--|:--|
| 作品名 | 7605776437705985086 |

### Роман с частями

| Номер части | Название части | ID книги |

| 第1部 | 分部一书名 | 7605776437705985086 |
| 第2部 | 分部二书名 | 7605776437705985087 |

## Соответствие названий томов

### 分部一书名

| Номер тома | Название тома |
|--:|:--|

## Описание полей

- `小说名称` / `分部名`: должны точно совпадать с «правилом определения названия книги» из SKILL
- `分部号`: необходимо использовать нормативный формат `第N部` (например, `第1部`, `第2部`) и однозначно сопоставлять с `分部名`, без смещений и повторного использования
- `书籍ID`: обычно большое целое число (например, `7605776437705985086`)

## Напоминание о безопасности

- Этот файл содержит пароль в открытом виде, храните его надёжно.
```

## Процесс выполнения (строго по порядку)

### Шаг 1: чтение локальных входных данных

1. Прочитать и разобрать `番茄小说/README.md`.
2. Убедиться, что получены: аккаунт, пароль, целевой ID книги (выбранный по «правилу определения ID книги»), целевое название романа, целевое название тома.
3. Прочитать `番茄小说/分发记录.md` и построить соответствие «уникальный ключ главы -> ID главы» (рекомендуемый уникальный ключ: `书籍ID|分部名|卷号|章号|章名`; если частей нет, название части фиксированно `NA`).
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: номер тома, название тома, номер главы (арабскими цифрами), заголовок главы, основной текст, слово от автора.
   - Заголовок главы при этом обязательно извлекать из содержимого файла по «правилу извлечения заголовка главы (обязательно)», подменять его именем файла нельзя.

### Шаг 2: вход в авторский кабинет

1. **Обязательно открыть новую вкладку браузера** и в этой новой вкладке перейти по адресу:
   - `https://fanqienovel.com/main/writer/book-manage`
2. Эта новая вкладка используется только для текущего процесса загрузки в Fanqie; вкладку, в которой вы сейчас решаете другие задачи, повторно не использовать.
3. Если состояние входа недействительно или вход не выполнен:
   - обязательно переключиться на «密码登录» (вход по паролю)
   - войти, используя имя пользователя и пароль из `README.md`
4. Если после входа по паролю страница выдаёт подсказку «为保证账号安全，请使用手机验证码登录» («для безопасности аккаунта войдите по коду из SMS») или аналогичную:
   - обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成» (вход завершён)
   - до получения обратной связи «登录完成» не продолжать никакие дальнейшие шаги и не имитировать состояние успеха

### Шаг 3: переход на страницу главы целевой книги (создание / изменение — одно из двух)

1. Перед переходом сначала проверить в `番茄小说/分发记录.md`, есть ли уже у этой главы `章节Id`.
2. Если у этой главы **нет** ID главы (режим создания), перейти по адресу:
   - `https://fanqienovel.com/main/writer/{书籍ID}/publish/?enter_from=newchapter`
3. Если у этой главы **уже есть** ID главы (режим изменения), перейти по адресу:
   - `https://fanqienovel.com/main/writer/{书籍ID}/publish/{章节Id号}`
4. После загрузки страницы зафиксировать текущий URL; чистое число от `publish/` до `?` (если `?` нет — до конца пути) и есть `章节Id` этой главы.
5. `{书籍ID}` обязательно берётся из `README.md` и должен быть строкой цифр.

### Шаг 4: проверка названия книги и названия тома в левом верхнем углу

1. Проверить, соответствует ли отображение в левом верхнем углу страницы:
   - `“{小说名} 第X卷：{卷名}”` (формат «{название романа} Том X: {название тома}»)
2. Пример: `归墟 第一卷：门禁不认我`
3. Если не совпадает:
   - немедленно остановить загрузку текущей главы
   - вернуть описание ошибки (название книги / названия тома не совпадают)
   - запрещено продолжать слепую загрузку в неверное произведение

### Шаг 5: заполнение области заголовка главы

Формат целевой области: `第_章 未命名草稿` (глава _ «безымянный черновик»)

1. Заменить `_` на арабский номер главы (например, `5`).
2. Заменить `未命名草稿` на фактический заголовок главы (из содержимого файла, обычно из строки заголовка `# ` в 1-й строке); использовать имя файла нельзя.

### Шаг 6: заполнение основного текста

1. Ввести основной текст главы в текстовое поле основного текста.
2. Необходимо гарантировать, что текст взят из указанного вами файла главы, без перепутывания глав.

### Шаг 7: добавление слова от автора

1. Нажать «作者有话说» (слово от автора).
2. Нажать «+添加» (добавить).
3. Выбрать «添加图文» (добавить изображение с текстом).
4. В появившемся поле ввода **сначала выделить всё и очистить старое содержимое**, затем ввести содержимое «слова от автора» этой главы, чтобы не склеивать его с прежним текстом.
5. После ввода обязательно проверить счётчик (обычно `X/300`):
   - при превышении лимита — сжать до лимита платформы по принципу «крючок в приоритете» и только затем сохранять.
   - при отсутствии превышения — сохранить смысл исходного текста и сохранить.
6. Нажать в области слова от автора «保存/完成» (сохранить / готово) (если такая кнопка есть на странице), убедиться, что слово от автора записано.

### Шаг 8: сохранение черновика

1. Нажать в правом верхнем углу «存草稿» (сохранить черновик).
2. Дождаться сообщения страницы об успешном сохранении (или эквивалентного сообщения об успехе).
3. После успешного сохранения записать «уникальный ключ главы + ID главы + время обновления» обратно в `番茄小说/分发记录.md`:
   - если записи нет: добавить новую.
   - если запись уже есть: обновить только `章节Id` (если изменился) и время обновления.

> Правило формирования уникального ключа главы (обязательно):
> - Порядок полей: `书籍ID|分部名|卷号|章号|章名`
> - При этом:
>   - `书籍ID` берётся из `README.md`
>   - `分部名` — название книги текущей части; если частей нет — `NA`
>   - `卷号`, `章号` должны быть арабскими цифрами
> - Это правило нужно для полного избежания конфликтов «одинаковый номер главы в одном томе» в многочастных романах.

### Шаг 9: цикл по нескольким главам

- Для каждой указанной главы строго повторять шаги 3–8, пока не будут завершены все главы.
- Перед началом каждой главы обязательно один раз запрашивать `分发记录.md` для определения режима создания / изменения, нельзя наследовать режим предыдущей главы.


### Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и расширенных полей платформы (например, «слово автора» / текст настроек публикации);
   - предпроверка ограничений платформы (например, число знаков в заголовке, число знаков в слове автора, обязательные пункты публикации);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `{каталог платформы}/.cache/content_parts/no_part/v{номер тома}/*.txt`, `{каталог платформы}/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (по записи — создание или изменение);
   2) заполнить заголовок;
   3) заполнить основной текст;
   4) заполнить расширенные поля платформы (например, слово автора / настройки публикации);
   5) сохранить черновик;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по `5–10` глав:
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- Так даже при ограничении частоты, колебаниях состояния входа или смене вёрстки страницы пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Для неблокирующих напоминаний, многократно появляющихся на платформе (напоминание о числе знаков, обучающие слои, окна-подсказки), при первом появлении можно убрать шум и продолжить основной процесс.
- Только когда всплывающее окно реально блокирует критический путь «ввод / сохранение / отправка», повышать до обработки как сбой или ручного вмешательства.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / расширенные поля платформы / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs`:
   - без частей: `/parts/v/{номер тома}/{номер главы}`
   - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии.
- Этот способ — средство ускорения; он не заменяет требования каждого платформенного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.
## Ключевые границы и жёсткие правила

- Загружать можно только главы, явно указанные пользователем, без самовольного расширения объёма.
- На шаге 2 для входа в авторский кабинет обязательно использовать **новую вкладку**; запрещено занимать исходную вкладку, которой пользуется пользователь.
- Перед входом в шаг 3 для каждой главы обязательно сначала запросить `番茄小说/分发记录.md`.
- Два вида адресов — `publish/{章节Id}` и `publish/?enter_from=newchapter` — обязаны разводиться автоматически по записи, смешивать их запрещено.
- После успешного «存草稿» каждой главы обязательно записать актуальный `章节Id` обратно в `番茄小说/分发记录.md`.
- Каждая глава обязана пройти «проверку соответствия названия книги / названия тома» до записи содержимого.
- Заголовок главы обязан браться из содержимого файла главы (обычно из строки заголовка `# ` в 1-й строке), использовать имя файла вместо заголовка нельзя.
- Номер главы обязан быть арабской цифрой, китайские числительные писать нельзя.
- Fanqie — платформа с делением на тома, номер главы обязан использовать относительный номер внутри тома, без накопления между томами.
- «作者有话说» (слово от автора) обязано вноситься по пути «作者有话说 → +添加 → 添加图文».
- Перед внесением слова от автора обязательно сначала очистить поле редактирования, затем вставить текст этой главы.
- Слово от автора перед сохранением обязано укладываться в лимит платформы по числу знаков (обычно 300 знаков).
- Итоговое действие — «存草稿», а не публикация.
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.
- По умолчанию **не использовать системный буфер обмена** как основной канал для основного текста; основной текст в первую очередь вносить способом «прямая запись в редактор», чтобы его не перезаписали внешние приложения, вызвав перепутывание глав.
- Буфер обмена допускается как аварийный вариант только тогда, когда ограничения элементов страницы не позволяют писать напрямую; при этом обязательно выполнять «проверку защиты буфера обмена от загрязнения» (см. ниже).

## Обработка сбоев и откатов

- Сбой входа: сообщить об ошибке аккаунта / пароля и остановиться, не продолжая последующие главы.
- Вход по паролю перехвачен и заменён входом по коду подтверждения: обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成»; до получения этой обратной связи любые последующие шаги выполнять нельзя.
- Отсутствие элемента страницы (например, изменение кнопки): записать текущий шаг сбоя и остановить эту главу; перед переходом к следующей главе сначала убедиться, что страница пригодна для действий.
- Несовпадение названия книги / названия тома: сразу остановить процесс загрузки этой книги, потребовать сначала исправить `README.md` или целевую ссылку.
- Сбой «存草稿»: отметить главу как сбойную; если после повторной попытки сбой остаётся — сохранить запись о сбое и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой сохранения слова от автора: не публиковать эту главу пока, повторить цепочку «редактирование слова от автора → сохранение слова от автора → сохранение черновика»; если сбой остаётся — записать причину и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой записи `分发记录.md`: хотя для этой главы черновик, возможно, уже сохранён, статус процесса обязательно пометить как «частичный сбой (запись не записана на диск)» и немедленно предложить ручную дозапись; молчаливый успех запрещён.

## Накопленный практический опыт (на основе реальных загрузок)

- Сначала проверять название книги + название тома в левом верхнем углу и только затем вносить любое основное содержимое; порядок нарушать нельзя.
- После первого входа на страницу создания URL часто превращается в `.../publish/{章节Id}?`; этот `章节Id` обязательно извлечь и записать в журнал распространения.
- После вставки основного текста следить за вверху показываемым «已保存/保存中» («сохранено / сохраняется») и ростом числа знаков основного текста, чтобы избежать ситуации «вроде вставлено, а на деле не записано на диск».
- Редактор слова от автора часто сосуществует с редактором основного текста; перед вводом необходимо убедиться, что фокус находится в области редактирования слова от автора.
- Единственным сигналом завершения каждой главы считать подсказку об успешном сохранении; без подсказки об успехе глава не считается завершённой.

### Новый опыт из раунда по главам 1–40 (запись от 2026-05-20)

- «添加图文» часто не появляется сразу: сначала нужно один раз нажать точный текст «添加» и затем выбрать «添加图文»; не использовать широкое соответствие `text=添加`, оно легко попадает в посторонние элементы вроде «添加更多设定» (добавить больше настроек).
- Если процесс этой главы превысил время ожидания, не спешить перезагружать всю главу; сначала прочитать текущее состояние страницы (номер главы / название главы / число знаков основного текста / состояние сохранения) — во многих случаях основной текст уже записан на диск, нужно лишь дополнить «слово от автора + сохранение черновика + проверку при повторном открытии».
- Извлечение заголовка должно быть отказоустойчивым: у некоторых глав заголовок `#` не содержит нумерации `1.1.X`, тогда номер главы должен откатываться на разбор имени файла; если заголовок `#` содержит нумерацию (например, `# 1.1.27 ...`), перед загрузкой нужно отрезать префикс и вносить только чистый текст заголовка.
- Для проверки страницы создания при повторном открытии предпочитать чистый URL `.../publish/{章节Id}`; некоторые адреса с `?enter_from=newchapter` могут влиять на стабильность повторного открытия.
- Журнал распространения нужно «записывать немедленно для каждой главы», а не дозаписывать пакетом; тогда при прерывании соответствие уже загруженных глав не потеряется.
- Если по ошибке записана запись о главе, фактически не загруженной успешно, её необходимо немедленно откатить из `分发记录.md`, сохраняя «факты в реестре совпадают с фактами в кабинете».
- Слово от автора часто превышает 300 знаков; на практике по умолчанию нужно готовить сжатую версию по принципу «крючок в приоритете», в первую очередь сохраняя: точку награды этой главы → оценку риска → драйв следующей главы.
- В сценариях больших партий системный буфер обмена реально рискует быть перезаписан другими приложениями; поэтому «прямую запись в редактор» нужно делать значением по умолчанию, а буфер обмена оставлять только как аварийный канал.

### Проверка защиты буфера обмена от загрязнения (включается только для аварийного канала)

1. Перед вставкой зафиксировать длину основного текста этой главы (или хэш-дайджест) как эталон.
2. Сразу после вставки проверить, достигло ли число знаков основного текста на странице ожидаемого порога (нельзя ориентироваться лишь на «сохранено в облаке»).
3. Если число знаков заметно меньше / больше, появились фрагменты предыдущей главы или заголовок не согласуется по смыслу с основным текстом, немедленно выполнить:
   - выделить весь основной текст и очистить
   - заново загрузить основной текст этой главы
   - вставить снова и перепроверить число знаков
4. Два подряд сбоя считать «риском загрязнения буфера обмена», для этой главы перейти на схему «прямая запись в редактор» и больше не использовать вставку.
5. Если процесс долгий (>10 минут) или параллельно работают несколько приложений, по умолчанию пропустить буфер обмена и идти по схеме без буфера обмена.
