# Загрузка указанных глав в GoodNovel с сохранением

Используется, чтобы загрузить указанную вами 1 или несколько глав в соответствующее произведение GoodNovel и сохранить их согласно требованиям кабинета.


<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (GoodNovel) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `GoodNovel/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `GoodNovel/`

> **О путях**: все пути вида `GoodNovel/` в нижеследующих разделах (например, `GoodNovel/README.md`, `GoodNovel/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `GoodNovel/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `GoodNovel/`.
- Вы уже записали в `GoodNovel/README.md` аккаунт, пароль, ID книги GoodNovel и название книги.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход в кабинет → подтверждение ручного входа → определение режима создания / изменения → заполнение заголовка главы → вставка основного текста → сохранение → переход к следующей главе.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт GoodNovel или ID книги.
- Цель — не «сохранить главу», а только сверка содержимого.

## Требования ко входным данным (обязательно)

### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `GoodNovel/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не берётся напрямую из имени файла**: его необходимо извлечь из содержимого файла главы, нормализовать и затем внести в поле заголовка на странице.

### 1.1) Правила извлечения и сборки заголовка главы (обязательно)

- Из файла главы обязательно извлечь: номер главы (арабскими цифрами), заголовок главы, основной текст.
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как исходный номер главы, а `三分钟` — как «заголовок главы».
- Хотя при итоговой загрузке в GoodNovel используется абсолютная нумерация глав, абсолютный номер можно вычислять только на основе последнего сегмента номера главы по правилам этого Skill; нельзя переносить в поле заголовка трёхуровневую нумерацию вроде `1.1.3`, `2.4.17` как есть; итоговая запись допустима только в формате вроде `Chapter 95 三分钟`.
- На странице GoodNovel есть только **одно поле заголовка главы**, итоговое вносимое значение — полная строка: `Chapter {绝对章号} {章节标题}`.
- Между `Chapter`, `绝对章号` (абсолютным номером главы) и `标题` (заголовком) обязательно сохранять **1 пробел**, например: `Chapter 1 天降奇缘`.
- Если строка заголовка файла главы уже имеет полный формат (например, `Chapter 12 Night Visitor`) и номер главы совпадает, её можно использовать напрямую.
- Если извлечённая строка заголовка содержит лишь текст заголовка (например, `夜半来客`), необходимо автоматически собрать `Chapter {绝对章号} 夜半来客`.
- Нельзя переносить в поле заголовка суффикс платформы из имени файла (например, `_GoodNovel版`).

### 1.2) Правило абсолютного номера главы (обязательно)

- Эта платформа **без деления на тома**, номер главы обязан использовать нумерацию «абсолютный номер главы» (см. `分发-七猫小说`).
- Абсолютный номер главы определяется комплексно по порядку загрузки и имеющимся записям:
  - если структура только из одного тома, абсолютным номером можно напрямую использовать порядковый номер этой главы в исходной рукописи;
  - если рукопись собрана из нескольких томов / частей, абсолютный номер обязан быть результатом накопления через тома.
- Абсолютный номер главы обязан быть арабской цифрой, китайские числительные использовать нельзя.
- Если в `分发记录.md` или локальном реестре томов и глав есть историческая запись, нумерацию нужно в первую очередь продолжать по истории, избегая повторных номеров.

### 2) Источник метаданных

- Обязательно прочитать `GoodNovel/README.md` и извлечь как минимум следующее:
  - имя пользователя авторского кабинета GoodNovel
  - пароль авторского кабинета GoodNovel
  - ID книги GoodNovel
   - название романа (название книги, для текущей цели загрузки)

### 2.1) Проверка платформы (обязательно)

После чтения `GoodNovel/README.md` необходимо проверить, равен ли его первый заголовок первого уровня `# GoodNovel 分发配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"GoodNovel 分发配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «GoodNovel 分发配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)

### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `GoodNovel/分发记录.md`:
  - если файла нет, сначала создать его, затем выполнять распространение.
  - у этой платформы нет поля ID главы, которое можно стабильно получить; вместо него используется «уникальный ключ главы + снимок заголовка / статуса в списке кабинета» для определения, в каком режиме находится глава — «создания» или «изменения».

### 4) Правило определения названия книги (обязательно)

- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава; нельзя ошибочно использовать общее название.

### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.

### 5) Шаблон `分发记录.md` (при первом создании использовать напрямую)

Если `GoodNovel/分发记录.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# GoodNovel 分发记录

> Назначение: у этой платформы нет стабильно извлекаемого ID главы, поэтому фиксируется «уникальный ключ главы -> снимок заголовка / статуса в кабинете», чтобы определять создание и изменение и выполнять прослеживаемую проверку.

## Описание полей

- `章节唯一键` (уникальный ключ главы): фиксированный формат `GoodNovel书籍ID|绝对章号|章名`
- `GoodNovel书籍ID` (ID книги GoodNovel): соответствует ID книги в `GoodNovel/README.md`
- `后台章节标题` (заголовок главы в кабинете): текст заголовка, видимый в списке глав слева после сохранения
- `后台状态` (статус в кабинете): статус, видимый в списке глав слева после сохранения (например, Draft/Published)
- `最近操作` (последняя операция): `新建` (создание) или `修改` (изменение)
- `最近保存入口URL` (URL последнего входа сохранения): URL страницы главы после последнего сохранения (для аудита, не используется как ID главы)
- `更新时间` (время обновления): `YYYY-MM-DD HH:mm:ss`
- `备注` (примечание): необязательно

## Таблица записей

|章节唯一键|GoodNovel书籍ID|后台章节标题|后台状态|最近操作|最近保存入口URL|更新时间|备注|
|:--|:--|:--|:--|:--|:--|:--|:--|
```

### 6) Шаблон `README.md` (при первом создании использовать напрямую)

Если `GoodNovel/README.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# GoodNovel 分发配置

> Назначение: хранит ID и названия книг GoodNovel. Процесс распространения требует ручного входа пользователя и пароль не читает.

## Информация о книге

### Роман без частей

| Название романа | ID книги GoodNovel |
|:--|:--|
| 作品名 | 11997642 |

### Роман с частями

| Номер части | Название части | ID книги GoodNovel |
|:--|:--|:--|
| 第1部 | 分部一书名 | 11997642 |
| 第2部 | 分部二书名 | 11997643 |

## Описание полей

- `小说名称` / `分部名`: должны точно совпадать с «правилом определения названия книги» из SKILL
- `分部号`: необходимо использовать нормативный формат `第N部` (например, `第1部`, `第2部`) и однозначно сопоставлять с `分部名`, без смещений и повторного использования
- `GoodNovel 书籍ID`: берётся из авторского кабинета GoodNovel

## Способ входа

- **Этот файл не хранит пароль.** Процесс распространения откроет GoodNovel в браузере, и вам нужно **войти вручную** в браузере.
- Убедитесь, что вошедший аккаунт имеет права редактирования перечисленных книг.

## Примечания

- Процесс распространения проверит состояние входа; если вход не выполнен, нужно вручную завершить вход и только затем продолжать.
- У GoodNovel нет отдельного входа для слова от автора, соответствующее содержимое отдельно отправить нельзя.
- Получение ID главы зависит от состояния текущей страницы, возможна задержка заполнения.
```

## Процесс выполнения (строго по порядку)

### Шаг 1: чтение локальных входных данных

1. Прочитать и разобрать `GoodNovel/README.md`.
2. Убедиться, что получены: аккаунт, пароль, целевой ID книги (выбранный по «правилу определения ID книги»), целевое название романа.
3. Прочитать `GoodNovel/分发记录.md` и построить соответствие «уникальный ключ главы -> снимок заголовка / статуса в кабинете».
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: исходный номер главы (последний сегмент номера), заголовок главы, основной текст.
5. Для каждой главы сформировать «итоговое значение поля заголовка на странице»: `Chapter {绝对章号} {章节标题}`.

### Шаг 2: вход в авторский кабинет

1. **Обязательно открыть новую вкладку браузера** и в этой новой вкладке перейти по адресу:
   - `https://www.goodnovel.com/uc/stories`
2. Эта новая вкладка используется только для текущего процесса загрузки в GoodNovel; вкладку, в которой вы сейчас решаете другие задачи, повторно не использовать.
3. Если состояние входа недействительно или вход не выполнен:
   - сначала перейти к процессу входа, но **обязательно дождаться, пока пользователь вручную завершит вход**.
   - до тех пор, пока пользователь явно не сообщит вам «登录完成» (вход завершён), запрещено выполнять любые дальнейшие шаги.
   - в это время не пытаться подставлять пароль и не имитировать состояние успешного входа.
4. После завершения входа продолжить последующий процесс редактирования.
5. Если на странице редактирования появляются слой для новичков, подсказки-перекрытия или окна подтверждения:
   - сначала закрыть, пропустить или свернуть, убедившись, что редактор нормально работает, и только затем продолжать.

### Шаг 3: переход на страницу главы целевой книги (создание / изменение — одно из двух)

1. Перед переходом сначала проверить в `GoodNovel/分发记录.md`, есть ли уже историческая запись для уникального ключа этой главы.
2. Если у этой главы **нет** исторической записи (режим создания), перейти по адресу:
   - `https://www.goodnovel.com/create_chapter/{书籍Id}`
3. Если у этой главы **уже есть** историческая запись (режим изменения), перейти по адресу:
   - `https://www.goodnovel.com/create_chapter/{书籍ID}?chapterId=0`
4. В режиме изменения после входа обязательно найти и нажать целевую главу в списке глав слева:
   - сначала сопоставить по заголовку главы;
   - затем выполнить вторичное подтверждение по статусу главы (статус, видимый в списке);
   - при конфликте одноимённых глав выбрать ближайшую к «статусу в кабинете» из записи и подтвердить вручную.

### Шаг 4: проверка информации о текущем произведении

1. Проверить, соответствует ли произведение на текущей странице редактирования целевому названию книги из `README.md`.
2. Если на странице есть информация о книге или метка произведения в левом верхнем углу, дополнительно проверить целевое название книги.
3. Если название книги не совпадает:
   - немедленно остановить загрузку текущей главы.
   - вернуть описание ошибки (название книги не совпадает).
   - запрещено продолжать слепую загрузку в неверное произведение.

### Шаг 5: заполнение поля заголовка

1. Найти поле заголовка главы.
2. Установить его содержимое в полную строку: `Chapter {绝对章号} {章节标题}`.
3. Перед вводом сначала выделить всё и очистить старое значение, чтобы не осталось «безымянная глава», «заголовок черновика» или прежние заголовки.
4. Ещё раз сверить:
   - использован арабский номер главы.
   - между `Chapter`, номером главы и заголовком только один пробел.
   - не подмешана посторонняя информация — суффикс имени файла, название книги, название платформы и т. п.

### Шаг 6: заполнение основного текста

1. Ввести основной текст главы в область редактирования основного текста.
2. Необходимо гарантировать, что текст взят из указанного вами файла главы, без перепутывания глав.
3. Если редактор — область форматированного или квазиформатированного текста, после ввода необходимо убедиться, что видимый основной текст действительно попал в область редактирования, а не в элемент с неверным фокусом.

### Шаг 7: обработка слова от автора

- У этой платформы нет места для ввода «слова от автора», **этот шаг фиксированно пропускается**.
- Нельзя выдумывать для этого поле и нельзя склеивать «слово от автора» с основным текстом вместо него.

### Шаг 8: сохранение и запись статуса загрузки

1. Нажать «SAVE».
2. Дождаться сообщения страницы об успешном сохранении или эквивалентного состояния успеха.
3. После успешного сохранения вернуться к списку глав слева / посмотреть на него и убедиться, что строка целевой главы видна, а заголовок и статус распознаваемы.
4. Записать «уникальный ключ главы + заголовок главы в кабинете + статус в кабинете + URL последнего входа сохранения + время обновления» обратно в `GoodNovel/分发记录.md`:
   - если записи нет: добавить новую;
   - если запись уже есть: обновить заголовок / статус в кабинете, последнюю операцию, URL последнего входа сохранения и время обновления.
5. Если у платформы нет стабильно получаемого ID главы, **нельзя выдумывать поле ID главы**, записывать только наблюдаемые свидетельства.

> Правило формирования уникального ключа главы (обязательно):
> - Порядок полей: `GoodNovel书籍ID|绝对章号|章名`
> - При этом:
>   - `GoodNovel书籍ID` берётся из `GoodNovel/README.md`
>   - `绝对章号` обязан быть арабской цифрой и непрерывно накапливаться по схеме без деления на тома
>   - `章名` — заголовок главы
> - Это правило нужно, чтобы и без ID главы сохранять стабильное соответствие «одна глава — один ключ».

6. Если сохранение успешно, но не удалось найти целевую главу в списке слева (или статус нечитаем):
   - статус этой главы обязательно пометить как «частичный успех (сохранено, снимок списка не подтверждён)»;
   - немедленно явно сообщить пользователю о точке блокировки;
   - запрещено молча засчитывать эту главу как полностью успешную.

### Шаг 9: цикл по нескольким главам

- Для каждой указанной главы строго повторять шаги 3–8, пока не будут завершены все главы.
- Перед началом каждой главы обязательно один раз запрашивать `分发记录.md` для определения режима создания / изменения, нельзя наследовать режим предыдущей главы.


### Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и расширенных полей платформы (например, «слово автора» / текст настроек публикации);
   - предпроверка ограничений платформы (например, число знаков в заголовке, число знаков в слове автора, обязательные пункты публикации);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `{каталог платформы}/.cache/content_parts/no_part/v{номер тома}/*.txt`, `{каталог платформы}/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (по записи — создание или изменение);
   2) заполнить заголовок;
   3) заполнить основной текст;
   4) заполнить расширенные поля платформы (например, слово автора / настройки публикации);
   5) сохранить черновик;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по `5–10` глав:
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- Так даже при ограничении частоты, колебаниях состояния входа или смене вёрстки страницы пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Для неблокирующих напоминаний, многократно появляющихся на платформе (напоминание о числе знаков, обучающие слои, окна-подсказки), при первом появлении можно убрать шум и продолжить основной процесс.
- Только когда всплывающее окно реально блокирует критический путь «ввод / сохранение / отправка», повышать до обработки как сбой или ручного вмешательства.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / расширенные поля платформы / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs`:
   - без частей: `/parts/v/{номер тома}/{номер главы}`
   - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии.
- Этот способ — средство ускорения; он не заменяет требования каждого платформенного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.
## Ключевые границы и жёсткие правила

- Загружать можно только главы, явно указанные пользователем, без самовольного расширения объёма.
- На шаге 2 обязательно сначала перейти на `https://www.goodnovel.com/uc/stories` и при необходимости входа **дождаться, пока пользователь вручную завершит вход**.
- Перед входом в шаг 3 для каждой главы обязательно сначала запросить `GoodNovel/分发记录.md`.
- Режим создания обязан использовать `https://www.goodnovel.com/create_chapter/{书籍Id}`.
- Режим изменения обязан сначала открыть `https://www.goodnovel.com/create_chapter/{书籍ID}?chapterId=0`, затем в списке глав слева нажать целевую главу.
- Поиск в списке глав слева обязан использовать двухфакторное подтверждение «заголовок + статус», чтобы не нажать по ошибке одноимённую главу.
- Поле заголовка главы обязано содержать полную строку `Chapter {绝对章号} {章节标题}` с одним пробелом между частями.
- Номер главы обязан быть арабской цифрой, китайские числительные писать нельзя.
- Эта платформа без деления на тома, нумерация глав обязана использовать абсолютный номер главы, без относительной нумерации внутри тома.
- У этой платформы нет места ввода «слова от автора», его необходимо игнорировать, нельзя выдумывать замещающее место.
- Для сохранения обязательно нажать «SAVE».
- Нигде нет места, откуда можно стабильно извлечь ID главы, поэтому схема записи обязана использовать «уникальный ключ главы + снимок заголовка / статуса в списке + URL последнего входа сохранения».
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.

## Обработка сбоев и откатов

- Вход не завершён: обязательно оставаться в состоянии ожидания входа, пока пользователь явно не сообщит «登录完成».
- Отсутствие элемента страницы (например, изменение кнопки, список не появился): записать текущий шаг сбоя и остановить эту главу; перед переходом к следующей главе сначала убедиться, что страница пригодна для действий.
- Название книги не совпадает: сразу остановить процесс загрузки этой книги, потребовать сначала исправить `GoodNovel/README.md` или целевой ID книги.
- Сбой сохранения: отметить главу как сбойную; если после повторной попытки сбой остаётся — сохранить запись о сбое и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой поиска в списке: пометить главу «частичный успех (сохранено, снимок списка подтвердить невозможно)» и потребовать ручной проверки; молчаливый успех запрещён.
- Сбой записи `GoodNovel/分发记录.md`: хотя эта глава, возможно, уже сохранена, статус процесса обязательно пометить как «частичный сбой (запись не записана на диск)» и немедленно предложить ручную дозапись; молчаливый успех запрещён.

## Накопленный практический опыт (на основе известной информации о странице и логики распространения)

### Вход и точка входа

- Шаги входа на `www.goodnovel.com` обязательно оставлять пользователю для выполнения вручную; это жёсткая граница.
- `https://www.goodnovel.com/uc/stories` при отсутствии входа **молча перенаправляет на главную**, а не на страницу входа. Более надёжная точка входа — сразу перейти на `https://www.goodnovel.com/login`, а после входа пользователя вручную перейти на `/create_chapter/{书籍Id}` или перейти через Playwright.
- На странице входа есть кнопка "Signin to Good Novel", после нажатия всплывает форма входа (Google / Facebook / email и др.).

### Редактор и ввод основного текста

- Редактор GoodNovel — **TinyMCE** (определяется через `typeof tinymce !== 'undefined'`).
- **Ключевая ловушка: прямое изменение innerHTML у body внутри iframe не вызывает внутренние события изменения TinyMCE**, из-за чего при нажатии SAVE появляется ошибка "Drafts can't be saved when empty".
- **Правильный способ**: обязательно писать содержимое через `tinymce.activeEditor.setContent(html)`, затем вызывать `tinymce.activeEditor.fire('change')` для запуска определения изменений. Только после того как TinyMCE заметит изменение содержимого, кнопка SAVE реально сохранит.
- Перед записью основного текста обязательно сначала удалить абзац `## 作者有话说` («Слово от автора») и всё после него — у этой платформы нет отдельного входа для слова от автора.

### Канал данных для пакетной загрузки

- Для больших партий (10+ глав) **не** прописывать в `page.evaluate()` Playwright большие текстовые строки жёстко: это приводит к тайм-аутам и уничтожению контекста.
- **Рекомендуемая схема**:
  1. Скриптом Node.js заранее локально извлечь основные тексты всех глав (убрав строку заголовка и слово от автора) и записать в каталог `.cache/content_parts/`.
  2. Запустить минимальный статический HTTP-сервис (например, `node -e "require('http').createServer(...)"`, слушающий порт `localhost`), возвращающий предварительно извлечённый текст по номеру главы.
  3. В браузере получать основной текст через `fetch('http://localhost:18765/ch/{n}')`, затем записывать через `tinymce.activeEditor.setContent()`.
- Этот способ разделяет «чтение файла» и «запись в редактор»: Node.js отвечает за чтение файлов, браузер — только за заполнение формы, что заметно сокращает время на одну главу.

### Дрожание навигации страницы

- После нажатия SAVE GoodNovel создаёт новую строку черновика "Untitled Chapter" и автоматически переключается на эту пустую главу; состояние редактора сбрасывается (поле заголовка очищается, TinyMCE очищается).
- Иногда после SAVE страница запускает полную навигацию (URL не меняется, но DOM перестраивается), из-за чего Playwright сообщает "Execution context was destroyed". В этом случае нужно `waitForTimeout(1500)`, дождаться готовности нового контекста и повторить.
- После SAVE в списке глав слева сразу появляется новая глава; сохранение можно подтвердить опросом текста `Chapter {N}` в элементах `li`.

### Заголовок главы и боковая панель

- Режим изменения не использует переход напрямую по ID главы, а сначала открывает точку входа редактирования с `chapterId=0`, затем в списке глав слева нажимается целевая глава.
- В списке слева показываются заголовок и статус главы; использование обоих вместе для поиска целевой главы стабильнее, чем один заголовок.
- У этой платформы нет входа для «слова от автора»; не нужно «насильно подклеивать» его в основной текст.
- Отсутствие ID главы не означает отсутствия реестра: через «уникальный ключ главы + снимок заголовка / статуса + URL последнего входа сохранения» тоже можно реализовать прослеживаемое инкрементальное обновление.

### Число знаков и фактическое поведение

- Редактор GoodNovel в правом нижнем углу показывает "Ideal word count: 600-1000", но это **лишь рекомендация**: длинные главы (в этот раз самая длинная — 7657 слов / 51959 знаков) сохранялись и публиковались без блокировок. Нет необходимости разбивать главы, чтобы дотянуть до 1000 слов.

### Типичный такт одной главы (ускоренная версия, секунды)

1. `page.locator('input[placeholder="Chapter title"]').fill('Chapter {N} {Title}')` — заполнить заголовок
2. `page.evaluate(async (n) => { const res = await fetch('http://localhost:18765/ch/' + n); ... tinymce.activeEditor.setContent(html); tinymce.activeEditor.fire('change'); }, chNum)` — получить основной текст + записать в TinyMCE
3. `click SAVE` — сохранить
4. Подождать 1–2 секунды, перейти к следующей главе

## Минимальный исполнимый чек-лист (версия на 10 секунд)

> Порядок применения: перед каждым распространением быстро пройтись по пунктам по порядку; если какой-либо пункт не выполнен, сначала исправить, затем загружать.

1. **Полны ли входные данные**
   - Чётко определено, какие именно главы загружаются на этот раз (объём не расширяется).
   - Из `GoodNovel/README.md` читаются имя пользователя, пароль, ID книги, название книги.

2. **Верна ли цель**
   - Название книги на текущей странице редактирования совпадает с `README.md`.
   - Режим главы определён: нет записи — идти на создание (`/create_chapter/{书籍Id}`), есть запись — идти на изменение (`/create_chapter/{书籍ID}?chapterId=0` + нажатие главы в списке слева).

3. **Выполнен ли ключевой ввод**
   - Поле заголовка в полном формате: `Chapter {绝对章号} {章节标题}` (Chapter + арабская цифра + один пробел).
   - Подтверждено, что основной текст записан в видимую область редактора (а не ошибочно внесён в другое место).
   - Подтверждено, что у этой платформы нет входа для слова от автора, и шаг пропущен по правилу.

4. **Замкнуты ли сохранение и запись**
   - Нажато «SAVE» и успех подтверждён.
   - В списке слева подтверждены заголовок и статус целевой главы.
   - Выполнена запись обратно в `GoodNovel/分发记录.md` (снимок заголовка / статуса + URL последнего входа сохранения).

5. **Явно ли обозначен сбой**
   - Если вход не завершён, сохранение не удалось, список не подтверждён, запись не внесена: обязательно пометить как сбой / частичный успех и указать точку блокировки.
