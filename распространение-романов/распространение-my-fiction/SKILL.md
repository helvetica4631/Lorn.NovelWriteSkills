# Загрузка указанных глав в My Fiction с сохранением

Используется, чтобы загрузить указанную вами 1 или несколько глав в соответствующее произведение My Fiction и сохранить их согласно требованиям кабинета.


<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (My Fiction) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `My Fiction/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `My Fiction/`

> **О путях**: все пути вида `My Fiction/` в нижеследующих разделах (например, `My Fiction/README.md`, `My Fiction/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `My Fiction/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `My Fiction/`.
- Вы уже записали в `My Fiction/README.md` аккаунт, пароль, ID книги My Fiction, название книги и прочую информацию.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход в кабинет → подтверждение ручного входа → определение режима создания / изменения → заполнение заголовка главы → вставка основного текста → добавление слова от автора → сохранение → переход к следующей главе.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт My Fiction или ID книги.
- Цель — не «сохранить главу», а только сверка содержимого.

## Требования ко входным данным (обязательно)

### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `My Fiction/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не берётся напрямую из имени файла**: его необходимо извлечь из содержимого файла главы, нормализовать и затем внести в поле заголовка на странице.

### 1.1) Правила извлечения и сборки заголовка главы (обязательно)

- Из файла главы обязательно извлечь: номер главы (арабскими цифрами), заголовок главы, основной текст, слово от автора.
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как исходный номер главы, а `三分钟` — как «заголовок главы».
- Хотя при итоговой загрузке в My Fiction используется абсолютная нумерация глав, абсолютный номер можно вычислять только на основе последнего сегмента номера главы по правилам этого Skill; нельзя переносить в поле заголовка трёхуровневую нумерацию вроде `1.1.3`, `2.4.17` как есть; итоговая запись допустима только в формате вроде `Chapter 95 三分钟`.
- На странице My Fiction есть только **одно поле заголовка главы**, итоговое вносимое значение — полная строка: `Chapter {绝对章号} {章节标题}`.
- Между `Chapter`, `绝对章号` (абсолютным номером главы) и `标题` (заголовком) обязательно сохранять **1 пробел**, например: `Chapter 1 天降奇缘`.
- Если строка заголовка файла главы уже имеет полный формат (например, `Chapter 12 Night Visitor`) и номер главы совпадает, её можно использовать напрямую.
- Если извлечённая строка заголовка содержит лишь текст заголовка (например, `夜半来客`), необходимо автоматически собрать `Chapter {绝对章号} 夜半来客`.
- Нельзя переносить в поле заголовка суффикс платформы из имени файла (например, `_My Fiction版`).

### 1.2) Правило абсолютного номера главы (обязательно)

- Эта платформа **без деления на тома**, номер главы обязан использовать нумерацию «абсолютный номер главы».
- Абсолютный номер главы определяется комплексно по порядку загрузки и имеющимся записям:
  - если структура только из одного тома, абсолютным номером можно напрямую использовать порядковый номер этой главы в исходной рукописи.
  - если рукопись собрана из нескольких томов / частей, абсолютный номер обязан быть результатом накопления через тома.
- Абсолютный номер главы обязан быть арабской цифрой, китайские числительные использовать нельзя.
- Если в `分发记录.md` или локальном реестре томов и глав есть историческая запись, нумерацию нужно в первую очередь продолжать по истории, избегая повторных номеров.

### 2) Источник метаданных

- Обязательно прочитать `My Fiction/README.md` и извлечь как минимум следующее:
  - имя пользователя авторского кабинета My Fiction
  - пароль авторского кабинета My Fiction
  - ID книги My Fiction (**шестнадцатеричная строка**, например `6a01207e51867`; выбрать значение, соответствующее текущей главе, по «правилу определения ID книги»)
   - название романа (название книги, для текущей цели загрузки)
### 2.1) Проверка платформы (обязательно)

После чтения `My Fiction/README.md` необходимо проверить, равен ли его первый заголовок первого уровня `# My Fiction 分发配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"My Fiction 分发配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «My Fiction 分发配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)
### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `My Fiction/分发记录.md`:
  - если файла нет, сначала создать его, затем выполнять распространение.
  - используется для запроса соответствия «уникальный ключ главы -> ID главы» и определения для главы «режима создания» или «режима изменения».

### 4) Правило определения названия книги (обязательно)

- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава; нельзя ошибочно использовать общее название.

### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.
- ID книги My Fiction не является чисто числовым: его необходимо использовать как шестнадцатеричную строку в исходном виде, самовольно переводить в десятичный нельзя.

### 5) Шаблон `分发记录.md` (при первом создании использовать напрямую)

Если `My Fiction/分发记录.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# My Fiction 分发记录

> Назначение: фиксирует соответствие «уникальный ключ главы -> ID главы My Fiction», чтобы процесс распространения мог определять «режим создания / режим изменения».

## Описание полей

- `章节唯一键` (уникальный ключ главы): фиксированный формат `MyFiction书籍ID|绝对章号|章名`
- `MyFiction书籍ID` (ID книги My Fiction): соответствует ID книги в `My Fiction/README.md` (шестнадцатеричная строка)
- `章节Id` (ID главы): ID главы, возвращаемый после сохранения главы
- `最近操作` (последняя операция): `新建` (создание) или `修改` (изменение)
- `更新时间` (время обновления): `YYYY-MM-DD HH:mm:ss`
- `备注` (примечание): необязательно

## Таблица записей

|章节唯一键|MyFiction书籍ID|章节Id|最近操作|更新时间|备注|
|:--|--|--|:--|:--|:--|
```

### 6) Шаблон `README.md` (при первом создании использовать напрямую)

Если `My Fiction/README.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# My Fiction 分发配置

> Назначение: хранит информацию о книгах My Fiction. Процесс распространения требует ручного входа пользователя и пароль не читает.

## Информация о книге

### Роман без частей

| Название романа | ID книги My Fiction |
|:--|:--|
| 作品名 | 6a01207e51867 |

### Роман с частями

| Номер части | Название части | ID книги My Fiction |
|:--|:--|:--|
| 第1部 | 分部一书名 | 6a01207e51867 |
| 第2部 | 分部二书名 | 6a01207e51868 |

## Описание полей

- `小说名称` / `分部名`: должны точно совпадать с «правилом определения названия книги» из SKILL
- `分部号`: необходимо использовать нормативный формат `第N部` (например, `第1部`, `第2部`) и однозначно сопоставлять с `分部名`, без смещений и повторного использования
- `My Fiction 书籍ID`: шестнадцатеричная строка, берётся из авторского кабинета My Fiction (например, `6a01207e51867`)

## Способ входа

- **Этот файл не хранит пароль.** Процесс распространения откроет My Fiction в браузере, и вам нужно **войти вручную** в браузере.
- Убедитесь, что вошедший аккаунт имеет права редактирования перечисленных книг.

## Примечания

- Процесс распространения проверит состояние входа; если вход не выполнен, нужно вручную завершить вход и только затем продолжать.
- ID книги имеет шестнадцатеричный формат, не путайте с десятичным.
```

## Процесс выполнения (строго по порядку)

### Шаг 1: чтение локальных входных данных

1. Прочитать и разобрать `My Fiction/README.md`.
2. Убедиться, что получены: аккаунт, пароль, целевой ID книги (выбранный по «правилу определения ID книги»), целевое название романа.
3. Прочитать `My Fiction/分发记录.md` и построить соответствие «уникальный ключ главы -> ID главы» (рекомендуемый уникальный ключ: `MyFiction书籍ID|绝对章号|章名`).
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: исходный номер главы (последний сегмент номера), заголовок главы, основной текст, слово от автора.
5. Для каждой главы сформировать «итоговое значение поля заголовка на странице»: `Chapter {绝对章号} {章节标题}`.

### Шаг 2: вход в авторский кабинет

1. **Обязательно открыть новую вкладку браузера** и в этой новой вкладке перейти по адресу:
   - `https://write.myfiction.com/my-stories`
2. Эта новая вкладка используется только для текущего процесса загрузки в My Fiction; вкладку, в которой вы сейчас решаете другие задачи, повторно не использовать.
3. Если состояние входа недействительно или вход не выполнен:
   - сначала перейти к процессу входа, но **обязательно дождаться, пока пользователь вручную завершит вход**.
   - до тех пор, пока пользователь явно не сообщит вам «登录完成» (вход завершён), запрещено выполнять любые дальнейшие шаги.
   - в это время не пытаться подставлять пароль и не имитировать состояние успешного входа.
4. После завершения входа продолжить последующий процесс редактирования.
5. Если на странице редактирования появляются слой для новичков, подсказки-перекрытия или окна подтверждения:
   - сначала закрыть, пропустить или свернуть, убедившись, что редактор нормально работает, и только затем продолжать.

### Шаг 3: переход на страницу главы целевой книги (создание / изменение — одно из двух)

1. Перед переходом сначала проверить в `My Fiction/分发记录.md`, есть ли уже у этой главы `章节Id`.
2. Если у этой главы **нет** ID главы (режим создания), перейти по адресу:
   - `https://write.myfiction.com/my-stories/chapter/new?book_id={书籍ID}`
3. Если у этой главы **уже есть** ID главы (режим изменения), перейти по адресу:
   - `https://write.myfiction.com/my-stories/chapter/edit?book_id={书籍ID}&real_chapter_id=6a01207e51867&_chap_order_id=1`
   - при этом для `book_id` использовать шестнадцатеричный ID книги из `My Fiction/README.md`.
   - `real_chapter_id` обязательно заменить на фактический ID этой главы.
   - `_chap_order_id` — порядковое значение этой главы в текущей абсолютной последовательности глав.
4. После входа на страницу редактирования сначала убедиться, что информация о текущем произведении совпадает с целевым названием книги.

### Шаг 4: проверка информации о текущем произведении

1. Проверить, соответствует ли произведение на текущей странице редактирования целевому названию книги из `README.md`.
2. Если на странице есть информация о главе, информация о книге или метка произведения в левом верхнем углу, дополнительно проверить целевое название книги.
3. Если название книги не совпадает:
   - немедленно остановить загрузку текущей главы.
   - вернуть описание ошибки (название книги не совпадает).
   - запрещено продолжать слепую загрузку в неверное произведение.

### Шаг 5: заполнение поля заголовка

1. Найти поле заголовка главы.
2. Установить его содержимое в полную строку: `Chapter {绝对章号} {章节标题}`.
3. Перед вводом сначала выделить всё и очистить старое значение, чтобы не осталось «безымянная глава», «заголовок черновика» или прежние заголовки.
4. Ещё раз сверить:
   - использован арабский номер главы.
   - между `Chapter`, номером главы и заголовком только один пробел.
   - не подмешана посторонняя информация — суффикс имени файла, название книги, название платформы и т. п.

### Шаг 6: заполнение основного текста

1. Ввести основной текст главы в область редактирования основного текста.
2. Необходимо гарантировать, что текст взят из указанного вами файла главы, без перепутывания глав.
3. **Редактор — форматированный текстовый редактор Draft.js** (селектор класса `.public-DraftEditor-content`); способы ниже расположены по надёжности:
   - **Предпочтительно**: `page.keyboard.insertText(bodyText)` — посимвольная имитация ввода, Draft.js корректно перехватывает и обновляет внутреннее состояние и подсчёт знаков. Цена — большая длительность (около 15 секунд на 10K знаков).
   - **Второй выбор**: `document.execCommand('insertText', false, text)` — разовая вставка простого текста, Draft.js её распознаёт, но чрезвычайно большой текст может вызвать ошибку внутреннего состояния React.
   - **Запрещено**: напрямую изменять `el.innerHTML` или `el.textContent` — Draft.js опирается на внутренний ContentState, операции DOM в обход React не запускают обновление подсчёта знаков и могут вызвать клиентское исключение "Application error".

### Шаг 7: добавление слова от автора

1. Нажать "+ Add Author's Note" под областью редактирования главы.
2. **Обратите внимание: это действие не открывает отдельный диалог**, а разворачивает встроенное поле ввода под редактором основного текста (`placeholder="Enter author's note here."`).
3. Внести в встроенное поле ввода содержимое «слова от автора» этой главы.
4. **Нажимать SUBMIT не нужно**: содержимое слова от автора и основной текст находятся на одной странице и в итоге отправляются вместе через "SAVE".
5. Если на странице есть подсказка об ограничении числа знаков, сохранить смысл исходного текста в пределах лимита, нельзя насильно превышать.
6. После завершения ввода убедиться, что содержимое видно, чтобы введённое не потерялось.

### Шаг 8: сохранение и получение ID главы

1. Нажать «SAVE».
2. Дождаться сообщения страницы об успешном сохранении или эквивалентного состояния успеха.
3. После успешного сохранения **обязательно сразу подтвердить, что URL текущей страницы главы изменился на**:
   - `https://write.myfiction.com/my-stories/chapter/edit?book_id={书籍ID}&real_chapter_id={章节ID}`
4. Извлечь из URL `{章节ID}` и считать его окончательным `章节Id` этой главы.
5. Если страница не перешла, но сохранение успешно, также нужно продолжить проверку адресной строки и состояния страницы, подтвердив, обновился ли адрес до URL редактирования.
6. Записать «уникальный ключ главы + ID главы + время обновления» обратно в `My Fiction/分发记录.md`:
   - если записи нет: добавить новую.
   - если запись уже есть: обновить `章节Id` (если изменился) и время обновления.
7. `最近操作` записывается как `新建` или `修改` в зависимости от текущего режима.

> Правило формирования уникального ключа главы (обязательно):
> - Порядок полей: `MyFiction书籍ID|绝对章号|章名`
> - При этом:
>   - `MyFiction书籍ID` берётся из `My Fiction/README.md`
>   - `绝对章号` обязан быть арабской цифрой и непрерывно накапливаться по схеме без деления на тома
>   - `章名` — заголовок главы
> - Это правило нужно, чтобы избежать конфликтов одинаковых номеров глав при параллельном распространении нескольких глав.

8. Если сохранение успешно, но `章节Id` по-прежнему не получен явно:
   - статус этой главы обязательно пометить как «частичный успех (сохранено, но ID главы не подтверждён)».
   - немедленно явно сообщить пользователю о точке блокировки.
   - запрещено молча засчитывать эту главу как полностью успешную.

### Шаг 9: цикл по нескольким главам

- Для каждой указанной главы строго повторять шаги 3–8, пока не будут завершены все главы.
- Перед началом каждой главы обязательно один раз запрашивать `分发记录.md` для определения режима создания / изменения, нельзя наследовать режим предыдущей главы.


### Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и расширенных полей платформы (например, «слово автора» / текст настроек публикации);
   - предпроверка ограничений платформы (например, число знаков в заголовке, число знаков в слове автора, обязательные пункты публикации);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `{каталог платформы}/.cache/content_parts/no_part/v{номер тома}/*.txt`, `{каталог платформы}/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (по записи — создание или изменение);
   2) заполнить заголовок;
   3) заполнить основной текст;
   4) заполнить расширенные поля платформы (например, слово автора / настройки публикации);
   5) сохранить черновик;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по **5 глав** (проверено как оптимальный ритм: 5 глав занимают около 3 минут, не вызывают ограничения частоты и позволяют быстро повторить при сбое):
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- В конце каждой партии выполнять сверку: `план = успех + сбой`, причём для всех успешных глав выполнена запись `章节Id` обратно.
- Так даже при крахе VS, колебаниях состояния входа или обрыве сети пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Для неблокирующих напоминаний, многократно появляющихся на платформе (напоминание о числе знаков, обучающие слои, окна-подсказки), при первом появлении можно убрать шум и продолжить основной процесс.
- Только когда всплывающее окно реально блокирует критический путь «ввод / сохранение / отправка», повышать до обработки как сбой или ручного вмешательства.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / расширенные поля платформы / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs`:
   - без частей: `/parts/v/{номер тома}/{номер главы}`
   - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии.
- Этот способ — средство ускорения; он не заменяет требования каждого платформенного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.
## Ключевые границы и жёсткие правила

- Загружать можно только главы, явно указанные пользователем, без самовольного расширения объёма.
- На шаге 2 обязательно сначала перейти на `https://write.myfiction.com/my-stories` и при необходимости входа **дождаться, пока пользователь вручную завершит вход**.
- Перед входом в шаг 3 для каждой главы обязательно сначала запросить `My Fiction/分发记录.md`.
- Режим создания обязан использовать `https://write.myfiction.com/my-stories/chapter/new?book_id={书籍ID}`, режим изменения — `https://write.myfiction.com/my-stories/chapter/edit?book_id={书籍ID}&real_chapter_id={章节ID}&_chap_order_id={顺序}`, смешивать их нельзя.
- Поле заголовка главы обязано содержать полную строку `Chapter {绝对章号} {章节标题}` с одним пробелом между частями.
- Номер главы обязан быть арабской цифрой, китайские числительные писать нельзя.
- Эта платформа без деления на тома, нумерация глав обязана использовать абсолютный номер главы, без относительной нумерации внутри тома.
- "ADD AUTHOR'S Note" обязательно сначала открывает диалог, затем «слово от автора» вносится в диалоге.
- После внесения «слова от автора» обязательно нажать "SUBMIT".
- Для сохранения обязательно нажать «SAVE».
- После `SAVE` URL должен измениться на `https://write.myfiction.com/my-stories/chapter/edit?book_id={书籍ID}&real_chapter_id={章节ID}`; если не изменился, нужно продолжить проверку, нельзя по умолчанию считать успешным.
- Если `章节Id` не получен, нельзя помечать эту главу как полностью успешную.
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.

## Обработка сбоев и откатов

- Вход не завершён: обязательно оставаться в состоянии ожидания входа, пока пользователь явно не сообщит «登录完成».
- Отсутствие элемента страницы (например, изменение кнопки, диалог не появился): записать текущий шаг сбоя и остановить эту главу; перед переходом к следующей главе сначала убедиться, что страница пригодна для действий.
- Название книги не совпадает: сразу остановить процесс загрузки этой книги, потребовать сначала исправить `My Fiction/README.md` или целевой ID книги.
- Сбой сохранения: отметить главу как сбойную; если после повторной попытки сбой остаётся — сохранить запись о сбое и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Аномалия состояния сохранения «слова от автора» или потеря содержимого после отправки: эта глава пока не считается завершённой, нужно повторить цепочку «открыть слово от автора → заполнить заново → отправить → сохранить снова»; если сбой остаётся — записать причину и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой получения `章节Id`: пометить главу «частичный успех (сохранено, но ID главы не подтверждён)», потребовать ручной дозаписи ID главы, молчаливый успех запрещён.
- Сбой записи `My Fiction/分发记录.md`: хотя эта глава, возможно, уже сохранена, статус процесса обязательно пометить как «частичный сбой (запись не записана на диск)» и немедленно предложить ручную дозапись; молчаливый успех запрещён.

## Накопленный практический опыт (на основе известной информации о странице и логики распространения)

### Редактор и внесение содержимого

- **Редактор Draft.js**: редактор основного текста My Fiction построен на Draft.js (React-фреймворк для форматированного текста), селектор класса — `.public-DraftEditor-content`. Draft.js опирается на внутренний ContentState, любые операции DOM в обход React (например, прямое задание `innerHTML`) не запускают обновление подсчёта знаков и могут вызвать клиентское исключение "Application error".
- **Предпочтительный способ внесения**: `page.keyboard.insertText(bodyText)` — посимвольная имитация набора, Draft.js полностью перехватывает и обновляет внутреннее состояние и Word count. По замерам 10K знаков занимают около 15 секунд, необходимо заложить достаточное время ожидания (`waitForTimeout(15000)`).
- **Второй способ**: `document.execCommand('insertText', false, text)` — разовая вставка простого текста, Draft.js её распознаёт, но слишком длинный текст (>15K знаков) может вызвать ошибку смещения внутреннего состояния React.
- **Внесение слова от автора**: тоже использовать `keyboard.insertText()`, после внесения дополнительные кнопки нажимать не нужно, сразу SAVE.

### Надёжность буфера обмена

- PowerShell `Set-Clipboard` нестабилен для большого текста (>10K знаков), `Get-Clipboard` может вернуть длину 0.
- `clip.exe` в неинтерактивном терминале может завершиться ошибкой из-за прав доступа («拒绝访问», «отказано в доступе»).
- **Вывод**: в сценариях пакетной загрузки в первую очередь использовать `keyboard.insertText()` или `execCommand`, не полагаться на системный буфер обмена как канал передачи данных.

### Предобработка данных и внесение

- Использовать `page.addScriptTag({ path: dataFile })`, чтобы внедрить данные главы (заголовок, основной текст, слово от автора) в глобальные переменные `window.__chapter*`.
- Затем прочитать данные через `page.evaluate(() => window.__chapterBody)` и передать их в редактор.
- Эта схема позволяет не прописывать полный текст жёстко в коде Playwright и избежать проблем экранирования строк в Playwright.
- При предобработке использовать PowerShell `ConvertTo-Json`, чтобы сериализовать основной текст в строку JSON (автоматически обрабатываются переносы строк, кавычки, экранирование Unicode), и записывать в файл `.js`.

### Навигация браузера и обработка всплывающих окон

- Шаги входа на `write.myfiction.com` обязательно оставлять пользователю для выполнения вручную; это жёсткая граница, не нужно «делать за пользователя» до перехода границы.
- **Окно `beforeunload`**: при каждом уходе со страницы редактирования главы (`/chapter/edit` или `/chapter/new`) страница показывает окно подтверждения `beforeunload`. Необходимо как можно раньше задать `page.on('dialog', async dialog => { await dialog.accept(); })`, иначе каждая навигация будет прерываться.
- После `SAVE` итоговый URL главы станет `https://write.myfiction.com/my-stories/chapter/edit?book_id={书籍ID}&real_chapter_id={章节ID}`; этот URL — приоритетный источник для извлечения ID главы.

### Восстановление ID главы (запасной вариант)

- Если при прерывании пакетного выполнения ID нескольких глав не удалось извлечь в реальном времени, можно по очереди нажимать Edit на странице списка `My Stories → Story Manage → Drafts` и получать их.
- Список Drafts отсортирован по времени обновления в обратном порядке, в каждой строке есть кнопка Edit; после нажатия происходит переход на страницу редактирования, в URL которой есть `real_chapter_id`.
- Этот вариант подходит для: глав, не записанных обратно после краха VS, потери ID из-за обрыва сети и подобных сценариев.

### Устойчивость сети

- Вкладка браузера может перейти в состояние `ERR_NETWORK_IO_SUSPENDED`: все сетевые запросы зависают, а страница не загружается.
- В этом случае пользователю нужно вручную обновить или заново открыть вкладку, и обычно нужен повторный вход. Сессия не сохраняется.
- После краха VS Code ID страницы браузера и контекст Playwright в сессии теряются, нужно заново установить соединение через `open_browser_page({ forceNew: true })`.

### Эта платформа без деления на тома

- Поэтому не записывайте «номер тома» в заголовок или уникальный ключ главы.
- Полным сигналом завершения каждой главы считать «сохранение успешно + подтверждено, что URL содержит ID главы + запись обратно выполнена»; отсутствие любого пункта не считается настоящим замыканием.

### Эффективность пакетного выполнения

- **Рекомендуемый размер партии**: 5 глав. 40 глав по 8 партий занимают около 16–20 минут.
- **Время на одну главу**: ~30–40 секунд (навигация 2 с + заголовок 1 с + вставка основного текста 15 с + слово от автора 3 с + SAVE 6 с + извлечение ID).
- **Интервал между партиями**: сразу после каждой партии записывать `分发记录.md`, чтобы не потерять прогресс.

## Минимальный исполнимый чек-лист (версия на 10 секунд)

> Порядок применения: перед каждым распространением быстро пройтись по пунктам по порядку; если какой-либо пункт не выполнен, сначала исправить, затем загружать.

1. **Полны ли входные данные**
   - Чётко определено, какие именно главы загружаются на этот раз (объём не расширяется).
   - Из `My Fiction/README.md` читаются имя пользователя, пароль, шестнадцатеричный ID книги, название книги.

2. **Верна ли цель**
   - Название книги на текущей странице редактирования совпадает с `README.md`.
