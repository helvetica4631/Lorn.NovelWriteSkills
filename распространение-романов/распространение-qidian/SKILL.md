# Загрузка указанных глав в Qidian Chinese Network с сохранением черновика

Используется, чтобы загрузить указанную вами 1 или несколько глав в соответствующее произведение Qidian Chinese Network и сохранить все как черновики.


<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (Qidian Chinese Network) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `起点/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `起点/`

> **О путях**: все пути вида `起点/` в нижеследующих разделах (например, `起点/README.md`, `起点/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `起点/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `起点/`.
- Вы уже записали в `起点/README.md` аккаунт, пароль, ID книги Qidian, название книги и названия томов.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход → определение режима создания / изменения → заполнение объединённого поля заголовка → вставка основного текста → добавление слова писателя → сохранение черновика → запись ID главы обратно.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт Qidian или ID книги.
- Цель — не «сохранить черновик», а «сразу опубликовать».

## Требования ко входным данным (обязательно)

### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `起点/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не берётся напрямую из имени файла**: его необходимо извлечь из содержимого файла главы, нормализовать и затем внести в поле заголовка на странице.

### 1.1) Правила извлечения и сборки заголовка главы (обязательно)

- Из файла главы обязательно извлечь: номер главы (арабскими цифрами), заголовок главы, основной текст, слово писателя.
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как «номер главы», а `三分钟` — как «заголовок главы».
- При загрузке в Qidian для нумерации глав разрешён только номер главы внутри тома; нельзя переносить в поле заголовка трёхуровневую нумерацию вроде `1.1.3`, `2.4.17` как есть; итоговая запись допустима только в формате вроде `第3章 三分钟`.
- На странице Qidian есть только **одно поле заголовка**, итоговое вносимое значение — полная строка: `第{章号}章 {章节标题}`.
- Между `章号` (номером главы) и `标题` (заголовком) обязательно сохранять **1 пробел**, например: `第1章 天降奇缘`.
- Если строка заголовка файла главы уже имеет полный формат (например, `第12章 夜半来客`) и номер главы совпадает, её можно использовать напрямую.
- Если извлечённая строка заголовка содержит лишь текст заголовка (например, `夜半来客`), необходимо автоматически собрать `第{章号}章 夜半来客`.
- Нельзя переносить в поле заголовка суффикс платформы из имени файла (например, `_起点版`).

### 2) Источник метаданных

- Обязательно прочитать `起点/README.md` и извлечь как минимум следующее:
  - имя пользователя авторского кабинета Qidian
  - пароль авторского кабинета Qidian
   - ID книги Qidian (только цифры, например `11997642`; выбрать значение, соответствующее текущей главе, по «правилу определения ID книги»)
   - название романа (название книги, для текущей цели загрузки)
  - название каждого тома
### 2.1) Проверка платформы (обязательно)

После чтения `起点/README.md` необходимо проверить, равен ли его первый заголовок первого уровня `# 起点中文网分发配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"起点中文网分发配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «起点中文网分发配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)
### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `起点/分发记录.md`:
  - если файла нет, сначала создать его, затем выполнять распространение.
  - используется для запроса соответствия «уникальный ключ главы -> ID главы» и определения для главы «режима создания» или «режима изменения».

### 4) Правило определения названия книги (обязательно)

- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава; нельзя ошибочно использовать общее название.

### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.

### 5) Шаблон `分发记录.md` (при первом создании использовать напрямую)

Если `起点/分发记录.md` не существует, его необходимо создать по следующему шаблону:

```markdown
# 起点中文网分发记录

> Назначение: фиксирует соответствие «уникальный ключ главы -> ID главы Qidian», чтобы процесс распространения мог определять «режим создания / режим изменения».

## Описание полей

- `章节唯一键` (уникальный ключ главы): фиксированный формат `起点书籍ID|分部名|卷号|章号|章名` (если частей нет, в поле названия части пишется `NA`)
- `起点书籍ID` (ID книги Qidian): соответствует ID книги в `起点/README.md`
- `章节Id` (ID главы): число после `#ccid=` в hash адреса редактирования главы Qidian
- `最近操作` (последняя операция): `新建` (создание) или `修改` (изменение)
- `更新时间` (время обновления): `YYYY-MM-DD HH:mm:ss`
- `备注` (примечание): необязательно

## Таблица записей

|章节唯一键|起点书籍ID|章节Id|最近操作|更新时间|备注|
|:--|--:|--:|:--|:--|:--|
```

Если `起点/README.md` не существует, его необходимо создать по следующему шаблону:

## Процесс выполнения (строго по порядку)

### Шаг 1: чтение локальных входных данных

1. Прочитать и разобрать `起点/README.md`.
2. Убедиться, что получены: аккаунт, пароль, целевой ID книги (выбранный по «правилу определения ID книги»), целевое название романа, целевое название тома.
3. Прочитать `起点/分发记录.md` и построить соответствие «уникальный ключ главы -> ID главы» (рекомендуемый уникальный ключ: `起点书籍ID|分部名|卷号|章号|章名`; если частей нет, название части фиксированно `NA`).
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: номер тома, название тома, номер главы (арабскими цифрами), заголовок главы, основной текст, слово писателя.
5. Для каждой главы сформировать «итоговое значение поля заголовка на странице»: `第{章号}章 {章节标题}`.

### Шаг 2: вход в авторский кабинет

1. **Обязательно открыть новую вкладку браузера** и в этой новой вкладке перейти по адресу:
   - `https://write.qq.com/portal/dashboard/books`
2. Эта новая вкладка используется только для текущего процесса загрузки в Qidian; вкладку, в которой вы сейчас решаете другие задачи, повторно не использовать.
3. Если состояние входа недействительно или вход не выполнен:
   - войти, используя имя пользователя и пароль из `README.md`.
4. Если в ходе входа появляется капча, проверка по телефону, вторичное подтверждение или проверка безопасности:
   - обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成» (вход завершён).
   - до получения обратной связи «登录完成» не продолжать никакие дальнейшие шаги и не имитировать состояние успеха.
5. Если при первом входе на страницу редактирования появляется окно «作家创作须知» (правила для писателей):
   - сначала отметить флажок «我已阅读...» (я прочитал...).
   - затем нажать «同意» (согласен).
6. Если на странице редактирования появляется слой-подсказка для новичков (например, подсказка «瑞特» («Ruite», маскот Qidian), «下一步 / 跳过 / 关闭» (далее / пропустить / закрыть)):
   - сначала закрыть или пропустить, убедившись, что редактор нормально работает, и только затем продолжать.

### Шаг 3: переход на страницу главы целевой книги (создание / изменение — одно из двух)

1. Перед переходом сначала проверить в `起点/分发记录.md`, есть ли уже у этой главы `章节Id`.
2. Если у этой главы **нет** ID главы (режим создания), перейти по адресу:
   - `https://write.qq.com/portal/booknovels/chaptertmp/CBID/{书籍Id}/#ccid=-1`
3. Если у этой главы **уже есть** ID главы (режим изменения), перейти по адресу:
   - `https://write.qq.com/portal/booknovels/chaptertmp/CBID/{书籍Id}/#ccid={章节Id}`
4. `{书籍Id}` обязательно берётся из `README.md` и должен быть строкой, состоящей только из цифр.
5. После входа в режиме создания необходимо помнить: `#ccid=-1` означает лишь «временное состояние создания», **это не итоговый ID главы**.

### Шаг 4: проверка информации о текущем произведении

1. Проверить, соответствует ли произведение на текущей странице редактирования целевому названию книги из `README.md`.
2. Если на странице есть информация о томе, информация о разделе тома или дерево глав слева позволяет распознать название тома, дополнительно проверить целевое название тома.
3. Если название книги или название тома не совпадает:
   - немедленно остановить загрузку текущей главы.
   - вернуть описание ошибки (название книги / названия тома не совпадают)
   - запрещено продолжать слепую загрузку в неверное произведение.

### Шаг 5: заполнение поля заголовка

1. Найти поле заголовка главы.
2. Установить его содержимое в полную строку: `第{章号}章 {章节标题}`.
3. Перед вводом сначала выделить всё и очистить старое значение, чтобы не осталось «безымянная глава», «заголовок черновика» или прежние заголовки.
4. Ещё раз сверить:
   - использован арабский номер главы.
   - между `章号` (номером главы) и `标题` (заголовком) только один пробел.
   - не подмешана посторонняя информация — суффикс имени файла, название тома, название платформы и т. п.

### Шаг 6: заполнение основного текста

1. Ввести основной текст главы в область редактирования основного текста.
2. Необходимо гарантировать, что текст взят из указанного вами файла главы, без перепутывания глав.
3. Если редактор — область форматированного или квазиформатированного текста, после ввода необходимо убедиться, что видимый основной текст действительно попал в область редактирования, а не в элемент с неверным фокусом.

### Шаг 7: добавление слова писателя

1. Нажать кнопку «作家的话» (слово писателя) (может находиться на панели инструментов редактора или внизу страницы).
2. Дождаться появления поля ввода в правом всплывающем слое.
3. В поле ввода во всплывающем слое **сначала выделить всё и очистить старое содержимое**, затем ввести содержимое «слова писателя» этой главы, чтобы не склеивать его со старым текстом.
4. Если на странице есть подсказка об ограничении числа знаков, сохранить смысл исходного текста в пределах лимита, нельзя насильно превышать.
5. После завершения ввода нажать «收起» (свернуть) в правом верхнем углу слоя.
6. После сворачивания убедиться, что содержимое «слова писателя» не потеряно; если на странице есть видимая сводка или состояние «заполнено», проверить, что оно обновилось.

### Шаг 8: сохранение черновика и получение ID главы

1. В зависимости от режима выбрать правильную кнопку:
   - в режиме создания в первую очередь нажимать «存为草稿» (сохранить как черновик); если на странице показано только «保存» (сохранить), нажать «保存» (этот вход тоже сохраняет в черновики).
   - в режиме изменения нажимать «保存».
2. Дождаться сообщения страницы об успешном сохранении или эквивалентного состояния успеха.
3. После успешного сохранения **обязательно сразу получить итоговый ID этой главы**, рекомендуется выполнять в следующем порядке:

#### 8.1) Предпочтительно определить по списку глав слева

1. Посмотреть на новую или только что обновлённую запись главы в списке глав слева.
2. Перекрёстно подтвердить, что это текущая глава, по следующей информации:
   - номер главы
   - Заголовок главы
   - время последнего сохранения
   - число знаков
3. Если сама запись главы является ссылкой, в первую очередь прочитать `#ccid={章节Id}` из адреса ссылки, hash, цели перехода или атрибутов элемента.

#### 8.2) Если ID прямо из записи слева прочитать нельзя, нажать эту запись главы

1. Нажать только что сохранённую запись главы слева, чтобы войти в неё заново.
2. Прочитать hash URL текущей страницы.
3. Если адрес страницы изменился на `https://write.qq.com/portal/booknovels/chaptertmp/CBID/{书籍Id}/#ccid={章节Id}`, извлечь чистое число после `#ccid=` как `章节Id`.

#### 8.3) Если URL по-прежнему явно не изменился, продолжить проверку атрибутов элемента

1. Проверить, содержат ли запись главы слева и её кликабельные дочерние элементы следующие атрибуты:
   - `href`
   - `data-ccid`
   - `data-id`
   - `data-chapterid`
   - другие атрибуты, явно указывающие на первичный ключ главы
2. Если удаётся получить чисто числовой первичный ключ главы, считать его `章节Id`.

#### 8.4) После получения `章节Id` записать его обратно в журнал

1. Записать «уникальный ключ главы + ID главы + время обновления» обратно в `起点/分发记录.md`:
   - если записи нет: добавить новую.
   - если запись уже есть: обновить `章节Id` (если изменился) и время обновления.
2. `最近操作` записывается как `新建` или `修改` в зависимости от текущего режима.

> Правило формирования уникального ключа главы (обязательно):
> - Порядок полей: `起点书籍ID|分部名|卷号|章号|章名`
> - При этом:
>   - `起点书籍ID` берётся из `起点/README.md`
>   - `分部名` — название книги текущей части; если частей нет — `NA`
>   - `卷号`, `章号` должны быть арабскими цифрами
> - Это правило нужно, чтобы избежать конфликтов одинаковых номеров глав при параллельном распространении многочастных и многотомных романов.

4. Если сохранение успешно, но `章节Id` по-прежнему не получен:
   - статус этой главы обязательно пометить как «частичный успех (черновик сохранён, ID главы не записан обратно)».
   - немедленно явно сообщить пользователю о точке блокировки.
   - запрещено молча засчитывать эту главу как полностью успешную.

### Шаг 9: цикл по нескольким главам

- Для каждой указанной главы строго повторять шаги 3–8, пока не будут завершены все главы.
- Перед началом каждой главы обязательно один раз запрашивать `分发记录.md` для определения режима создания / изменения, нельзя наследовать режим предыдущей главы.


### Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и расширенных полей платформы (например, «слово автора» / текст настроек публикации);
   - предпроверка ограничений платформы (например, число знаков в заголовке, число знаков в слове автора, обязательные пункты публикации);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `{каталог платформы}/.cache/content_parts/no_part/v{номер тома}/*.txt`, `{каталог платформы}/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (по записи — создание или изменение);
   2) заполнить заголовок;
   3) заполнить основной текст;
   4) заполнить расширенные поля платформы (например, слово автора / настройки публикации);
   5) сохранить черновик;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по `5–10` глав:
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- Так даже при ограничении частоты, колебаниях состояния входа или смене вёрстки страницы пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Для неблокирующих напоминаний, многократно появляющихся на платформе (напоминание о числе знаков, обучающие слои, окна-подсказки), при первом появлении можно убрать шум и продолжить основной процесс.
- Только когда всплывающее окно реально блокирует критический путь «ввод / сохранение / отправка», повышать до обработки как сбой или ручного вмешательства.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / расширенные поля платформы / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs`:
   - без частей: `/parts/v/{номер тома}/{номер главы}`
   - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии.
- Этот способ — средство ускорения; он не заменяет требования каждого платформенного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.
## Ключевые границы и жёсткие правила

- Загружать можно только главы, явно указанные пользователем, без самовольного расширения объёма.
- На шаге 2 для входа в авторский кабинет обязательно использовать **новую вкладку**; запрещено занимать исходную вкладку, которой пользуется пользователь.
- Перед входом в шаг 3 для каждой главы обязательно сначала запросить `起点/分发记录.md`.
- Режим создания обязан использовать `#ccid=-1`, режим изменения — `#ccid={章节Id}`, смешивать их нельзя.
- После успешного сохранения каждой главы обязательно попытаться получить итоговый `章节Id` из списка глав слева или hash страницы и записать обратно в `起点/分发记录.md`.
- Поле заголовка главы обязано содержать полную строку `第{章号}章 {章节标题}` с одним пробелом между частями.
- Номер главы обязан быть арабской цифрой, китайские числительные писать нельзя.
- Qidian — платформа с делением на тома, номер главы обязан использовать относительный номер внутри тома, без накопления между томами.
- «作家的话» (слово писателя) обязано вноситься после открытия правого всплывающего слоя кнопкой «作家的话» (на панели инструментов или внизу страницы).
- После внесения «слова писателя» обязательно нажать «收起» в правом верхнем углу слоя.
- В режиме создания в первую очередь «存为草稿»; если на странице показано только «保存», нажать «保存» и в качестве критерия успеха использовать добавление / время обновления в черновиках; в режиме изменения использовать «保存».
- Если `章节Id` не получен, нельзя помечать эту главу как полностью успешную.
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.

## Обработка сбоев и откатов

- Сбой входа: сообщить об ошибке аккаунта / пароля и остановиться, не продолжая последующие главы.
- Вход вызвал капчу или проверку по телефону: обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成»; до получения этой обратной связи любые последующие шаги выполнять нельзя.
- Отсутствие элемента страницы (например, изменение кнопки, слой не появился): записать текущий шаг сбоя и остановить эту главу; перед переходом к следующей главе сначала убедиться, что страница пригодна для действий.
- Название книги / названия тома не совпадает: сразу остановить процесс загрузки этой книги, потребовать сначала исправить `起点/README.md` или целевой ID книги.
- Сбой сохранения: отметить главу как сбойную; если после повторной попытки сбой остаётся — сохранить запись о сбое и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Аномалия состояния сохранения «слова писателя» или потеря содержимого после сворачивания: эта глава пока не считается завершённой, нужно повторить цепочку «открыть слово писателя → заполнить заново → свернуть → сохранить»; если сбой остаётся — записать причину и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой получения `章节Id`: пометить главу «частичный успех (черновик сохранён)», потребовать ручной дозаписи ID главы, молчаливый успех запрещён.
- Сбой записи `起点/分发记录.md`: хотя для этой главы черновик, возможно, уже сохранён, статус процесса обязательно пометить как «частичный сбой (запись не записана на диск)» и немедленно предложить ручную дозапись; молчаливый успех запрещён.

## Накопленный практический опыт (на основе известной информации о странице и логики распространения)

- При первом входе на страницу редактирования `write.qq.com` сначала может появиться окно «作家创作须知» (правила для писателей); если не отметить флажок и не нажать «同意» (согласен), область редактирования потом может быть недоступна.
- На странице редактирования может быть слой-подсказка «瑞特»; сначала «跳过» (пропустить) или «关闭» (закрыть), не давайте подсказке перехватывать фокус, иначе заголовок, основной текст и кнопка сохранения будто играют в прятки.
- `#ccid=-1` в адресе создания — не настоящий ID главы; настоящий `章节Id` нужно определять уже после сохранения черновика по списку глав слева или hash после перехода.
- Список глав слева после сохранения показывает номер, заголовок, время сохранения и число знаков новой главы — это ключевой якорь для подтверждения «какая именно это глава».
- Если запись главы слева кликабельна, в первую очередь вернуться на эту главу и затем прочитать `#ccid=`; это обычно надёжнее, чем сидеть и смотреть на текущую страницу.
- Полным сигналом завершения каждой главы считать «сохранение успешно + ID главы получен и записан обратно»; отсутствие любого пункта не считается настоящим замыканием.

### Дополнение по реальной практике этого раунда (2026-05-09)

- При входе часто срабатывает слайдер-проверка безопасности; её пользователь должен пройти вручную в реальном времени, пока она не пройдена, дальнейшие шаги выполнять нельзя.
- Флажок «согласие с соглашением» на странице входа может быть перекрыт пользовательским `label`; если отметить не удаётся, нужно нажимать `label` для запуска, а не упорно жать исходный `input`.
- Всплывающий слой «作家的话» имеет известный **лимит 500 знаков** (на странице показывается, например, `248/500`); при превышении сначала сжать, затем сохранять.
- Ключевые действия на одной странице — «收起», «保存» и т. п. — следует **выполнять последовательно**, чтобы избежать состязания состояний и ложных срабатываний при параллельных нажатиях.
- Если `起点/分发记录.md` использует таблицу Markdown, разделитель `|` внутри `章节唯一键` обязательно экранировать как `\|`, иначе нарушится число столбцов (например, MD056).

### Дополнение по реальной практике этого раунда (2026-05-21)

- Если в длинной партии появляется окно «保存失败» (сбой сохранения) (например, «请输入1~20000字以内的章节内容» (введите содержимое главы в пределах 1–20000 знаков)), оно перехватывает последующие нажатия; **обязательно сначала нажать «我知道了» (понятно), чтобы убрать окно**, и только затем продолжать со следующей главой, иначе цепочка тайм-аутов приведёт к сбоям.
- И поле заголовка, и поле «作家的话» могут содержать заполнитель «请输入» (введите); при автоматизации следует использовать **более узкие локаторы** (для поля заголовка предпочтительно `请输入章节号与章节名`, для слова писателя предпочтительно правый выдвижной ящик `textarea[placeholder="请输入"]`), чтобы не внести слово писателя по ошибке в поле заголовка.
- После сохранения каждой главы рекомендуется сразу выполнить «**трёхточечную обратную проверку**»:
   1) значение поля заголовка равно `第{章号}章 {章节标题}`;
   2) в текущем URL получен действительный `#ccid=число`;
   3) в списке черновиков слева появился соответствующий заголовок.
   Если любой пункт не пройден — считать «замыкание не выполнено», сразу переходить к следующей главе нельзя.
- При «загрязнении безымянной главой» сначала разветвить обработку:
   - если удаётся точно найти нужный `ccid`: войти в этот `ccid`, исправить заголовок / основной текст / слово автора и сохранить;
   - если содержимое главы уже перемешалось или принадлежность подтвердить невозможно: сразу загрузить эту главу заново как новую, получить **новый `ccid`** и по нему записать `分发记录.md`.
- По завершении партии обязательно выполнить «**сверку номер главы — заголовок — ccid**» (как минимум для диапазона этой партии), убедившись, что у каждого номера главы только одно действительное соответствие; прежние ошибочные / временные `ccid` нельзя записывать в итоговый `分发记录.md`.
- При пакетном создании по умолчанию каждую главу начинать с `#ccid=-1`, чтобы избежать последовательной перезаписи по аномальному черновику, ведущей к перемешиванию глав; режим изменения использовать только тогда, когда в `分发记录.md` уже есть явное соответствие.

## Минимальный исполнимый чек-лист (версия на 10 секунд)

> Порядок применения: перед каждым распространением быстро пройтись по пунктам по порядку; если какой-либо пункт не выполнен, сначала исправить, затем загружать.

1. **Полны ли входные данные**
   - Чётко определено, какие именно главы загружаются на этот раз (объём не расширяется).
   - Из `起点/README.md` читаются имя пользователя, пароль, ID книги, название книги, названия томов.

2. **Верна ли цель**
   - Название книги и названия тома на текущей странице редактирования совпадают с `README.md`.
   - Режим главы определён: нет `章节Id` — идти на создание (`#ccid=-1`), есть `章节Id` — идти на изменение (`#ccid={章节Id}`).

3. **Выполнен ли ключевой ввод**
   - Поле заголовка в полном формате: `第{章号}章 {章节标题}` (арабские цифры, один пробел).
   - Подтверждено, что основной текст записан в видимую область редактора (а не ошибочно внесён в другое место).
   - «Слово писателя» заполнено, не превышает 500 знаков, нажато «收起».

4. **Замкнуты ли сохранение и запись**
   - Сохранение успешно (в режиме создания в первую очередь «存为草稿»; если есть только «保存» — судить по добавлению / времени обновления в черновиках).
   - Получен итоговый `章节Id` (запись главы слева или URL `#ccid=`).
   - Выполнена запись обратно в `起点/分发记录.md`, причём `|` в `章节唯一键` экранирован как `\|`.

5. **Явно ли обозначен сбой**
   - Если капча не пройдена, сохранение не удалось, `章节Id` не получен, запись не внесена: обязательно пометить как сбой / частичный успех и указать точку блокировки.

## Контрольный список завершения

- Прочитан `起点/README.md` и извлечены необходимые поля.
- Выполнена поглавная загрузка по указанному списку глав.
- Перед выполнением каждой главы выполнен запрос `起点/分发记录.md` и корректно выбран URL создания / изменения.
- Для каждой главы выполнено: поле заголовка, основной текст, слово писателя, сохранение черновика / сохранение.
- После сохранения каждой главы предпринята попытка получить `章节Id`, причём в первую очередь через список глав слева.
- Для каждой главы выполнена запись или обновление в `起点/分发记录.md` (с соответствием главы и ID главы).
- Перед загрузкой каждой главы выполнена проверка информации о целевом произведении.
- Выведен результат по каждой главе (успех / сбой / частичный успех и причина).
