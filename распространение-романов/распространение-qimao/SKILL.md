# Загрузка указанных глав романа в Qimao Novel с сохранением черновика

Используется, чтобы загрузить указанную вами 1 или несколько глав в соответствующее произведение Qimao Novel и сохранить все как черновики.


<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (Qimao Novel) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `七猫小说/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `七猫小说/`

> **О путях**: все пути вида `七猫小说/` в нижеследующих разделах (например, `七猫小说/readme.md`, `七猫小说/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `七猫小说/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `七猫小说/`.
- Вы уже записали в `七猫小说/readme.md` или `七猫小说/README` аккаунт, пароль, ID книги Qimao и название книги.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход → заполнение номера и названия главы → вставка основного текста → добавление слова от автора → сохранение черновика.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт Qimao или ID книги.
- Цель — не «сохранить черновик», а «сразу опубликовать».

## Требования ко входным данным (обязательно)

### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `七猫小说/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не определяется именем файла**, его необходимо извлечь из основного текста файла главы.

### 1.1) Правила извлечения заголовка главы (обязательно)

- Заголовок главы берётся из содержимого файла главы, обычно это строка заголовка Markdown в 1-й строке (начинается с `# `).
- Эта строка заголовка иногда содержит номер главы, иногда только текст заголовка; допустимы оба варианта.
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как исходный номер главы, а `三分钟` — как «заголовок главы».
- При заполнении поля «章节标题» (заголовок главы) на Qimao допускается использовать только текст заголовка `三分钟`; если на странице есть отдельное поле номера главы или позже потребуется вычисление абсолютного номера, также можно использовать только последний сегмент номера `3`, нельзя загружать `1.1.3` как есть.
- При заполнении поля «章节标题» на Qimao следует использовать извлечённый текст заголовка, нельзя напрямую использовать имя файла.

### 2) Источник метаданных

- Обязательно прочитать `七猫小说/readme.md` или `七猫小说/README` и извлечь как минимум следующее:
  - имя пользователя Qimao Novel
  - пароль Qimao Novel
   - ID книги романа на Qimao (только цифры, например `11997642`; выбрать значение, соответствующее текущей главе, по «правилу определения ID книги»)
   - название романа (название книги, для текущей цели загрузки)
### 2.1) Проверка платформы (обязательно)

После чтения `七猫小说/readme.md` (или `七猫小说/README`) необходимо проверить, равен ли его первый заголовок первого уровня `# 七猫распространение-романов配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"七猫распространение-романов配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «七猫распространение-романов配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)
### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `七猫小说/分发记录.md`:
  - если файла нет, сначала создать его, затем выполнять распространение.
  - используется для запроса соответствия «глава -> ID главы» и определения для главы «режима создания» или «режима изменения».

### 4) Правило определения названия книги (обязательно)

- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `readme.md`/`README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава; нельзя ошибочно использовать общее название.

### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `readme.md`/`README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.

### 5) Шаблон `分发记录.md` (при первом создании использовать напрямую)

```markdown
# 七猫распространение-романов记录

> Назначение: фиксирует соответствие «уникальный ключ главы -> ID главы Qimao», чтобы процесс распространения мог определять «режим создания / режим изменения».

## Описание полей

- `章节唯一键` (уникальный ключ главы): фиксированный формат `七猫书籍ID|分部名|卷号|章号|章名` (если частей нет, в поле названия части пишется `NA`)
- `七猫书籍ID` (ID книги Qimao): соответствует ID книги в `七猫小说/readme.md` или `七猫小说/README`
- `章节Id` (ID главы): чистое число, возвращаемое после сохранения главы
- `最近操作` (последняя операция): `新建` (создание) или `修改` (изменение)
- `更新时间` (время обновления): `YYYY-MM-DD HH:mm:ss`
- `备注` (примечание): необязательно

## Таблица записей

|章节唯一键|七猫书籍ID|章节Id|最近操作|更新时间|备注|
|:--|--:|--:|:--|:--|:--|
```

## Процесс выполнения (строго по порядку)

### Шаг 1: чтение локальных входных данных

1. Прочитать и разобрать `七猫小说/readme` (если нет — читать `七猫小说/README.md`).
2. Убедиться, что получены: аккаунт, пароль, целевой ID книги (выбранный по «правилу определения ID книги»), целевое название романа.
3. Прочитать `七猫小说/分发记录.md` и построить соответствие «уникальный ключ главы -> ID главы» (рекомендуемый уникальный ключ: `七猫书籍ID|分部名|卷号|章号|章名`; если частей нет, название части фиксированно `NA`).
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: номер тома, номер главы (арабскими цифрами), заголовок главы, основной текст, «слово от автора».
   - Заголовок главы при этом обязательно извлекать из содержимого файла по «правилу извлечения заголовка главы (обязательно)», подменять его именем файла нельзя.

### Шаг 1.5: вычисление абсолютного номера главы (без деления на тома)

1. Qimao обрабатывается как платформа без деления на тома, номер главы использует нумерацию «абсолютный номер главы».
2. Формула расчёта:
   - `абсолютный номер главы = сумма числа глав предыдущих томов + относительный номер этой главы в её томе`.
3. Пример:
   - если в томе 1 — 90 глав, а в томе 2 — 100 глав:
   - том 1, глава 5 → абсолютный номер главы: глава 5;
   - том 2, глава 5 → абсолютный номер главы: глава 95;
   - том 3, глава 5 → абсолютный номер главы: глава 195.
4. Если `分发记录.md` не существует или в нём нет истории записей, вычислять по приведённой формуле из известной структуры томов и глав; если число глав предыдущих томов определить нельзя, сначала нужно восполнить реестр и только потом публиковать.
5. Если на странице поле «第X章» (глава X) не редактируется, оно используется лишь для проверки; продолжать процесс по значению, показанному платформой.

### Шаг 2: вход в авторский кабинет

1. **Обязательно открыть новую вкладку браузера** и в этой новой вкладке перейти по адресу:
   - `https://zuozhe.qimao.com/front/book-manage`
2. Эта новая вкладка используется только для текущего процесса загрузки в Qimao; вкладку, в которой вы сейчас решаете другие задачи, повторно не использовать.
3. Если состояние входа недействительно или вход не выполнен:
   - войти, используя имя пользователя и пароль из `readme`/`README.md`.
4. Если после входа страница требует капчу или другую вторичную проверку:
   - обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成» (вход завершён).
   - до получения обратной связи «登录完成» не продолжать никакие дальнейшие шаги и не имитировать состояние успеха.

### Шаг 3: переход на страницу главы целевой книги (создание / изменение — одно из двух)

1. Перед переходом сначала проверить в `七猫小说/分发记录.md`, есть ли уже у этой главы `章节Id`.
2. Если у этой главы **нет** ID главы (режим создания), перейти по адресу:
   - `https://zuozhe.qimao.com/front/book-upload?id={书籍Id}`
3. Если у этой главы **уже есть** ID главы (режим изменения), перейти по адресу:
   - `https://zuozhe.qimao.com/front/book-upload?id={书籍Id}&cid={章节Id}`
4. После загрузки страницы зафиксировать текущий URL; обратите внимание: после создания главы в URL ID главы не появляется, его нужно определить обратной проверкой после «存为草稿».
5. `{书籍Id}` обязательно берётся из `readme`/`README.md` и должен быть строкой цифр.

### Шаг 4: проверка названия книги в левом верхнем углу

1. Проверить, соответствует ли отображение в левом верхнем углу страницы:
   - `“{小说名}”`
2. Если не совпадает:
   - немедленно остановить загрузку текущей главы.
   - вернуть описание ошибки (название книги не совпадает).
   - запрещено продолжать слепую загрузку в неверное произведение.

### Шаг 5: заполнение области заголовка главы

- Номер главы Qimao вида «第2章» изменить нельзя, пропускать напрямую.
- Заголовок главы заполнить заголовком, извлечённым из 1-й строки содержимого главы.

### Шаг 6: заполнение основного текста (редактор Quill — обязательна вставка с клавиатуры, `fill()` / операции DOM запрещены)

> **▲ Серьёзное предупреждение: ядро Quill этого редактора считает прямую запись в DOM через `fill()`, `innerHTML`, `appendChild` и т. п. «недопустимой внешней операцией», из-за чего основной текст обрезается до 30–60 % без какой-либо ошибки. Это первопричина самой тяжёлой аварии в истории этого Skill. Ниже — единственный безопасный способ.**

1. **Предварительно: скопировать основной текст в системный буфер обмена**
   - Использовать PowerShell или Playwright для вызова API системного буфера обмена и записать в буфер очищенный основной текст:
   ```powershell
   # Пример PowerShell (извлечь основной текст из файла и убрать строку заголовка и послесловие):
   $c = [System.IO.File]::ReadAllText($chapterPath)
   $body = $c -replace '(?s)^# .+?\n\n',''
   $body = $body -replace '(?s)\n\n## 作者有话说.*',''
   Set-Clipboard $body
   ```
   - Либо в Playwright использовать `navigator.clipboard.writeText(fullBody)`.

2. **После заполнения заголовка сфокусировать редактор основного текста**
   - Найти первый элемент `.q-contenteditable.book` и нажать на него, чтобы получить фокус.
   - После нажатия подождать не менее 200 мс, чтобы редактор был готов.

3. **Выделить всё + очистить (избежать остатков)**
   - Отправить `Control+A` (выделить всё), затем `Delete` (удалить выделенное содержимое).
   - Подождать не менее 200 мс.

4. **Вставить основной текст**
   - Отправить `Control+V`.
   - **Обязательно подождать не менее 3 секунд**, чтобы Quill завершил асинхронную обработку содержимого (для больших текстов может потребоваться больше, безопасное значение — 3–5 секунд).

5. **Очистить Markdown-начало и конец, вставленные вместе с текстом (ключевой побочный шаг)**
   - После вставки редактор будет содержать строку `#第N章` и области вроде `##作者有话说` / `## 章节后记` из исходного файла, которым в основном тексте не место.
   - Выполнить очистку DOM через Playwright:
   ```javascript
   const editor = document.querySelector('.q-contenteditable.book');
   const ps = editor.querySelectorAll('p');
   // Удалить первый абзац (строку #第N章)
   if (ps[0] && ps[0].textContent?.startsWith('#第')) ps[0].remove();
   // Удалить 作者有话说 и всё, что после него
   for (const p of ps) {
     if (p.textContent?.includes('##作者有话说') || p.textContent?.includes('## 作者有话说')) {
       let c = p; while (c) { const n = c.nextElementSibling; c.remove(); c = n; } break;
     }
   }
   // Запустить событие input у Quill, обновить подсчёт знаков
   editor.dispatchEvent(new Event('input', { bubbles: true }));
   ```

6. **Проверка числа знаков (обязательно — ни одного знака меньше)**
   - После очистки сразу прочитать показываемое на странице «当前字数» (текущее число знаков):
     ```javascript
     const wcMatch = document.body.textContent.match(/当前字数(\d+)/);
     const actual = wcMatch ? parseInt(wcMatch[1]) : 0;
     const source = sourceBody.length;  // число знаков основного текста исходного файла, извлечённого на шаге 1
     ```
   - **Критерий: фактическое число знаков должно быть ≥ числа знаков основного текста исходного файла. Ни одного знака меньше.**
   - Если фактическое число знаков < числа знаков основного текста исходного файла, немедленно признать это аварией обрезки, **обязательно повторить шаг 6 (вставить заново)**, продолжать к сохранению черновика нельзя.
   - Если два раза подряд после вставки фактическое число знаков всё ещё < числа знаков исходного файла, значит, путь вставки с клавиатуры тоже, возможно, нарушен; следует приостановиться и привлечь человека.

7. **Обязательно гарантировать, что основной текст взят из указанного вами файла главы, без перепутывания глав.**

> **Приложение: чек-лист проверки аварии**
> - Фактическое число знаков ≥ числа знаков основного текста исходного файла? (ни одного знака меньше)
> - В редакторе виден большой непрерывный основной текст (а не только первые абзацы)?
> - В редакторе нет остатков строки «#第» или «## 作者有话说»?
> - Не равен ли счётчик знаков нулю (возможно, редактор не получил фокус, нужно активировать заново и повторить)?

### Шаг 7: добавление слова от автора (редактор Quill — `fill()` тоже запрещён)

- Слово от автора появляется прямо на странице редактирования главы, нажимать кнопку не нужно.
- **Перед вводом обязательно выделить всё и очистить старое содержимое** (`Control+A` → `Delete`), затем вставить содержимое «слова от автора» этой главы.
- Способ вставки — как на шаге 6: сначала скопировать содержимое в буфер обмена, сфокусировать редактор и нажать `Control+V`, избегая обрезки от `fill()`.
- После ввода обязательно проверить счётчик (обычно `X/300`):
  - при превышении лимита — сжать до лимита платформы по принципу «крючок в приоритете» и только затем сохранять.
  - при отсутствии превышения — сохранить смысл исходного текста и сохранить.

### Шаг 8: сохранение черновика (после обновления)

1. Нажать кнопку «存为草稿» (сохранить как черновик).
2. Обратите внимание: после нажатия может появиться окно «重要提醒» (важное напоминание).
3. Если окно появилось, обязательно дождаться, пока кнопка «我已阅读并知晓» (я прочитал и принимаю к сведению) в окне станет доступной для нажатия (обычно около 5 секунд), и затем нажать её для подтверждения.
4. Пока не нажато «我已阅读并知晓», нельзя считать сохранение успешным.
5. Дождаться сообщения страницы об успешном сохранении (или эквивалентного сообщения об успехе).
6. После успешного сохранения переключиться на вкладку черновиков:
   - перейти по URL: `https://zuozhe.qimao.com/front/book-manage/draft?id={书籍Id}`.
   - черновики используют домен авторского кабинета Qimao `zuozhe.qimao.com`.
   - если страница показывает окно подтверждения «重要提醒 / 我已阅读并知晓», обязательно сначала дождаться доступности кнопки (обычно около 5 секунд) и нажать подтверждение, только тогда черновик действительно попадёт в хранилище.
   - найти в списке черновиков строку целевой главы, нажать «修改» (изменить) и из URL после перехода извлечь `cid` как ID главы.
7. Записать «уникальный ключ главы + ID главы + время обновления» обратно в `七猫小说/分发记录.md`:
   - если записи нет: добавить новую.
   - если запись уже есть: обновить только `章节Id` (если изменился) и время обновления.

> Правило формирования уникального ключа главы (обязательно):
> - Порядок полей: `七猫书籍ID|分部名|卷号|章号|章名`
> - При этом:
>   - `七猫书籍ID` берётся из `readme`/`README.md`
>   - `分部名` — название книги текущей части; если частей нет — `NA`
>   - `卷号`, `章号` должны быть арабскими цифрами
> - Это правило нужно для полного избежания конфликтов «одинаковый номер главы в одном томе» в многочастных романах.

### Шаг 9: цикл по нескольким главам

- Для каждой указанной главы строго повторять шаги 3–8, пока не будут завершены все главы.
- Перед началом каждой главы обязательно один раз запрашивать `分发记录.md` для определения режима создания / изменения, нельзя наследовать режим предыдущей главы.


### Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и расширенных полей платформы (например, «слово автора» / текст настроек публикации);
   - предпроверка ограничений платформы (например, число знаков в заголовке, число знаков в слове автора, обязательные пункты публикации);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `{каталог платформы}/.cache/content_parts/no_part/v{номер тома}/*.txt`, `{каталог платформы}/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (по записи — создание или изменение);
   2) заполнить заголовок;
   3) заполнить основной текст;
   4) заполнить расширенные поля платформы (например, слово автора / настройки публикации);
   5) сохранить черновик;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по `5–10` глав:
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- Так даже при ограничении частоты, колебаниях состояния входа или смене вёрстки страницы пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Для неблокирующих напоминаний, многократно появляющихся на платформе (напоминание о числе знаков, обучающие слои, окна-подсказки), при первом появлении можно убрать шум и продолжить основной процесс.
- Только когда всплывающее окно реально блокирует критический путь «ввод / сохранение / отправка», повышать до обработки как сбой или ручного вмешательства.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / расширенные поля платформы / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs`:
   - без частей: `/parts/v/{номер тома}/{номер главы}`
   - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии.
- Этот способ — средство ускорения; он не заменяет требования каждого платформенного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.
## Ключевые границы и жёсткие правила

- Загружать можно только главы, явно указанные пользователем, без самовольного расширения объёма.
- На шаге 2 для входа в авторский кабинет обязательно использовать **новую вкладку**; запрещено занимать исходную вкладку, которой пользуется пользователь.
- **Шаг 6 (ввод основного текста) обязан использовать системный буфер обмена + Ctrl+V; категорически запрещено использовать `fill()`, `innerHTML`, `appendChild` и другие прямые записи в DOM** (см. шаг 6 и раздел практического разбора).
- **После вставки основного текста обязательно проверить число знаков**: фактическое число знаков < числа знаков основного текста исходного файла — это авария обрезки, ни одного знака меньше, обязательно вставить заново.
- Перед входом в шаг 3 для каждой главы обязательно сначала запросить `七猫小说/分发记录.md`.
- URL создания и изменения главы обязаны разводиться автоматически по записи, смешивать их запрещено.
- После успешного «存为草稿» каждой главы обязательно записать актуальный `章节Id` обратно в `七猫小说/分发记录.md`.
- Если после нажатия «存为草稿» появилось окно «重要提醒», обязательно дождаться, пока кнопка «我已阅读并知晓» станет доступной (обычно около 5 секунд), и затем нажать для подтверждения.
- Каждая глава обязана пройти «проверку соответствия названия книги» до записи содержимого.
- Заголовок главы обязан браться из содержимого файла главы (обычно из строки заголовка `# ` в 1-й строке), использовать имя файла вместо заголовка нельзя.
- Номер главы обязан быть арабской цифрой, китайские числительные писать нельзя.
- Qimao обрабатывается как платформа без деления на тома, нумерация глав определяется и проверяется по «абсолютному номеру главы».
- Слово от автора вносится прямо в области редактирования главы, нажимать кнопку не нужно.
- Перед внесением слова от автора рекомендуется сначала очистить поле редактирования, затем вставить текст этой главы.
- Слово от автора перед сохранением обязано укладываться в лимит платформы по числу знаков (обычно 300 знаков).
- Итоговое действие — «存为草稿», а не публикация.
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.

## Обработка сбоев и откатов

- Сбой входа: сообщить об ошибке аккаунта / пароля и остановиться, не продолжая последующие главы.
- Вход перехвачен и заменён входом по капче: обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成»; до получения этой обратной связи любые последующие шаги выполнять нельзя.
- Отсутствие элемента страницы (например, изменение кнопки): записать текущий шаг сбоя и остановить эту главу; перед переходом к следующей главе сначала убедиться, что страница пригодна для действий.
- Название книги не совпадает: сразу остановить процесс загрузки этой книги, потребовать сначала исправить `readme`/`README.md` или целевую ссылку.
- Сбой «存为草稿»: отметить главу как сбойную; если после повторной попытки сбой остаётся — сохранить запись о сбое и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой сохранения слова от автора: не публиковать эту главу пока, повторить цепочку «редактирование слова от автора → 存为草稿»; если сбой остаётся — записать причину и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой записи `分发记录.md`: хотя для этой главы черновик, возможно, уже сохранён, статус процесса обязательно пометить как «частичный сбой (запись не записана на диск)» и немедленно предложить ручную дозапись; молчаливый успех запрещён.

## Накопленный практический опыт (на основе реальных загрузок)

- Сначала проверять название книги в левом верхнем углу и только затем вносить любое основное содержимое; порядок нарушать нельзя.
- После создания главы в URL ID главы не появляется, его нужно получить обратной проверкой в черновиках после «存为草稿».
- Если в черновиках видна строка целевой главы, в первую очередь нажать в этой строке «修改» и из URL после перехода извлечь `cid` — это самый надёжный способ обратного определения ID главы.
- После первого нажатия «存为草稿» на странице загрузки часто появляется окно «重要提醒 / 我已阅读并知晓»; обязательно дождаться доступности кнопки (обычно около 5 секунд) и только потом нажимать; если не подтвердить или нажать слишком рано, сохранение может фактически не попасть в черновики.
- После вставки основного текста следить за вверху показываемым «已保存/保存中» («сохранено / сохраняется») и ростом числа знаков основного текста, чтобы избежать ситуации «вроде вставлено, а на деле не записано на диск».
- Редактор слова от автора сосуществует с редактором основного текста, перед вводом необходимо убедиться, что фокус находится в области редактирования слова от автора.
- Единственным сигналом завершения каждой главы считать подсказку об успешном сохранении; без подсказки об успехе глава не считается завершённой.

### Разбор практической пакетной загрузки 40 глав (2026-05-21)

- **Лимит заголовка нужно проверять заранее**: лимит заголовка Qimao строго обрезается по `20` знакам. На практике у глав `13/14/15/17/18/19/20/22/25/26/30/36/38/40` исходные заголовки превышали лимит, и только после единообразного сокращения последующее «изменение черновика» стабильно записывалось.
- **Элемент ввода заголовка — `textarea`, а не `input`**: для поиска названия главы предпочтительно `textarea[placeholder*="章节名称"]`; при ошибочном использовании `input` возникает «видно, но значение внести нельзя» или тайм-аут.
- **Пакетное изменение заголовков должно идти прямым переходом по `cid`**: уже существующие главы обязательно открывать через `book-upload?id={书籍Id}&cid={章节Id}` в режиме «обновить черновик», чтобы случайно не попасть в «создать черновик» или не изменить не ту главу.
- **«Сохранено успешно» и «действительно попало в черновики» — не одно и то же событие**: после нажатия «存为草稿 / 更新草稿» необходимо обработать окно «我已阅读并知晓» и затем сверить в черновиках; иначе страница сообщает об успехе, а число знаков / записи в черновиках не меняются.
- **Поиск в черновиках нужно вести по двойному ключу «номер главы + префикс заголовка»**: длинные заголовки в списке черновиков обрезаются, поиск по полному заголовку легко пропускает; рекомендуется находить по `第X章` + `первые 8 знаков заголовка`, затем нажимать «修改» и обратной проверкой определять `cid`.
- **Журнал распространения нужно синхронизировать по ключу названия главы**: после сокращения заголовка главы «уникальный ключ главы (с названием главы)» в `分发记录.md` тоже нужно обновить и пометить последнюю операцию как `修改`; иначе определение «создание / изменение» впоследствии начнёт дрейфовать.
- **По завершении партии обязательна тройная сверка**:
   1. локальные заголовки глав и названия глав в `分发记录.md` — `mismatch=0`;
   2. статистика локальных слишком длинных заголовков `>20` равна `0`;
   3. целевая глава видна в черновиках и префикс заголовка совпадает.
### Разбор практической пакетной загрузки 25 глав · новый редактор Quill на Qimao (2026-06-20) — глубокий разбор аварии с обрезкой основного текста

> **Квалификация аварии**: использование `fill()` / `innerHTML` / `appendChild` над `.q-contenteditable.book` (форматированный редактор Quill) приводит к тому, что редактор молча теряет 40–70 % основного текста без каких-либо сообщений об ошибке. Затронуто минимум 12 из 25 глав, у некоторых осталось лишь 30 %.

#### Анализ первопричины

- Редактор основного текста кабинета Qimao построен на фреймворке **Quill.js**, который ведёт внутреннюю модель Delta для отслеживания содержимого.
- И `fill()` (имитация ввода в Playwright), и `innerHTML` (прямая запись в DOM) **обходят конвейер Delta в Quill**, редактор не может корректно разобрать эти внешние изменения, что приводит к потере содержимого.
- Та же проблема существует у **метода `fill()` в Playwright Chromium** — он имитирует ввод посимвольно, но на длинном тексте Quill часто запускает собственный механизм защиты, приводящий к обрезке.

#### Единственный правильный способ: системный буфер обмена → Ctrl+V

```javascript
// Правильная схема
await page.locator('.q-contenteditable.book').first().click();
await page.waitForTimeout(200);
await page.keyboard.press('Control+a');
await page.keyboard.press('Delete');
await page.waitForTimeout(200);
await page.keyboard.press('Control+v');
await page.waitForTimeout(3000);  // Ключевое: дать Quill время на обработку
```

Обратите внимание: `navigator.clipboard.writeText()` в Playwright требует включить разрешение на буфер обмена в контексте браузера, рекомендуется надёжнее заменить на PowerShell `Set-Clipboard`.

#### Проверка числа знаков: после вставки обязательно проверять (ни одного знака меньше)

- Сразу после вставки и очистки прочитать `document.body.textContent.match(/当前字数(\d+)/)` и сравнить с числом знаков основного текста исходного файла, извлечённым на шаге 1.
- **Критерий: фактическое число знаков должно быть ≥ числа знаков основного текста исходного файла. Ни одного знака меньше.**
- Если фактическое число знаков < числа знаков основного текста исходного файла, немедленно признать это аварией обрезки, обязательно вставить заново, сохранять нельзя.
- После вставки рекомендуется прокрутить редактор, чтобы убедиться в полноте основного текста (Playwright может проверить, совпадает ли число абзацев с исходным файлом).

#### Необходимость очистки после вставки

Ctrl+V вносит в редактор всё содержимое исходного файла `.md` (включая заголовочную строку `#第N章` и хвост `##作者有话说` / `##章节后记`). После вставки метаданные-строки обязательно удалить операциями DOM и затем запустить событие `input`, чтобы подсчёт знаков синхронизировался.

#### Приёмы повышения эффективности при непрерывной пакетной загрузке

- Сначала с помощью PowerShell по очереди записывать основные тексты глав в буфер обмена (обрабатывать по одному, чтобы не перепутать главы).
- Связка между главами: после сохранения вернуться в черновики → нажать «新建草稿» (создать черновик) → заполнить заголовок → сфокусировать редактор → выделить всё и очистить → вставить (в этот момент в буфере уже основной текст следующей главы).
- Редактор слова от автора (`.q-contenteditable.font-size-14`) — тоже экземпляр Quill, также рекомендуется вставка с клавиатуры, а не `fill()`.
- Если при записи главы в журнал распространения нет `cid`, после сохранения можно зайти в черновики, нажать «修改» в строке и извлечь параметр `cid` из URL после перехода.

#### Быстрая самопроверка аварии с обрезкой

| Пункт проверки | Норма | Обрезка |
|--------|------|------|
| Доля знаков | Фактическое число знаков ≥ числа знаков исходника | Фактическое число знаков < числа знаков исходника |
| Первый абзац | Первый абзац основного текста | Строка заголовка или беспорядок |
| Прокрутка поля редактирования | Можно прокрутить и увидеть весь основной текст | Только первые абзацы |
| Число абзацев | ≈ числу абзацев исходника | Намного меньше исходника |

#### Запрещённое (жёсткие правила)

- ❌ **NEVER** использовать `fill()` для записи основного текста в `.q-contenteditable.book`
- ❌ **NEVER** использовать `innerHTML` / `outerHTML` / `insertAdjacentHTML` для внесения основного текста
- ❌ **NEVER** использовать `appendChild` / `insertBefore` для поэтапного добавления текстовых узлов
- ❌ **NEVER** нажимать «存为草稿» без проверки числа знаков
- ✅ **Единственное допустимое**: буфер обмена + Ctrl+V + проверка числа знаков
