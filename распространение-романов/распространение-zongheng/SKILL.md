# Загрузка указанных глав в Zongheng Chinese Net с сохранением черновика

Используется, чтобы загрузить указанную вами 1 или несколько глав в соответствующее произведение Zongheng Chinese Net и сохранить все как черновики.


<!-- ===== Layer 3: кэш сценария ===== -->

## Правило маршрутизации рабочего каталога (обязательно)

Перед выполнением этого Skill необходимо определить рабочий каталог по следующим правилам:

1. **Прочитать `Agents.md` в корне проекта** и проверить в нём объявление `主输出平台` («основная платформа вывода»)
2. Если текущая платформа (Zongheng Chinese Net) совпадает с `主输出平台` → рабочий каталог — `小说正文/`
3. Если текущая платформа не совпадает с `主输出平台`, либо `Agents.md` не существует / `主输出平台` не объявлена → рабочий каталог — `纵横小说/`

Все последующие пути к файлам глав, README.md и 分发记录.md (журнал распространения) строятся от этого рабочего каталога. **Явно уточняется**:
  - **Когда эта платформа — основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `小说正文/`
  - **Когда эта платформа — не основная платформа вывода** → файлы глав, `README.md`, `分发记录.md` находятся в `纵横小说/`

> **О путях**: все пути вида `纵横小说/` в нижеследующих разделах (например, `纵横小说/README.md`, `纵横小说/分发记录.md`) приведены как примеры написания рабочего каталога. Фактический каталог определяется приведённым выше «Правилом маршрутизации рабочего каталога»: если эта платформа — основная платформа вывода, все эти пути соответствуют `小说正文/`; если нет — `纵横小说/`.

## Когда использовать

- Вы уже положили главы для загрузки в каталог `纵横小说/`.
- Вы уже записали в `纵横小说/readme.md` или `纵横小说/README.md` аккаунт, пароль, ID книги Zongheng и название книги.
- Вы хотите, чтобы по фиксированному процессу автоматически выполнялось: вход → определение режима создания / изменения → заполнение «第X章 标题» → вставка основного текста → ввод слова от автора → сохранение черновика → запись ID главы обратно.

## Случаи, когда не применяется

- Вы хотите лишь отшлифовать текст и не нуждаетесь в открытии сайта для загрузки.
- Вы не предоставили аккаунт Zongheng или ID книги.
- Цель — не «сохранить черновик», а «сразу опубликовать».

## Требования ко входным данным (обязательно)

### 1) Каталог файлов глав

- Файлы для загрузки должны лежать в `纵横小说/`.
- Вы явно указываете, какие главы загружать (одну или несколько).
- Заголовок главы **не берётся напрямую из имени файла**: его необходимо извлечь из содержимого файла главы и нормализовать.

### 1.1) Правила извлечения и сборки заголовка главы (обязательно)

- Из файла главы обязательно извлечь: номер тома, название тома, номер главы (арабскими цифрами), заголовок главы, основной текст, слово от автора.
- Если строка заголовка файла главы — `# 1.1.3 三分钟`, где `1.1.3` означает `номер части.номер тома.номер главы`; при извлечении необходимо взять только последний сегмент `3` как «номер главы», а `三分钟` — как «заголовок главы».
- Zongheng — платформа с делением на тома, при загрузке используется только номер главы внутри тома; нельзя загружать трёхуровневую нумерацию вроде `1.1.3`, `2.4.17` как есть; итоговая запись допустима только в формате вроде `第3章 三分钟`.
- Заголовок главы Zongheng обязательно заполнять вручную в полном формате: `第{章号}章 {章节标题}`.
- Между `章号` (номером главы) и `章节标题` (заголовком главы) обязательно сохранять **1 пробел**.
- Например: `第1章 天亮了`.
- Нельзя переносить в поле заголовка суффикс платформы из имени файла (например, `_纵横版`).

### 2) Источник метаданных

- Обязательно прочитать `纵横小说/readme.md` или `纵横小说/README.md` и извлечь как минимум следующее:
  - имя пользователя Zongheng Chinese Net
  - пароль Zongheng Chinese Net
   - ID книги Zongheng (только цифры, например `11997642`; выбрать значение, соответствующее текущей главе, по «правилу определения ID книги»)
   - название романа (название книги, для проверки названия книги перед загрузкой)
### 2.1) Проверка платформы (обязательно)

После чтения `纵横小说/readme.md` (или `纵横小说/README.md`) необходимо проверить, равен ли его первый заголовок первого уровня `# 纵横中文网分发配置`:
  - **Совпадает** → продолжить последующий процесс
  - **Не совпадает** → немедленно остановить загрузку и сообщить пользователю об ошибке: `README.md 平台标识与当前 Skill 不符：预期"纵横中文网分发配置"，实际读取到"{实际读取到的标题}"。请检查是否将其他平台的 README.md 误放到了当前工作目录。` (Идентификатор платформы в README.md не соответствует текущему Skill: ожидалось «纵横中文网分发配置», фактически прочитано «{фактически прочитанный заголовок}». Проверьте, не положен ли в текущий рабочий каталог README.md другой платформы.)
### 3) Источник журнала распространения (обязательно)

- Обязательно прочитать `纵横小说/分发记录.md`:
  - если файла нет, сначала создать его, затем выполнять распространение.
  - используется для запроса соответствия «уникальный ключ главы -> ID главы» и определения для главы «режима создания» или «режима изменения».

### 4) Правило определения названия книги (обязательно)

- Если у романа нет частей: название книги берётся из «названия романа (названия книги)» в `readme.md`/`README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): название книги — название той части, в которой находится глава; нельзя ошибочно использовать общее название.

### 4.1) Правило определения ID книги (обязательно)

- Если у романа нет частей: ID книги берётся из парной записи к «названию романа (названию книги)» в `readme.md`/`README.md` каталога этой платформы.
- Если у романа есть части (несколько частей): ID книги берётся из парной записи к названию той части, в которой находится глава.
- Запрещено использовать ID книги общего названия для глав частей или ID книги одной части для глав другой части.

### 5) Шаблон `分发记录.md` (при первом создании использовать напрямую)

```markdown
# 纵横中文网分发记录

> Назначение: фиксирует соответствие «уникальный ключ главы -> ID главы Zongheng», чтобы процесс распространения мог определять «режим создания / режим изменения».

## Описание полей

- `章节唯一键` (уникальный ключ главы): фиксированный формат `纵横书籍ID|分部名|卷号|卷名|章号|章名`
- `纵横书籍ID` (ID книги Zongheng): соответствует ID книги в `纵横小说/readme.md` или `纵横小说/README.md`
- `章节Id` (ID главы): чистое число, возвращаемое после сохранения главы
- `最近操作` (последняя операция): `新建` (создание) или `修改` (изменение)
- `更新时间` (время обновления): `YYYY-MM-DD HH:mm:ss`
- `备注` (примечание): необязательно

## Таблица записей

|章节唯一键|纵横书籍ID|章节Id|最近操作|更新时间|备注|
|:--|--:|--:|:--|:--|:--|
```

## Процесс выполнения (строго по порядку)

### Шаг 1: чтение локальных входных данных

1. Прочитать и разобрать `纵横小说/readme.md` (если нет — читать `纵横小说/README.md`).
2. Убедиться, что получены: аккаунт, пароль, целевой ID книги (выбранный по «правилу определения ID книги»), целевое название романа.
3. Прочитать `纵横小说/分发记录.md` и построить соответствие «уникальный ключ главы -> ID главы».
4. Прочитать указанные вами файлы глав и извлечь для каждой главы: номер тома, название тома, номер главы, название главы, основной текст, слово от автора.
5. Собрать заголовок страницы: `第{章号}章 {章名}` и проверить, что «между номером главы и названием главы только 1 пробел».

### Шаг 2: вход в авторский кабинет

1. Обязательно открыть новую вкладку браузера и перейти по адресу:
   - `https://zuozhe.zongheng.com/front/book-manage`
2. Эта новая вкладка используется только для текущего процесса загрузки в Zongheng, вкладки других задач не использовать повторно.
3. Если состояние входа недействительно или вход не выполнен:
   - войти, используя имя пользователя и пароль из `readme`/`README.md`.
4. Если после входа появляется капча или вторичная проверка:
   - обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成» (вход завершён).
   - до получения обратной связи «登录完成» не продолжать никакие дальнейшие шаги.

### Шаг 3: переход на страницу целевой главы (создание / изменение — одно из двух)

1. Перед началом каждой главы сначала проверить в `纵横小说/分发记录.md`, есть ли уже у этой главы `章节Id`.
2. Если у этой главы **нет** ID главы (режим создания), перейти по адресу:
   - `https://zuozhe.zongheng.com/front/book-upload?id={书籍Id}`
3. Если у этой главы **уже есть** ID главы (режим изменения), перейти по адресу:
   - `https://zuozhe.zongheng.com/front/book-upload?id={书籍Id}&cid={章节Id}`
4. Обратите внимание: в режиме создания после перехода в URL ID главы не появляется, его нужно получить обратной проверкой по списку черновиков после сохранения.
5. `{书籍Id}` обязательно берётся из `readme`/`README.md` и должен быть только цифрами.

### Шаг 4: двойная проверка страницы (название книги + информация о томе и главе)

1. Проверить, что название книги в левом верхнем углу страницы совпадает с названием книги романа из `readme`.
2. Проверить номер и название тома после `卷：` (том:) в верхней части страницы: они обязаны совпадать с текущим файлом главы.
3. Номер и название главы, показанные сразу после `卷：...`, обязаны совпадать с целевой главой.
4. При непрохождении любой проверки немедленно остановить загрузку текущей главы и сообщить об ошибке, слепая загрузка запрещена.

### Шаг 4.1: обязательное подтверждение во всплывающем окне выбора тома (новое, обязательно к выполнению)

1. Перед заполнением содержимого каждой главы обязательно нажать вход `卷：` в левом верхнем углу интерфейса редактирования главы, открыв всплывающее окно выбора тома.
2. В окне обязательно явно выбрать «название тома, к которому относится текущая глава» (полностью совпадающее с названием тома, извлечённым из файла главы).
3. Обязательно нажать в окне «确认» (подтвердить), чтобы завершить переключение / подтверждение тома; недопустимо лишь смотреть и не нажимать.
4. После подтверждения снова проверить, что показанное на странице `卷：{卷名}` совпадает с целевым томом; при несовпадении запрещено продолжать заполнение.
5. Нельзя наследовать состояние выбора тома от предыдущей главы; в цикле по нескольким главам этот шаг повторяется для каждой главы.

### Шаг 5: заполнение заголовка главы

- Заголовок главы обязательно заполнять вручную в полном формате: `第{章号}章 {章名}`.
- Между `章号` и `章名` обязательно строго сохранять 1 пробел.
- Если на странице уже есть старый заголовок, сначала выделить всё и очистить, затем внести заголовок этой главы, чтобы избежать перепутывания глав.

### Шаг 6: заполнение основного текста

1. В поле редактирования основного текста ввести основной текст этой главы.
2. Необходимо гарантировать, что текст взят из указанного вами файла главы, без перепутывания глав.

### Шаг 6.1: норма верного по абзацам ввода основного текста (новое, обязательно к выполнению)

1. При чтении основного текста главы обязательно сохранять границы абзацев исходного текста (пустые строки / разделители абзацев) и записывать по абзацам, нельзя сжимать всю главу в один длинный абзац.
2. При записи в редактор обязательно использовать «стратегию записи на уровне абзаца» (вставка по абзацам), гарантируя, что каждый абзац на странице — самостоятельный узел абзаца.
3. Запрещено перезаписывать целым блоком простого текста, теряя деление на абзацы; запрещено схлопывать переводы строк в один пробел.
4. После записи обязательно выполнить обратную проверку деления на абзацы: число абзацев на странице должно совпадать с числом непустых абзацев исходного текста (либо границы абзацев должны сохранять смысловую эквивалентность после автоматической очистки пустых абзацев платформой).
5. Если проверка деления на абзацы не пройдена, сначала очистить основной текст и записать заново; если после повтора сбой остаётся — остановить текущую главу и записать «сбой сохранности деления основного текста на абзацы».

### Шаг 7: заполнение слова от автора

- Слово от автора **появляется прямо** на странице редактирования главы, дополнительные кнопки нажимать не нужно.
- Напрямую найти область ввода «слова от автора» и внести содержимое этой главы.
- Перед вводом рекомендуется выделить всё и очистить старое содержимое, чтобы не склеивать с прежним текстом.

### Шаг 8: сохранение черновика и обратная проверка ID главы

1. В режиме создания нажать кнопку: `存为草稿` (сохранить как черновик).
2. В режиме изменения нажать кнопку: `更新草稿` (обновить черновик).
3. Дождаться сообщения страницы об успехе (или эквивалентного состояния успеха).
4. После успешного сохранения переключиться на страницу списка черновиков и определить ID главы обратной проверкой:
   - перейти на `https://zuozhe.zongheng.com/front/book-manage/draft?id={书籍Id}`.
   - найти в списке черновиков целевую главу, нажать «修改» (изменить).
   - извлечь из URL после перехода `cid` как ID главы.
5. Записать «уникальный ключ главы + ID главы + последняя операция + время обновления» обратно в `纵横小说/分发记录.md`:
   - если записи нет: добавить новую.
   - если запись уже есть: обновить `章节Id` (если изменился), `最近操作` и `更新时间`.

### Режим ускорения для непрерывных нескольких глав (рекомендуется)

> Цель: без ослабления действующих обязательных правил сократить затраты на повторные клики, повторные вставки и повторные определения.

#### A. Сначала пакетная предобработка, затем непрерывное выполнение в браузере

- Перед открытием страницы разом выполнить следующую предобработку:
   - извлечение номера / заголовка главы;
   - разделение основного текста и расширенных полей платформы (например, «слово автора» / текст настроек публикации);
   - предпроверка ограничений платформы (например, число знаков в заголовке, число знаков в слове автора, обязательные пункты публикации);
   - предварительное определение режима создания / изменения (по `分发记录.md`).
- Рекомендуется складывать результаты в единую временную очередь (например, объект в памяти либо `{каталог платформы}/.cache/content_parts/no_part/v{номер тома}/*.txt`, `{каталог платформы}/.cache/content_parts/p{номер части}/v{номер тома}/*.txt` + таблица соответствий); на стадии браузера выполняется только «взять данные → заполнить → сохранить».

#### B. На стадии браузера использовать «фиксированный вход + повторяющийся такт»

- Для каждой главы сохранять единый такт:
   1) открыть целевой адрес (по записи — создание или изменение);
   2) заполнить заголовок;
   3) заполнить основной текст;
   4) заполнить расширенные поля платформы (например, слово автора / настройки публикации);
   5) сохранить черновик;
   6) извлечь ID главы;
   7) записать запись обратно.
- Кроме «целевого адреса» и «вносимого текста», остальные действия по возможности держать в одном наборе локаторов и в одном порядке, избегая смены стратегии на каждой главе.

#### C. Вместо «разовой отправки всей партии» использовать «малые партии»

- Рекомендуется выполнять малыми партиями по `5–10` глав:
   - после завершения каждой малой партии сразу записывать обратно в `分发记录.md`;
   - затем переходить к следующей малой партии.
- Так даже при ограничении частоты, колебаниях состояния входа или смене вёрстки страницы пострадает только текущая малая партия, а прогресс всей партии не откатится.

> Три раздела D / E / F исполняются по единому правилу: в приоритете непрерывность партий и возможность отката; подсказки о проверке безопасности всегда считать блокирующими; сбои канала данных должны допускать деградацию.

#### D. Однократное «шумоподавление» для «частых всплывающих окон»

- Для неблокирующих напоминаний, многократно появляющихся на платформе (напоминание о числе знаков, обучающие слои, окна-подсказки), при первом появлении можно убрать шум и продолжить основной процесс.
- Только когда всплывающее окно реально блокирует критический путь «ввод / сохранение / отправка», повышать до обработки как сбой или ручного вмешательства.

#### E. Многоуровневая обработка сбоев: быстро пропустить, можно продолжить

- При сбое отдельной главы применять стратегию «записать причину и перейти к следующей главе» (если пользователь не требует остановки при первой ошибке).
- Для сбойной главы нужно зафиксировать минимально необходимую информацию:
   - уникальный ключ главы;
   - шаг сбоя (открытие страницы / заголовок / текст / расширенные поля платформы / сохранение / запись обратно);
   - ключевая подсказка страницы.
- После завершения партии догружать главы по списку сбоев отдельно, не застревая на них в основном цикле.

#### F. Ускорение канала данных (по желанию)

- В сценариях длинной пакетной автоматизации можно использовать `scripts/content_parts_server.mjs`:
   - без частей: `/parts/v/{номер тома}/{номер главы}`
   - с частями: `/parts/p/{номер части}/v/{номер тома}/{номер главы}`
   - плоский `/parts/{номер главы}` допустим только для временного использования в одной партии.
- Этот способ — средство ускорения; он не заменяет требования каждого платформенного Skill к определению ID книги, уникальному ключу главы, правилам записи обратно и обработке сбоев.

#### G. Патч защиты от неправильного применения при пакетном выполнении (рекомендуется включать по умолчанию)

- «Предварительное определение режима создания / изменения» служит только ускорению и не заменяет запрос к `分发记录.md` в реальном времени перед выполнением каждой главы.
- «Шумоподавление частых всплывающих окон» допускается только для небезопасных подсказок; если речь о контроле риска при входе, капче, проверке реального имени, подсказках безопасности аккаунта — всегда считать блокировкой и приостанавливать.
- В многоуровневую обработку сбоев нужно добавить «остановку при фатальной ошибке»: при несовпадении названия книги / тома (или произведения), ошибочном ID книги, неснятой аномалии состояния входа продолжать к следующей главе нельзя.
- При использовании канала данных (например, `content_parts_server`) обязательно предусмотреть путь деградации: при недоступности сервиса автоматически откатываться на чтение локальных файлов, не прерывая выполнение партии.
- В конце каждой малой партии обязательно выполнять сверку: `плановое число глав = число успешных глав + число сбойных глав`, причём для всех успешных глав должна быть выполнена запись `章节Id` обратно.
## Ключевые границы и жёсткие правила

- Zongheng и Qimao относятся к близким кабинетам, поэтому, кроме «проверки тома», остальной процесс (включая логику обратного определения ID главы) по умолчанию следует устойчивой практике Qimao.
- Zongheng — **платформа с делением на тома**, обязательно выполнять тройную проверку «название книги + информация о томе + информация о главе».
- Адрес создания фиксирован: `https://zuozhe.zongheng.com/front/book-upload?id={书籍Id}`.
- Адрес изменения фиксирован: `https://zuozhe.zongheng.com/front/book-upload?id={书籍Id}&cid={章节Id}`.
- После создания в URL нет ID главы, после сохранения `cid` обязательно определять обратной проверкой по списку черновиков.
- Кнопка сохранения в режиме создания — `存为草稿`; в режиме изменения — `更新草稿`.
- Заголовок обязан быть `第X章 标题` (между частями 1 пробел) и вноситься самим процессом, без опоры на прямое перенесение из имени файла.
- Zongheng — платформа с делением на тома, номер главы обязан использовать относительный номер внутри тома, без накопления между томами.

- При записи основного текста обязательно сохранять деление исходного файла на абзацы, категорически недопустим результат на диске «вся глава одним абзацем без деления».
- Слово от автора вносится прямо на странице, дополнительные кнопки нажимать не нужно.
- Итоговое действие — «保存草稿», а не публикация.
- Аккаунт и пароль используются только для текущего входа, не записываются в артефакты и не раскрываются.

## Обработка сбоев и откатов

- Сбой входа: сообщить об ошибке аккаунта / пароля и остановиться, не продолжая последующие главы.
- Перехват капчей: обязательно немедленно приостановить процесс, дождаться, пока пользователь вручную завершит проверку и явно сообщит «登录完成»; до получения этой обратной связи любые последующие шаги выполнять нельзя.
- Отсутствие элемента страницы или смена вёрстки: записать шаг сбоя и остановить эту главу.
- Несовпадение названия книги / названия тома / номера тома / информации о главе: остановить загрузку текущей главы и сообщить об ошибке.
- Окно выбора тома не открывается / не подтверждается / после подтверждения название тома не совпадает: остановить загрузку текущей главы и сообщить об ошибке.
- Проверка сохранности деления основного текста на абзацы не пройдена: очистить, записать заново и повторить; если сбой остаётся — отметить как сбой и остановить текущую главу.
- Сбой сохранения черновика: повторить для этой главы; если после повтора сбой остаётся — отметить как сбойную и перейти к следующей главе (если пользователь не требует остановки при первой ошибке).
- Сбой записи `分发记录.md`: процесс помечается как «частичный сбой (запись не записана на диск)» и предлагается ручная дозапись.

## Практический опыт и уроки текущего раунда (2026-05-22)

- Обратную проверку по черновикам **нельзя ограничивать текущей страницей**, обязательно подтверждать по страницам или поиском по всему списку; иначе легко пропустить уже сохранённые главы.
- Появление на странице «已保存到云端» (сохранено в облаке) не означает, что глава уже попала в черновики, **итоговая приёмка — по фактической проверке черновиков**.
- Основной текст обязательно записывать на уровне абзацев; после сохранения ещё и проверять число абзацев основного текста, чтобы «вся глава не схлопнулась в один абзац».
- Окно выбора тома должно быть замкнуто циклом «выбор целевого тома + нажатие подтверждения + повторная проверка названия тома», нельзя полагаться лишь на состояние по умолчанию.
- Если на странице загрузки сохранение ведёт себя странно, но в черновиках запись стабильно ложится, можно использовать запасной путь «сначала создать черновик-заглушку, затем изменением перезаписать настоящий основной текст».
- При записи в `分发记录.md`, если в уникальном ключе главы есть `|`, его необходимо экранировать или использовать запись, не ломающую таблицу; иначе строка будет разбита на несколько столбцов.
- Встретив слой платформы / окно подтверждения, сначала нужно убрать блокирующее всплывающее окно, затем продолжать нажатие сохранения; не принимать напоминание за успех.
- Окончательный успех главы нельзя определять лишь по числу знаков на странице редактирования или подсказке облака, **критерий — в черновиках появился целевой заголовок + вход «修改» открывается + `cid` извлекается**.
